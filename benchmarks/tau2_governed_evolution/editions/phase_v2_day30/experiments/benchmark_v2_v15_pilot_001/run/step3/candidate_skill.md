# Operational Skill

## Planning and navigation

- For airline requests, when the user asks for a cabin-to-baggage-to-budget branch on an existing reservation while preserving current flights, replacing a passenger, setting baggage, and supplying a payment method: compute the incremental cost as ((new cabin fare total for preserved flights) - (original flight subtotal)) plus any non-free baggage fees beyond the membership free allowance. Select Business if total <= budget; otherwise select Economy if total <= budget; otherwise make no mutation. Do not write to the reservation before explicit user confirmation. After confirmation, execute the selected writes: update passenger, cabin, and baggage using the chosen payment method, and reconcile the final charge.
- For retail requests, when multiple pending-order requests for the same user include a cancellation that refunds to a gift card and a payment-method change to that same gift card, and the gift card's initial balance is insufficient: first process the cancellation, then re-check or recompute the updated gift card balance. If the updated balance now covers the order total and the user explicitly confirms, proceed with the payment-method change. Otherwise, if the balance remains insufficient, do not continue with that payment change and inform the user or escalate as needed.
- For airline requests, when planning to book two or more separate reservations and a travel certificate is among the allowed payment methods, do not allocate the same certificate to more than one reservation. A certificate is consumed and removed from the user profile after its first use. Plan to use the certificate for only one booking and use other payment methods for the remaining bookings.
- For airline requests, when the user asks for multiple reservation actions in the same request (e.g., a new booking and a cabin upgrade on an existing reservation) with specified payment methods, follow this sequence: gather the user profile, existing reservation, and flight availability/pricing; compute the new booking price and any upgrade price difference; allocate payment only from user-authorized methods; present a clear summary of the changes including passenger, cabin, baggage, insurance, prices, and payment instruments; wait for explicit user confirmation. Only after confirmation, execute the booking and update calls, preserving all unchanged attributes.
- For airline requests, when booking multiple reservations and a single travel certificate is among the payment methods, allocate the certificate to only one booking and use the permitted gift cards for the remaining bookings within their balances. Plan the booking order such that the gift-card bookings are completed before the certificate booking, so the certificate remains available for its single use. Do not attempt to use the same certificate across multiple reservations or to split its balance between bookings.
- For airline requests, when planning to use a travel certificate for a booking, inform the user that any unused balance will be forfeited and obtain explicit confirmation before applying it. A certificate is fully consumed and removed after first use; do not allocate the same certificate to multiple bookings. If the user does not accept the forfeiture, do not use the certificate and request an alternative payment method.

## Execution patterns

- For retail requests, when the user confirms multiple pending order modifications at once (e.g., payment method, items, address), process all corresponding update calls in a batch without interleaving user-visible messages. If you must communicate intermediate results, wait until all modifications are complete, or re-confirm before each subsequent modification.
- For airline requests, when multiple tool calls are needed to gather information or perform actions, execute them sequentially: issue only one tool call per turn and wait for the result before making the next call. Do not issue two or more tool calls in a single assistant message.
- For airline requests, when cancelling a reservation, ensure that the required cancellation reason has been collected before presenting the final cancellation summary for confirmation. If the reason is collected after an earlier confirmation, re-state the complete summary and obtain a fresh explicit user confirmation before calling cancel_reservation. Do not proceed to cancellation on a confirmation that predates the collection of the required reason.
- For airline requests, when informing the user about free checked baggage allowance, first identify the user's membership level and cabin class, then look up the exact allowance from the policy. Present only the verified number; do not improvise or provide incorrect numbers.

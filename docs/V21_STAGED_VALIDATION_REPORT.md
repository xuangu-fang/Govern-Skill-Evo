# v21 分阶段真实模型复验

日期：2026-10-10。执行范围为 1 次 Memory、3 次固定输入 Review、2 次固定输入 Fusion，共 **6 次真实调用**，没有重试。对应前三步的最小强化；实现说明见[退化保留](V21_REGRESSION_RETENTION.md)、[证据比较](V21_EVIDENCE_COMPARISON.md)和[提案依据](V21_FUSION_PROPOSAL_BASIS.md)。

**结论：Memory 的退化保留获得一次正面验证；行李 Review 的关键证据遗漏仍存在；Fusion 减少了送审，但出现过度筛选风险和一次引用错误。不能据此宣布 v21 语义验证通过或直接进入完整调度。**

## 1. 验证设置与比较边界

通过既有 Prompt 构建器、transport 和 validator 执行。Memory 使用既有 run_memory_update 保存与复验；Review/Fusion 在各自阶段停止，不调用 Editor 或 Replay。独立请求可以并行执行，但各阶段输入相互独立，没有将新 Memory 偷换进冻结的 Fusion 输入。

| 阶段 | 固定输入/旧输出 | 新提示 | 总输出预算 |
|---|---|---|---:|
| Memory | 原 update-48k 的同一输入及成功响应 | memory_update_v21.6 | 48,000 |
| Review | 原 treatment Review 6、5、3：行李、拆单、保障 | evidence-review-v21.5 | 各 24,000 |
| Fusion | 原 control、treatment 的各自固定 Fusion 输入 | issue-fusion-v21.4 | 各 24,000 |

模型请求与返回均为 deepseek-v4-pro，temperature=0，reasoning_effort=high。Memory 的 48,000 沿用旧成功调用的有效配置，通过原 transport 注入接口设置；默认源码预算没有修改。2,000 字符硬限制始终保留。

六组比较均验证 user payload、input_ref、引用映射、响应 schema、模型与上述运行参数不变，只更新各阶段系统提示。原代码和实验来源均冻结哈希，结束后确认未变化。旧输出直接复用，没有重跑旧 Prompt；因此是每组一次的新旧观察比较，不是同时随机化的消融或稳定性实验。control/treatment 是历史输入的名字，不是本轮重新开展完整两组消费。

## 2. Memory：关键来源缺口本次补齐

本次来源报告的未引用、仅单侧引用和不可读取列表均为空。引用完整是工程事实，不能单独证明归因正确。

人工核查 T009 新认识发现，它单独保存 business 两件行李的比较：两侧任务均成功，Parent 记录 nonfree_baggages=0、支付 $55，Candidate 记录 nonfree_baggages=2、支付 $155 且不合规。认识明确内部合同不可见，这一配对不能建立通用 business 行李规则，也不能解释其他 basic_economy 例子；原因和确切边界保留未知。该新 issue 的 attempts 为空，没有伪造对应修改或将观察强绑给无关 edit。

拆单认识保留“七人拆分成功合规、六人拆分合规但失败”，没有把失败归因到某一局部修改。保障认识保留用户知情选择与拒绝选择的不同分支，没有将所有转人工概括为有害。这些支持本次保留和有界解释有所改善，但新认识未进入本轮冻结的 Fusion 调用，尚未证明后续修改受益或更长跨轮稳定性。

确切旧正面事件为 `CURRENT/ed12295dba0354058acdf02017fda65a198b2cbbd49db08fea5fa9a469cb6c94/T022/R036/R1/E0013`。本轮另存两条事件及标签，详见 [已加载观察核查](../artifacts/v21_staged_validation_001/baggage-loaded-comparison.json)。二者是不同轮观察，不能当作 T009 的显式配对或单独证明因果。

**不通过的理由是未比较关键证据，不是 NO_EDIT 本身错误。** 不能强制其推导完整行李规则。结果表明仅增加通用比较要求，在这次真实调用中不足以修复遗漏；尚不能判断是长输入、证据组织、注意力分配还是判断偏差导致。

## 4. Fusion：送审减少，但不能当作质量通过

旧历史 control 输入上的新响应通过校验：**2 个 PROPOSE、8 个 NO_EDIT**，旧响应为 10 个 PROPOSE。两项送审是条件航班选择、乘客姓名拆分。其他覆盖方向转为 NO_EDIT，四条 OBSERVED_PROBLEM 均保留问题归属，未被藏入 unassociated_findings。

人工复查发现两点需要继续验证：

- 地址确认中将 Court 说成 Street 的可见行为错误被 NO_EDIT。理由主要强调用户已纠正、最终写入正确、没有违规且只有单例。这可以成为保守判断的理由，但不能自动否定确认文字的行为缺陷；本次尚未说明为何其不足以支持有限修订。不能把这项拒绝直接算作正确节省。
- 姓名提案要求避免 first_name/last_name 的重复 token。核实用户期望的姓名字段有依据，但把重复 token 本身当作普遍错误，可能超出单例证据的适用范围。该提案未经过本轮 Review，不能视为可直接实施的规则。

更新历史 treatment 输入上的响应完整返回，但包含 `current_finding_refs: ["F20", "F21", "34", "F30"]`，被原校验器以 **unknown F reference: 34** 拒绝。没有补成 F34，没有生成有效 result，没有送到后续阶段。失败原文和全部用量保留。

只作失败诊断读取时，该原文还提出在行李额度不可见时问用户或拒绝的做法，并承认不知道工具能否提供额度。这暴露了从未知追加确认/拒绝义务的风险，不能因为“建议更具体”就当作成功。该未通过响应不计入有效决策统计。

## 6. 后续建议

保留 Memory 本次有依据的改进，优先定位 Review 为什么忽略已加载正面观察。下一次应固定同一行李材料，检查相关证据的呈现和可定位性；不继续泛泛叠加提示，不加入预设答案，也不直接要求编辑。Fusion 应把引用生成稳定性与语义问题分开处理：格式错误不能人工修成成功，语义上还需检查“少提案”是否漏掉可修订缺陷，以及具体方向是否制造了无依据的普遍限制。

这些局部问题得到处理后，再用新 Memory 做一次受控串联。若之后生成候选，实际双维效果还需 Replay，不能用本轮文本判断代替效果验证。

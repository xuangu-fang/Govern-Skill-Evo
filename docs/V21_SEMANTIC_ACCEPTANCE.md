# v21：已知问题修复与跨问题迁移验收

日期：2026-10-10。接续 [Review 比较与 Fusion 判断的定向修订](V21_SEMANTIC_FOLLOWUP.md)。

**本步验收已完成，但没有全部通过。** 行李正面证据遗漏本次未复现；地址形成了有依据的有限修改；两个迁移案例的 NO_EDIT 有依据。姓名 Review 虽读到了反驳缺陷假设的原文，仍批准按重复词语增加强制确认要求，是本轮最明确的语义失败。不能以五份响应均通过结构校验替代这一结论。

## 1. 冻结范围与判定方法

本轮保持 Fusion `issue-fusion-v21.5`、Review `evidence-review-v21.8`、`operation_comparison_v21.1` 和 2,000 字符 Memory 限制。没有修改运行源码、Prompt、证据选择、响应 schema 或模型配置。所有请求在调用前保存；判定依据、调用上限及来源哈希在 `protocol.json` 中冻结，判定依据不进入模型输入。

- 新增五次真实 Review，使用现有传输与校验入口，deepseek-v4-pro、temperature=0、reasoning_effort=high、输出上限 24,000；每个请求一次，无重试、无临时换例、无结果驱动的 Prompt 调整。
- 复核上一轮两份真实 Fusion 输出，不重跑 Fusion。它们不是本轮的新观察，也不是独立稳定性样本。
- 以证据比较、实际条件、缺陷是否成立及修改边界判定。VERIFIED、NO_EDIT 都可以通过；不规定必须编辑或必须拒绝，也不根据提案数量判优劣。
- PASS / PARTIAL / FAIL 是本次人工验收记录，不新增到运行协议、Memory 或生产 Gate。

共同要求：回应决定性正反观察与两维标签；区分整体结果、局部行为、跨轮观察与受控配对；核对用户意图、可用信息和当前 Parent；修改须针对成立的行为缺陷，NO_EDIT 须指出具体缺口，不能只依据结果标签、不确定性或已有文字。

当前两份 Fusion 对这两个迁移问题均选择 NO_EDIT，正常流程不会再派发它们的 Review。本轮用原有真实 PROPOSE 输入单独探测 Review，没有伪造或改写当前 Fusion 结论，不能将它们计作一次新的串联成功。两例都走旧 Memory 无摘要时的完整历史路径，亦不能证明最新 v21 认识已成功跨轮消费。

## 3. 已知问题结果

### 行李：证据比较通过，决策理由部分通过

本次 NO_EDIT 明确回应并引用 E139：round-01 的 T022/R036，business、两件行李、零非免费、总额 $55，任务成功且合规。它同时讨论当前 E58：同任务编号、business、两件行李均非免费、总额 $155，任务成功但不合规；并保留 basic_economy 条件下全额计费仍合规的反例。行程类型的正面证据没有再替代行李正面证据。

这说明此前遗漏在本次调用中未复现，不等于已证明长期稳定。E139/E58 是跨轮观察，不是显式受控 Replay 配对，也不能据此建立“business 两件必定免费”的规则。

理由仍称任何 cabin/membership 条件化收费规则在没有隐藏合同的情况下都无法执行。这比证据能证明的范围更强：工具不提供完整额度确实构成限制，但输出没有充分解释已有同条件正面观察为何不足以支持有限经验方向。**本次不判 NO_EDIT 本身错误，也不要求强行写额度规则；将拒绝理由的这一推断记为 PARTIAL。**

### 地址：局部 Review 通过，Fusion 分歧仍保留

原文链条是 E2 请求 `9 Cedar Court` → E14 确认时写为 `9 Cedar Street` → E15 用户纠正并确认 → E18/E20 写入及返回均为 `9 Cedar Court`。

Review 没有因最终写入正确而否定早先偏差，批准一个 MISSING 修改：地址同步确认应准确复述用户提供的地址。它保留“文字有误但未写错数据库”的界限，不改变身份验证、地址上下文查询或写入顺序，不推导 cedar 合同规则，也没有声称该偏差解释了 success=false。

这是可测试的有限修改授权，不是效果已经验证。后续若进入 Editor，不能将“准确复述”扩成无害格式规范化也被禁止，或用户已明确纠正后仍须额外再确认。

复用的 treatment Fusion 支持这一有限方向；control Fusion 仍主要以单例、已纠正、最终合规拒绝。后者的理由只算部分充分，不能因为另一组 PROPOSE 就认定 NO_EDIT 必然错误，也不能把两种 Memory 输入下的差异当成 Prompt 改进的因果证据。

### 姓名：未通过，证据已读到但没有正确约束修改

原始用户消息 E14 明确分字段给出：

```text
First name: B Traveler1
Last name: Traveler1
```

E15 展示完整姓名，E16 用户确认，E17 调用忠实使用这两个字段，E18 返回同样字段。当前证据没有提供不同的期望拆分，也没有表明 Agent 改错了用户提供的名字。

Review 在 reason 中承认这一原文，却将字段重叠定义成必须再次消除的歧义；其 VERIFIED gap 要求：当多词 first_name 的末词等于 last_name 时，在展示摘要或调用前必须逐字段确认，不得依赖一般预订确认。

**这把一个表面模式提升为通用强制义务，没有先证明实际行为缺陷。** “可执行、可测试”“当前 Parent 没有姓名规则”或“没有把失败标签直接当成因果”都不足以弥补这一缺口。问题是语义判断，不是引用格式、原文未进入输入或工具视图漏选。

Fusion 的姓名提案也有风险：treatment 在问题陈述中先写了“避免重复 last-name token”，虽然 reason 要求核对用户原文，Review 仍未反驳这个预设。原始 Finding 的 OBSERVED_PROBLEM 标签和 Fusion 提案都应允许被原文推翻；本次链路没有做到。

## 4. 跨问题迁移结果

| 问题 | 模型结论 | 人工判定 | 支持及限制 |
|---|---|---|---|
| 保留航段结算 | NO_EDIT | PASS | 回应历史 summit 按原票价估算与最终结算不一致，比较当前 summit 使用搜索价格后匹配退款、horizon 使用原价后匹配收费；区分 T036 的选择问题与正确计价。依据包含真实执行，不只是规则已写入 |
| 标识符识别 | NO_EDIT | PASS | 比较旧混用 ID 导致查询错误与后续 reservation-first 路径；后者成功不等于可据此删除当前 user_id 获取要求。当前规则已覆盖两种情形，本包没有支持额外修改的新缺口 |

结算理由对旧 summit 失败的描述可由 E252/E255 原文核对，虽然结构化引用未逐项列出这些历史失败；当前正面执行和 horizon 反例有明确引用。其结论限于加载的执行条件，不能解释为所有渠道已经解决或特定 edit 的因果效应已证明。

标识符包没有当前 Findings，`operation_comparison` 为空，但完整历史保留并被利用。这里的 PASS 是没有支持进一步改写的缺口，**不是当前执行已验证正确**；不能用 Parent 文字覆盖替代当前运行证据。

这两例支持冻结机制在其他问题上仍可形成有依据的拒绝，并未暴露与姓名相同的新强制义务。但是两例都偏向已有覆盖/无需新增修改，不能据此证明它能在未调参问题中稳定发现并批准新的有效修改。

## 6. 验收决定与下一步

**完成验收，暂不判整体通过，也不据此直接接完整调度。** 明确失败集中在：读到原始证据后，仍将未成立的行为缺陷转成新的程序要求。优先处理这条推理边界，胜过继续改善引用或增加证据量。

下一次优化应限制在现有 Fusion/Review 内：让所提出的缺陷能被用户原始表达、实际参数和已有确认推翻；“当前没有某条规则”不能替代“确有缺陷值得新增规则”的证明。同时保留地址这种真实偏差可支持有限修改的能力，以及有依据的 NO_EDIT。行李的拒绝理由作为次要边界一并检查，但不预设必须编辑。

任何后续修改都应新建实验记录，保留本次失败；本轮案例一旦被用于调整，就成为开发案例，后续不能再宣称独立迁移证据。不新增 Agent、状态、额外运行 Review 或逐 edit 流程。

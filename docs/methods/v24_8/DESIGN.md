# ALFWorld v24.8 设计方案

v24.8 从共同的 Initial Skill 和空 Memory 出发。主目标是让训练过程学出一条搜索规则，Actor 在中途查空时，仍能凭当前观察、动作菜单和最近两步选出下一站。Pick Two 是这项能力的第二个应用场景，放好第一件后需要重新选择动作。一次 134 题 Test **至少成功 117 题**即达到成绩目标。步数是次要指标。

## 实验依据

v24.7 和 SkillAdam 在同一批题上分别成功 115 和 116 题。共同成功 109 题，仅 v24.7 成功 6 题，仅 SkillAdam 成功 7 题。后面这 7 题中，5 题的 v24.7 轨迹在取到第一件物体前耗尽步数，另 2 题是 Pick Two。v24.7 已在 R02 学出利用目的地线索，在 R05 学出优先检查开放表面。值得优化的是这些优先级在首次生效之后怎样接续。历史 Test 用于选研究问题与最终同题比较，模块的指令、离线样例和正式训练输入均取自方法描述或训练侧证据。[v24.7 成绩](../../../artifacts/methods/v24_7/v24_7_alfworld_20261108_020254_test134/summary.json) · [SkillAdam 成绩](../../../artifacts/methods/skilladam/alfworld/native_retry/skilladam_alfworld_retest134_20261107_231301/summary.json) · [v24.7 最终 Skill](../../../artifacts/methods/v24_7/v24_7_alfworld_20261108_020254/final_skill.md)

## 两处 prompt 改动

### Diagnosis：找到第一次倒回去的选择

v24.7 已要求检查成功路线和第一次查空。v24.8 把提案落在一个更具体的位置：当 Actor 已按 Parent 的偏好走了几步，找出它第一次开始重走、错过阶段切换或丢掉已取得进展的动作。指出当时的两个竞争选项、可见线索和能区分它们的偏好。再到同批有相关证据的轨迹里，检查继续、切换或退出的条件。必要的决策点放进原有 `basis`，行为本身写入 `text`。

训练侧例子是 R04 的 `train:0034`。Actor 依次检查抽屉 1 到 4，第 9 步折回抽屉 1，后来又走到抽屉 5。可以从该步菜单检验什么规则能让搜索往前走。R05 的 `val:0007` 则是一项约束：Actor 已连续打开多个抽屉，仍然失败。由此要区别两个选择：当前值得搜索哪一类地点，以及已选定一类后怎样在其中前进。后者的证据不能用来规定所有房间都要先查完抽屉。编号是可供归纳的一种线索，具体优先级由本批证据产生。[R04 训练轨迹入口](../../../artifacts/methods/v24_7/v24_7_alfworld_20261108_020254/rounds/R04/parent_runs/train_0034/record.json) · [R05 训练侧反例](../../../artifacts/methods/v24_7/v24_7_alfworld_20261108_020254/rounds/R05/parent_runs/val_0007/record.json)

多件任务用同一原则。沿着第一次有效放置往后看，第二件是否仍有可见线索，哪个动作撤销或重复了第一次交付，下一次放置是否推进了整题。R04 的 `train:0036` 候选少了对同一钥匙扣的重复取放，最后仍未完成；`train:0038` 的 Parent 把两件不同的盐罐放到了同一个边桌。只有训练证据支持时才提出相应更新。搜索与交付若能分别采用，就给不同 ID。每轮由证据决定提案数量。[R04 候选轨迹](../../../artifacts/methods/v24_7/v24_7_alfworld_20261108_020254/rounds/R04/candidate_runs/train_0036/record.json) · [R04 成功轨迹](../../../artifacts/methods/v24_7/v24_7_alfworld_20261108_020254/rounds/R04/parent_runs/train_0038/record.json)

### Preconditioner：用中途菜单决定审核结论

v24.7 已经要求检查第二个决策点。v24.8 的变化是让这个检查决定提案能以多大范围进入 Editor。对声称能连续推进的更新，从引用轨迹中选一个首次偏好已经用过、菜单里仍有竞争选项的时刻。仅按当时 Actor 可见的输入，在现有 `reason` 中回答三个问题。

1. Parent 仍允许哪两个具体动作？新文本让哪个动作或哪一组动作优先？依据在当前观察、菜单或最近两步的哪里？
2. 下一次落空后，这个依据还在吗？到达该类末尾、出现目标或需要交付时，旧的优先级怎样结束？只检查与本提案有关且有证据的边界。
3. 相近的成功轨迹里是否有应该保留的选择？例如可直接拿到另一件时，继续搜索会不会反而绕路？

若能区分有意义的选择，保留规则；若只能解释第一步，用 `REPLACE` 写成证据支持的局部优先级，或收窄为一次性动作；若与 Parent 在相关菜单上等价、又找不到可执行的修正，使用 `WITHDRAW`。证据容许几个并列动作时可以保留偏好。遇到证据不足时不强行编出唯一下一站，也不把完整轨迹里可追溯的物品编号或目的地当成 Actor 此刻知道的事实。

## 其余模块与实验预算

Editor、Replay、Gate、Memory 和 Actor 沿用 v24.7。Editor 已能把触发、继续、退出写成同一个独立补丁；Preconditioner 应把必要行为交进有效 `text`。Replay 按实际配对结果归因，Gate 逐 ID 发布。R04 的局部改善适合指导下一次诊断，不能单独证明整题收益。预算仍为六轮、同批 Parent/Candidate 执行和原有模块调用。

## 验证与成功判据

1. **离线走查一次。** 从上述归档重建 Actor 在决策前看到的输入。检查能否在 R04 的回头点区分前进与重走、能否在 R05 的反例限定同类连续搜索的范围、能否在 Pick Two 区别“少拿回一次”和“完成第二次交付”。验收看提案能否指向实际可用动作、依据是否可见、边界是否与成功轨迹相容。沿用原有结构校验。
2. **正式训练一次。** 使用与 v24.7 相同的 Initial Skill、空 Memory、Actor 环境、50 步上限与六批 10、10、10、10、10、7 题。训练结束时追踪 `basis → 有效 text → Gate → R06 发布文本`，报告哪条学得的规则能解释一个真实的中途选择。
3. **最终 Test 一次。** 用 R06 发布的 Skill 做全部 134 题，以 117/134 为成功线。对 v24.7 报同题新增成功数和新增失败数，净增至少 2 题即过线。额外列出全程未取物的题数、Pick Two 成功数、双方共同成功题的配对步数。若成绩过线但发布文本没有学到续行规则，分别报告成绩达标和方法证据不足。

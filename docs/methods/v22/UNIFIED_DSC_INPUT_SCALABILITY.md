# V22 全流程证据输入与长期 Token 可扩展性审计

日期：2026-10-16。对象：冻结 `v22.unified_dsc.v3`。本次仅做归档审计、独立输入原型和离线压力测试；没有模型 API、ALFWorld episode、正式迁移或实验恢复。

## 1. 判断与边界

**当前 v3 不具备直接启动 57 项、五轮实验的完整条件。** 无损共享可大幅降低已有材料和重复较多轨迹的输入，Editor 职责视图还可能降低额外开销；但新的输入表达尚未经真实模型验证，50 步持续变化轨迹的 Replay/Memory 仍可超过 400,000 字符。无限累积的有效认识与证据也不可能在完全展开、完全保真前提下具有固定上下文上限。

这属于证据消费和运行协议的扩展问题，不意味着统一 D/S/C 算法必须推翻。研究职责和正常调用数量均可保留。对规模风险的处理也不应变成让 Fusion 更倾向 Keep 或让 Editor 更容易拒绝更新。

另有独立的运行兼容问题：当前协议每批最多 10 项、严格两轮、Train-only。拟议 12+12+12+12+9 和 Train+Selection 必须另立用途明确的实验协议，并适配 Adapter、分类、Gate、学习与运行预算；不能只改 manifest 或把 Selection 改名为 Train。Selection 改作学习后不能继续作为独立 Selection 评价集合。本报告不选定 57 个真实任务，也不运行这些任务。

## 2. 审计对象、计量口径与实际成本

源码读取隔离修订目录 `experiments/methods/v22/12_contract_alignment/revision`，并读取实际归档的完整 System/User messages 与 HTTP 调用记录。08 为旧 `v22.grouped_update.v1`，15 为当前 v3 的八项输入；二者明确区分。

- **工程字符数**：`len(json.dumps(messages, ensure_ascii=False, separators=(",", ":")))`，含外层 JSON 转义；400,000 限制采用此口径。
- **正文字符数**：System/User content 长度之和；通常小于工程字符数。
- **真实 Token**：仅从保存的服务 usage 读取，不能把字符当 Token。
- **原型 Token**：仅用正文字符数/4 至 /2 做密度敏感性估算，既不是 DeepSeek tokenizer，也不是上下文上界。新编码的数字与引用密度变化尤其可能使比率漂移。未获得本地对应模型 tokenizer，未联网获取。

归档审计的 15 个样本均通过 messages 与 call 内请求一致性检查。失败/恢复的相同消息不当作独立算法样本或重复获益。

|---|---:|---:|---:|---:|
| 分类 | 3,006 | 140,036 / 41,019 | 3,006 | 131,044 / 38,531 |
| Diagnosis | 4,742 | 182,565 / 53,888 | 4,742 | 172,176 / 51,174 |

08 R1/R2 Parent 各为 240/235 条步骤记录，双侧学习为 415/474 条。最新八项 v3 的 Diagnosis 为 120,984 工程字符 / 36,049 输入 Token；Editor 为 127,034 / 37,704（同一输入发生的技术失败不影响输入体积统计）。

08 R2 学习实际正文为 363,710 字符，工程字符为 398,816，余量仅 1,184；当时失败却是输出 `finish_reason=length`，16,384 输出上限被推理占用后截断，并非输入超限。提高输出预算没有解决输入增长。

### 输入增长的三种来源

**A 当前批次。** 分类、Diagnosis、Fusion、Editor 均拿到全批 Parent；学习拿到全批配对 Parent/Candidate。步骤数增加、每个观察更长、候选动作更多，都会增大输入。08 R2 学习内层字段：runs 136,515 字符；command_sets 79,191；sources 30,345；update_context 14,778；grouping 6,095；Plan 2,857；Parent/Candidate 2,821/4,426；diff 4,580；机械 current_run_facts 6,490。System 不是主要成本。

**B 跨轮历史。** v3 每次消费全部有效 Effect 和累计 basis。替换 Effect 继承旧 basis 和未退役 limits，去重仅针对完全相同内容；固定 Effect 数不等于固定输入。没有把历轮完整轨迹递归塞回 Memory，所以不是必然指数增长；在每轮增加固定量证据时，单次历史通常线性增长、多轮累计读取可近似平方增长。有效 claim/limits 自身也没有固定大小上界。

**C 重复展开。** 08 R2 的 147 个 command_sets 含 4,191 个命令条目，只有 367 个不同命令字符串；命令字符串总长 65,402，去重后 8,466。完全相同观察重复约 26,813 字符；机械事件 sources 目录占 22,409；grouping 在 root/update_context 重复 6,095。不同阶段还重复读同一 Parent+Memory。这些统计是冗余潜力，不是净 Token 节省，原型计入索引和说明开销后才比较。

v3 已经把 08 历史中重复的 actual_update 按上下文共享，并不展示历史事件的大动作列表和旧 Findings 解释全文；这些既有收益不能算作本次新增优化。v3 对历史动作机会也已有边界：不能从省略的历史 admissible 列表推断某动作当时可用。

## 3. 从职责确定证据需求

| 阶段 | 必须保持的语义 | 可先做的整理 | 不应自动删除 |
|---|---|---|---|
| 分类 | 全部 Parent 的顺序行为、任务要求、当前状态、结果、重要差异 | 命令原子共享、观察文字共享、公共协议一次展示 | 成功任务、局部进展、不同决策路径；不能用成败替代分类 |
| Diagnosis | 当前 Parent、真实能力、失败与有效行为、可调整 Update 的证据 | 保留全部事件，用共享表示减少重复；机械来源目录生成 | 未被预先猜中相关的条件，不把未展示当不存在 |
| Fusion | 完整原始 Plan、能力、Parent 差异、可比较历史编辑响应、反例与限制 | 当前证据无损共享；全有效 Effect 作用目录；历史实际更新共享 | 为支持新方向所必需的旧 diff/行为，跨组响应、未知条件 |
| Editor | 完整 Parent Skill、有效 Goal/Update/Watch/Open、条件、强度、依赖和保留要求 | 独立落实视图；精确授权来源闭包；减少不相关历史 | Plan 中的例外、条件、义务强度；不能独立选择新策略 |
| Replay/Memory | 全任务双侧结果、实际 diff/Editor、两侧机会、行动和反馈、未触发与未执行之别 | 共同更新只展示一次；所有事件可逆编码；历史共享 | 组外副作用、成功保持、反例；不能只取 Watch 命中或失败任务 |

当前 `prepare_grouped_learning` 同时提供有效 Plan、Editor 映射、diff、全配对执行和已有 Memory；单次 `post_gate_learning` 产生 Findings 和 Memory delta。原型保持这种职责分工，没有增加轨迹总结 Agent。

## 4. 独立原型及候选层级

原型只在 [16_input_scalability](../../../experiments/methods/v22/16_input_scalability/README.md) 中，正式运行器不导入它。

### P1：全量、确定性、可逆共享

继续保留现有 runs/steps/command_sets/Plan/Effect 信息，通过消费编码减少重复，**没有选择或删除事件，也没有生成语义摘要**：

1. 不同 command_sets 中相同命令用共享原子索引，保留列表顺序、重复次数及全部未选动作。
2. 相同长文本或观察的精确句段/换行片段共享；独特文本保持原样。`@concat` 仅按原顺序拼接，不插空格、不改写事实。
3. steps 重复字段名改为 columns+rows；缺键与 JSON null 分开，保留每个事件和顺序。
4. 重复的大对象共享，如分组、协议和部分更新上下文。
5. 仅当完整事件来源目录精确等于 runs 的全部 0/step 来源时，按明确规则生成 `P1:step/C1:step`，静态来源仍保留。若目录是子集或不同结构，则不套该规则。

编码可完整还原原消费视图，原始归档不改变。这里复用的是已有证据结构，新增的是输入表达约定，不是统一轨迹摘要。即便可逆，也需要模型理解引用和表格；不能直接附在旧 Prompt 后即认定模型消费正确。正式迁移应只对齐一次路径/引用说明，并给出独立消费版本。

### P2：Editor 落实视图（条件性候选）

原型保留完整 Parent 和有效 Plan、能力、基础协议、分组；保留 requirements.basis 明确事件及前后相邻步骤，保留明确引用 Effect 的全部 basis，移除不相关完整轨迹/历史。逐项输出显示范围与原始 digest，声明省略不等于不存在。

**这不是已证明充分的语义闭包。** ±1 是待验证的工程窗口；分组中的跨任务比较可能需要更远步骤，来源图闭包不能从任意自然语言中恢复全部隐含依赖。此外，非连续窗口首行的真实前观察可能未展示；沿用旧“上一条观察就是动作前观察”的规则会错误连接跨间隙事件。P2 原型未补齐这一契约，未来必须显示片段边界与原始 observation_before，不能按相邻展示行推断执行相邻性。故 P2 的体积收益只作为设计候选，不能据此投产或阻断不确定的合法编辑。正式方案应由有效 Update 明确实现所需条件；遗漏影响落实时使用现有 issues/Watch，不能让 Editor 在后台重新规划。

### H：历史目录/正文分离（设计边界）

长期方向是“全部有效 Effect 的作用认识+限制目录”与“有依据展开的历史响应证据”分开。历史全档案仍保留；选择不得以 group ID、任务名称、近期优先或成败单独决定。

本次加入 `cards_only_insufficient` 对照：保留所有 active claim/limits 和来源摘要索引，隐藏历史 basis 正文。它确实省空间，**但不合格作为独立 Fusion/学习方案**：模型不能检查旧认识是否误读行为，也不能据原始条件比较适用性。归档 hash 可追溯不等于模型已经看见证据。这个对照被保留用于揭示代价，不推荐采用。

可立即设计且无需语义猜测的展开规则是：Editor 展开有效 Plan 明确依赖的 Effect/事件；学习展开其正在对照或修订的作用证据。但“Fusion 当前原始 Update 尚未显式引用哪些历史”以及“模型尚未判断将修订哪条 Effect”不能靠同组/关键词窗完整解决。当前单次调用接口不支持模型先选择证据再读取而保持相同一次请求。对这些阶段，五轮首选仍应是完整紧凑历史；不要先制造不可靠的相关性筛选。

未来若超过其容量，应另行验证一个条件化证据选择契约：全目录可见、选择理由可审计、历史支持和反证均可展开、未展开证据不得冒充已核验、显式来源可见性校验。没有得到这样的规则前，不承诺任意长程固定 Token。基于新旧事实保留所有有效未知条件，比机械只留“最新结论”更重要。

## 6. 五轮压力测试

共 **205 个输入情境**：5 个真实材料反事实重编码，以及 4 种轨迹×2 种历史增长×5 轮×5 阶段=200 个合成视图。每个视图做 P1 解码全等断言；P2/cards 的保留与遗漏另行说明。

所有五轮数据明确标记 `SYNTHETIC_CAPACITY_ONLY`，从 08 结构按固定顺序克隆，不依据模型输出或成败挑选。新增 task/run 使用 synthetic 身份；不代表实际 57 项任务、独立执行或分类结果。分组文本和 outcome 仅作大小模板，未伪造为真实可运行输入。不存在任何 Gate 或 Memory 正式发布。

四种轨迹情境：

- `observed_mix`：沿用真实长度分布，顺序复制至 12/9 项。
- `repeat50`：每条轨迹补到 50 步，使用末次非终止交互模拟重复段；保留不同事件位置。
- `diverse50`：50 步，每步附加明确标记的不同条件文本，测试低重复、变化中的观察。不是声称这些状态可由环境实际产生。
- `wide50`：50 步，额外约 650 字符观察和每步 80 个不同合成候选动作，作为显著更宽的对抗压力。08 R2 真实菜单为 12—71 项，中位数24；观察16—275字符，中位数70。此极端情境不是典型预测，也不是环境理论最大值。

历史分别测试固定3条Effect、basis每轮累积，以及每轮新增3条Effect。加入明确相互冲突的合成认识、正/反响应事件、每轮未测试限制；没有通过 prefix 伪装同一句话为矛盾。所有这类事实都带 synthetic 标志。跨轮复制用来估体积，不计作真实重复实验支持。

## 7. 保真、估算与复杂度验证

14项独立单元测试通过，包括：

- 08 两轮9份真实消息的用户视图完整解码相等；当前v3的5种重编码视图相等。
- 每条当前动作、前/后观察可恢复；Parent/Candidate 即使文本相同也不合并执行身份；事件ID、步骤顺序、轨迹结局不变。
- 命令池恢复候选动作的顺序与重复次数；同集合不同顺序、空列表、短动作、数字字符串不混淆。
- 拼接恢复空格、Tab、CRLF、空行、中英文标点和首尾空白；缺字段与null不同。
- 真实历史basis、更新上下文、反例和未知限制全文保留；来源目录仅在严格等价条件下可隐式生成。
- Editor保留完整Plan/Parent但声明非无损；cards保留claim/limits却明确没有完整历史正文。

这些证明字面事实/结构可逆与来源定位，**不证明模型能正确推断行为机会、判断D/S/C或遵循复杂引用**。本次也没有声称实现了语义关键事件选择器。原型没有把“未触发、未执行、未验证、执行后无效”自动合并或自动赋值；它们仍由模型依据保留事实判断。

原始存储保持不变，原型额外增加小型共享字典/消息档案；不以删历史降低磁盘占用。程序要先装配完整payload再投影，当前原型依然占用O(历史)内存/CPU，尚非数据库检索优化。正常调用数量不增加：五轮完整更新按原流程推算最多24次语义调用（第一轮Fusion恒等），该数字只是规划算术，不是已授权的新运行配置。无额外总结/压缩/Review Agent。

字符结果是确定值；Token估算不是模型容量认证。共享索引可能降低字符却提高单位字符的Token密度，还可能增加模型解码负担。后续真实语义探针需同时观察输入Token、推理Token、引用错误与更新质量，不能仅凭字符缩减率给成本承诺。

## 8. 最少迁移内容与明确不做的事项

| 候选改变 | 影响位置 | 必要验证 | 当前结论 |
|---|---|---|---|
| 统一的精确共享编码函数 | 分类消息装配、grouped_messages消费层 | 全量roundtrip、sources闭包、模型理解 | 值得优先迁移验证；正式源码未改 |
| Editor实现职责视图 | grouped_update.update_payload之后的消费投影 | Plan/条件/例外完整、非本地依赖、现有issues可用 | 值得做，但±1原型不能直接采用 |
| 历史目录与证据分离 | effective_consumption_payload及消费契约 | 反证/未知/跨组迁移、历史误判可修订 | 设计方向；cards-only拒绝采用 |
| 可见来源约束 | 消费manifest及validate refs入口 | 引用必须映射已展示事实或明确仅索引 | 若有损视图采用则必要，不能只验原payload有ID |
| 容量计划与提前检查 | runtime预算/preflight及每阶段消息冻结 | 按任务步数/观察/菜单密度计量；Token校验 | 值得做；不能只等Candidate花费完成才失败 |
| 五轮及Selection用途适配 | runtime/state/Adapter/分类/Replay | 原始split保真、任务用途、预算与Gate一致 | 独立协议事项，非本次输入原型的隐含授权 |

若迁移模型可见表示，需明确新profile/输入视图身份（名称待定），绑定装配代码、Prompt、解码说明、消息摘要和可见来源清单。旧v3及08—15按原规则重建；输出Schema、D/S/C决策语义、Gate规则、Memory持久化含义不必随之改变。正式验证仍针对原始payload，消费视图在调用前另做投影一致性检查；有损路径另限制哪些证据可用于事实引用。

本次不采用：按任务成败选轨迹、按group ID筛历史、固定最近N轮、无条件Token截断、只保留首尾/Watch关键词、自动总结旧因果关系、把压缩失败转为no_change/Keep、临时拆分成多个独立学习Agent。也没有上调400k掩盖结构问题。

## 9. 五轮实验准备判断

**尚不能直接开始。** 当前证据支持先落地/验证低风险的精确共享消费层，随后验证Editor落实视图；但仍有三项不同性质的剩余事项：

1. **输入表达可用性未验证**：可逆不是模型语义正确，需独立profile及小规模真实模型验证后才能替换冻结输入。
2. **容量覆盖不足**：持续变化的50步双侧轨迹和更宽动作候选仍可能超限；必须决定具有证据覆盖承诺的进一步组织方式或另行调整实验预算/批次协议，不能静默裁剪。300k目标并未在全部情境达到。
3. **运行协议未适配**：57项Train+Selection、五轮、12项批次与当前v3运行器不兼容。

长期历史优化还需有可检验的选择/展开规则。若坚持单次调用、固定窗口，同时允许任意增长的独特历史与观察，无法承诺全部信息永远直接展示。合理目标应是：已声明输入工作范围内可运行、超范围可检测、关键判断证据有明确可见性，而非声称无限扩展。

这项结论不否定统一D/S/C更新机制，也不将压缩作为新的论文创新。它确定了可先做的工程整理、尚不能省略的证据，以及仍需验证的边界。

## 1. 本次要检验的机制

前次固定初稿消费已经出现“历史认识进入具体要求并落实为文本”，也暴露了重要缺口：另一条路径成功，并不意味着可以跨状态取消原来仍有用的完成步骤。与此同时，两组对旧初稿的解释不同，且历史输入不同，不能据此判断预条件化规则优于同信息的普通历史辅助修订。

本次研究问题是：**在当前证据、认真初稿、有效 Memory 和调用预算相同的情况下，显式利用更新作用认识来调整方向、尺度与组合，是否能形成更合理的条件化要求，并在冻结后的新任务中表现出来？**

研究假设是：将历史响应对齐到具体更新决定，并保留支持范围以外的已知完成／恢复路径，有望减少错误放宽、无依据加强和相互干扰。恒等、需要修订、没有收益或发生回归均是可报告结果，不预设必须发生变换或得到提升。

这次扩大任务覆盖，避免围绕旧 `train:0000` 与 `train:0012` 反复修订。它仍是一次小规模探索性检验，不能单独证明跨轮持续收益、普遍泛化或数值二阶优化。

## 2. 先分清目标与实现策略

Diagnosis 继续使用紧凑 Plan，不增加新的目标／策略字段：

- `intent` 表达希望达到的行为结果和共同保留义务。
- `requirements` 表达实现该目标的初步策略，以及可见触发条件、范围、依赖、继续执行／恢复和停止要求。
- `watch` 保留会影响更新判断的重要观察问题；`open` 只记录真实阻断。

例如，“完成任务要求的对象处理和最终目标”是共同目标；“将处理后的对象送到指定容器”是任务确实要求交付时的策略。不能因为某条轨迹需要交付，就把所有任务的共同目标写成统一交付流程。

合法命令只说明动作当前可执行，不说明动作必然满足目标；动作名字也不等于完成信号。Diagnosis 应使用 Actor 实际能访问的观察和短历史，不假设它拥有学习器的全轨迹、隐藏状态或全局记事本。成功轨迹可能暴露冗余，但“任务成功”本身不是 Skill 缺陷。

流程在 Diagnosis 返回 `revise` 时从新的 Train 反馈形成一个认真初稿，随后两组共享并冻结它；`no_change` 或 `need_evidence` 则按协议停止。不人为弱化初稿，不事后分别解释共同目标来扩大组间差异。

## 3. 通用变换规则

新规则位于 [conditional_update.py](../../../src/skill_evolution/v22/conditional_update.py)，版本为 `v22.conditional_update.v1`。原有提示、历史输出及校验契约保留，不覆盖前次实现。

### 3.1 对齐具体决定，再判断是否需要变换

一条历史响应应当对应当前要求中的具体决定：什么时候采用哪种策略、义务有多强、作用范围有多大，或者如何与其他要求配合。相似的任务主题或措辞不足以确定适用性，还要比较可见条件、实际 Parent／Skill 依赖与执行反馈。

如果初稿已经覆盖相关问题，就保留它。需要变换时，在原 `change.reason` 中简要说明历史观察及其限制如何支持这项决定，不输出逐规则检查表或自评分。

| 维度 | 实际改变的内容 | 边界 |
|---|---|---|
| 方向 | 替换策略、调整顺序，使更新更接近目标行为 | 替代路径必须可执行；不能将一次成功路径写成通用必经步骤 |
| 尺度 | 调整义务强度、可见触发条件和适用范围 | 文本长短不等于行为影响大小；不能越过已知反例放宽范围 |
| 关联 | 协调重复、冲突或有依赖的要求 | 需要保留共同构成可用路径的局部义务；不能孤立修改一句后破坏其余条件 |

一次更新不需要同时展示三种变换。没有可支持的增量时，`changes=[]` 是有效决定。

### 3.2 替代成功只支持相应条件下的放宽

放宽某项义务前，要比较两类状态：替代路径成功时是什么状态；原路径或后续动作仍然有用时又是什么状态。

**替代路径支持范围以外的已知完成与恢复路径必须保留。** 若环境提供的完成反馈、当前合法动作、可见持物／放置状态能够区分，就用这些可见条件组织分支。若关键区别无法由 Actor 获知，且因此不能构造可执行要求，应返回 `needs_revision`；不能以隐藏状态测试补齐。

某个动作在一种配置下完成任务，不意味着在另一种配置下也完成。没有完成反馈时，应保留适用的下一步或恢复动作，而不是从另一条成功轨迹推出普遍停止规则。未验证的推广可以作为有范围的探索，但不能抹掉已经观察到的反例。

### 3.3 事实纠错与作用学习分开

修正动作次数、步数或事件描述，首先改变的是事实认识。它不自动证明某项编辑有效，也不自动支持加强过滤、增加必做检查或扩大规则范围。

单项因果作用尚未隔离，不代表禁止一切有界构造；但试探性策略需要明确保留归因和迁移的不确定性。没有观察到副作用，也不构成扩大适用范围的证据。

### 3.4 Editor 保持共同职责

两组都将有效 Plan 交给同一个 Editor 提示。Editor 落实已选要求，可调整等价措辞与组织位置，不能重新选择策略、扩大条件或将未知改写为否定。重要冲突返回 `needs_revision`，不能发布悄悄删掉要求的部分 Candidate。

两组 Editor 都得到完整的同一有效 Memory，而不是按各组引用筛选出不同历史子集。Memory 用于解释已选要求及其边界，不授权 Editor 重新作一次更新决策。

输出继续使用原有组级准确摘录、少量实质问题及新增 `watch`。Plan 的观察问题由程序继承，不要求模型重复输出。完全相同的继承项可以按既有确定性规则去重；同 ID 的实质变化不能借去重通过。原始响应和归一化记录分别保留。结构通过不证明语义保持或行为收益。

## 5. 同信息、同调用上限的两个构造策略

| 条件 | `direct`：普通历史辅助修订 | `conditioned`：显式预条件化修订 |
|---|---|---|
| 输入 | 同一 Parent、新 Train 当前证据、认真初稿、完整有效 Memory 及限制 | 完全相同 |
| 第一次调用 | 普通胜任的历史辅助 proposal：综合当前反馈和历史尝试，决定保留、修订或协调要求 | 显式使用前述方向、尺度、关联及条件保留规则的 proposal |
| 输出与装配 | 同一紧凑 Fusion 增量结构，由同一程序装配有效 Plan | 完全相同 |
| 第二次调用 | 共享 Editor 将有效 Plan 落实为 Skill | 相同 Editor 提示、完整 Memory、执行前约定 |
| 合法结果 | Candidate、恒等、`no_change`、`needs_revision` 或处理失败 | 完全相同 |

两个 proposal 的用户消息在同一输入下逐字相等。只改变系统提示中的修订策略，不给实验组额外历史、轨迹或回放预算。普通组允许独立改变方向、范围及组合，不限制它进行合理条件化，也不要求它照抄历史。

这不是“一个直接 Editor 调用”与“Fusion＋Editor 两个调用”的不等预算比较。普通组同样分为提出修订与落实文本两个调用，以控制调用上限和中间表示。**因此，本次识别的是同信息、同结构下两种提示策略的差异，不能将结果外推为相对所有历史辅助方法的优势，也不能把任何差异直接命名为优化器效果。**

输入 token、思考与生成长度仍可能不同，两个实际有效 Plan 也可能不同。调用次数相同不代表实际计算量完全相同；报告必须分别列出实际用量、失败及未知用量。

## 7. 05 原预算与共用解释边界

05 的原预算上限是 **21 个新环境 episode**：三条 Train 的 No Skill 执行，加六条 Selection 的三个执行条件。这个上限不用于描述 06；06 的独立预算见第 9 节。每个预定条件只有一次 episode，不按失败、步数或候选排名重新采样。若构造未形成可执行候选，相应评价保留未完成，不临时用另一份历史候选替代。

05 的语义调用上限是 **5 次**：一次共享 Diagnosis、两次 proposal、最多两次满足条件的 Editor，实际只调用一次 Diagnosis。执行模型为 `deepseek-v4-flash`，上述语义模块为 `deepseek-v4-pro`。具体最大步数、模型参数、网络重试上限和运行顺序由各自实验配置冻结。

没有额外语义修复、返工或结果驱动的 episode 重试。已有客户端若保留有界 HTTP 传输重试，须明确记录其配置、实际尝试、费用及未知用量；不能将传输尝试与五次语义调用的上限混为一谈。失败或输出截断不算合法 `no_change`，也不把未报告用量记成零。

结果报告需区分以下层次：

- **构造差异：** 同一初稿究竟发生了什么实际要求变化；引用历史或增加理由不等于有效变换。
- **实现保持：** 文本有没有落实有效要求，是否丢失其他条件下仍有用的义务；结构核验不替代这一判断。
- **执行结果：** 六个任务逐项列出三组的原生完成情况与成本，呈现失败和回归；不只报告更好的任务。
- **机制解释：** 轨迹是否提供与预期变换相符的局部线索；联合候选的一次执行不能隔离单项编辑因果作用。

每种条件只有一个小样本批次，不能据一次成功或总分差异声称统计显著、稳定提升或全面泛化。若两组相同、恒等或表现接近，应按事实报告；若构造失败或评价不完整，应先说明缺失而非计算一个看似可比的结论。

本页不填入预期成功率。执行状态、实际用量、冻结身份、核验结果及局限以本次实验报告为准。

## 8. 05 实际停点：保留原结果

三个新 Train 的 No Skill 执行分别在 10、9、11 步成功。Diagnosis 认为单次非法动作是对已有执行规则的未遵守，没有形成具体 Skill 可修复缺口，返回 `no_change, plan=null`。因此本轮仅调用一次 Diagnosis，未实际调用两种 proposal／Editor，未生成候选冻结记录，也未执行预选 Selection。总计 30 次 Actor 请求、1 次语义调用、36,513 tokens。

这不是预条件化的负面或正面效果结论。离线复核指出 Diagnosis 没有充分讨论重复访问和可复用成功程序，基础协议未被遵守也不普遍意味着 Skill 无法帮助。本轮结果不覆盖、不补造初稿，未执行的评价不写成零分。

## 9. 06 失败 Train 续验：独立构造与派生冻结

这次依据先前六类任务原生核对中**全部两条完整 No Skill 失败**选题，属于明确的失败修复开发抽样，不是无偏的 Train 成功率样本。历史轨迹只承担选题来源；为满足当前固定 Skill 执行与核验协议，两项任务各新执行一次 No Skill，新的成功或失败都会保留，不因结果换题或追加运行。

| `train:0034` | `pick_two_obj_and_place` | 50 步达到上限，原生未成功 |

两条新反馈使 Diagnosis 返回 `revise`，形成搜索避重与持物交付两项初步要求。两组随后消费同一初稿、当前证据和原有效 Memory，调用上限与信息条件相同。没有重学或手改 Memory，没有增加新的机制模块，也没有把研究转向成功轨迹提炼。

### 9.2 已观察到的构造差异及边界

| 对象 | Direct | Conditioned |
|---|---|---|
| 实际要求变化 | `u1/u2 → u3/u4`，增加容器检查并明确剩余对象与最后转移 | `changes=[]`，保留原 `u1/u2` |
| 观察问题 | 随要求替换原问题，继续观察来源回放限制等风险 | 保留原问题，增加两步历史之外仍可能重复访问的 `w3` |
| Memory 依据 | 变更只引用当前 Train 来源，无 Memory effect ID | 无要求变更，也无 Memory effect ID 引用 |
| 原 Editor 状态 | 形成通过结构校验的 Candidate | 有完整原始 Skill，但一项摘录跨编号拼接，被准确定位校验拒绝 |

因此，本次已经观察到同信息策略产生不同要求决定，但**没有观察到可明确追溯的历史响应驱动非恒等要求变换**。不能把 Direct 的非恒等或 Conditioned 的恒等直接当作机制优劣。所有 Memory 都已提供，未引用也不能证明模型内部完全没有受到历史影响。

只读检查还识别出必须随结果保留的语义边界：Direct 将 P1:19 柜面为空的观察解释为未打开的关闭容器，而当时下一状态没有对应 `open` 动作；两组均保留绝对来源禁回放及含糊的处理前置条件。Conditioned 的 Editor 原文又加入非目标物禁取、禁止把所持目标放回已完成的中间位置等规则，文本差异不能全部归因于 proposal。局部两步避重也不等于解决长周期搜索循环。这些记录没有作为反馈送回更新器，未据此修补本次候选。

### 9.3 原定位错误保留，另行冻结不变文本

原 06 操作保留 Conditioned 的 `mapping.excerpt: not found on declared side` 错误。其第三项摘录把原 Skill 中编号 6、7 的两段连续正文用一个空格拼接，省去了中间的换行及编号；这使摘录不是原文中的连续字符串。原错误不回填为成功，原始响应和失败成本继续保留。

在任何 Selection 执行前，另行声明了 [span_reconciliation.json](../../../experiments/methods/v22/06_failure_trial/config/span_reconciliation.json)，显式修订原协议只允许 watch 去重的边界。两组使用同一个确定性函数：只有将摘录中的单个空格替换为换行及编号后，能够在 Candidate 中找到唯一准确匹配，才将其拆成两个准确摘录；拆分后的正文拼接必须等于原引用。缺词、歧义或语义变化均拒绝。

该派生操作只改变引用分段，保留要求 ID、引用侧、其他输出字段及 **Candidate 全部原文字节**，不改变要求或修复上述语义问题。新增语义调用为 **0**，没有重写 Skill、重跑 Train 或追加候选。原操作、修订协议、归一化引用、两份原始文本及有效 Plan 在 Selection 前重新绑定冻结；结构定位恢复不等于语义保持已经证明。

### 9.4 独立预算与当前执行状态

06 的总上限是 **20 个新 episode、5 次语义调用**：两条新 Train，加原六条 Selection 的 No Skill／Direct／Conditioned 三个条件，共 18 次 Selection 尝试。每条 episode 最多 50 步，每种条件只执行一次。实际使用两条 Train、五次构造调用和全部 18 次评价尝试；Selection 16 项完整结束，No Skill 的清洁与加热两项因连接中断为未知，未重跑。

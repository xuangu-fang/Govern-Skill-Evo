# V22 Actor 并行调度修订

本修订只改变独立任务轨迹的派发方式。后续通用运行器默认读取 `experiments/methods/v22/08_grouped_continual/config/plan_parallel8.json`：协议 `v22.grouped_continual.v3`，同批最多 8 个 Actor 并行。Diagnosis、Fusion、Editor、Memory 以及跨轮继承继续按依赖顺序运行。

## 冻结和兼容

- 原 `plan.json`、任务清单和分类 Prompt 不修改。显式传入旧 `plan.json` 时继续使用 v2 串行调度，已有 v2 档案可继续离线核验。
- 新 v3 计划引用原任务清单及其哈希，新增固定调度声明并把 `actor_workers_max` 改为 8；任务、模型、单任务步数、Gate、两轮总调用预算都保持原值。
- 无论 v2 还是 v3，都必须在调用前冻结实际配置、源码和输入。运行中的旧冻结配置不能就地改成 v3。本修订不提供恢复旧运行的入口，也不会自动重跑旧任务；当前实验的调度修订应以独立 amendment 记录来源。
- 默认计划保留 08 的任务列表，表示同一协议的调度修订，不代表已经授权再次执行相同任务。准备另一批训练任务时仍须先形成相应的冻结计划。

## 执行规则

每批按固定任务顺序派发，最多保留 8 个已派发且尚未收齐的任务。空位出现后补发后续任务。任务可以乱序完成，输入分类、Diagnosis 和 Replay 的记录仍按冻结任务顺序组装。整批核验通过后才进入下一个语义阶段。

工作线程只运行独立 Actor 子进程及其任务目录；派发记录、结果核验、报告和成本归集由主线程处理。普通原生失败是有效执行结果，继续收齐整批。技术异常、轨迹不完整、冻结内容漂移会停止补发，已派发任务等待完成并归档。保留全部已发生成本和不可读轨迹的未知项，不把技术错误记为 RETAIN，不继续语义阶段或发布下一轮。

运行器保留 `preflight / run / verify` 接口。默认入口改为 v3；需要核验或复现旧声明时显式指定 `--plan experiments/methods/v22/08_grouped_continual/config/plan.json`。`verify` 读取档案内的冻结计划，不受默认入口变化影响。

## 当前实验的显式调度修订核验

对于原 v2 运行途中经用户授权改为 8 并行的档案，核验器仅识别 `serial_then_user_authorized_parallel_8` 这一明确标记，并要求报告绑定独立的 `amendment.json`、`continuation.py`、`continuation_freeze.json`，同时核对初始并行 Replay 调度源码。全部文件哈希、原 runtime 文件哈希、campaign 路径和续行授权记录必须一致，变更范围必须严格限于串行转最多 8 并行，且声明没有算法改动或重复工作。缺失、漂移、跨 campaign 或不受绑定的外部路径均拒绝。

修订材料仅可位于与 campaign 同父目录的一个独立目录；整体搬迁父目录后仍按原绑定关系解析。该路径只允许核验已经明确记录的调度修订，原有阶段、预算、冻结证据和 Skill/Memory 继承核验照常执行。结果明确返回原声明调度、实际混合调度与 `amended=true`，不会把修订后的运行称为未经变更的原 v2 实验。

## 离线验证

新增合成测试覆盖 8 路并发重叠、乱序完成后的固定组装顺序、语义阶段等待整批、技术异常后停止补发并归集所有已派发成本、中断后等待在途任务，以及旧 v2 串行兼容。测试不调用真实模型或 ALFWorld，也不证明调度提速比例或研究方法收益。

## 1. 研究问题与统一主张

问题一：对一批具有不同决策条件的 Train 任务，一份统一 Skill 更新能否修复实际失败，并保持本批已有成功行为？

问题二：第一轮真实编辑及 Replay 形成的条件化响应，能否在第二轮改变实际更新方向 D、尺度 S 或关联 C，并获得可核对的执行反馈？

假设：以共同决策问题组织当前经验、要求和历史响应，有助于识别更新的适用边界与相互影响；对这些结构作非均匀的语义更新，可能比仅参考历史生成文本更有针对性。这里的 block-wise preconditioning 是设计类比，不计算数值预条件矩阵，不假定组间独立，不预设统计收益。

**统一算法的核心联系是：任务经验形成决策结构；Diagnosis 把结构转成更新要求；Memory 保存相关实际编辑的响应；Fusion 用响应改变要求；Editor 落实；Replay 检验；Gate 决定版本继承；新的响应继续修正更新器。** 分类本身不证明响应适用，组名或引用字段出现也不算完成预条件化。

首版只验证这条机制和两轮连续状态，不单独宣称分类带来了因果收益。两轮约十项任务是探索规模，不能代替重复实验或泛化评价。成功任务用于保护和条件比较，不开展成功程序提炼或效率优化。

## 2. 轮初状态与正常流程

轮初读取同一发布记录绑定的 Skill `S_t`、Memory `M_t`。第一轮为 No Skill／空数组；不导入 01—07 的候选、Effect、历史初稿或诊断。旧 Train 结果仅用于事前选题。

~~~mermaid
flowchart TD
    A["当前已发布 Skill / Memory + 固定任务与预算"] --> B["Parent 执行整批 Train"]
    B --> C["程序生成紧凑事实摘要"]
    C --> G["一次全局分类；冻结共同决策结构"]
    G --> D["Diagnosis：独立当前初稿"]
    D --> F["Fusion / Compiler：按响应调整 D / S / C"]
    A --> F
    F --> E["Editor：相对实际 Parent 构造一份统一 Candidate"]
    E --> R["冻结要求和文本；同批 Replay 与配对事实"]
    G --> R
    R --> K["程序 Gate：ACCEPT / RETAIN；输入无效则停止"]
    K --> M["一次行为解释与 Memory 增量处理"]
    G --> M
    M --> P["核验并发布下一轮 Skill / Memory 引用"]
    P --> N["第二轮读取实际发布状态"]
~~~

图示为有合法候选及完整可比执行的单一主路径。每轮最多构造一份统一 Candidate，不设置 Direct 对照分支。无候选、技术失败和未发布状态见第 8 节。

**顺序固定为 Replay → Gate → Memory。** Replay 先提供程序核对的真实配对事实、原生结果、覆盖和冻结来源。Gate 只使用预声明的机械判据。Gate 后的一次 Pro 调用联合解释分组行为响应并生成 Memory 增量，不在 Gate 前后重复分析同一轨迹。详细行为解释在该次后处理中形成；Gate 不得假装已经读取这些尚未生成的结论。

Gate 的 ACCEPT 是待发布采用决定。只有 Memory 处理有效完成（包括合法空增量），才用一个不可变轮末记录发布相应 Skill／Memory。该记录即可表达连续状态，不引入调度 Agent 或复杂状态机。

## 3. 紧凑经验摘要与一次全局分类

### 3.1 摘要固定为程序生成，零摘要模型调用

使用现有紧凑轨迹方式整理每个 Parent 任务，保留：实际可见请求、当前 Parent、基础协议／可见 policy、工具及 Actor 能力、初始观察、顺序交互、原生成功结果和执行完整性。没有环境提供的 policy 时只保存实际基础协议，不创造 τ 合规字段。

共享 policy／工具协议／Skill 只保存一次；相同合法动作列表用完整字典引用；每步保留动作、执行后观察、步骤来源及必要原生反馈，执行前观察可由初始观察及前一步还原。删除请求包装、推理正文、HTTP 细节和重复上下文，不删除重复行动、失败命令、循环或“不重要”的观察。原始轨迹完整归档。

这是有来源的紧凑事实摘要，不是另一轮诊断。模型消费的摘要不含选题目的、旧成功／失败标签、gamefile 名称、场景编号、隐藏任务类型、标准答案或评价器内部状态。原生结果来自本轮允许学习的执行，不能据其划分成功组／失败组。分类与 Diagnosis 看全批当前 Parent，不只看失败。

初版所有 Pro 请求的完整序列化输入上限为 **400,000 个 Unicode 字符**（包括系统提示及输出形状），输出上限 16,384 tokens。字符数是工程体积上限，不冒充 tokenizer 的 token 数或模型上下文保证。实际传输前还须满足所接端点的上下文限制。超限则保存材料并停止；不临时删任务、截断事件、拆成多次分类或自动增加摘要调用。若需要更换表示，另立执行前协议版本，不以结果驱动变更。

### 3.2 固定分类协议

每轮只调用一次 `deepseek-v4-pro`，使用[固定 Prompt](../../../experiments/methods/v22/08_grouped_continual/config/grouping_prompt.md)。它同时读取全批摘要，依据共同的具体选择、前提、范围、执行顺序、继续／停止边界分类，不按业务名称、工具名称、任务类型或成败直接分类。共同条件和差异均来自观察，不推断正确修复。

沿用旧分类的五项输出：`group_id / decision_problem / members / shared_basis / important_differences`。每任务恰好归一组，允许单例和空差异，不固定组数。任务含多个问题时选主要可比较问题归组；其他问题仍允许进入后续分析，不能因分组而消失。

使用固定种子 200 的不透明任务／轨迹别名及稳定输入顺序，保存反向映射；别名不传递场景、任务族或旧结果。程序只核对格式、成员全覆盖、排他性、引用和版本，不自称核验分类语义正确，也不新增分类审查 Agent。一次调用失败或输出无效则停止，不继承旧 v17／v20 的第二次格式修复调用。

Diagnosis 前冻结：摘要版本和实际输入、轨迹 hash、Parent hash、别名映射、Prompt 正文／版本／hash、调用参数、原始响应与有效分组。冻结使已发生操作可回放核对，不保证再次请求远端模型会产生相同输出。

### 3.3 分组怎样成为更新结构

把分组作为当前来源的一类引用，例如 `r1:G1`，其正文包含共同决策问题及条件差异；实际任务和步骤引用仍负责支撑事实。分组引用本身不能证明任务缺陷或正确修复。

| 环节 | 决策结构的实际用途 | 最小边界 |
|---|---|---|
| Diagnosis | 将真实问题形成带可见条件、目标行为和决策来源的初步要求；保留成功中的有效行为 | 一次联合诊断、一份 Plan，不按组分别造 Skill；独立于 Memory |
| Fusion | 在当前要求对应的决策问题上核对旧 Effect 的条件、实际编辑和 Parent 依赖，调整 D/S/C | 同组不自动适用；不同组也可共享影响；不另加跨轮匹配调用 |
| Editor | 在当前 Parent 上实现最终联合要求，保持范围、顺序与保护义务 | 一份全文 Candidate 和实际 diff，不自行增加策略义务 |
| Replay | 按冻结分组观察同批配对执行，保留改善、退化、未触发与跨组影响 | 不依据 Candidate 表现重新分类；新发现保留为跨组／未覆盖认识 |
| Memory | 把实际编辑、条件化响应、限制和版本来源与决策问题联系起来 | 不按组复制 Memory；联合编辑不拆成单条因果收益 |

任务归组排他，要求和响应的作用范围不排他。一项要求可引用多个组；同一 Effect 可关联多个受影响组，保留一份来源即可。未知影响不能补成零影响。跨轮组 ID 只作定位，匹配依据决策问题语义、可见条件、实际编辑及当前 Parent；不建立永久分类标签或假设“同名 G1”相同。

## 4. Diagnosis、预条件化更新与 Editor

Diagnosis 使用本轮真实 Parent、全批摘要／可解析轨迹和冻结分组，独立形成认真初稿。目标与实现策略继续分开；原本正确的行为可以成为保护要求，但不因任务成功就新增优化目标。不使用 Memory 或旧方案来塑造一个刻意较弱的初稿。

Fusion 在一次既有语义构造内完成：定位当前决策 → 核对 Effect 条件与反例 → 判断初稿已覆盖什么 → 形成必要的完整要求变更。仍使用 `from/to/basis/reason` 与稀疏 `watch`，不生成逐组自证表。

| 响应认识与当前初稿的关系 | 更新规则 |
|---|---|
| 没有适用响应，或初稿已妥善覆盖相关决定 | Keep，保留具体限制；不能因有 Memory 就强制修改 |
| 历史显示联合策略在某条件下仍未解决问题 | 判断限制涉及当前哪个决定；可以保留有用局部范围或提出有依据的有限替代，不把单次失败判为某条规则普遍无效 |
| 历史成功只覆盖较窄可见条件 | 只在有支持的条件下调整方向或义务范围，保留其他状态下的必要继续／恢复路径 |
| 多项要求共享条件、重复强化或相互干扰 | 协调相关要求的条件、顺序与保护义务；跨组影响不因唯一归组而被遗漏 |
| 新策略可执行但作用尚未验证 | 明确为待 Replay 的有限探索；不得把未经执行的动作写成已验证 Effect |
| 所需区分依赖 Actor 没有的信息或能力 | 不用 Skill 文字假装增加状态；Keep 有效范围或声明构造阻断，不将观察问题当作已完成修复 |

实际 Actor 仍只有当前观察／动作候选与最近两步交互，无全局访问记录；跨轮 Memory 是更新器状态，不改变 Actor 任务内能力。07 的搜索／交付现象只说明研究动机，不作为本次空历史运行的隐藏提示或固定修复模板。

Editor 接收准确 Parent 与有效 Plan；重写完整文本只是交付形式，修改语义仍相对于当前 Parent。已采用条款不重复机械追加，被拒候选的条款也不被误认为已经存在。组级文本定位与真实 diff 沿用已有方式；程序格式核验不等于语义保持已证明。

**第一轮空历史 Fusion 预声明为程序恒等，零调用。** 这是未进行独立历史变换判断的 identity，不宣称模型主动选择 Keep。Diagnosis 已联合构造要求；若 Editor 发现实质问题，按本次零返工协议保留无候选出口。

第二轮如果 Memory 为空仍可继续：Fusion 依据当前输入判断并允许 Keep，不因无 Effect 而补造历史或停止整套实验。报告明确历史机制未获检验机会。

## 6. Replay、Gate 与 Memory

### 6.1 冻结与配对执行

每个实际 Candidate 在本轮相同十项任务各执行一次，与同轮 Parent 配对；“同条件一次”限定在轮内，下一轮使用另一批不重叠 Train，按实际继承的 Parent 重新执行；不得只回放失败或有利组。重置环境并保持任务、seed、Actor 协议、步数上限及模型参数一致，核对保存条件；采样随机性不因此消失。记录完整与中断、原生成功、动作、非法动作和实际费用。

执行前冻结分组、初稿、有效要求、Memory 版本、实际 Skill／diff、观察问题及运行实现来源。Candidate 反馈不反向改写这些材料。全批执行不按早期结果提前判赢或选样本；独立任务技术失败可保留其余已声明运行，但不重跑失败项。

### 6.2 Gate：完整配对上的整体成功率晋级

仅在候选不同于 Parent，十项 Parent／Candidate 都完整、来源一致且配对条件匹配时评价。两侧整体成功率均以相同十项任务为分母。令修复数为 `Parent 失败 → Candidate 成功` 的任务数，退化数为 `Parent 成功 → Candidate 失败` 的任务数；它们用于描述响应，不能另设零退化门槛。

- `ACCEPT`：Candidate 的整体成功率严格高于 Parent；在相同完整十项任务上，等价于 Candidate 成功数大于 Parent 成功数，亦等价于修复数大于退化数。
- `RETAIN`：Candidate 的整体成功率等于或低于 Parent。
- 即使发生局部退化，只要整体成功率严格提高，仍然 ACCEPT；例如 Parent 4/10、Candidate 5/10，含两项修复和一项退化，仍采用 Candidate。局部收益、退化及限制由 Memory 保存，不改变整体晋级判据。
- 技术错误、缺失运行、来源或条件不匹配：Gate 输入校验失败，保存错误且不生成有效采用决定，保持最后发布状态并停止后续轮次；不新增质量等级，也不把技术未知记成 RETAIN。
- 合法无实际候选／无修改：在全批 Parent 完整核验后记录 `RETAIN`、`reason=no_change`；Candidate 比较分数缺省，不声称已观测到成绩持平。保留 Parent，按第 8 节处理已有认识并结算，不伪造 Candidate Replay。

50 步正常耗尽是完整的任务失败，网络／解析／执行器错误是未知。Gate 不使用分组数量、组平均分、token、速度或非法动作数作临时加权与破同分。该规则只决定本批整体版本晋级，不保证逐任务成功保持；行为退化即使未改变成功位，也必须进入后续响应认识。小样本 Gate 是开发采用政策，不是稳定优势或部署安全认证。

### 6.3 Gate 后一次后处理与发布

有效 Gate 后，一次 Pro 调用同时形成必要行为发现、未知和 Memory 增量。输入包括实际 Parent／Candidate、diff、冻结要求和分组、全批紧凑轨迹、旧有效 Memory 及机械 Gate 记录。行为解释仍以执行为依据；ACCEPT 不能当作全部修改正确，RETAIN 不能抹掉局部改善或把每条规则判坏。

每条重要发现说明实际任务／条件范围；可以关联多个组或计划外行为。区分触发机会、实际执行、目标变化和未覆盖；因 Candidate 改变路径而未到达目标阶段，可能也是整体负面观察，不能统一当作无关缺失。联合编辑保留联合归因；不要求每个任务、每条要求各输出一张表。

Effect 延续 `claim / basis / limits`：程序把决策问题语义及冻结来源、实际 Parent／Candidate／diff、配对证据和 Gate 档案绑定在已有 basis 上。旧有效条件与反例继续保留；已采用修改可被新证据修订，被拒修改的局部响应也可复用。分类不证明因果，Gate 状态只说明版本采用。

处理通过后发布：ACCEPT 选择 Candidate，RETAIN 选择原 Parent；两种情况下都使用有效处理后的 Memory，允许内容不变。Memory 技术失败、无效输出或来源不完整时，Gate ACCEPT 暂不生效，旧发布状态保持，停止下一轮。不能用旧 Memory 配新 Skill 偷渡发布。

## 7. 冻结预算与调用组织

| 阶段 | 第一轮上限 | 第二轮上限 | 组织方式 |
|---|---:|---:|---|
| Parent 执行 | 10 episodes | 10 episodes | 全批、每条件一次 |
| 程序摘要／全局分类 | 0／1 Pro | 0／1 Pro | 不按组或任务拆调用 |
| Diagnosis | 1 Pro | 1 Pro | 当前全批、一份初稿 |
| Fusion／Editor | 0／1 Pro | 1／1 Pro | 第一轮程序 identity；第二轮按历史响应预条件化 |
| Candidate Replay | 10 episodes | 10 episodes | 与本轮 Parent 配对 |
| 程序 Gate | 0 Pro | 0 Pro | 固定原生结果规则 |
| 主行为解释／Memory | 1 Pro | 1 Pro | Gate 后一次联合后处理 |
| 合计 | 20 episodes／4 Pro | 20 episodes／5 Pro | 最大 40 episodes／9 Pro |

每 episode 最多 50 次 Actor 请求／动作机会，累计最多 2,000 次逻辑 Actor 请求；技术错误的请求也占预算，不只统计成功执行动作。模型为 Actor `deepseek-v4-flash`、语义阶段 `deepseek-v4-pro`，两者沿用 temperature=1、max_tokens=16384、thinking=enabled、reasoning_effort=medium、stream=false；环境 seed=42，原v2声明最多三个Actor worker、实际初始串行；用户授权当前剩余任务改为最多8并行，独立记录调度amendment；后续v3默认最多8并行。单请求timeout=300秒。分类 Prompt 固定不等于远端输出确定。

每逻辑请求最多六次有界传输尝试，内容和参数不改变；传输尝试与未知费用全部记录。它不授权语义修复、续写或重跑 episode。分类／Diagnosis／proposal／Editor／学习各阶段至多一次；语义重试、构造返工、候选再生成、episode 重跑均为零。最多 2,009 次逻辑请求、12,054 次 HTTP 尝试只是上界，不要求耗尽；API 实际费用按报告用量记录，未知不能当零。

未执行的阶段不补调用，未用预算不换题或补跑。累计预算跨轮不清零；第一轮失败不能通过新建输出目录刷新额度。单一主线无候选或失败时按规定结算／停止，不用剩余预算创建替代分支。

## 8. 停点与合法不变

| 情况 | 本轮处置与下一轮 |
|---|---|
| 完整主 Replay，Gate ACCEPT／RETAIN，Memory 有效 | 发布绑定的 Skill／Memory，第一轮后进入固定第二轮 |
| 第一轮 RETAIN | 第二轮仍可为 No Skill，但必须读取第一轮有效 Memory；不降低 Gate 以展示非空继承 |
| Diagnosis `no_change`／`need_evidence`，或合法 proposal／Editor `needs_revision` | 保存语义决定，跳过无候选的 Replay，Gate 记录 `RETAIN / no_change`，不填造 Candidate 成绩；无历史时直接保持空 Memory，有历史时可用预留的一次后处理限定旧认识，不能制造本轮编辑响应；结算后可进入下一轮 |
| Editor `no_change` 或 Candidate 与 Parent 字节相同 | 不重跑同一 Skill；按无实际编辑处理，不把继承文本当新效果 |
| 空 Memory 或空增量 | 合法，不强迫 Effect／变换；第二轮继续或 no_change 均如实报告 |
| Parent 批次不完整、摘要超限、分类／主构造技术失败 | 保存真实输出及错误，保持最后发布状态，停止主线；不得改成语义 no_change 或换题 |
| 主 Candidate 配对不完整或不匹配 | Gate 输入校验失败，不形成有效采用决定，不正式更新／发布 Memory，不进入下一轮；完整局部轨迹保存供独立后续研究，不丢弃 |
| 主 Memory 调用／校验／写入失败，或发布绑定失败 | 保存 Gate 待发布决定与材料，保持最后已发布状态，停止；本协议无自动补调用 |

合法无候选但有历史时，Parent-only 后处理只纠正、限定或保留既有认识，不能新增声称“本轮编辑已产生效果”的记录；与实际 Candidate 反馈学习共用一次预算和语义职责，具体接口已在[第二步实现](CONTINUAL_INTERFACES.md)中支持。因不可判定或技术失败停下，不声称完成了两轮。

本次零自动重试不否认未来恢复能力，但任何后续恢复都需另存明确协议和旧失败成本，不覆盖原结果或暗中重置任务、候选和预算。

## 10. 验收与研究结论边界

实现验收先离线覆盖整体提升但局部退化时 ACCEPT、持平／下降时 RETAIN、非空 Parent、空 Memory、no_change、组号变化、跨组影响、未知、轮间重复任务拒绝和 Memory 发布失败等关键分支；不把字段可解析当作行为判断正确。

真实报告分开回答：

1. 两轮是否实际执行并形成正确的 Skill／Memory 继承；未发生 ACCEPT 时说明没有得到非空 Skill 继承实例。
2. 每项完整配对的修复、保持、回归和未知；沿冻结分组报告决策行为变化及跨组影响，不能只报总分。
3. 第二轮哪些要求因哪条条件化响应改变了 D/S/C，哪些 Keep、哪些只是当前诊断或文字变化。
4. Editor 的实际文本是否落实要求；额外义务或遗漏与 Fusion 决定分开记录。
5. 对应行为是否触发、实际效果是否支持调整；未触发不算验证有效，也不自动算该规则无效。
6. 单一主线的实际调用、成本、错误与停点是否符合声明；轮内配对不能消除采样随机性，无跨轮旧任务回归或独立泛化评价时，不能扩张相应结论。

不强制分类产生特定组数、不强制 Effect、不强制非恒等、不强制 ACCEPT 或正向收益。Gate、分组和完整链路本身均不作为已证明的性能贡献。当前只研究两轮 Train 机制；分类消融、更多重复和独立泛化评价留待后续。

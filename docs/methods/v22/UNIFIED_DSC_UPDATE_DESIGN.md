# V22 统一 D/S/C 预条件化更新算法设计与最小落地方案

日期：2026-10-15。状态：**第一步设计完成，尚未修改实现或验证新算法效果。**

本文件从统一更新关系推导算子、学习方式和模块职责。它不将 [机制审查][audit] 的 P0/P1 清单直接转成开发任务；审查中的实际失配仅作为通用规则的反例。当前代码、Prompt、输出契约及两轮历史实验产物保持不变。本轮没有新增模型调用、ALFWorld 执行或测试运行。

## 1. 算法目标与核心决定

V22 要持续学习的是：**相对于特定 Parent，某种 Skill 更新在什么决策条件下产生了什么行为响应；这些认识怎样改变下一次更新的构造。**

预条件化的对象是行为更新，不是任务答案、历史片段的排序，也不是 Skill 文本的字数。算法保留两项分别评价的目标：

- **进化效果：** 持续改善失败行为并保留有效能力；不能以减少可执行更新来换取形式可靠。
- **方法作用：** 历史编辑—行为响应对当前更新的策略、作用条件／强度或关联组织产生可说明、可落实、可继续校准的影响。影响可以是有依据的保持，不要求非恒等变化。

本设计采用以下决定：

1. 用同一 Plan 承载 Goal / Update / Watch / Open，继续复用现有字段。
2. Fusion 实现一个基于条件化响应的联合语义变换算子；Compiler 负责增量装配，不负责推断自然语言因果关系。
3. Memory 学习实际修改的条件化联合响应。历史的作用范围随新证据修订；不要求识别每条编辑的独立因果收益。
4. Editor 保持所选更新的行为语义；Replay 比较选定更新、实际修改和实际行为，帮助区分失配发生在哪一段。
5. 以可见条件、明确依赖和可挑战的预期约束探索，不以“尚未证明有益”为拒绝更新的理由。
6. 常规调用结构保持：分类、Diagnosis、Fusion、Editor、Replay/Memory 联合后处理；不增加独立审阅 Agent、三套 Memory 或逐项 D/S/C 自证表。

这些决定构成待实现和验证的算法规格，不是对论文新颖性、优于普通历史辅助修订或稳定增益的现成证明。

## 2. 同一更新关系的定义

### 2.1 状态、输入与输出

用下式表达一次更新：

\[
\widetilde U_t=P(U_t,M_t,G_t\mid Q_t,S_t,A_t),\qquad
S'_t=E(S_t,\widetilde U_t),\qquad
\Delta S_t=\operatorname{diff}(S_t,S'_t).
\]

其中：

| 符号 | 含义与边界 |
|---|---|
| \(S_t\) | 当前实际 Parent Skill，包含需要继承的有效行为；不是空白重建模板 |
| \(Q_t\) | Goal：期望行为结果与共同保留义务，不把某条待比较的策略预先锁死 |
| \(U_t\) | Diagnosis 提出的条件化更新集合，允许多个要求联合表达一个策略 |
| \(M_t\) | 版本可追溯的历史实际编辑—行为响应认识及其限制 |
| \(G_t\) | 当前共同决策结构及其所引用的实际条件／Parent 事件；分组是组织坐标，不是适用性标签 |
| \(A_t\) | 当前 Agent 的观察、动作、记忆及控制能力，由真实协议提供 |
| \(P\) | 根据当前预期与可比历史响应的关系，变换原始更新 |
| \(\widetilde U_t\) | 已选择方向、条件、强度和关联组织的有效更新 |
| \(E\) | 将有效更新落实在实际 Parent 上的 Editor |

用户提出的简写 \(\widetilde U_t=P(U_t,M_t,G_t)\) 沿用；完整式仅显式列出已存在的目标、Parent 和能力条件，**不新增三个模块或必填输出对象**。当前 Parent 轨迹通过 \(G_t\) 的证据引用进入判断。

执行后形成：

\[
\Delta B_t^{\mathrm{obs}}
=\operatorname{Compare}(O_t^{P},O_t^{C};G_t,Q_t,W_t),
\qquad
M_{t+1}=L(M_t,\widetilde U_t,\Delta S_t,\Delta B_t^{\mathrm{obs}},G_t).
\]

这里的 Compare 是带条件和局限的行为对照，不是轨迹逐元素相减，也不是已识别的因果效应。\(\Delta B_t^{\mathrm{obs}}\) 可以包含局部进展、行为保持、无明显变化、作用机会改变或未测范围，不要求压成单一分数。\(L\) 是同一次 Replay/Memory 后处理中的认识修订职责。

Gate 独立决定 \(S'_t\) 是否成为下一轮 Parent；无论 ACCEPT 或 RETAIN，都可以保留有效的局部响应认识。技术失败不伪装成无效果或 Keep。实际顺序仍是执行 Replay → Gate → Replay 语义解释/Memory → 共同发布，与当前 [主线][runner]、[状态继承][state]一致。

### 2.2 Update 的最小语义

一项原始 Update 应能回答：

> 相对于当前 Parent，准备在什么可见条件下，用什么策略改变什么行为；哪些已有行为仍应保留，与哪些要求需要共同成立？

“加强搜索”“提高正确率”只是方向提示，不是足够的更新。相反，也不要求穷举所有触发条件与后果。只需明确会改变当前决定的条件、关系和预期。

| 语义 | 现有载体 | 设计要求 |
|---|---|---|
| Goal | `intent` | 行为目标和共同保留义务；策略必须可被替换而不改变目标 |
| Update | `requirements[].text / basis` | 相对 Parent 的行为修改，含策略、作用条件和必要关联；允许与既有条款共同实现 |
| Watch | `watch[].about / question` | 对实质更新的关键预期、反例或保留条件；一个问题可覆盖多个要求 |
| Open | `open[].about / reason` | 当前不能构造可执行更新的具体矛盾／必要能力缺口；不收纳所有未知收益 |

D/S/C 是 Update 的三种可调整性质，不是必须拆出的三个字段：

- **D，方向：** 实现目标的策略、信息获取方式、行动程序或顺序。不能以更换目标伪装成调整方向。
- **S，尺度：** 作用条件、适用对象、义务强度、持续程度及边界。既可以收窄／减弱，也可以在有依据时扩展／加强；与编辑字数无固定关系。
- **C，关联：** 更新之间、更新与既有 Parent 行为之间的前置依赖、冲突、重复和共同作用。可以跨决策组；不等于必须识别统计交互项。

要求与策略、文本段落和行为事件允许多对多对应。判断和变换的单位是**当前真正相关的一组要求及其必要依赖**，不默认每个 requirement 或每个 group 独立优化。

### 2.3 预期必须足够具体，但不另建预测模型

Goal 说明要改善什么；Update 说明怎样改变；Watch 表达少量能够挑战该决定的行为预期。例如“遇到条件 c 时是否出现 b，同时是否仍保留 k”。不用另加每项 expected_effect 字段或数值预测。

不能仅问“任务是否成功”。当方向、范围或关联发生实质改变，至少保留能够区分该改变是否落实、是否出现对应机会、是否影响关键保留行为的问题。无实质改变时沿用现有问题，不强迫重新生成一套 Watch。

## 3. 历史响应如何成为预条件器的依据

### 3.1 学习对象是作用关系

历史 Effect 在语义上表达：

> 在条件 c 和相关 Parent 依赖 d 下，实际采用的更新方式 e，与观察到的行为响应 r 存在何种有证据支持的关系；哪些解释和迁移范围仍未确定。

此句式用于设计检查，不是新的五字段 schema。现有 `claim / limits / basis` 足够承载。不同于一般经验摘要，e 必须能回到实际 Skill 修改，r 必须能回到执行事实；“曾经失败”“遇到某工具就这样做”不足以构成更新作用认识。

同时保留三个层次：

1. **观察：** 写入了哪些义务、机会是否出现、采取了哪些动作、观察到什么结果。
2. **作用解释：** 这些观察怎样支持某种更新的有效条件、局限或关联认识；可以是有限联合解释。
3. **构造用途：** 该认识可为下一次保持、调整范围或尝试替代提供何种依据。用途由下一轮 Fusion 在当前条件下判断，Memory 不预写未来 Skill 命令。

一项作用解释不必达到独立因果证明才能参与有界探索，但不能因为参与了构造就提升为“已验证有效”。

### 3.2 适用性是比较，不是同组匹配

Fusion 只需对会影响当前决定的历史检查以下关系，不输出逐 Effect 打分表：

- **决策含义：** 历史实际修改与当前 Update 是否在改变可比较的行为选择，而非仅共享对象／工具名。
- **条件可比性：** 历史产生响应的条件在当前是否存在；哪些差异可能改变响应。
- **Parent 与能力依赖：** 历史作用是否依赖某条已有规则、动作或记忆能力；当前仍具备这些条件吗。
- **实际实现与执行：** 历史到底采用并执行了什么，不能把未落实方案的结果迁移到当前策略。
- **证据限制：** 关键反例、联合修改、未到达机会、一次性随机执行和未测试范围，怎样限制本次结论。

同组不能省略这些判断，不同组也不禁止迁移。分类提供共同问题及差异的比较入口，实际触发条件决定是否适用。

同一表述在不同 Parent 上不一定是同一更新：对空白 Parent 新增一条持续性规则，与在已经含多条类似义务的 Parent 上再次强化，可能有不同作用。若当前 Parent 已实现历史成功策略，历史可以支持保留它，不能自动授权重复追加。

### 3.3 历史不一致时怎样处理

先判断差异能否由已观察条件或依赖解释。能解释时，保留条件化分支及各自证据；不能解释时，保留竞争解释和未知，不按最新一条、成功次数最多或文字最强自动取胜，也不虚构条件完成分割。

历史与当前事实冲突时，当前事实决定本轮可执行条件；历史认识的正式修订留在学习阶段，Fusion 不在消费时改写已发布 Memory。可在当前理由和 Watch 保留这一冲突。

## 4. 预条件化算子 P 的通用规则

### 4.1 基本过程：找到作用差异，再决定是否变换

P 在一次联合语义构造中完成四步：

1. **定位当前选择。** 确认原始更新准备改变的行为，以及相关 Parent 行为和共同保留义务。
2. **比较可用响应。** 找出历史响应对这一选择的支持、作用偏差或未知；区分当前能力修正与历史响应驱动。
3. **构造充分的变换。** 保持合理部分，仅改变有理由改变的策略、条件／强度及必要关联；必要时一并修订相关要求。
4. **保留可挑战性。** 新要求完整表达仍有效义务，并给关键变换／保留问题观察去向。未改项原样继承。

“仅改变有理由改变的部分”不等于最短文本、最小作用范围或默认弱化。若较大的协调修改才能消除冲突，就应联合修改；若原方向合理且没有适用反证，就保持它继续构造。

### 4.2 响应关系 → 当前决定

下表是决策原则，**不是模型必须选择的类别，也不是要求输出七行表格**。

| 历史及当前关系 | 对当前 Update 的决定原则 | 不足以支持什么 |
|---|---|---|
| 可比较条件下，实际更新与目标行为改善相符；当前方案已包含合理策略 | 保持方向及适用要求，保留已知限制；不为了体现历史作用重复加规则 | 联合成功不能证明每个子动作必要；未记录副作用不证明全范围无干扰 |
| 目标行为改善，但某些已观察条件下出现相关副作用或不必要义务 | 优先保留有效方向；按可见条件调整 S，必要时用 C 分支、排序或解除重复强化 | 不因局部负面响应删除所有正面分支，也不凭猜测建立条件区分 |
| 当前范围过窄，已有可比证据覆盖更多条件，或当前问题确需更强作用 | 可扩展 S；加强义务需说明此前不足为何与强度有关。证据只支持探索时，明确为待检验方案 | 不能从“仍然失败／未遵从”直接推出“规则必须更强”；一次成功不支持全局扩展 |
| 已落实且在相关机会中执行的策略未改善目标，同时存在有依据的可执行替代 | 可调整 D，保留共同目标和仍有效的延续／恢复要求；替代依据可以是当前证据加有限历史支持 | 旧方向的负面证据不自动证明新方向更好；最终失败不等于该策略无局部作用 |
| 多项修改或修改与 Parent 之间存在明确依赖、冲突、重复 | 联合调整 C：合并重复义务、区分条件、安排顺序或保留配套步骤，必要时联动 D/S | 联合成功不能证明协同增益；不能为凑 C 强行合并不相关要求 |
| 旧策略有局限，但无可靠替代；历史不适用或支持不足 | 原始更新仍合理时保持并执行；也可据当前证据提出范围明确、可观察的探索。保留未知，不强迫变换 | 不能把缺少历史当安全证明，也不能把未知自动转成撤回／阻断 |
| 观察来自未实现方案、未到达机会、其他执行分支或技术失败 | 限制响应归属；若有落实或路径变化证据，处理相应联系，而非判该方向无效 | 不用这些记录直接否定方向或支持替代；技术错误不能成为负面 Effect |

规则应用不依赖固定的 D→S→C 次序。例如方向仍有效但只在部分条件下可用时，S 与 C 的分支处理通常比整体替换 D 更有依据；但若当前可见信息无法区分这些条件，就不能把学习侧知道的差异写成 Actor 可用触发。

### 4.3 两种依据必须区分，但不禁止共同使用

**当前证据修正**处理原始更新与当前能力／事实的失配；**历史响应预条件化**处理原始更新预期与可比历史实际作用的关系。两者都可以产生合法更新，但只有后者直接支持本文的跨轮方法主张。

一次实质变换的简短理由应回答：

> 历史实际更新在何种条件下出现什么响应；这些条件和依赖为什么与当前选择有关；因此保留什么、改变什么，以及还要观察什么。

若决定完全由当前能力支持，应如实说明，不补挂 Effect ID 来制造历史作用。若历史只提供未知边界，就说明其限制了哪个结论，而非宣称它决定了新方向。Keep 可在总体 reason 解释关键历史适用性，不为每个未变要求增加证明行。

`changes.basis` 引用提供可追溯性；**引用存在、提及次数、解释长度都不能替代具体的更新作用**。充分的短理由优于固定格式的长论证。

### 4.4 如何避免过度保守

- **Keep 保留 \(U_t\)，不是令 \(\Delta S_t=0\)。** 程序仍将原始更新交给 Editor；只有 Parent 已满足更新或确无可构造更新时才没有 Candidate。
- 有限证据可以支持有界探索；边界是可见触发、相关依赖和可观察问题，不是必须有任意次数的成功历史或极小编辑。
- 未验证收益放 Watch／limits。真正不可执行的必需动作、不可表达的必要区分或矛盾目标，才进入 Open／needs_revision。
- 对可独立撤回且不破坏目标与依赖的部分，Fusion 可显式 withdraw，让其他完整更新继续；Editor 不得自行删项。若撤回导致整体目标无法满足，不能把局部候选称作完整方案。
- 若全部要求被合法撤回，应记录“无有效更新”，不是历史 Keep，也不是技术失败。现有 Compiler 的 ready 非空限制需在未来落地时接入已有无 Candidate 出口；本设计不新增一套状态机。
- 没有历史时保留明确记录的程序 identity 起点；它没有完成历史适用性判断。Diagnosis 的构造能力检查仍然存在，不额外启动第二个无历史诊断器。

### 4.5 输出与编译

沿用 `changes: from → to`，可多对多；完整替换受影响要求，继承未变项和依据。Watch 随实际决定变化迁移，不删去仍重要的反例。Compiler 核验来源、ID、去向、版本和合法路由，不用关键词或字符串相等判断自然语言策略是否正确。

不同组的相关要求必须在同一次 Fusion 构造中协调，不将 P 实现成逐组独立变换后拼接。新增无关目标不属于预条件化增量；涉及 Goal 变化时使用现有需修订出口，并保留原因，不由 Fusion 悄悄改写 intent。

## 5. 从实际响应修订预条件器

### 5.1 三种比较共同决定学什么

Replay/Memory 在一次后处理中对会影响认识的关键部分进行比较：

| 比较 | 要回答的问题 | 对认识修订的作用 |
|---|---|---|
| 有效 Update ↔ 实际 Skill 修改 | 策略、触发、强度和关联是否落实，是否有额外义务或有效例外丢失 | 有偏离时响应归于实际版本，不能拿它验证未落实的方案；保留落实限制 |
| 相关条件／机会 ↔ 实际行为 | 决策条件是否到达；行为是否发生；是否换了分支；机会是否因路径改变而消失 | 区分行为反例、未执行与未测。路径改变本身可能有作用，不能简单排除 |
| 预期及 Parent 行为 ↔ Candidate 行为／结果 | 目标行为、作用范围和关键保留有何变化，哪些与预期不同 | 支持、限定或修订条件化作用认识；允许局部改善而整体失败、整体成功而局部变化 |

这三种比较不是三个新增调用，也不要求每条更新、每项任务逐格填写。把能改变下一次决定的发现写在现有 `findings.observation`，把真实未覆盖范围写在 learning `open` 或 Effect `limits`；关键 Watch 都有明确去向。

**learning.open 与 Plan.open 语义不同。** 前者描述证据／覆盖限制，不自动变成下一轮构造阻断；后者才表示当前有效方案的必要缺口。

### 5.2 认识更新的具体规则

1. **响应归于实际更新。** 以 \(\Delta S_t\) 和实际执行为准，不能以 Diagnosis 或 Fusion 的预期覆盖它们。若多个改动共同存在，保留联合条件，不分摊收益。
2. **只修订得到支持的关系。** 新证据覆盖旧认识的一部分时，只更新这一部分；其余未知与反例继续有效。可以保留复合自然语言，不要求拆为原子字段。
3. **正面范围可扩展，负面边界可撤销。** 当旧限制确被新证据否定时，更新 active claim／limits，而不是永远机械继承；部分反证不能带走未检验条件。
4. **相反结果优先检查条件和落实差异。** 不能解释时保留冲突；不因新结果更晚就覆盖旧结果，也不维持已被明确反证的无条件结论。
5. **未触发、未落实、未评估分别限制可学内容。** 未触发不支持方向无效；实现偏离不支持预期策略失败；未评估不等于保持或零影响。
6. **没有改变认识就不生成同义 Effect。** 新来源只有在改变范围、可信解释或关键边界时才值得更新。重复读取不增加独立证据。
7. **拒绝版本也能学习。** Gate RETAIN 不删除其中局部正面或负面响应；但下一次适用性须核对未被采用的 Candidate 依赖是否存在。
8. **无 Candidate 不产生本轮新编辑效果。** 当前 Parent 事实可以修订历史认识，但不能把未执行建议写成已观察响应。

`replace / retire_limits / basis / supersedes` 继续负责认识版本及来源。程序检查修订引用和版本是否合法，语义规则负责修订范围是否有依据；两者不能混为“限制退役已被程序证明正确”。

### 5.3 学习如何改变下一轮 P

Memory 不是更新后的总结附件。一次修订必须有可能改变未来的适用性判断，例如：

- 以前只支持条件 a，现在在 b 也有实际响应，下一次可考虑扩大作用范围。
- 原来把负面结果归于方向，后来发现实际没有落实该方向，应撤回对应负面推断。
- 原来将两项要求视为可分开更新，新证据显示其中一项依赖另一项的状态变化，应联合考虑。
- 原来把整体成功当范围安全，发现另一条件下相关行为受损后，应限定原认识。

是否立刻发生非恒等修改由下一轮 Update 决定；认识变得更准确不要求马上“用一次”或强制改 Skill。

## 6. 由算法推导五模块职责

| 模块 | 从统一算法推导出的职责 | 使用和交付 | 与一般模块的实质区别 |
|---|---|---|---|
| Diagnosis | 构造可被变换的行为更新，而非仅报告错误 | 当前 Parent／轨迹／组／能力 → Goal、条件化 Update、关键 Watch／Open | 明确准备怎样改变行为，区分目标和可替换策略；不穷尽所有问题，也不读 Memory 后伪造独立初稿 |
| Memory | 提供并修订实际更新方式的条件化响应认识 | 实际修改和行为事实 → 有来源、依赖和限制的 Effect | 认识围绕编辑—行为关系组织，不能退化为失败摘要或风险禁令库 |
| Fusion／Compiler | 根据作用差异选择 D/S/C 变换并形成有效更新 | 原始 Plan＋当前条件＋Effect → 显式增量＋有效 Plan | 变换必须针对同一更新的选择，不能只读历史后重写一份无对应关系的方案 |
| Editor | 保持有效更新的行为语义并实现到实际 Parent | 有效 Plan＋Parent → Candidate、映射、重要异常 | 可改措辞和位置，不独立重选策略、强化义务或删除例外；效果未知不是落实失败 |
| Replay | 观察实际响应并定位预期—实现—行为的差异 | 真实 diff／映射／Watch／配对轨迹 → findings 与认识修订 | 成功数只是一种结果；机会、策略执行、范围与关联变化共同决定可学习内容 |

五模块不是五个独立创新点。**Memory → Fusion → 实际落实和 Replay → Memory** 是学习循环；Diagnosis 提供有实际价值的起始更新，Editor 使算子输出可被行为检验。Gate 只管采用和状态衔接，不参与 D/S/C 推断。

实际运行中发现 Editor 异常时，复用 needs_revision 保留上游问题，不默认追加修复调用或建立自动多轮协商。后续是否允许有界返工须另定执行协议，不纳入本次最小设计。

## 7. 一次完整过程与通用走查

### 7.1 语义伪代码

```text
输入：当前已发布 Parent、Memory、新 Train 批次与真实能力协议
执行 Parent；冻结共同决策问题和实际条件 G
Diagnosis 构造并保存 (Goal, 原始 Update, Watch, Open)

若有可构造更新：
    空历史可记录程序 identity；否则在一次 Fusion 中：
        定位原始更新中的关键行为选择及相关依赖
        按实际条件、Parent 和实现情况比较相关历史响应
        对合理部分保持；对有依据的作用差异构造 D/S/C 调整
        对探索保留可挑战预期；处理真正构造阻断
    Compiler 装配有效 Update 和 Watch，保存原→新关系
    Editor 在实际 Parent 上落实，保存 Candidate 与实际 diff
    有合法 Candidate 才执行同批 Replay

Gate 按既有规则决定 Skill 采用
一次 Replay/Memory 后处理：
    比较有效更新、实际修改、机会、行为和目标结果
    学习有条件联合响应；修订被证据支持的认识范围
完成有效 Memory 后共同发布下一轮状态
```

上述循环不是对每条要求分别调用模型。保存原→新关系也不要求把所有历史稿件反复塞入每条 Effect。

### 7.2 正向变换示例：验证义务与重复检查

以下为**构造性机制示例，非两轮实验事实，不能作为实证收益**。

**原始 Update。** 目标是让后续操作基于有效前提，Diagnosis 提出“每次操作前重新检查全部前提”。

**假设已有的实际响应认识。** 某次增加重复检查的联合更新，在前提已经变化时伴随错误减少；在依赖未变且有效证据仍可用时，出现重复查询和进度延迟。两类条件都有实际记录，但更新的独立因果份额未识别。

**当前适用性。** 当前协议能在观察或已有状态中显示证据及相关依赖是否变化；这一能力必须真实存在，不能由学习器替 Actor 假设。

**P 的决定。** 保留“校验前提，再执行依赖动作”的策略方向 D；S 将无条件重新检查调整为前提变化或缺少可用证据时重新检查；C 与会改变前提的操作协调，在其后恢复相关检查，其他条件保留已有有效证据的使用。这里保留的 D 是实现目标的行动策略，不是把 Goal 本身称为方向。若历史只测了一个依赖，只对它限定结论，不取消所有检查。

**Editor。** 实现检查条件与相关顺序，不能写成无条件跳过检查，也不能把“可复用有效证据”写成“总是禁止重新查询”。

**Watch／Replay。** 分别观察前提变化后是否恢复检查、前提未变时是否减少无效重复，并检查有没有跳过必要检查。若本轮从未遇到前提变化，只能学习已覆盖分支，不宣称两边都成立。

**Memory 修订。** 若实际行为支持部分分支，扩充该条件下的认识；若 Editor 误写为无条件跳过，则记录实际偏离及其响应，不能据此判定条件化复用方向失败。

如果当前 Actor 无法辨认依赖变化，条件分支不能照搬。P 应依据可见信息选择仍可执行的原方案或其他有依据的方案；不能借历史优势把不可见状态变成触发条件。必要区分确实无法表达且无可行方案时，才报告构造缺口。

### 7.3 其余必要走查

| 输入关系 | 合理结果 | 用来防止的误解 |
|---|---|---|
| 当前 Update 已覆盖历史成功条件及关键限制 | Keep 原始更新并继续 Editor | Keep 不代表停止进化 |
| 旧方向有负面观察，但当时未真正执行且没有替代证据 | 不以该记录否定方向；明确未执行范围 | 任务失败不直接导出 D 替换 |
| 新反馈实际覆盖了过去未测条件，目标行为出现且无已观察冲突 | 可在该条件扩展 S，保留其余未知 | 预条件化不只会缩小更新 |
| 两项要求分别合理，但一项操作改变了另一项的必要前提 | 联合调整顺序或条件，保留共同目标 | C 处理实际依赖，不强求协同收益证明 |
| 同组历史缺少当前必需能力，不同组历史却有可比决策与能力 | 前者限制迁移，后者可条件化参考 | 分组不是适用性硬边界 |

## 8. 与当前实现的实质差距及最小落地范围

当前实现已拥有大部分必要容器与通用原则。[契约][contracts]、[条件规则][rules]、[共享接线][grouped]均已表达条件化要求、历史限制、D/S/C 变换和忠实落实。**因此本设计的增量不能表述为“首次增加这些原则”，而应落实为作用关系在决定与学习中更具体、交接信息足以支持这些判断。**

### 8.1 从算法需求推导差距

| 算法需要 | 当前已有 | 必要差距及处理 |
|---|---|---|
| 可调整的原始 Update | `intent/requirements/watch/open`，当前证据与组引用 | 目标与策略、更新与关键行为预期的语义联系不稳定；修订规则组织，不先改字段 |
| 条件化响应决定变换 | CONDITIONED_RULES、显式 from/to、Watch 迁移 | 已有抽象原则；实际决定可能只做能力修正、口头提历史。按 §3–4 形成具体决策过程，实质理由连接响应与选择 |
| 实际响应能归回实际修改和有效要求 | 全文、diff、轨迹、Effect.actual_update | 学习输入未直接携带 Editor 映射；Effect 只保存显式 refs，可能缺少 about 对应的要求快照。补齐必要交接，避免后续只剩行为结论 |
| 反馈改变认识的受支持范围 | findings、replace、retire_limits、历史上下文 | 需要 §5 的机会／落实／行为区分及局部修订原则；不因一个复合句的部分反证删除其余未知 |
| 不因未知阻止合理更新 | Watch 与 Open 区分、允许探索和 Keep | 保持这些出口；明确全撤回与 Keep 的区别，避免契约把合法无更新误报技术失败 |
| 低成本持续运行 | 一次联合学习、历史 source 去重 | 新信息必须按 context 共用并只展开相关片段；不把整份初稿、变换、映射重复复制进每条 Effect |

### 8.2 建议修改位置与影响

这是后续实现范围，不是本轮已执行的修改。

**A. 一组协调的语义规则修订，模型输出 schema 默认不变。**

- `conditional_update.py`：以 §4 组织 Fusion 的响应比较与变换原则；Diagnosis 强调可调整的行为更新与关键预期，Editor 强调相对有效 Update 的策略／条件／强度／关联保持。合并已有重复文字，替换而非不断追加规则。
- `compact_learning.py` 与 `effective_memory.py`：以 §5 组织实际修改、机会与响应的比较和认识修订。保留现有 findings／Effect 增量；不新增固定 D/S/C 分类或风险评分。
- `grouped_update.py`：保持分组是比较坐标、当前事实是依据；统一接入上述规则，并明确单主线角色。

这部分的价值必须体现在输出决定与认识变化中；只增加标准措辞、引用要求或声明“已检查”不算实质完成。

**B. 小范围程序装配改动，让现有对象能互相解释。**

1. 在 `prepare_grouped_learning` 的程序上下文中附带本轮已经保存的 Editor 映射／重要异常，绑定有效 Plan 和实际文本；Replay 仍读取真实 diff，不能相信映射自证。
2. 在 Effect 持久化时，从 findings.about 解析相关 requirement/watch，再沿 watch.about 补齐其有效要求快照，使用现有 `sources`／`resolve_source` 机制。共同目标有实际解释需要时同样保留；不自动复制所有无关要求。
3. 已存 initial/effective Plan、Fusion 增量、Editor 和 diff 继续作为完整轮次档案。**不要求每条 Effect 都复制原始 Plan 与全部 Fusion 理由**：Memory 学习的是实际采用更新；需要辨认变换或落实差异时，再给相关上下文片段。新模型消费视图中的引用必须在该次请求中可解析，不能只给不可读取的本地路径。
4. 相同 context 下公共 diff／grouping／版本信息尽量只展开一次；如果新增关联造成明显重复，连同该装配一起去重。无需先建全局检索系统或历史压缩 Agent。

这些属于程序拥有的输入／持久化元数据扩展，虽然不改模型输出形状，仍是接口内容变化，后续需要新 profile／版本和离线回归。旧产物及旧消息重建路径保持原样，不回写历史来“补齐”证据。

**C. 一处需要确认的路由衔接，而非扩展决策体系。**

`apply_fusion` 当前禁止 ready 且 active requirements 为空。[Compiler][compiler] 允许逐项 withdraw，但整项合法撤回最终不能进入现有无 Candidate 流程。后续若按 §4.4 支持该语义，应保留明确理由／Watch 去向，直接接入当前 candidate=None 的版本结算路径，跳过 Editor 和 Candidate 执行。继续禁止 ready 带阻断 Open。无需新增第五种预条件化类别，也不能把格式／网络失败导入此路由。

其他 Compiler 行为——多对多替换、未变项继承、来源合并及 Watch 去向检查——继续复用。无需让程序尝试证明自由文本 D/S/C 等价。

### 8.3 当前不需要进入实现范围的事项

不迁移 `intent` 为 `goal`，不引入强制 D/S/C 三字段，不为限制建立原子状态系统，不修改 Gate，不给 Actor 增加全局记忆或特定停止动作，不增加常规审阅调用或自动重试。具体任务特例和“某单词不能改成另一单词”规则不进入算法。

若下一步发现现有接口已经能完整表达某条原则，就只调整其使用方式；若问题只影响一般格式或报告展示，按工程维护处理，不包装成核心算法创新。

## 9. 验证标准：更新能力与方法作用分别判断

### 9.1 离线检查的目标与边界

后续落地前使用旧产物作为不可变反例，再使用去除对象名、替换任务语境的机制案例。人工或确定性检查可以验证数据流和推理边界；**不能把人工写出的正确答案当成新 Prompt 的实际表现**。新 Prompt 的行为能力需在另行冻结的模型验证中观察，本轮不执行。

| 验证问题 | 预期通过条件 | 不能用什么替代 |
|---|---|---|
| 原始方案合理时是否保留更新能力 | Keep 后仍可产生有效 Candidate；未知收益不自动进入 Open | 只统计 changes=[] 比例 |
| 响应是否支持变换 | 能定位可比条件、实际更新和行为证据，说明具体改变及剩余未知 | 只检查 Effect ID 是否出现在 basis |
| 正向与负向 S 是否均可表达 | 条件支持时可扩展／加强；副作用证据支持时可收窄／协调 | 一律选择更小或更弱更新 |
| C 是否保留实际依赖 | 联合变换后前提、顺序和有效延续仍成立 | 要求每次填一条 interaction |
| Editor 是否落实选定更新 | 关键策略、条件和义务强度保持；实质异常如实报告 | 精确摘录存在或 issues=[] |
| Replay 是否按机会和实际实现学习 | 未到达／未执行不误判无效；路径变化和局部进展可保留 | 最终任务成功／失败 |
| Memory 是否局部校准且可继续修订 | 新证据只改变其支持的关系，未覆盖条件保留；已反证旧结论可以退出 active view | 全部继承或整条无条件删除 |
| 分类是否组织比较 | 同组不同条件不强迁移，跨组同类决策可参考；组外影响不默认零 | 只检查 group ID 引用齐全 |

现有反例分别检验一般的条件许可强化、不可见条件／不可执行动作、部分反证、机会变化；不要求旧两轮任务全部成功。对保持、扩展和有界探索也设正向案例，避免测试集只有“何时拒绝”的案例。

程序测试只检验值得机械保证的性质：对象身份与来源、相关静态片段补齐、受影响 Watch 去向、历史版本不串用、合法无更新路由、消费去重不丢关键内容。自然语言语义不能用关键词匹配的测试伪装已通过。

### 9.2 新 Train 流式验证

实现稳定后再单独冻结新任务批次、初始状态、Prompt/profile、调用预算、Gate 和技术失败处理。至少覆盖一次“本轮新认识被下一轮 Fusion 消费”的完整周期。不得根据同批结果反复修改 Prompt、换题或补跑，直到得到期望表现。

旧正式 Memory 若继续作为起点，必须明确其已知认识边界的处理：保留原快照，并用单独可追溯的新版本修订，或在实验协议中明确采用其他起始状态；不能把审查旁注默认为算法已经消费的事实。选择哪种起点在实验阶段冻结，本设计不自动改旧 Memory，也不把两种起点的结果混作同一比较。

分别记录：

- **进化结果：** Parent/Candidate 成败转移、关键行为改善与保留、局部退化和是否持续产生合理 Candidate。不能只报告总成功率。
- **机制证据：** 哪个响应认识改变或支持了哪个决定，实际文本是否落实，机会到达后出现了什么响应，Memory 如何据此修订。只要求关键链条，不要求每轮必须有非恒等变换。
- **成本与稳定性：** 总调用、输入／输出 Token、失败及恢复成本、端到端耗时、合法方案因格式或不必要阻断无法执行的情况。

默认常规语义调用数不增加；输入扩展必须说明其改变哪项决定或学习，优先复用／去重。任务表现、Token 和失败率的可接受差距需在真实比较前按预算预声明，不能事后挑阈值。当前两轮不同任务的结果不足以设定或证明统计非劣性；小样本只报告观察，不声称“没有明显损害”已获统计确认。

### 9.3 方法收益的后续验证

主机制能稳定运行以后，再增加无历史响应的消融；若进一步区分 D/S/C 规则与一般历史辅助修订，再考虑相同历史信息和可比预算的普通修订对照。单独去掉 Memory 只能检验历史整体作用，不能独立证明 D/S/C 算子的额外价值。

同样的起始状态、任务与预算须在比较协议中明确；方法主线不必永久保留多分支。本文不安排具体新实验或调用，不用两次 7/10→8/10 替代消融结论。

## 10. 后续落地顺序与机制准入原则

设计之后按依赖顺序实施，而非按五模块各立一个项目：

1. **确定语义规则及最小输入。** 以 §2–5 为规格，将现有 Prompt 中重复原则合并成一组协调规则，确认有效 Update、实际 diff 和响应的必要来源。
2. **完成小范围装配及接线。** 补相关 Update／映射信息，保持现有输出 schema，处理必要路由和由新增信息引起的重复；旧档案不迁移。
3. **离线验证通用性质。** 先程序一致性，再机制案例检视；保留反例与正向探索案例，不根据旧任务成败调 Prompt。
4. **冻结新协议后观察流式响应。** 分别评价进化质量、具体机制作用和成本，决定是否需要继续修订。
5. **机制稳定后才检验额外收益。** 消融或对照是研究验证阶段，不先扩大运行框架。

任何新增机制都要说明：与 D/S/C 更新作用的直接关系；去掉任务名称后的通用意义；实际改变哪项构造、落实或学习；以及新增约束／Token／失败风险是否值得。这个准则用于设计取舍，**不变成运行时每条 Update 的四项强制自证表**。

本设计的完成标准是已经明确：P 怎么决定、L 怎么学习、五模块如何服务同一关系，以及现有实现最少需要补什么。实现有效性和研究收益仍由后续验证决定。

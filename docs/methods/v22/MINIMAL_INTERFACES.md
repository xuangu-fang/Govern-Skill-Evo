## 1. 选择：共享一份工作方案，模块交付必要增量

最小路径是：**当前证据形成认真初稿 → 适用作用认识改变具体要求 → Editor 构造实际文本 → 执行发现修订作用认识。** “最小”意味着每项信息都有决策用途，不意味着只留下笼统建议。

一份工作方案有不可变的初稿和后续版本；并非所有模块共同覆盖同一个可变文件。初稿 \(u\)、有效要求 \(\widetilde u\)、实际 Skill 差异 \(\Delta S\) 仍是三个不同对象。模型只生成本模块负责的语义内容，程序管理来源、版本、解析和派生视图。历史只使理由变长、没有改变要求时，不记作非恒等变换。

| 更新规则需要判断什么 | 最少需要什么信息 | 它改变哪个决定 |
|---|---|---|
| D：当前策略在哪个环节受限，替代是否可执行 | 行为目标、条件化策略、相关实际响应及限制、Actor 能力 | 保留、替换或调整先后；不能用任务总分直接选方向 |
| S：哪种范围或义务影响目标／保留行为 | 可见条件、作用对象与强度、目标和非目标响应、区别条件的依据 | 收窄、扩展、条件化；不能用字数或未遵循代替尺度依据 |
| C：哪些要求共享决策、冲突或相互依赖 | 相关要求组、共同判定或前置条件、实际联合观察及归因边界 | 合并、分支、安排顺序或配套修改；不能由共同成功推导单项贡献 |
| 三类规则的共同边界 | 原始方案、反例、未知、实际落实、可反驳的观察问题 | 决定是否变换，以及后续应撤回或修订什么 |

上述内容不需要分别对应一个字段。比如一条条件化要求就能同时表达策略、范围和必要顺序；一条联合观察可以同时回答多个相关问题。

## 2. 共享表示：少量可寻址的语义单元

以下名称约定共享信息的含义、所有者和缺失处理。后续最小实现已经将其落实为独立的 `v22.compact_update.v1` 与 `v22.compact_learning_input.v1` 本地协议；具体序列化和停止规则见 [实现说明](COMPACT_CYCLE.md)。这些版本是研究原型的约定，不是冻结的最终算法；不为“可扩展性”增加空字段、嵌套评分或固定维数。

### 2.1 工作方案 Plan

| 内容 | 最小表达 | 形成与修改权限 |
|---|---|---|
| `intent` | 一段话表达要改善的行为及共同必须保留的行为；引用关键当前依据 | Diagnosis 形成；Fusion／Editor 发现目标或事实解释需变时返回相关诊断 |
| `requirements` | 每项为局部 ID、条件化行为要求正文、依据引用。正文说明在什么可见条件下做什么、必要范围／停止条件及局部保留要求 | Diagnosis 形成初稿；Fusion 修改受影响项；Editor 落实 |
| `watch` | 每个问题有局部 ID、关联要求／目标和一条观察问题，包含所需情境及重要预期或反驳情形 | Diagnosis 提出关键问题；Fusion 随实质变换修订；Editor 仅补充新发现的重要实现不确定性 |
| `open`（无阻断时为空） | 阻止可执行构造的具体缺口、冲突或不可落实部分，指向受影响对象 | 发现者报告；相关负责环节处理，程序不替模型补答案 |

`intent` 中的共同约束写一次；局部保留要求留在对应正文，不能只提取全局 `preserve`。有共同判定的要求可以组织成一个组，或在正文引用另一项要求。ID 只用于引用和变更，不是固定编辑坐标，不要求一个问题对应一项要求、一段 Skill 或一个独立效应。引用始终绑定所属方案／认识版本；不同轮次同名 `u1` 不自动表示同一个方向。

当前紧凑协议中的 **`Plan.open` 表示构造阻断**，例如不可用能力、尚未解决的要求冲突或会改变可执行策略的关键缺口。尚未验证的行为收益、泛化边界和竞争解释通常进入 `watch` 与 Effect `limits`；不能因为预期还未执行验证，就自动阻止一项条件明确的有限构造。Replay 的 `open` 则说明反馈中的未覆盖或未知范围，不会被程序直接转换成下一轮 Plan 的构造阻断。

**要求与预测分开。** “暂时故障进入恢复分支”属于要求；“这能减少提前退出且不增加重复查询”属于观察问题。历史限制不能改写成无条件命令。原因解释只保留决定该策略所需的简短依据与竞争解释，不再复制成 gap、hypothesis、proposal 三套叙述。

`watch` 不是完整行为指标库：保留目标、会影响本次取舍的保留行为、实质变换的可观察差异和已知重要反例。相关问题可合并，数量由决策需要决定。被合并的局部保留条件必须仍可辨认；不能因没有专门字段而消失。不是每项要求都必须配一个问题，但每项实质变换及关键保留要求应有观察去向或明确的未检验限制。这一语义覆盖不能只靠 ID 检查证明。

### 2.2 作用认识 Effect

一条认识保留三块语义内容，外加程序管理的 ID 与版本：

- **`claim`：** 在什么条件和相关 Parent 依赖下，什么实际策略／编辑组出现了什么行为响应，目前支持何种作用判断。区分观察、解释和未执行假设。
- **`basis`：** 指向实际版本、diff 和行为发现的来源；比较对象由来源解析，不让模型重抄 hash 或完整运行记录。
- **`limits`：** 会限制消费的反例、未覆盖条件、竞争解释及单项／联合判断边界；引用相应来源。没有反例记录不表示全范围安全。

例如“整包候选下未再出现列表外动作，p1 的独立贡献未知”可以成为局部认识；“p1 已证明普遍有效”不能由这份证据得到。明确识别的条件、能力或要求冲突可记为实现限制；网络、解析、字段或引用校验失败只记处理错误，不能据此形成策略作用或不可落实认识，更不能存成未执行策略的负面行为响应。

Memory 的消费视图由这些记录派生，不再让另一个模型生成一套历史摘要。读取某条认识时连带其已知关键反例、相关依赖和必要证据片段；不能只取正面结论。若预算或缺失来源使这部分不完整，应说明该认识不足以支持哪项变换，缩小处理范围或暂缓。未检索到相关认识不等于已证明没有相关历史。

后续 [有效认识消费实现](FIXED_CONSUMPTION.md) 增加一项必要的状态操作：`memory_delta.retire_limits` 按旧 Effect ID 与具体索引退役已被反驳的限制，并绑定当前 finding。旧正文、原因和依据归档，未退役的未知与反例默认继承；不能只追加纠正说明却让错误限制继续生效。claim 与各条 limit 分别记录上下文，旧来源混合且无法还原时保留未知。消费保留原始来源，不重复将旧 finding 解释作为当前事实。仅修订已有认识时可用独立 reconciliation profile，不重做完整 Replay 或新增 Effect；这不会修改原执行问题或固定初稿。

### 2.3 程序管理的上下文与事实

程序负责 Parent／Candidate 内容身份、初稿与要求版本、允许的数据用途、能力说明、来源目录、实际 diff、调用记录、可比条件、原生结果和成本。模型请求只带判断所需的语义视图与可解析短引用；不要求模型生成长路径、hash、成本、原生成功率或另一份运行索引。

短引用必须在该次请求中解析为必要内容，不能只给文件名期待模型已经读过。存档可保留完整材料，模型输入避免同一轨迹同时出现在原始包装、摘要和逐项证据中。初版小任务批可直接使用一份完整的紧凑 Train 轨迹；以后局部读取须显式保存读取范围，并按相关边界补读，不能只给成功片段。

## 3. 模块接口：谁决定什么，交付什么

### 3.1 Diagnosis：交付初稿，不交付全套分析报告

**输入：** 当前 Parent、基础执行协议和能力、允许的当前任务轨迹与反馈。为检验历史变换的贡献，先独立保存 Diagnosis，再向 Fusion 提供历史；同次调用先看到历史再输出的“初稿”不能冒充无历史对照。

**输出：** `revise` 时交付 Plan；`no_change` 或 `need_evidence` 时交付一条足以解释停止的理由及相关来源／缺口，不强制生成空方案、假设列表或假边界案例。严肃初稿仍须区分 Skill 缺陷和其他解释，核对关键行为与可执行性，但逻辑工作不逐步外显为必填字段。

只有关键歧义会改变方向时才补充读取。没有被分析的行为保持未评估，不能因删除了诊断矩阵就默认全部正常。

### 3.2 Memory 读取：交付有关联限制的认识

**输入：** 当前 Plan 和相关 Parent／能力条件。**输出：** 相关 Effect 及其必要来源和限制；允许为空。程序做身份解析与已有反例／联合依赖的关联展开；语义适用性由 Fusion 在同一次构造中判断，不单设检索判断或历史复核 Agent。

小历史集合可直接装配当前认识；规模增大后再决定检索方式。已发现冲突或未加载的关键材料作为当前消费限制保留，不能将检索成功标志当作证据适用。这里只读取已存在的认识，不根据本轮尚未发生的 Candidate 反馈更新 Memory。

### 3.3 Fusion／Compiler：交付要求变更，程序生成有效方案

**输入：** 已冻结初稿、有关 Effect、当前证据及能力。**常规输出：** 受影响要求的变更、简短决定依据，以及确有变化的观察问题／未决项。每项实质变更至少能回答：

> 改原方案中的哪些要求；改成什么条件化要求；哪条认识或当前依据揭示了什么作用偏差；什么观察可能使这项决定需要回修？

建议用“来源要求 ID 集合 → 替换后的要求”表示变更：既支持单项改写，也支持合并、拆分和协调组。只重写受影响的完整语义单元，避免易碎的自然语言字符串 patch；不重复输出整个初稿。被替换单元中仍有效的义务必须保留在新正文，不能只写“其他保持”让程序猜测继承。若撤回／暂缓，明确区分两者并说明依据，不把空 replacement 当作默认删除；相关未实现目标保留在未决范围，不能宣称全案目标已覆盖。没有原要求来源的新目标或新方向先返回 Diagnosis，不由增量接口无来源地新增。

程序根据基准 Plan 和这些变更装配 \(\widetilde u\)。未涉及项原样继承；所有被替换、合并、拆分或撤回的项留下来源对应。目标与共同保留要求不能被 Fusion 静默改写。实质变更涉及已有观察问题时，显式替换或保留原问题及其去向，不删除不利问题。每个新变更可共享一个观察问题，不要求每项附一套预测表。

**恒等输出也是决定。** 无需变换时输出简短理由和必要限制，程序沿用同一方案；没有调用 Fusion、解析失败或材料不足均不能伪装成“判断后恒等”。无历史且当前初稿无已知作用偏差时，可显式走程序 identity 路径，记录其未进行独立历史变换判断。

Compiler 默认是程序装配职责；联合要求的条件、顺序与取舍由同一次 Fusion 语义构造完成。程序验证基准版本、引用、变更目标、去向及以 ID 明示的依赖是否缺项，不能从正文发现所有隐含依赖或自动证明自然语言无冲突。语义含糊则返回受影响部分，不能靠自动删项凑出可执行计划。

Editor 接收装配好的完整有效要求，必要时连带变更理由与有关证据；不要求它重放所有历史，或自行从初稿和新要求中选择策略。

### 3.4 Editor：实际文本、组级定位和重要例外

**输入：** 精确 Parent、有效 Plan、执行能力、有关条款／证据。**输出的最小内容：**

| 内容 | 约定 |
|---|---|
| 构造决定 | `candidate`、`no_change` 或 `needs_revision`；后两者给具体条款依据或限制 |
| Candidate 文本 | 小 Skill 初版仍交付完整文本；实际 diff 由程序生成。若无合法 Candidate，不交付可执行版本 |
| 组级定位 | 要求 ID 集合对应实际 Candidate／Parent 的短摘录或可解析位置；允许多对多，不逐触发、策略、范围等六方面重复摘录 |
| 重要例外 | 只输出未落实、实质偏离、不可用能力或真正影响更新的未知，附受影响项及必要反例／建议；没有发现时可为空 |

Editor 在同一次构造中核对实际文本的条件、范围、保留行为和依赖；这些责任不删除，只取消每项六维自证的强制输出。它可以调整位置和等价表达，不能因构造方便而换策略或放宽条件。实质问题回到 Fusion；涉及目标／观察解释再回到 Diagnosis。已知阻断问题未解决时不执行受影响组；若要只执行其他部分，先形成依赖完整的新有效 Plan，不能由 Editor 偷删。

要求有去向、实际实质改动有来源仍需双向核对。程序检查定位确实存在、已声明要求没有遗失、diff 对应实际文本；标题、空白不再要求逐字符映射。删除条款使用 Parent 定位，新增或修改使用 Candidate 定位。组级引用可以覆盖多个相关段落，但不能用引用整份 Skill 代替定位，或给无关新增义务挂一个泛化 ID。语义对应由 Editor 负责，程序只能提示未定位的改动，不能据锚点存在证明保持。

**`candidate` 仅表示构造交付；“例外为空”表示没有报告例外。** 不再制造 `faithful` 六维全绿，亦不生成“语义保持已验证”标志。准确摘录、程序检查和模型自述都不证明语义等价或行为正确。已有 p2 条件漂移、p3 能力不足等问题即使定位齐全，也必须回修；不能等待一次成功执行来追认其忠实性。

Editor 不重复生成上游已有的预期；只提出新发现的重要观察问题。程序在执行前冻结有效 Plan、实际 Candidate 和当前 `watch`，保留问题来源。执行结果出现后不能回填这个快照。

### 3.5 Replay：稀疏发现与明确未评估范围

**输入：** 实际版本和 diff、有效要求与组级定位、执行前 `watch`、程序事实、允许的真实轨迹，以及可能受影响的 Effect。Replay 仍需看实际文本，不能只信 Editor 定位；但不再对每项要求重复输出一份全覆盖落实报告。

**输出：** 对更新或作用认识有影响的 `findings`，以及影响判断的 `open`。一条发现引用相关要求／问题／认识，简述实际观察、条件与可比性限制，并给足以定位它的事件来源。可同时回应多个问题；允许记录计划外变化，不得只搜原先列出的有利证据。

机会是否出现、路径是否改变、行为是否发生及结果是否改善，仍须在相应判断中区分，但不强制为每个目标和每项任务填完整一行。**每条发现必须注明适用的实际运行范围**，不能用某一任务的观察替整批任务作结论。

程序为执行前问题维护一个小的去向索引：关联了哪些发现、哪些运行被分析、哪些范围未评估。没被回应的问题默认是 `not_assessed`，不能补成未触发、已保持或零影响；模型若认定外部条件未出现，要给相应观察依据。Candidate 改变路径导致机会消失，可能本身就是负面发现，不能归入无关未覆盖。

这个索引不是目标 × 任务的模型输出矩阵，也不是成功认证。正常收尾需使关键问题和已知反例有发现或有依据的限制说明；模型漏答造成的 `not_assessed` 是待处理缺口，不能由程序填状态后宣告完成。已经确认未覆盖的条件可作为合法有限结论保留；语义处理失败与这种有限结论分开。未评估部分不支持正负作用判断，不阻止保存其他有效局部观察，但不能据此发布依赖这些判断的认识或采用结论。

已经发现的文本偏离、不可见条件和执行不完整只在它们改变解释时重点报告。观察到两侧都有相关机会且行为符合要求，才支持限定范围的保持判断；原生成功不证明所有保留行为保持。仅整包对照时以实际更新组为观察单位，不能分摊单项收益或协同效应。

### 3.6 Replay／Memory 联合后处理：发现变成认识增量

同一次后处理可交付两部分：`findings` 描述实际发生了什么；`memory_delta` 指出哪些作用判断需要补充、限定、替换、拆分或撤回。前者不会因为后者修改而被覆写；合在一次调用不改变逻辑边界，不要求另起总结、归因或压缩 Agent。

一个增量引用待修订 Effect 版本和新增发现，给出新的 `claim`／`limits` 或明确保持正文仅补来源。新认识则没有旧版本。程序继承旧证据与反例关联、追加新来源，避免模型每次重抄全部证据；替换认识不能删除原始观察。旧反例为何不再限制新范围，必须有明确解释或新依据，不能因换了措辞或 ID 自动消失。

来源重复只关联一次；没有改变认识就不添加同义历史。未执行方案只记假设，模型输出的增量先是待核验提议。程序能检查来源、版本、去重及是否越权，但不能证明从观察到认识的推理成立；后续反例仍应修订它。尚未处理的重要反例不能以“未评估”为由继续使用旧的无条件正面认识。

Gate 沿用独立职责：采用决定不提高认识的证据等级，Memory 更新不部署 Skill。下一轮发布边界仍按 DESIGN 第 5.7 节；局部合法未知可以保留，处理错误不能伪装成 Memory 无变化。

### 5.2 构造分支：关联认识怎样进入实际更新，再被反馈修订

固定认真初稿：`u1` 在有效空结果后，在预算内进行保留任务约束的改写或未覆盖路径探索，避免重复已确认无效的路径；`u2` 暂时故障按工具规则恢复，满足目标后停止。目标包含保留恢复机会，不刻意省掉它以制造收益。构造环境假设公开路径、调用状态及所需历史可读取，不能迁移到缺少这些能力的 Actor。

1. **Memory → Fusion。** 假设既有实际联合编辑把“请求已发起”记作覆盖，导致故障后恢复被跳过。Effect `m1` 表述该联合策略、可见条件、行为后果；保留未识别单项贡献及其他条件未测的限制。不是仅提供“过去失败过”的摘要。
2. **Fusion → 有效 Plan。** 变更来源为 `[u1,u2]`，新要求组 `u3` 的完整正文是：“先按可见结果区分已完成查询和未完成的暂时故障；仅相同对象、约束和有效条件下的已完成查询参与覆盖复用。有效空结果后，在预算内进行保留任务约束的改写或尚未覆盖路径探索，避免直接重复已确认无效的路径；暂时故障不按已覆盖跳过，仍按工具规则和预算恢复。改写、选路与恢复共用此覆盖判定，结果满足任务要求时停止。”依据是 `m1` 揭示共同覆盖判定会阻断恢复；原有探索、范围保持和停止义务实际留在新正文中。`watch` 问暂时故障是否仍可恢复、等价路径是否被重复探索，继承原目标／范围问题；不生成两任务乘多个维度的表。
3. **Editor → 实际 Skill。** 用一个共同的结果分类／覆盖程序落实 `u3`，给实际文本定位；无须分别复制“改写、去重、恢复”的六维证明。程序生成真实 diff 和执行前快照。此处的示意要求不是已经生成、执行过的 Candidate。
4. **执行 → Replay／Memory。** 假设后续轨迹中故障恢复正常，但同一对象的查询范围改变后仍被旧空结果跳过。一个发现保存恢复观察，另一个保存范围反例；先核对实际文本及执行。如果仅违反已有“相同约束”规则，保留遵循／表达等解释，不能直接声称学到新关系。若进一步证据显示覆盖比较使用了刷新前的约束，且组织顺序未被规定，才限定“现有程序足以保证覆盖判断正确”的认识，并提出先刷新当前约束再比较的待验证依赖。
5. **下一次 Fusion。** 消费修订后的认识，在完整 `u3` 中增加“先从当前任务信息刷新约束，再做共同覆盖判断”的前置顺序；交付包含结果分类、范围保持、空结果探索、恢复及停止义务的完整新版要求，不用这一短句替换整组。新方案尚未执行，不能将这次构造视为已解决反例。若已有同样顺序却未遵循，则不重复添加它。

整个链只需追溯：`初稿要求 → 认识及限制 → 要求变更 → 实际文本 → 行为发现 → 认识修订 → 下一次变更`。事实、预测和假设仍分开，但不重复证明每个中间字段。

### 5.3 同一接口怎样承载其他规则与失败分支

| 输入变化 | 接口必须体现的结果 |
|---|---|
| 仅方向依据支持公开标识索引优先 | 只改相应条件下的路径先后；观察问题关注同预算目标到达；不顺带改变改写范围或恢复 |
| 仅尺度依据支持某限定词承载范围 | 只细化改写的范围保持要求；保留合法表达仍待验证的限制；不推导索引优先 |
| 没有适用认识，初稿已处理相关关系 | 明确 identity，保留依据不足／未检验范围，不硬造非恒等更新 |
| 认识带反例，但正文相似而实际 Parent 依赖已变 | 反例与依赖随认识交付，Fusion 核对适用；不能以相似度直接重用旧命令 |
| 某观察问题没有被输出回应 | 程序仅标未评估；不能生成“保持”发现或相应正面 Memory；关键缺口须处理或保留有依据的有限结论 |
| Replay JSON 失败，或 Memory 增量引用不存在的发现 | 保存错误和已有真实产物；不自动改成空增量／未知，不发布成功闭环 |
| 整包候选被拒或后续已采用 Skill 出现反例 | 有效局部认识仍可修订；不把拒绝等同全部无效，也不把采用等同知识正确 |

这些走查确认接口能表达选择性变换、保持及回修，不证明自动生成质量、节省 token 数或任务收益。

## 6. 实现边界与验收

**紧凑入口已按本契约组织真实反馈学习及后续更新构造，当前验收仍须区分接口执行与语义机制。** 实现范围见 [COMPACT_CYCLE](COMPACT_CYCLE.md)，不扩展为通用审查系统、全局关系库或完整实验矩阵。

1. 已新增独立协议版本与程序装配，包含 Plan、要求变更、组级文本定位、稀疏发现和 Memory 增量；旧协议继续按原格式核验。现有 p2／p3 等问题仍用于核对重要条件在压缩中是否保留，不能把字段引用存在当作语义保持证明。
2. 最小入口组织独立 Diagnosis、带作用认识的 Fusion、程序 Compiler、Editor 及 Replay／Memory 联合后处理；各阶段的来源、调用和停止状态分别保存。真实验证按预先记录的预算进行，技术失败保留原始产物，不在后台修复成成功结果。结构校验通过仍可能漏读轨迹或形成不充分认识，须继续检查关键判断与真实来源是否相符。
3. 后续更新保留同一初稿，核对所学认识是否实际改变方向、尺度或组合，以及 Editor 是否落实。真实证据若只支持恒等或未知，就记录这一结果；先获得必要的可辨识观察，不能拿构造搜索认识冒充 ALFWorld Memory，也不能把错误认识驱动的文本变化认作有效预条件化。

固定初稿入口现已单独实现：同一完整 Plan 与当前证据分别输入空 Memory 和有效 Memory，Fusion／Editor 沿用原紧凑输出形状；具体状态、失败和结果见 [固定消费报告](../../../experiments/methods/v22/04_fixed_consumption/reports/REPORT.md)。这是单样本构造检查，两个分支的信息量不同，不能充当同信息的机制收益对照。

验收分开记录：**程序可靠性**（身份、来源、增量和失败）；**语义链完整性**（关键条件／反例保留、认识实际改变要求、文本准确落实）；**效果**（执行响应及可比总成本）。前两项通过仍不等于预条件化优于同信息、同预算的直接历史辅助编辑。未执行原始修订对照时，不能声称相对初稿收益。

紧凑路径将轨迹调用 `deepseek-v4-flash` 与自进化语义调用 `deepseek-v4-pro` 分开配置，不把模型切换当作接口或机制收益。初次接口设计阶段没有修改配置；后续实现记录由 [COMPACT_CYCLE](COMPACT_CYCLE.md) 承接。规模扩大后的局部读取／检索、后续异常恢复策略及正式采用协议仍需研究；已经确定的最小信息责任和不允许的默认推断继续适用。

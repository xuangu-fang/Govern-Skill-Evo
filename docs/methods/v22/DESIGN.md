Govern 研究一种基于诊断预条件化的持续 Skill 自进化机制。系统按多任务经验中的共同决策问题组织更新结构，从当前执行与历史 Skill 修改中学习不同编辑方向的行为影响及其相互关系：Diagnosis 形成目标和初步要求，Memory 提供跨轮响应认识，Fusion／Compiler 调整方向、尺度及组合，Editor 在实际 Parent 上落实统一 Skill，Replay 检验反馈，Gate 决定版本采用，随后 Memory 学习并统一发布下一轮状态。

**核心创新假设是：学习并利用 Skill 更新本身的作用结构，能够使后续更新更有针对性、减少不必要的行为干扰，并提高持续自进化的效果。** 当前已明确共同表示和各模块机制草案，并新增紧凑学习与更新实现。历史认识是否被读取、要求是否真正变化、Candidate 是否落实、执行是否受益分别核对；程序贯通不证明认识正确或方法有效。

## 1. 研究定位的调整

此前 V22 以“响应结构 Memory＋基于预测残差的纠偏”为中心，将局部响应矩阵、预条件矩阵和离散求解作为主要设计路线。现在将预条件化扩展为整个 Skill 更新过程的统一设计思想，以**更新方向、更新尺度、更新方向之间的关联**组织各模块。

响应结构 Memory 继续保留，但其角色是更新器的跨轮历史状态。当前诊断、局部行为影响分析和实际更新构造也参与预条件化；Memory 为空时，这些过程仍应能够工作。

| 方面 | 调整后的定位 |
|---|---|
| 研究中心 | 初步修订如何根据更新作用结构被变换为更合理的实际修订 |
| 决策结构 | 一次全局分类形成可比较的语义问题，贯穿要求、响应、变换与 Replay；不假定组间独立 |
| Memory | 持续积累和修正历史响应，为统一更新机制提供状态 |
| Fusion／Compiler | 实际构造更新方向、尺度及组合，不只选择历史上下文 |
| Editor | 面向行为影响构造并落实修改，不只改写文字 |
| 数值响应模型 | 后续技术候选，不是默认算法或方法成立的前提 |
| 层级与跨层更新 | Editor 可探索的表示和协调方式，不是整套方法的主要创新 |
| 实验环境 | 优先考察通用公共 Agent Skill benchmark，不继续以旧成功／合规双维设置约束方法 |

当前设计属于预条件化启发的离散语义更新研究，不代表已经计算真实梯度、Hessian 或 Fisher，也不代表已经实现数值二阶优化。

## 2. 问题与创新假设

Agent 从执行经验中得到的初步修订可能存在几类偏差：

- 任务失败源于临时环境、工具或执行问题，却被解释成 Skill 缺陷。
- 真正需要改变的行为与所选修复策略不一致。
- 修改影响不足，或作用过强、条件过宽，干扰已有有效行为。
- 多个方向作用于相同或相关行为，产生重复强化、冲突或未被处理的依赖。
- 历史修复的效果、条件和限制虽然被保存，却未转化为当前更新的具体调整。

核心研究问题是：

> 当 Agent 得到初步 Skill 修订方向时，如何利用当前诊断、历史执行反馈和编辑方向之间的关系，将其变换为方向更合适、行为影响范围更合理、相关修改更协调的实际更新？

| 假设 | 需要观察的证据 | 会削弱该假设的结果 |
|---|---|---|
| 方向调整有价值 | 在相同问题与证据下，改变修复策略能够更准确地改善目标行为 | 只改变措辞或理由，实际策略与效果没有改善 |
| 尺度调整有价值 | 调整条件、强度或作用范围，减少更新不足和不必要干扰 | 收益仅来自减少编辑，且新任务学习停滞 |
| 关联处理有价值 | 协调重复、冲突、互补或依赖方向，优于逐项独立修改后拼接 | 联合构造未优于独立处理，或效果只来自更多调用 |
| 跨轮学习有价值 | 新反馈修正作用认识，并改善后续方向、尺度或组合选择 | 历史增加但更新方式未受影响，或直接读取历史同样有效 |

以上均是待验证假设。更多历史、结构化字段或更复杂流程本身不证明创新成立。

## 3. 三个核心设计维度

### 3.1 更新方向

方向描述为实现目标行为而采用的修改策略，例如补充信息获取、改变判断条件、修正执行程序或调整恢复方式。

系统需要检查初步方向是否针对真实缺陷，是否存在更合适的策略，以及当前证据是否支持保留、替换或撤回该方向。撤回无依据的修改是合法结果，但方法效果不能仅靠拒绝候选来证明。

### 3.2 更新尺度

尺度描述修改对行为的影响程度和覆盖范围，包括适用条件、规则作用对象、执行强度及对相关行为的影响。既要避免过宽或过强，也要识别修改不足。

编辑字数和条数只是实现量，不能替代行为尺度。短的通用指令可能改变许多任务，较长的条件化程序反而可能更局部。抽象层不天然等于“大步”，具体层也不天然等于“小步”。

不预设连续步长。尺度可以通过调整触发条件、限定作用范围、改变程序分支或选择不同的具体修改方式来实现。

### 3.3 更新方向之间的关联

关联包括共同作用于同一行为、重复强化、冲突、前置依赖和需要协调的互补方向。它既可能发生在同一层、不同模块，也可能发生在通用原则与具体程序之间。

处理关联要改变实际组合，例如合并重复要求、替换冲突方案、拆开适用条件、安排必要顺序或形成配套修改。关联不能仅作为一段说明附在独立生成的编辑之后。

需要区分文本或逻辑上推断的关系、执行中观察到的联合响应，以及经过额外比较才能支持的独立效应或非加性交互。不能把语义关联直接称为 Hessian 非对角项。

三个维度不要求每轮全部触发；证据未提示偏差时也可以保留原修订，不为展示“预条件化”而机械改变候选。

## 4. 整体方法与信息流

~~~text
当前 Parent 执行整批 Train 与可见反馈
→ 紧凑经验摘要／一次全局分类：冻结共同决策结构
→ Diagnosis：识别目标、保留行为、初步方向及潜在影响
→ Memory：提供适用的历史响应、限制与方向关联，允许为空
→ Fusion／Compiler：根据方向、尺度和关联构造更新要求
→ Editor：将更新要求落实为实际 Skill 修改
→ Replay：按冻结结构形成同批配对执行事实
→ Gate：按预声明标准决定是否采用主候选
→ 反馈学习：解释实际编辑响应并更新 Memory，保留采用来源
→ 统一发布：下一轮继承实际 Skill 与 Memory
~~~

这是逻辑职责，不要求每个箭头增加独立 Agent、固定模型调用或新的状态机。现有 Fusion、Evidence Review、Compiler 的职责可以在接入新环境时重新划分；必要的证据核查融入实际更新构造，避免重复审阅。

为解释方法，可将初步修订记为 \(u_t\)，经过预条件化的更新要求记为 \(\widetilde u_t\)，Editor 实际落实的修改记为 \(\Delta S_t\)。这些对象可以使用可核对的结构化文本，不预设连续坐标。

研究要检验的是：对于同样的 \(u_t\)，更新作用认识能否使 \(\widetilde u_t\) 和实际的 \(\Delta S_t\) 在方向、尺度或组合上发生有依据的变化，并产生更合适的执行效果。

### 4.1 一轮更新的五个对象

以“有条件的行为修订方案”作为模块间的共同表示，是 2026-10-14 讨论后明确的设计方向。它比问题描述具体，能够说明准备如何改变行为，又保留策略、范围和实际写法的调整空间。以下约定对象的含义与关系，不冻结 JSON schema、固定字段数量或连续编辑坐标。

当前 Parent、任务要求、轨迹和可见反馈构成共同依据。修改前观察记为 \(O_t^{\mathrm{pre}}\)，由此提出的原因与作用假设记为 \(H_t\)：观察到早停，不等于已经证明早停由 Skill 缺陷导致。基于这些依据，区分五个对象：

| 对象 | 回答的问题 | 主要形成环节 |
|---|---|---|
| 行为目标 \(G_t\) | 哪些行为需要改善，哪些有效行为需要保留？ | Diagnosis |
| 初步修订 \(u_t\) | 初步准备通过什么修改策略实现目标？ | Diagnosis |
| 变换后的更新要求 \(\widetilde u_t\) | 根据作用认识，最终采用什么方向、范围和组合？ | Fusion／Compiler，必要时结合 Editor 的可行性反馈修订 |
| 实际修改 \(\Delta S_t\) | 相对于哪个 Parent，实际改变了哪些 Skill 内容？ | Editor |
| 执行观察 \(O_t^{\mathrm{post}}\) | 修改后发生了什么，哪些预期获得支持或出现反例？ | Replay |

例如，“减少过早结束”是目标，“引导 Agent 探索尚未覆盖的相关路径”是方向，“修改退出条件和路径选择程序”是编辑，“执行中尝试了其他路径”才是修改后观察。写入指令、执行指令和任务改善需要分别判断；行为变化的观察也不自动构成编辑的独立因果效应。

共同表示需要保留这些对应关系，不能用意图替代实际 diff，或用预期替代执行效果。初始目标、初步方案和修改前依据应留存；若后续证据改变它们，应记录修订及其依据，不能根据 \(O_t^{\mathrm{post}}\) 回填并覆盖原始记录。

Diagnosis 应认真推导 \(u_t\)，不刻意弱化初步方案以制造预条件化收益。若初步方向、尺度和组合已经合适，允许 \(\widetilde u_t=u_t\)。这些符号表示语义对象，不意味着自由文本可以直接进行向量运算。

### 4.2 有条件的行为修订方案

一项方案应能用下面的问题来检查：

> 在哪些条件下，希望改变什么行为，初步准备采用什么策略；预计还会影响什么，需要保留什么，以及这些判断有什么依据？

| 信息 | 在更新中的作用 |
|---|---|
| 目标与依据 | 说明为什么需要修改，区分直接观察、原因解释和未知 |
| 初步策略 | 说明通过什么行为路径实现目标，允许后续替换或重组 |
| 适用条件与作用范围 | 说明修改应在什么情境作用，影响哪些对象与程序 |
| 预期影响与保留要求 | 说明期望改善什么、可能干扰什么，以及需要保留的有效行为 |
| 与其他修订的关系 | 保存已有依据支持的重复、冲突、依赖或互补关系 |

这些是语义要求，不要求每项都成为独立字段，也不要求预测所有影响。缺少信息时保留未知，避免用形式完整的字段制造确定性。

方向体现为策略选择；尺度体现为条件、强度和行为范围；关联体现为方案之间需要怎样协调。修订中可以同时改变多个方面，但应说明具体改变及其依据。

修订方案与实际编辑允许多对多对应：一个问题可以有多种策略，一个方向可以需要多处编辑，一处编辑也可能影响多个目标。Issue、方向、段落和 patch 不具有天然的一一对应关系。保留联合构造的来源，不据此将联合效果拆成单项贡献。

共同表示使更新可讨论、可检查，但结构化本身不构成创新。第 5.3 节提出作用信息驱动实际更新的规则草案；第 5.2、5.5 节设计响应认识的获得、修订和复用；第 5.7、6.5 节贯通跨轮接口与构造走查。真实运行与实际效果仍需后续验证。

### 4.3 全流程调用与成本约束

Diagnosis 六步、Editor 五步以及 Fusion／Compiler 的子步骤描述的是必须完成的判断，不对应固定数量的 LLM 调用。整个 V22 都应设计紧凑的常规路径和有界的异常反馈，避免同一份轨迹与 Skill 在多个阶段被重复解析、总结和审阅。

一种用于后续实现的起点如下，不将其冻结为每轮固定调用次数：

| 工作 | 常规组织方式 | 额外处理的触发 |
|---|---|---|
| 证据与版本装配 | 程序统一管理 Parent、轨迹、条款与来源，复用已有可解析材料 | 出现新版本、缺失来源或当前摘要不足以支持判断 |
| Diagnosis | 一次完整诊断内完成相关逻辑步骤，输出紧凑方案、关键依据与未知 | 关键歧义确实会改变初步方向，且可补充相关信息 |
| Fusion／Compiler | 一次联合语义构造处理适用性、方向／尺度／关联及要求编排；程序完成引用和显式结构检查 | 具体证据冲突、缺项或 Editor 的实质实现反例 |
| Editor | 一次编辑构造内处理相关要求、配套修改及语义核对；程序生成和核对实际 diff | 发现要求内可修复的问题，或需要上游实质修订 |
| Replay 与 Memory | 复用允许的执行反馈；程序装配观察，相关行为解释与认识增量可在一次后处理中完成 | 只有会影响认识或后续决策的重要未知，且存在有效可比方案时，才考虑额外有界比较 |

“一次”是常规组织起点，不代表必须把所有问题塞入超长输入，也不保证必然只需一次。多个小步骤合为一次超长调用可能更慢、更贵；应根据上下文容量和判断质量选择合并或拆分。批处理时保留相关方向的共同约束，不能为缩小输入丢掉已知反例。

共享证据装配减少重复读盘、解析和摘要生成，不意味着模型跨请求自动共享状态或自动节省 token。每次请求仍需显式获得完成其职责所需的信息；短引用必须可解析到原始材料，摘要不能替代必要证据。优先传递相关内容与增量，保留回读来源。

追加调用应说明缺少什么、不同答案会怎样改变方案、需要补读哪部分；不因某个字段写着“未知”就自动调用，也不将每项方向分别交给独立审阅 Agent。反馈只处理受影响部分，已经满足要求则直接继续，无修改且无其他适用方向时不调用 Editor。语义暂缓与网络／格式重试分开记录，并共同受预算约束。

逻辑模块可以合并，但输入权限和时间顺序必须真实。如果同一次调用已看到历史后才生成所谓初步方案，不能把该方案当作“未受历史影响的当前诊断”对照。需要比较相同 \(u_t\) 的机制实验时，应先独立留存初稿，再提供待比较的作用信息；不能靠输出字段的先后假装输入隔离。

成本记录覆盖调用数、输入／输出 token、模型推理用量（若可获得）、补读与失败重试、环境执行／回放、历史维护以及端到端耗时。不额外要求模型输出冗长推理，只保存必要决策、证据引用、变换差异与未决项。方法与对照按同等可见信息和可比总预算评价，不能只报告主路径调用次数。

### 4.4 实现收敛：复杂度用于更新决策

轻量化不以流程更短或字段更少为独立目标。每项分析、输出和检查应能说明它改变哪项更新决策、作用认识或结果解释；重复已有内容、只证明“认真检查过”的表达应合并或删除。完整原始证据留档，不要求每个模块重复读取和复述。同一模型逐维自述不构成独立验证。

第 5.1–5.7 节描述的语义责任继续成立，但其中的步骤、表格和检查问题不应逐项翻译成强制输出字段。第 5.3.4 节给出当前最小规则，第 6.6 节检查规则能否产生具体决策，第 4.5 节据此确定紧凑接口；不先完善一个通用审查系统。关键保留行为、反例和决定性未知不能被裁掉；未分析项保持“未评估”，不补成保持或零影响。

预条件化核心贯穿 Diagnosis 的初步方向、Memory 的作用认识、Fusion 的变换、Editor 的落实和反馈修订；不能把模块简单划为“核心”与“可省略”。程序承担身份、原始来源、实际 diff 和成本，模型承担会改变更新的语义判断。最小规则设计阶段只完成设计与走查；后续紧凑实现另行记录于 [COMPACT_CYCLE](COMPACT_CYCLE.md)，不修改旧协议与产物。

### 4.5 由规则反推最小共享表示和模块接口

具体接口、旧字段迁移表和走查见 [MINIMAL_INTERFACES.md](MINIMAL_INTERFACES.md)。独立紧凑实现采用**一份有版本的工作方案、各模块必要增量和真实执行产物**。初稿、有效要求和实际 diff 分别留存；共享不是覆盖历史，也不要求所有模块传递同一个越来越大的 JSON。

| 交接 | 最小语义交付 |
|---|---|
| Diagnosis → Plan | 行为目标与共同保留要求、条件化修订及依据、少量决策相关观察问题和重要未决项；局部保留条件留在对应要求 |
| Memory → Fusion | 条件与 Parent 依赖下的实际策略／编辑组响应认识，连带来源、关键反例和限制 |
| Fusion／Compiler → Editor | 受影响要求的原→新变更及作用依据，程序装配完整有效 Plan；未变项继承，不让 Editor 重新从历史选择策略 |
| Editor → 执行 | 实际 Skill、要求组到条款的定位、重要无法落实或偏离；取消六方面逐项自证的强制输出 |
| Replay／Memory → 下一轮 | 有明确运行范围的重要行为发现、旧认识到新认识的增量及限制；未回应的观察问题标为未评估 |

每条要求可以用条件化文本同时表达方向、尺度和依赖，不为三类规则各建一套字段。保留要求约束实际更新，观察问题说明本轮准备检查什么；不能因观察范围缩小就删除保留要求。关键局部保留必须进入相关观察或明确的未检验限制，不能继续只覆盖全局 `preserve`。

程序负责身份、来源、实际 diff、运行事实、问题去向和成本。Editor 无例外只表示未报告例外，定位存在不证明语义保持；Replay 无记录只表示未评估，不证明未触发或保持；Memory 紧凑读取也必须连带已知反例及依赖。模型仍须判断实际文本与行为，但不再重复输出全套证明表。

接口已形成独立本地协议：Replay／Memory 共用一次语义后处理；Diagnosis 只读取当前 Parent 反馈；Fusion 输出要求与观察问题增量；Editor 输出实际文本、组级定位和重要例外。程序装配有效 Plan，保存操作内 Memory、实际 Candidate、执行和费用。Plan.open 表示阻断构造的缺口，未验证收益放 watch 与认识限制。旧 p1／p2／p3 走查及搜索构造案例仍按原证据等级解释；新运行状态见 [COMPACT_CYCLE](COMPACT_CYCLE.md)。

### 4.6 共同决策结构与统一两轮算法

2026-10-15 新阶段把多任务自动分类作为语义更新结构的起点，详见 [GROUPED_TWO_ROUND_PROTOCOL](GROUPED_TWO_ROUND_PROTOCOL.md)。每轮将当前 Parent 全批经验整理成紧凑事实摘要，一次固定 Prompt 的 Pro 调用形成互斥任务分组；允许单例，不按业务、工具或成败分类。分类在 Diagnosis 前冻结，后续 Candidate Replay 沿用，不据结果重分组。

分组不仅提供诊断材料：要求绑定具体决策问题和可见条件；Memory 学习这些条件下的实际编辑响应；Fusion 核对跨轮语义、条件及 Parent 依赖，对方向、尺度和关联作实际变换；Editor 生成一份统一 Skill；Replay 保留组内与跨组变化。任务只属一组不意味着要求或 Effect 只能影响一组，也不证明块间独立。该分块预条件化类比仍不涉及数值矩阵或二阶优化。

当前协议固定两轮各十个且轮间不重复的 Train，从 No Skill／空 Memory 开始。第一轮程序恒等 Fusion，第二轮读取首轮 Gate 与学习后正式发布的状态；每轮只有一份统一 Candidate，不设置 Direct 分支。每轮先 Replay、再程序 Gate、再一次行为解释／Memory 后处理，完成后统一发布。完整可比时 Candidate 整体成功率严格高于 Parent 即 ACCEPT，否则 RETAIN；局部退化不另设否决，由 Memory 与局部收益一并保留，技术未知不伪装成拒绝。最多 40 个 episode、9 次 Pro，零语义／episode 重试，暂不进行 Selection／Test。轮内同任务 Replay 用于观察当前更新，不等于轮间重复训练；本阶段不另设旧任务回归验证。

本段及独立协议说明研究设计，现有紧凑 Plan、Effect、D/S/C 与执行核验继续复用；共享表示、Gate 和实际 Parent 发布接口的完成边界见[持续接口说明](CONTINUAL_INTERFACES.md)。自动分类与连续运行器已完成接线及合成验证，尚待真实执行验证，见[运行器说明](CONTINUAL_RUNNER.md)。旧 01—07 记录按各自协议保留；08 不导入旧 Effect，只使用旧 Train 结果作事前选题覆盖。

## 5. 各模块怎样参与预条件化

### 5.1 Diagnosis：从行为片段形成有依据的初步修订

本节给出第二步的具体机制设计草案。Diagnosis 采用“决策片段对照 → 当前条款检查 → 原因解释与修复路径 → 边界核查”的过程，输出认真推导的 \(G_t,u_t,H_t\)，或说明当前为什么不宜修改。下面的步骤是逻辑操作，不分别对应独立 Agent 或固定模型调用。后续[单次构造实现](NO_HISTORY_ROUND.md)将这些判断组织为一次调用，并核对结构与来源；不代表语义正确性或完整机制效果已获证明。

#### 5.1.1 输入与证据装配

输入由当前 Parent 及版本、任务要求、学习侧可见工具说明与反馈、相关执行轨迹组成。当前成功与失败轨迹都可使用；旧轨迹只能按其真实版本解释。历史可以提供查找线索，但本阶段对当前问题的发现不先由旧尝试限定。

先建立“哪些观察可以支持当前判断”的依据：

- 将行为片段绑定实际运行、Skill 版本、任务条件和原始步骤引用。旧轨迹提示的问题必须回查当前 Parent 是否已被修复。
- 同时保留相关成功行为、反例和失败前的有效步骤。不同初始条件、工具返回或版本的结果差不能直接归为某个动作的效果。
- 截断轨迹、缺失反馈和没有记录的动作标为未知；没有记录不等于没有执行。若摘要不足以判断，应回读相关原始上下文。
- 学习器只读取协议允许的反馈。评价器隐藏状态、答案或未来步骤不能变成 Agent 运行时可用的条件。

输出是带来源和可比性限制的证据集合。版本无法对应或关键输入读取失败时，先返回输入问题，不把处理错误记成“无需修改”。

#### 5.1.2 定位决策片段，形成行为差异

基本分析单元是一个能够说明决策的片段：

> 当时可见什么 → 需要作出什么判断 → 实际采取或遗漏了什么动作 → 随后观察到什么。

从任务未满足处、明显重复或已有反馈指出的问题回到相关决策；成功轨迹也可以提供有效路径、效率问题和保留行为。片段需要包含足以理解前置条件与后果的上下文，不预设固定窗口，也不把最终失败标签直接绑定到最后一个动作。

比较顺序是：先核对明确任务要求与工具语义，再找条件相近的成功／失败片段，最后检查同一轨迹内已经有效的步骤。条件不一致时先记录差异；没有合适的对照轨迹时，仍可依据任务要求提出假设，但不能编造“执行另一动作必然成功”的结论。

将重复片段按“相似条件下的同类决策缺口”组织，而非按失败词语或任务对象归并。仅有措辞相似不合并；触发条件不同则保留不同边界。此处的临时组织不等于创建跨轮 Memory Issue。

产出应是可定位的差异，例如“有效查询为空后，在仍有可见信息支持其他路径时停止”，以及需要保留的行为，例如“没有可行路径时允许说明限制”。“提高搜索能力”不足以进入下一步。

#### 5.1.3 检查当前条款，比较原因解释

以决策片段为线索读取相关条款、触发条件、共享默认规则及必要上下文。记录实际核对范围；只读过一个段落时，不能断言整个 Skill 不包含某要求。

对会导致不同修订的解释进行比较，而不强制穷举所有原因：

| 可能解释 | 如何核对 | 可支持的初步修订方向 |
|---|---|---|
| 必要行为没有表达 | 核对相关程序及其引用条款，确认缺少哪个决策步骤 | 补充该步骤或条件，不直接泛化为全局义务 |
| 条件含糊、顺序不清或条款互相抵消 | 在同一可见情境下展开各条款，检查是否导出相反动作或漏掉分支 | 澄清触发条件、程序关系或例外 |
| 已有规则未被遵循 | 检查规则是否适用、信息是否可见、是否被其他要求覆盖 | 有依据时将触发条件放入决策程序、处理冲突或重组表达；不能仅重复同义规则 |
| 工具、环境或随机执行问题 | 区分有效完成但结果不理想、未完成调用、临时故障及不同结果 | 有明确恢复缺口时考虑恢复程序；否则不把偶发失败写成永久禁止 |
| 当前 Parent 已覆盖旧问题 | 对照轨迹实际版本与当前相关条款 | 没有新缺陷时不重复添加旧修复 |
| 关键证据不足 | 指出缺少哪个观察，以及不同答案会怎样影响策略 | 保留竞争解释，必要时请求有区分力的证据 |

每个保留的原因解释说明支持、反例、未决条件，以及它指向哪个可由 Skill 改变的决策。无需证明唯一原因才能继续，但“模型没有遵循规则”本身还不能说明怎样编辑会改善执行。

可选的局部比较只针对会改变修订选择的歧义，例如区分调用未完成与成功返回空结果。先使用已有证据；仍需执行探测时，将所需比较交给后续协议安排并计入预算，不由本设计强制每轮新增回放。

#### 5.1.4 从解释构造并选择初步策略

先写目标行为与保留行为，再将有依据的解释转成策略：要改变哪个决策或程序、为什么可能影响目标行为、依赖哪些可见条件。初步策略可以是新增步骤、修订分支、调整执行顺序、删除冲突要求或重组已有表达，不提前绑定某一句最终文本。

默认给出有依据的首选方案；只有存在实质不同且仍成立的修复路径时，才保留备选和区分它们所需的证据。不固定候选数量，也不把相互排斥的备选全部拼进同一次修订。

局部选择依次检查：

1. **针对性。** 策略是否作用于所解释的决策缺口，而非仅要求“更加谨慎／更加努力”。
2. **增量价值。** 当前 Parent 是否已经表达该策略；若已表达，新方案究竟改变什么。
3. **可执行条件。** Agent 能否获得触发信息、执行所需动作；新的状态或工具依赖必须明示。
4. **适用范围。** 区分由证据支持的条件和待验证的外推，避免把单个对象名称或一次结果写成通用规律。
5. **已知干扰。** 检查是否破坏已识别的有效行为、恢复路径或停止条件。

在能够实现目标的方案中，优先采用依据更直接、额外假设更少、行为影响范围更可解释的方式；这不是最少字数原则，也不一律偏好范围最小的修改。可扩大条件范围，但需说明为何同一决策机制适用于更广情境。

如果几种方向都可行而证据不足以排序，明确首选只是待检验的选择，保留竞争方案与原因。若歧义使基本目标或执行方式都不成立，则返回待补证据，不任意选一个方向。

Diagnosis 可以修正当前已发现的明显条件问题和局部冲突，不故意将这些缺陷留给 Fusion。依据作用信息在多个方向间作进一步变换的机制见第 5.3 节，不在本阶段重复完成。

#### 5.1.5 执行前的边界推演

对拟输出方案检查当前已知的目标场景、成功场景、例外与停止条件。每个检查写出“情境—按方案会采取的动作—是否符合目标和保留要求”，不能只输出一个无依据的“通过”。

检查至少覆盖已有证据揭示的相关边界：

- 对照成功行为和反例，检查是否扩大成不必要的限制或义务。
- 区分工具成功完成但结果为空、暂时执行失败和信息不足。
- 检查是否以不可观测状态作为条件，或将“未知”当成“条件不成立”。
- 检查是否因一次失败永久禁止可行操作，或引入没有退出条件的持续尝试。
- 对照当前条款，说明是否仍存在已知冲突。

发现问题时修正初步策略或适用条件，并保留修订理由。构造情境只用于检验方案含义，必须与真实轨迹分开；文字推演通过不代表行为效果成立。没有证据支持的副作用可以作为待查假设，不应为了填写完整而伪造影响。

#### 5.1.6 输出、暂缓与完成条件

按问题给出以下语义结论；名称不预设为未来 schema 枚举：

| 结论 | 适用条件 | 交付内容 |
|---|---|---|
| 有依据的初步修订 | 能指出行为目标、Skill 可改变的机制和可落实的局部策略，未决假设已明示 | \(G_t,u_t,H_t\)、条件与保留行为、已发现关联、来源、边界检查及待验证预期 |
| 当前无需修改 | 没有支持 Skill 修订的缺口，或当前 Parent 已覆盖且没有新问题 | 判断理由与相关观察；不声称该问题永久解决 |
| 需要补充证据 | 缺少的信息会改变目标或策略，现有依据不足以形成可检验方案 | 具体缺失、竞争解释，以及最有区分力的可见观察 |

允许在原因尚未完全确定时提出有依据、明确标注为待检验的局部方案。既不能把猜测当事实，也不能要求证明因果后才允许探索。某个问题无需修改，不代表其他问题或后续历史分析也必须不修改。

在具备上述输出或明确停点时，Diagnosis 本轮完成。输入失败、调用失败与格式错误单独记录，不能伪装成语义上的“无需修改”。格式和引用可以由程序核查，行为解释与策略选择仍需模型判断，不能将结构校验当成诊断正确性的证明。

### 5.2 Memory：从执行观察修订条件化作用认识

Memory 是更新器的跨轮状态。第四步将它与第 5.5 节的 Replay 联合设计：Replay 提供实际修改及其执行观察，Memory 判断这些观察支持怎样的作用认识、改变了哪些旧判断，再为第三步提供可复用的依据。这个职责不等于保存更多摘要，也不授予 Memory 直接修改 Skill 的权限。

延续 V20 的三个目标：保留整体被拒 Candidate 中仍有依据的局部方向；允许已接受修改继续修订；保存失败尝试的具体限制，避免机械重复。Issue—Attempt、修改后证据学习、当前认识与原始来源分层读取已有 V20/V21 基础。V22 本步要具体建立的是“观察改变作用认识，作用认识改变方向／尺度／组合”的对应，而不是将这些已有能力重新命名为创新。

#### 5.2.1 共同学习单位与保存内容

一条作用认识的对象是**相关 Parent 条件下的一项实际更新或不可拆分的更新组，以及它在某类情境中的行为响应**。它既不是一次任务的答案，也不是整份 Candidate 的统一好坏标签。先根据实际 diff 确认体现了什么策略和范围，再关联初步方向、最终要求及其来源；无法确认时保留未对应部分，不按原意图补出“已经实施”的策略。

| 内容 | 保存与使用方式 |
|---|---|
| 执行事实与来源 | 精确 Parent／Candidate、实际 diff、要求版本、任务与执行设置、原始事件、允许学习的评价、覆盖和可比性说明；追加保存，不随解释变化 |
| 当前作用认识 | 哪些条件下的实际策略或组合出现了什么响应，这支持什么判断，有哪些反例、依赖、竞争解释和未知；可修订并保留历次版本 |
| 消费视图 | 按当前更新需要组织相关认识、关键限制和来源入口；由已有内容派生，不作为第三套独立事实 |

这些是内容边界，不要求三套数据库、Agent 或固定 schema。原始档案不会整体进入每次模型输入。采集错误需要留下纠正记录和来源，不能通过改写旧轨迹迎合新的解释。

一条认识应能用如下形式检查：

> 在这些 Parent 依赖与可见情境条件下，实际修改 D（或联合修改组 D）后观察到行为 B；与什么参考执行相比、比较有什么限制；据此可暂时支持怎样的方向、范围或组合判断；哪些反例仍成立，什么信息可能推翻或改变它？

没有可比参考时，只写在该版本下观察到了什么。观察、解释、未来预测分别保留；未执行的替代策略留作假设，不能并入已观察响应。无需为每条认识补齐所有维度，未知不填零。

Issue—Attempt 继续承担问题和具体尝试的来源组织。跨 Issue 的作用认识可以共享引用，不能把同一运行复制为多份独立支持。同一行为机制与适用范围的新增证据修订已有认识；实际策略或范围实质改变时保留新尝试及其与旧尝试的关系，不覆盖旧版本。仅认识的适用范围被重新解释，而没有实际新编辑时，不伪造新尝试。

#### 5.2.2 从观察到认识的增量更新

常规更新只处理本轮新观察触及的记录，包括当前引用过的认识、实际编辑涉及的尝试，以及新增行为或退化明确关联的旧认识。未被 Fusion 选中的问题也可以受新证据影响；不能仅凭关键词给整轮历史都分配功劳或责任。

在一次相关语义更新内完成以下判断，不为每项单独调用模型：

1. **核对观察边界。** 使用第 5.5 节已整理的执行身份、实际落实情况、触发机会、可比性和信息权限；来源缺失或不可比的部分明确降为未知。
2. **对照执行前预期。** 分别检查行为是否发生、目标是否改善、保留行为是否受影响及是否出现未预期变化。不按最终任务分数推演缺失的中间行为。
3. **定位被影响的认识。** 说明新事件与哪项旧策略、适用条件或联合关系有关；不能关联时保留观察或新问题线索，不强塞进旧认识。
4. **形成证据支持范围内的修订。** 使用下表选择补充、限定、拆分、替换、保留冲突或不改正文，并说明依据。修订可以提出假设，不要求先证明因果，但不能提高到证据不支持的确定性。
5. **输出紧凑增量与消费依据。** 保留旧版、改变的判断、新来源及仍成立的限制。指出这可能影响哪类后续变换，不提前生成必须执行的修改命令。

| 新观察与旧认识的关系 | 具体更新规则 |
|---|---|
| 相近条件下获得新支持 | 增加有身份的来源，在实际覆盖范围内补充判断；同一次运行的别名、重复读取或重复摘要不增加支持次数，相关运行也不假定独立 |
| 没有覆盖目标条件，或没有新判断 | 保存覆盖限制或必要来源，原认识正文可保持不变；不写“效果为零”，也不逐轮追加同义叙述 |
| 条件已出现，但预期动作未发生 | 记录未响应及执行上下文，检查条款表达、可见性、执行遵循和竞争要求；不直接认定方向无效或力度不足 |
| 预期行为已发生，目标收益却未出现 | 保留行为实现事实，修订“该行为足以实现目标”的假设或标注其他未决原因；不把行为变化当作任务能力提升 |
| 出现相关反例或非目标退化 | 保留双侧事实及限制，重新检查原解释和适用范围；反例可以削弱或否定过强主张，不能因总分上升而被抹掉 |
| 支持与反例有可支持的条件差异 | 将原来混合的范围拆开或收窄，分别说明依据；事后发现的区别先作为待检验解释，不按任务 ID 拼出必然正确的条件 |
| 区别条件未知、运行时不可见，或冲突仍未解释 | 保留冲突与竞争解释；可以记录解释性限制，但不能据此编造可部署分支，也不按多数、最近记录或 Gate 结果消除反例 |
| 新证据否定旧解释 | 替换或撤回当前解释，保留旧观察、旧判断和修订依据；其他仍成立的认识不随之删除 |
| 多项修改共同执行，贡献无法区分 | 更新联合认识，并保留各方向到该组的来源关联；不能把正面行为归给一项、负面行为归给另一项 |
| 版本不明、日志不完整或执行中断 | 保存可确认的事实与处理错误，暂缓相应作用判断；负面结果不能仅因不符合预测就被改称基础设施噪声 |

触发机会因更新而改变时，不能简单归为“没有覆盖”。例如 Candidate 更早退出而未进入恢复步骤，这种路径缺失本身可能是相关行为变化，需要连同更早的决策一起分析。详细观察规则见第 5.5.3 节。

#### 5.2.3 学到什么，以及怎样服务三类变换

从具体尝试提炼可复用认识时，保留造成响应差异的条件、相关 Parent 依赖和组合边界，仅去掉不影响作用判断的任务实例细节。跨任务迁移需要说明共同的决策机制；表面文本相似不是归并依据。只有单个情境时可以保留局部假设，不能直接写成普遍规律。

| 学习对象 | 可形成的认识与后续用途 | 所需边界 |
|---|---|---|
| 方向作用 | 某种策略在什么可见条件下到达目标行为，另一种策略在哪个环节受限；供 Fusion 判断保留、替换或条件化排序 | 没有可比策略执行时，不声称一种已被证明优于另一种 |
| 行为尺度 | 同一要求在什么范围、触发频率或义务强度下出现目标响应与干扰；供 Fusion 收窄、扩展或改变触发条件 | 没观察到副作用不代表全范围安全，文本更短不代表行为尺度更小 |
| 方向关系 | 哪些要求共享行为对象、存在前置依赖，或在联合执行时出现重复／冲突；供 Fusion 合并、分支或联合落实 | 逻辑依赖、联合观察与可辨识交互分别表达，不能由共现推出独立贡献或非加性 |

不同尝试间可以比较，但必须保留各自 Parent、工具和任务条件；实现变化、环境变化与策略变化不能混成同一个效应。对同一组编辑，只要不能分离作用，就以组为认识对象。后续有适当局部比较时再修订粒度，不默认回放所有编辑子集。

当前 Parent 已包含旧修改时，其新执行可以支持或反驳“此版本在这些条件下会怎样表现”，但它不是再次施加旧编辑的干预。不能据此重复计算该编辑的新增收益，或将当前成功回填到历史失败版本。

#### 5.2.4 增量维护与下一轮读取

读取以 Fusion 当前的目标行为、初步策略、适用条件和待处理关系为入口，同时查找可能相关的有利认识和失败限制。Issue、文本或行为标签可以帮助定位，但最终适用性仍由第 5.3.2 节判断。检索方法与索引实现留待工程选择，不预设向量库、固定 top-k 或全局方向分类。

常规路径先读取相关当前认识和尝试目录，再沿显式来源、联合编辑与反例关系局部展开。模型完成语义匹配，程序完成版本和来源解析；不增加独立检索、关联或压缩 Agent。摘要未覆盖关键依据时补读原始材料，不能声称读过只被引用而未加载的轨迹。

交给 Fusion 的内容至少能说明：作用认识及其条件、实际修改或编辑组、相关 Parent 依赖、支持与关键反例、单项或联合判断的范围、未知，以及可回查来源。若一条被检索认识所依赖的已知反例或配套关系未能装入，不能只发送其正面结论；应缩小处理范围或明确材料不足。

Parent 改变时按相关依赖重新核对：共同生效的条款、前置步骤、工具能力、反馈含义及条件可见性是否仍成立。不因版本号改变就全量作废，也不因规则文字相同就认定可迁移。相关依赖改变的旧认识可成为待验证线索；历史事实仍按原版本保存。

没有相关新证据的记录保持不变；同一事实去重，同义认识只有在条件、依赖和归因范围一致时才可合并。当前视图可紧凑重写，原始来源及历次解释留档，冷门内容不必常驻上下文。压缩、未检索和暂未处理都不等于已证伪或已解决。具体容量、索引与归档策略尚未冻结。

#### 5.2.5 三个历史目标的实际处理

| 情形 | Memory 保存和修订什么 | 下一轮怎样使用 |
|---|---|---|
| 整体 Candidate 被拒，但部分行为符合预期 | 保留实际版本、局部行为观察、可继续研究的方向及联合来源；没有隔离证据时，不标记该方向独立有效 | Fusion 可结合当前条件重构该方向及必要依赖，再由 Editor 形成新候选；不直接抽取并部署“好 patch” |
| Candidate 已采用，后来出现反例 | 照常修订范围、依赖或解释，保留采用时与新运行的来源；采用状态不增加证明等级 | 后续诊断与变换可修改已部署条款；Memory 本身不静默回滚 Skill |
| 相似失败方案再次被提出 | 返回原来的具体失败条件、未满足的预期和未知，不保存成永久黑名单 | 重试需回应哪些实现、条件或证据已改变；为区分随机性进行明确、有界的重复比较也可以，但不能无解释循环 |

这三项目标不要求强行从每个失败候选中找出正面结论。保留“值得进一步检验的方向”与认定“已证实的有效方向”不同。

没有新 Candidate，但有允许学习的 Parent 新执行时，可以按相关新证据修订已有认识或问题，不伪造新的编辑响应或尝试；仅发生构造失败时只记录该限制。本设计允许证据驱动的维护，不为此默认增加独立回放或额外维护轮次。

#### 5.2.6 写回、成本与完成条件

Replay 的行为解释与 Memory 的语义修订默认组织为一次相关后处理：共同读取必要证据，直接产出有来源的观察解释和认识增量，不串接逐 edit 归因、总结、压缩及复核 Agent。程序提前核验身份、收集原生反馈和显式事件，事后核验引用、版本及重复写入。语义判断仍可能错误，结构通过不等于认识正确。

执行前预期和本轮使用的 Memory 版本先保存，再读取修改后证据。不能用结果改写原预测，也不能让同轮尚未取得的反馈提前进入 Fusion。已有历史材料优先复用；追加读取或调用只处理会改变认识或后续变换的重要未知，受第 4.3 节总成本约束。

写回先保存证据和认识增量，再校验并发布一致的版本记录，标明本轮实际采用的 Skill 与 Memory 来源。被拒分支的证据可以进入 Memory，但不能被记成已部署 Skill 的效果。更新失败保留可恢复产物，不发布“已更新成功”的 Memory；同一批更新重试不能新增重复证据或重复尝试。第 5.7.5 节规定采用与学习分别决定、下一轮入口统一发布，不能出现未标明的 Skill／Memory 版本错配。

本轮完成可以是有依据的认识修订、仅补充来源／覆盖限制、明确无需更新，或因缺证据而暂缓相关判断；其余记录保持原样。完成标准是能说明“哪些观察改变了哪些作用判断，以及可能影响什么后续变换”，不是摘要变长或每条记录获得一个好坏标签。

第 5.3.4 节将上述学习规则与方向、尺度、关联变换配对。只学习到未覆盖或联合响应时，必须限制后续决策的范围；只有新认识实际改变了要求，才发生相应的更新变换。Memory 维护完成本身不计为变换收益。

### 5.3 Fusion／Compiler：依据作用信息重构更新要求

第三步采用一份持续修订的工作方案：保留原始 \(u_t\)，根据当前及历史作用信息判断哪里需要变换，直接调整其方向、条件、强度与组合，再编排为 Editor 可落实的 \(\widetilde u_t\)。不默认生成大量候选、遍历所有编辑子集或建立全局关系模型。

Fusion 负责作用判断和方案变换；Compiler 负责将确定的行为要求绑定到当前 Parent，组织完整的条件、依赖与落实要求。需要语义判断的编排可与 Fusion 在同一次调用内完成；引用、版本、显式关系和请求装配由程序检查。两者是逻辑职责，不要求两个模型或两个 Agent。Compiler 不能只是追加历史摘要，也不能以“确定性编译”为名默默作出新的语义决策。

#### 5.3.1 输入、判断范围与原始方案保留

输入为当前 Parent 及版本、\(G_t,u_t,H_t\)、Diagnosis 已整理的观察与边界、相关历史作用认识及其来源、当前工具能力和执行限制。历史可以为空。先区分：

- Diagnosis 已经解决的局部问题，默认复用其结论及依据；
- 多个方向共同作用于某个行为时，仍需检查的重叠、冲突或依赖；
- 当前或历史反馈可能改变的作用判断；
- 当前缺少信息、尚不能形成作用判断的部分。

保存原始方案及来源，以其中的有效要求为工作方案起点。没有新的适用依据，也没有尚未处理的关联时，允许原样保留。Fusion 的价值不能来自重做 Diagnosis、故意弱化初稿或强制制造变化；原方案若已被证据否定，也不能仅为省事而继续执行。

新信息若改变的是任务目标、事实解释或当前缺陷是否存在，应将具体冲突返回 Diagnosis。历史发现一个本轮未诊断的问题时，可以提供线索和依据，但应先形成有来源的目标与初步方案，不能将历史建议直接扩成新的编辑义务。

#### 5.3.2 将历史与当前信息对齐到实际作用

以当前要改变的行为、策略及适用条件查找相关信息；Issue 名称、任务对象或文本相似只能作为查找线索。先消费已有的紧凑认识和来源，只有影响决策的歧义才补读相关原始轨迹或 diff，不逐条重读全部历史。

一条可用于变换的作用认识应能说明：

> 在什么 Parent 条件与任务情境下，实际采用过什么修改，观察到哪些目标或非目标行为变化；该认识为什么适用于当前方案，以及它仍有哪些限制？

这是 Memory 的消费接口要求；第 5.2 节给出增量学习与读取规则，具体存储结构和检索算法仍未冻结。当前分析也可形成作用假设，但应与已执行观察分开。

| 核对对象 | 具体判断 |
|---|---|
| 实际修改 | 历史实际 diff 是否实现了所称策略；只提出但未落实的建议不能当成已测方向 |
| Parent 与依赖 | 相关默认规则、程序、工具能力是否仍成立；版本变化可能改变作用，时间新旧本身不决定可靠性 |
| 情境与条件 | 当前哪些条件匹配、不同或未知；历史任务相似不代表触发条件相同 |
| 响应来源 | 是实际行为观察、可比执行、逻辑推演，还是事后解释；不同来源支持不同程度的判断 |
| 归因范围 | 单项效果是否可辨识，还是只能确认多项编辑共同出现时的结果 |
| 支持与反例 | 限制是否覆盖本轮，摘要有没有省略会改变判断的反证 |

据此区分“可以支持当前判断”“只能在部分条件下迁移”“可作为待检验线索”“当前不适用”。这些是判断结果，不是固定枚举或置信分数。未知条件不自动算匹配，缺少历史不等于零影响。

历史 Candidate 被接受不证明其中各项均有效，被拒也不否定所有局部方向。未落实的编辑、没有覆盖目标场景的回放或工具执行错误，都不能直接推导成策略无效。若只有整包变化，则保留联合认识，不能拆出某项有益、另一项有害的结论。

#### 5.3.3 按受影响行为检查当前方案

将适用信息与本轮方向对应，围绕可能共同受影响的决策进行检查，而不是孤立处理每个 Issue。局部工作表示只需说明“方向—条件—受影响行为—依据及未知”，再标明必要的方向关系；不预设行为维度数量、矩阵或完整两两关系图。

对每一项拟变换，必须形成具体判断：

> 在条件 C 下，当前方向 D 可能使行为 B 发生什么变化；这种变化与目标或保留要求有什么偏差；其他方向是否也作用于 B；哪些观察支持这一判断，哪些仍是假设？

可能的偏差包括策略作用路径不合适、适用范围过宽或不足、重复强化同一行为、相反动作同时触发，或缺少配套前置条件。“历史说有风险”或“两个修改很相似”本身不足以决定变换。

支持和反例若对应不同的可见条件，可以形成条件化解释；无法区分时保留竞争解释，不按记录数量、最近时间或整包分数机械投票。共同影响同一行为不等于重复，也不证明非加性交互。通过逻辑发现的依赖与执行中观察到的联合效果分别记录。

没有新的作用偏差时，保留当前方案。Memory 为空时仍可利用当前证据和方向间关系进行本节分析；已经由 Diagnosis 处理的关系无需再次改写。

#### 5.3.4 最小预条件化更新规则：认识修订与实际变换配对

本节将原操作清单收敛为三类作用规则及共同决策边界。规则规定如何利用响应改变方案，不是新增三类 Agent、固定字段、置信分数或候选搜索器。具体条件匹配和行为解释仍由语义判断完成；这里完成的是可反驳的规则设计，不是已经验证的确定性优化算法。

**共同学习单位。** 围绕某个受影响的决策，保留“在条件 C 和相关 Parent 依赖下，实际策略 D 或更新组产生了什么可见响应 B，以及什么支持、反例和未知限制这一判断”。条件、策略、响应是可修订的语义内容，不建立固定编辑坐标或全局关系图。任务 ID 只用于来源；用于部署的条件须能被 Actor 观察或由其实际状态能力维护。

这里规定的是如何消费作用知识；随执行持续学习的是策略的作用路径、适用边界与方向依赖，不是给每轮套相同的编辑模板。同一初稿在这些认识改变后应能得到不同的实际要求，相关认识被撤回时也应重新判断变换依据。若历史只让解释更长，却不影响任何更新决策，则这一机制没有发生作用。

**先决定证据能支持什么，再决定怎样改变更新。** 一轮执行后的新反馈修订认识，下一次构造才消费该认识；不能让未来反馈回填原始初稿。当前 Parent 的新观察可以立即参加本轮判断，但不是重新施加历史编辑的收益。以下判别复用 Replay 的材料，不重复调用模型：

| 实际观察 | 对作用认识的修订 | 对后续变换的直接限制 |
|---|---|---|
| 实际文本偏离所称策略，或相关条件外部未出现 | 分别记为“只测到了实际版本”或“未检验此条件”；不追加该策略有效／无效的结论 | 修复落实问题或保留未知，不能据此增强、撤回该方向 |
| 条件可见，但预期行为未发生，或更新改变路径使机会消失 | 定位未响应、前序分支及竞争要求；保留遵循、条件可见性、依赖等解释 | 先处理有证据的落实／关联问题；不能直接把“没有效果”变成“加大力度” |
| 预期行为已发生，目标或关键保留行为却未达到预期 | 修订该策略足以实现目标、适用范围或组合依赖的认识；任务总分本身不能定位中断环节 | 按下述方向、尺度或关联规则，改变被证据触及的部分 |
| 目标变化与干扰出现在可区分情境中 | 对旧认识增加适用限制；区别条件若为事后推测，先保留为假设 | 只有可支持、可观察的条件才能直接形成部署分支；未知区别不自动生成例外 |
| 只有整包对照、多个方向共同出现 | 保留联合响应；可定位事件，不能分摊收益或副作用 | 后续可调整联合要求，但单项重加权或移除须有独立依据，或明示为探索 |

不可比、来源缺失、工具故障和格式失败按第 5.2、5.5 节保留相应边界。它们不自动产生负面作用认识，也不能用来抹去真实反例。新支持只补充实际覆盖；反例优先撤销被它否定的过强主张，而不是删除所有旧观察。没有新认识则保持原状态。

**规则 D：根据作用路径选择或替换方向。**

- **成立条件：** 有证据定位当前策略与目标之间的具体缺口，且替代策略具有可执行、能回应该缺口的作用路径。要区分“策略没有被落实／触发”与“行为已经发生，但不足以到达目标”。最终任务失败不单独满足此条件。
- **认识怎样改变：** 从“D 在 C 下可达成 B”修订为“D 在 C 下到达了哪个行为、在哪个环节受限”，并保存替代 D′ 的执行支持或待检验依据。反驳 D 不等于证实 D′。
- **更新怎样改变：** 在适用的 C 内把原策略替换为 D′，或改变原来未确定的策略先后；保留目标及 C 外仍有效的原要求，重查被替换步骤的依赖。必须给出新的条件化行为要求，不能只附“D′ 更好”的建议。
- **不足与反驳：** 没有可行替代时不编造方向；原案仍有依据可保持，原案已被否定则暂缓相关部分或提出明确的有限探索。若 D′ 实际发生但未解除所称缺口、引入关键回归，或原失败被证实源于另一环节，应修订替换依据；不能只提高 D′ 的执行强度。

**规则 S：根据目标响应与干扰，调整作用范围或强度。**

- **成立条件：** 能指出哪个触发条件、作用对象、重复频率或义务影响了目标／保留行为，且新的范围可被 Actor 判断。不同情境的支持与反例可以提示边界，但必须保留 Parent 与其他编辑差异。
- **认识怎样改变：** 将笼统的“D 有效／有害”修订为“D 在哪些已覆盖条件下伴随目标响应，在哪些条件下产生或疑似产生干扰”。出现冲突而区别条件未知时，保留冲突，不能凭任务名称制造分支。
- **更新怎样改变：** 将过宽要求改为明确触发的要求，将过强义务改为有依据的条件或例外；未受影响部分沿用原方案。反向扩展必须有正面的可迁移依据，或有证据表明当前义务范围遗漏了目标所需行为；分别说明扩展到哪里、如何保护邻近行为。不能用字数、统一预算或“降低权重”代替实际要求。
- **不足与反驳：** 未遵循不直接支持增强，未发现副作用不直接支持扩大。副作用不能定位到单项时，不能直接缩减该单项。窄化后若阻断必要目标行为、干扰仍存在，或扩展后新增回归，应重新检查边界和作用解释；不能把保守缩减本身当收益。

**规则 C：根据共享行为与依赖，重构方向的组合。**

- **成立条件：** 有具体决策证据或可核对的逻辑关系，说明一个方向改变了另一个方向的前提、机会或允许动作；或多个要求在同一可见条件下造成重复／冲突。仅共同成功或作用于同一指标不满足条件。
- **认识怎样改变：** 保存“D₁、D₂ 在条件 C 下如何共同生效或相互妨碍”的关系及其证据粒度。单纯共现保持联合观察；逻辑依赖、观察到的执行依赖和经比较支持的交互作用不能互换名称。
- **更新怎样改变：** 把依赖明确为前置条件和顺序，把冲突拆成有依据的分支或例外，把等价重复行为组织为一次共同要求，同时保留各自独有条件。先检查 Parent 是否已提供依赖，不机械新增配套规则；只有行为对象、有效条件与结果均可复用时才合并检查。
- **不足与反驳：** 关系未分离时保留编辑组，不随意拆出好坏方向；缺少可见区分条件时不制造分支。协调后若目标分支或恢复仍被阻断、出现重复或循环，应修订所用关系；若去掉所称依赖仍能完成，只能据相称比较修订必要性，不反推其他方向独立有效。

**怎样在一份方案上应用，而不变成三个重复分析模块。** 在同一份工作方案上完成以下逻辑动作，不为它们另设调用或字段组：

1. 对齐适用认识：定位当前哪个可见条件、初步策略和行为决策与历史响应相对应，连同关键反例读取。
2. 定位作用偏差：说清原方案预计引起的行为与目标／保留要求差在哪里；没有新偏差且已处理关联时，直接保持原案。
3. 构造必要变换：用 D、S、C 改变涉及的策略、条件、义务或关系，保留无关部分。“必要”指不额外引入无依据的行为变化，不是文本最短。
4. 确定待观察差异：指出变换应在什么机会产生不同决策，什么实际反馈会要求重新修订认识。

方向或尺度变化后只重查受影响的依赖；关系问题也可先触发协调。三类规则没有固定顺序、固定变换次数或所有方向两两检查。收窄条件、重排步骤或重新组合都形成待检验的新要求，不能继承旧 Candidate 的已验证效果标签。

当多个依据指向不兼容修改时，先检查它们是否属于不同条件、Parent 依赖或联合编辑组；可支持的可见条件允许形成分支。仍不能区分时不按最近记录、多数或总分投票；保留有依据且不违背关键要求的方案，或将受影响的关联组暂缓。不能静默牺牲目标或关键保留行为来换取更少动作。其余可独立部分可以继续，不因此全局停摆。

合法结果包括具体变换、恒等保留、有边界的探索和相关部分暂缓。**恒等保留**要求原方案仍有依据，且新信息不适用、没有作用偏差或已经被初稿处理；不是“尚未分析”。**探索**要求明确回应哪项缺口、为什么可执行、什么观察会改变判断及本次范围；没有证明因果也可以探索，但不能记成已学到的规律。撤回、拒绝和可行性检查只规定更新边界，单靠它们不构成预条件化收益。

每项实质变换只需留下紧凑的“原要求 → 新要求、所用作用认识与来源、仍未解决的限制、会推翻判断的行为观察”；完整身份与原始材料由程序绑定。这是审查问题，不冻结为四个字段，也不要求输出逐维推理。初稿中未变部分可以引用，不能让 Editor 再从历史自由决定策略。执行前保存变换，执行后对照实际 diff 和响应修订认识；规则依据被删去或反例改变时，变换应能相应改变或退出。

这套规则借鉴预条件化的**非均匀调整和方向关联处理**：同一初稿的不同方向按作用差异改变策略、适用尺度和组合。规则名、输出合规及读取 Memory 都不能证明创新；必须进一步验证这些决策确实改变实际 Skill，并优于同信息、相近预算下的直接历史辅助编辑。

#### 5.3.5 联合复核、取舍与结束条件

每次有实质调整后，只检查受影响的方向、条件及已知依赖：目标是否遗漏，保留行为是否被破坏，新分支是否引入冲突或循环，原来的依赖是否仍成立。若发现新的相关关系，再扩展检查范围；不声称局部检查覆盖全部未知影响。

默认直接修订一份方案。只有实质不同、无法同时采用且会影响编辑的方案才保留备选，不生成固定数量的候选池。取舍优先依据当前条件下的证据适用性、作用机制的明确程度、目标覆盖和额外假设多少，并解释对有效行为的影响；不伪装成已校准的数值评分。若候选难以区分，可以选择有依据的有限探索并保留未知；若连基本行为要求都冲突，返回具体未决问题，不让 Editor 自行猜测。

每个原始目标及初步方向都应有去向：保留、变换、被其他要求覆盖、撤回或暂缓。只处理可独立部分时，明确本轮范围并重新核对依赖；不能静默丢掉无法处理的目标，或拆开必须配套的要求。

可以结束于可落实的新方案、原样保留、部分范围明确的方案，或带理由的返回／暂缓。没有新依据、解释澄清或可行修订且同一问题持续未解时停止；到达预算上限也停止。调用失败、缺引用等处理错误应与语义判断分开。

只保留必要的决策记录：改变前后是什么、依据是什么、相关条件与未知是什么、什么观察可能推翻判断。无需输出冗长的逐步推理。判定没有变化时也应说明历史不适用、无偏差或当前方案已覆盖的依据。

#### 5.3.6 Compiler 将联合方案组织为落实要求

Compiler 的语义工作是把已确定的方案组织成在当前 Skill 中可共同落实的要求。它与 Fusion 可在同一语义调用中完成以下编排，再由程序装配与校验：

1. **组织条件与行为要求。** 对同一决策的要求明确触发、动作、例外、未知处理及停止条件；没有相关变化的要求可以引用，但传给 Editor 时必须能完整解析。
2. **保留组合结构。** 标明哪些要求共同落实、哪些先后依赖、哪些是尚未选定的互斥备选。不能把联合方案拆成互不知情的编辑请求；不同文本位置也不意味着行为独立。
3. **绑定当前条款与实现边界。** 给出已核对的相关条款、冲突位置和可见条件，指出应共同检查的范围。条款是落实线索，不提前锁死 Editor 的最终措辞或全部修改位置。
4. **核对目标与方向的去向。** 保留 \(u_t\rightarrow\widetilde u_t\) 的对应，说明取代、合并、撤回及暂缓；落实方案与历史引用不能互相替代。
5. **组织后续观察要求。** 对实质变换列出目标效果、需保留行为及可能推翻判断的情境。它们是 Replay 的输入需求，不是独立效应已经被识别的声明。

程序适合核对 Parent 版本、引用可解析性、原方向是否有明确去向、声明的前置要求是否缺项或互相等待而无可用起点，以及互斥方案是否被同时标为必需，再装配 Editor 请求。正常恢复程序中的有界循环不因此一律判错。程序不能仅凭引用存在认定证据充分，也不能证明两个自然语言要求没有语义冲突。

缺项或矛盾返回具体问题，由语义构造环节修订；不能靠自动删要求、补策略或缩减范围让请求“合法”。已经完整且结构一致时不再增加一次 LLM Review。若实现中设有独立 Compiler，其默认程序职责无需模型；必要语义判断归入同一次 Fusion／Compiler 构造或明确的有界反馈，不额外隐藏一个 Agent。

交给 Editor 的结果应包含当前有效要求及版本、联合／分支／依赖关系、相对初稿的变化与依据、相关条款及能力边界、保留行为和待验证预期。Editor 负责实际文本及程序构造；不能把一包历史交给它，再让它重新决定应该采用哪套策略。

#### 5.3.7 与 Diagnosis、Editor 及反馈学习的接口

| 情况 | 处理 |
|---|---|
| 新依据推翻当前观察解释或目标 | 返回 Diagnosis 复查相关依据；保留原始目标和方案，不静默改写 |
| Editor 只需多处改动以落实同一要求 | 在要求内构造并记录，不因文本位置增多自动返回 |
| Editor 必须改策略、条件、顺序、义务或能力依赖 | 返回 Fusion／Compiler 的方案形成环节；涉及目标或事实解释再返回 Diagnosis |
| Parent 或相关执行能力改变 | 重新绑定并检查受影响条款和证据适用性，旧 patch 不直接沿用 |
| 证据有冲突且条件不能区分 | 保留未决解释，选择仍有依据的方案或暂缓相关部分，不凭摘要覆盖反例 |
| 已形成完整可落实要求 | 交给 Editor，再由真实执行检验；不写入“已验证有效”的 Memory 结论 |

反馈只修订受影响部分，并按第 5.6 节保留原版、理由和执行前预期，避免整轮重新诊断。第 5.5 节规定 Replay 如何将实际 diff、目标与非目标变化、联合观察和未覆盖条件返回，第 5.2 节据此修正认识；具体算法实现仍待后续确定。

第三步的完成标准是：同一初步方案在不同适用信息下，可以得到有依据且内容明确的变换，也可以保持不变；变化能落到 Editor 的具体要求并被后续执行反驳。规则草案不等于算法已实现、数值二阶优化成立或创新性已被实验确认。

### 5.4 Editor：受更新要求约束的实现构造

Editor 通过“核对要求 → 检查当前条款与可见条件 → 构造修改 → 检查边界 → 核对实际 diff”落实行为要求。它主动处理表达、局部程序和配套关系，但不默默更换目标或修复策略。本节给出具体机制，仍不固定文本操作 API、模型调用数或 Skill 层级。

后续首版 `v22.editor.v1` 在一次 Editor 调用内检查触发、策略、范围、保留、关联与能力，明确忠实落实、表达调整或需上游修订；程序绑定来源并阻断已声明的实质偏离。它不证明自然语言语义等价，旧 v0 输出也不追认为通过 v1。具体格式与限制见[实现说明](BEHAVIOR_FEEDBACK.md)。

下一版按第 4.5 节改用实际文本、组级定位与重要例外；以下逻辑核对责任继续成立，但不逐项成为必填检查结果。该收敛目前仅是设计，现有 v1 代码和失败状态未改变。

#### 5.4.1 绑定版本与可落实要求

输入包括当前 Parent 及版本、\(G_t\)、当前待落实的更新要求、相关证据与条款线索、可见工具能力及执行限制。原始 \(u_t\) 保留用于追溯；有变换时，Editor 按当前有效的 \(\widetilde u_t\) 构造，而不能从原始与变换方案中任意择取。

先将每项要求展开为“触发条件—应采取的决策／动作—范围或例外—保留要求”。分开必须表达的行为要求与尚待验证的效果预测，例如“有效空结果时检查其他路径”是要求，“任务成功率提高”是待验证效果。

目标、条件或版本缺失到无法判断时，返回具体缺口；不自行补造任务目标。后续 Parent 若改变，需要重新绑定并核对相关条款，不把旧版本的 patch 直接套用到新版本。

#### 5.4.2 建立相关读取范围，核对条件可观测性

从要求涉及的条款出发，检查共享默认规则、触发条件、前置步骤、恢复与停止要求，以及显式引用或已发现的冲突条款。本文称这些为“相关读取范围”，不要求额外建设关系数据库。Skill 较小时可以完整读取；局部读取时保留已检查范围，出现新依赖再扩展。

对每个会影响分支的条件，说明信息从哪里来、在何时可用、缺失时怎样处理：

| 条件来源 | 构造要求 |
|---|---|
| 工具或任务直接提供 | 沿用其公开含义，区分失败、空结果与未知 |
| 可由已有执行历史判断 | 指明使用哪些历史观察；不能默认截断记录仍然完整 |
| 需要增加记录步骤 | 明示所需状态、更新时点和已有执行能力是否支持；超出原要求时返回修订 |
| 只能依赖隐藏状态或未来信息 | 说明无法落实；提出可见替代时重新检查语义与范围，不把它视为等价措辞 |

例如，“环境状态未变化”与“没有观察到新信息”并不等价，替换条件可能扩大适用集合，必须作为实质变化处理。条件未知时也不能自动当作没有其他路径、从未尝试或可以继续；应沿用有依据的未知处理要求，缺少此类要求则返回澄清。

#### 5.4.3 选择修改位置和构造方式

依据行为要求选择实际写入位置，优先修改相关决策发生处及必要依赖，而不是只在文末追加原则。位置选择说明：哪条要求在这里生效、当前表达缺什么、改动可能触及哪些其他行为。

| 当前条款情况 | 可采用的构造方式 | 必须核对的边界 |
|---|---|---|
| 已有正确行为，但触发条件含糊 | 明确条件或改写为可判断的分支 | 不将原先不适用的情境无意纳入 |
| 默认规则与修订要求冲突 | 修订原默认规则及必要例外 | 不能保留旧矛盾，再靠新增条款期待 Agent 自行取舍 |
| 缺少必要的决策或前置步骤 | 在对应程序中补充步骤与衔接 | 信息何时获得、动作能否执行、失败或停止分支是否有定义 |
| 重复条款产生不一致解释 | 在不改变行为要求的前提下合并或删除重复项 | 不删除具有不同适用条件的有效规则 |
| 同一要求必须改动多处 | 将相关修改作为配套组构造并保留多对多来源 | 多处条件、顺序与例外应一致，不赋予各处独立效果 |
| 实现需要新增目标、能力或程序义务 | 暂存具体实现建议并返回上游 | 不能借“配套修改”扩大要求 |

在有依据实现要求的方式中，优先减少无关行为变化和无关重写；字数最少不是目标。若较长的条件化程序更准确，应允许使用。修改抽象原则或具体程序由需求决定，不强制分层或跨层编辑。

先表达待修改的位置、操作意向及其服务的要求，再生成 Candidate 文本，并依据 Parent 与 Candidate 得到实际 diff。这些逻辑操作可以在同一次编辑过程中完成；具体 patch 表示及应用工具留给实现阶段确定。

#### 5.4.4 检查实现后的条件与条款一致性

用 Diagnosis 提供的边界场景，加上编辑时发现的关联情境，逐项展开修改后实际文本会要求什么。检查目标场景能否触发、保留行为是否仍被允许、例外是否被默认规则覆盖，以及程序是否遗漏前置条件或形成循环。多个条款同时适用时，必须检查它们是否要求相反动作。

此处检查的是“实际文本表达了什么”，不能用编辑前的意图代替。比如要求只限制重复的有效空查询，文本却写成“禁止任何相同查询”，即使解释写得正确，实际修改仍不合格。

在原要求范围内发现措辞或位置问题，可以局部修复后重查；若修复需要改变触发范围、策略、义务或依赖，就进入第 5.6 节的反馈流程。没有新发现时不反复自由改写；调用和编辑预算耗尽时返回已知限制，不能放松要求以宣布完成。

这些是执行前的语义核对，不是 Replay，也不能证明 Agent 一定按文本执行。必要时留下具体未决预期，供后续执行检验。

#### 5.4.5 对照实际 diff，交付候选或限制

进行双向核对：

1. 从每项更新要求查到对应的实际修改或当前已满足它的条款，解释条件、动作和保留行为怎样体现；未落实项不能隐藏。
2. 从每处实际改动查回其依据和服务的要求，识别无来源的新义务、无关重写、静默删除以及方向、范围或组合的偏离。

差异应由实际 Parent／Candidate 内容确定，不能仅依靠 Editor 声称“修改了什么”。版本、引用、patch 是否成功应用等可由程序核验；语义覆盖与干扰仍是有不确定性的模型判断。

| 结果 | 交付与后续 |
|---|---|
| 可进入后续执行的 Candidate | Parent／要求版本、完整 Candidate、实际 diff、要求与编辑对应、边界核对、尚待 Replay 检验的预期 |
| 当前条款已经满足全部要求 | 指出实际条款与依据，返回无新增修改；不为了生成 diff 重写同义内容 |
| 要求需实质修订或信息不足 | 返回具体限制、最小反例、可选实现建议及可能改变的范围，不将草案当成已完成 Candidate |
| 输入、调用或应用失败 | 保留错误及已有草案，与语义上的无修改区分 |

只完成部分相关要求时不能静默丢弃其余要求。若可独立拆分，应先形成范围明确、依赖核对后的新版要求，再对它生成 Candidate；相互依赖的配套组不能以不完整形式执行。Editor 不决定正式采用，也不把候选构造完成称为行为改善。

### 5.5 Replay：获得可比较的行为观察并交给 Memory 学习

Replay 接收 Editor 的实际产物和执行前预期，组织允许的执行与反馈，回答“这次实际更新发生了什么作用、观察边界在哪里”。Memory 据此更新第 5.2 节的认识。Gate 回答是否采用 Candidate；采用决定、行为观察和作用解释分别保存，不由一个总分或接受标记相互替代。

后续最小实现已将执行前观察说明与实际版本绑定，并提供一次语义后处理的独立行为反馈包：机械事实、落实判断、机会、目标／保留行为、关联及未知分别保存。新轮次在执行前存说明；旧轮次仅从冻结材料重建并显式标记。这是旧首版路径，真实调用失败见原报告；后续紧凑路径另行实现 Replay／Memory 联合增量与操作内快照，见 [COMPACT_CYCLE](COMPACT_CYCLE.md)。追加比较调度与正式 Gate 尚未实现。

下一版按第 4.5 节共享执行前观察问题，以有范围的稀疏发现和问题去向索引承接以下职责；取消目标 × 任务的强制语义输出矩阵。遗漏只能标为未评估，不能自动完成关键问题或生成保持结论。Replay／Memory 可在一次后处理中分别交付发现和认识增量，尚未实现。

常规路径优先复用已有且可比的 Parent 执行，对实际 Candidate 运行协议允许的任务并分析完整反馈。以下步骤是逻辑职责，不要求逐步骤调用模型，也不默认每轮额外生成原始初稿 Candidate、逐 edit 回放或运行全部变体。

#### 5.5.1 执行前绑定对象与观察问题

输入包括精确 Parent／Candidate、实际 diff、当前有效的更新要求及其与编辑的对应、原始 \(u_t\) 与变换记录、目标与保留行为、作用假设及反驳条件、相关 Memory 版本，以及环境能力和学习侧反馈权限。

执行前形成紧凑的观察说明，复用 Diagnosis、Fusion／Compiler 和 Editor 已给出的内容，只补缺项：

| 问题 | 需要明确的内容 |
|---|---|
| 实际测试什么 | 当前 Candidate 中哪些条款体现了哪个方向、范围或联合要求；有无未落实或偏离 |
| 哪里可能观察到作用 | 哪些可见条件和决策机会涉及目标行为，哪些邻近条件可能暴露干扰 |
| 什么算支持或反例 | 预期动作、目标响应、需保留行为，以及能反驳预测的具体表现 |
| 可以比较到什么程度 | 参考版本与执行、共同条件、已知差异及未覆盖范围 |
| 结果如何进入学习 | 实际事件与原生评价的来源，可能受影响的作用认识及尚未确定的归因 |

这里的“应当执行什么”是要求，“预计执行后怎样”是预测，两者不能混淆。解释性行为指标必须能指向环境事件或明确标注的语义判断，不能用模型自评替代原生任务评价，也不冻结通用行为指标数量。

应用、版本或关键要求落实检查失败时，先返回 Editor／方案形成环节，不以残缺 Candidate 测试原方案。若执行后才发现偏离，保存真实运行，但其结论只适用于实际版本；下一次修复形成新版本，不能覆盖已执行内容。

#### 5.5.2 选择观察范围并核对可比性

先使用当前协议本来安排的学习／开发任务与已有 Parent 执行。围绕实际受影响行为，兼顾目标机会、需保留行为、条件边界及重要组合关系；缺少其中某类时标明未覆盖，不默认增加固定数量任务或完整测试矩阵。新增任务或局部比较须符合第 5.5.5 节的价值与成本条件。

记录选择了哪些任务、为什么选择、哪些未执行，以及运行是否完整。选择范围不能只保留预期有利案例。对全部已完成、允许学习的执行收集原生结果、成本及可机械提取的事件信号，再把目标相关行为、已知反例和新退化纳入详细分析；不能只分析最初 Diagnosis 引用的失败轨迹。

原生结果持平时仍可能出现新的行为问题。可以依据当前观察说明检查可见的非目标变化，但有限分析不保证发现所有语义回归。不存在通用程序可以从任意轨迹自动识别所有行为变化；补充语义分析与所需上下文应计入预算。材料过多时缩小本轮可作的判断或明确未分析范围，不能静默删掉已发现反例。

形成 Parent／Candidate 比较前，核对：

- 任务身份及初始条件、可见输入与工具环境是否对应，是否发生外部状态变化；
- 两侧精确 Skill、执行器、模型配置、任务预算与评价协议是否一致，除待比较更新外还有哪些差别；
- 既有 Parent 执行是否仍可作为当前参考，是否与诊断引用同属一次运行；
- 重置、随机性和运行完整性是否足以支持所需结论。

相同任务名或 seed 不保证动态执行完全一致；同一次 Parent 执行的多个引用不是多个样本。环境不能可靠重置或条件无法对齐时，可以保留各版本观察，但不将结果差直接归为编辑效应。新补跑 Parent 也不能冒充原先触发诊断的那次执行；两者身份和结果都要保存。

对可比执行，比较任务层面的完整结果，并围绕相应行为机会对齐事件，不要求动作序列或步号相同。主动挑选的失败与边界案例只能支持相应范围的判断，不能直接估计总体收益。

#### 5.5.3 分开观察落实、机会、行为与结果

下面是可以同时存在的观察维度，不是一组互斥状态或固定 schema。每项判断附来源及未知；“未记录”不自动等于“未发生”。

| 观察维度 | 需要区分的情况 | 对学习的意义 |
|---|---|---|
| 实际落实 | 要求已体现在实际文本、存在偏离，或无法确认 | 判断是否真的测试了所称策略；不能仅凭 Editor 描述认定 |
| 机会与路径 | 外部条件未出现、条件可见但未到达决策位置、已到达，或证据不足 | 区分未覆盖与路径改变；比较 Parent／Candidate 为什么到达或未到达 |
| 执行行为 | 按要求行动、未遵循、选择了其他分支、工具返回错误，或无法判断 | 定位作用链的可见中断，不直接等同于策略有效或无效 |
| 行为响应 | 目标变化、保留行为变化、触发频率／范围及重复、冲突或依赖表现 | 支持方向、尺度和组合的局部认识，保留未预期影响 |
| 原生任务结果与成本 | 成功、失败、分数、耗时、调用／动作消耗及运行完整性 | 记录方案整体表现；行为改善不等于最终任务改善，整体结果不分摊为每条编辑贡献 |

例如 Parent 会到达某个恢复步骤，Candidate 因新的停止规则提前退出，则“恢复未触发”同时包含一项路径变化。需要向前追到可见决策，检查是否违背保留要求，不能将它归为无信息样本。若两侧都没有相关条件，则只能说本次未检验该响应。

若 Candidate 执行了要求的行为但任务仍失败，可以同时记录局部行为实现与任务未完成；不能强行选定“方向失败”或“方向成功”作为唯一结论。工具错误也须区分被测恢复情境、Agent 误用及基础设施中断；只有有来源的运行问题才作为相应比较限制，不能为解释不利结果事后排除样本。

对每个实质预期，给出观察是否支持、出现了什么反例、还缺什么信息；新发现的非目标变化单独保留。后续更新由第 5.2.2 节完成，不在 Replay 之后再串接一轮同内容的独立归因和总结。

#### 5.5.4 比较支持什么，以及不支持什么

| 已有证据 | 允许形成的判断 | 不能直接形成的判断 |
|---|---|---|
| 只有 Candidate 的可用执行 | 在该实际版本和条件下发生了这些行为及结果 | 编辑使行为优于 Parent，或优于未执行初稿 |
| 可比 Parent 与完整 Candidate | 当前编辑组合在已覆盖条件下伴随哪些行为与结果差异，并说明随机性与其他限制 | 每一项编辑的独立功劳、普遍因果效应 |
| 两个完整可执行方案只在重要局部分支上不同，其他条件可比 | 该分支在其余方案固定、该情境下的条件性比较 | 该方向脱离其他条款仍有效，或可迁移到全部任务 |
| 多个方向共同出现且结果改善 | 联合响应，或有事件依据的执行依赖 | 非加性交互、相互增强程度或数值二阶结构 |
| 只有整包评价，没有足够轨迹 | 该方案的整体表现与局部未知 | 具体行为、触发条件与编辑作用的细粒度解释 |

将一个事件对应到某条要求，可以定位行为，却不自动隔离其贡献。即使只有一条文本编辑，也可能同时改变多种行为。单项或交互主张需要与其力度匹配的比较；不能由共同成功推出互补，不能为方便归因忽略共同修改。

若要验证预条件化优于原始修订，应把同一 \(u_t\) 和 \(\widetilde u_t\) 分别落实为有效 Candidate，核对各自实际 diff 与要求的一致性，并在可比条件下执行。这样的对照属于机制实验或有明确价值的额外比较，不是每轮默认成本。只执行最终 Candidate 时，只报告其自身及已有参考下的表现。

#### 5.5.5 按需补充比较与有限停止

优先补读已有证据。只有同时满足以下条件，才考虑新增执行：

1. 当前未知对应具体决策，例如会改变下一轮某方向的采用条件、某项保留要求，或重要关联的处理；能说明不同结果分别会改变什么。
2. 存在可执行、有区分力的比较：任务条件允许、必要依赖完整、反馈可见，环境能够提供足够可比性。
3. 预期信息价值足以承担成本，且没有耗尽事先约定的总预算。

可以比较一个有争议分支、一个关键边界或一项完整的配套变体，也可在随机性妨碍判断时进行有理由的重复运行。不预设统一次数、所有编辑子集或每项方向都必须隔离。删除或替换编辑时须重新核对配套依赖，不能把破坏依赖的残缺 Skill 当作有效消融。

每次追加前保存要区分的问题、比较对象、可解释结果和停止边界。追加结果与所有失败、持平、不利观察一起保存；新增假设可以继续研究，但不能倒写为原定问题，也不能只保留有利试验。预算耗尽、条件无法区分，或追加观察仍不能改变判断时保留未知并停止，不能反复运行直到通过 Gate。

局部比较可支持认识修订，不绕过正常 Candidate 采用流程；若据结果继续改 Skill，形成新要求、实际 diff 与执行身份。额外生成、执行、语义分析及失败重试均计入总成本。

#### 5.5.6 Replay、Gate 与信息权限

当前两轮协议要求先形成 Replay 配对事实，再执行 Gate，之后才正式更新 Memory；详细行为解释与认识增量共用 Gate 后的一次调用。

Gate 根据事先声明的开发期采用协议决定下一轮使用哪个 Skill。它可以在协议允许时复用 Replay 的执行，不要求额外建立私有 Monitor 或重复跑同一任务；若使用单独选择集，应明确其用途、预算和学习侧可见范围。Gate 不能临时为了通过候选改评价规则。

Memory 接收被采用和被拒候选的允许学习证据。采用决定可以进入版本档案，但不能当作单项作用真值；Gate 的私有分数、解释或隐藏机制不能通过摘要进入 Memory。若协议允许原生评价用于学习，就按该权限使用，并与对照方法保持一致，不直接搬用旧成功／合规双维或旧 Gate 阈值。

最终独立测试不参与修改、Replay 选题、Gate 采用或 Memory 更新；即使只返回采用位也会形成自适应反馈。用于持续选择的集合应标为开发资源，不能同时声称是未触及的最终测试。反复用于修改的案例只能提供开发期证据，迁移主张需要独立新实例及相应评价。

遇到不允许学习的观察、不可解析来源或运行失败时，分别保留权限／错误说明与可用事实，不伪造反馈。没有有效 Candidate 时不产生 Candidate Replay；当前 Parent 的真实新执行仍可按第 5.2.5 节的有限范围使用。

#### 5.5.7 交付与联合完成条件

Replay 与 Memory 共用一份可追溯的后处理输入，并分别保留：

- **观察依据：** 实际版本与 diff、选取和运行范围、可比性、行为事件、原生结果与成本、覆盖限制和意外变化。
- **认识增量：** 哪些预期获得支持或出现反例，哪些作用认识被补充、限定、替换或仍未确定，以及相关来源。
- **版本采用记录：** Gate 的决定及其协议身份，实际保留哪个 Skill；它不替代前两项。

程序负责版本、来源、任务和运行身份、可直接计算的结果及成本；相关行为解释与 Memory 修订可合并为一次后处理语义调用。没有新增可解释信息时可以只追加有效来源或保持原状态，不为了流程完整固定增加调用。

第四步在“可用观察已经有相称的认识处理，无法判断的部分有明确限制，后续 Fusion 能读到会影响决策的支持和反例”时完成。它不要求每轮识别全部因果效应、让每条认识变得更确定，或每次都改变下一轮 Skill。

### 5.6 Diagnosis 与 Editor 的协作、反馈及有限停止

本节保留第二步连接两端的独立推演：当 Fusion／Compiler 原样传递时，显式令 \(\widetilde u_t:=u_t\)，将 Diagnosis 的认真推导方案交给 Editor，不宣称已经发生预条件化变换。第三步的一般变换路径见第 5.3 节，其反馈继续遵循本节的版本和有限停止原则。

~~~text
当前证据与 Parent
→ Diagnosis：形成目标、初步策略、边界及依据，或给出不修改／待证据结论
→ 将当前有效的初步方案作为待落实要求
→ Editor：检查条款和可见条件，构造并核对实际修改
  ├─ 要求内的表达或位置问题：局部修复，再核对
  ├─ 目标、解释或初步策略需改变：返回 Diagnosis，保留原版并形成修订版
  ├─ 缺少信息或不可实现：返回具体限制；无法获得必要依据或形成可行修订时停止本轮构造
  └─ 要求已落实：交付 Candidate、diff 及待验证预期给后续 Replay
~~~

Editor 的反馈至少包含：受影响要求、具体条款或不可判断的条件、一个能暴露问题的情境、为何现有实现不满足要求，以及可能的替代实现和行为范围变化。不是只返回“有冲突，请重新诊断”。

| 发现 | 处理责任与规则 |
|---|---|
| 已明确要求的措辞、位置或等价重复有问题 | Editor 在原要求内修复并核对，不要求新增审阅调用 |
| 原始观察缺失、目标解释不成立，或当前 Parent 已覆盖旧缺陷 | 返回 Diagnosis 复查相应证据与条款，不重新做无关诊断 |
| 需改变策略、触发范围、顺序、义务或执行依赖 | 原样传递路径返回 Diagnosis 修订初步方案；若要求经过 Fusion 变换，则返回形成该要求的 Fusion／Compiler，涉及目标时仍返回 Diagnosis |
| 需要原输入中不存在的证据或能力 | 指出缺失及其决策作用；不能用改写文本替代缺失能力 |

上游收到反馈后，先判断是依据不足、原方案有误，还是 Editor 误读要求。可以补充已有证据、修订方案或说明原要求如何落实，也可以返回无需修改或待证据。每次实质修订保留旧 \(u_t\)／\(\widetilde u_t\) 和原因，在执行前更新假设与预期，再让 Editor 核对对应 diff；原始方案不能被覆盖。

保留行为不是永久不变的额外目标。如果新证据表明某个保留要求本身有误，应返回 Diagnosis 明确修订及依据；不能由 Editor 为了让文本通过而静默删除。

该协作允许使用一次或少量已有调用，不要求新增 Agent。若重复反馈没有带来新的可用依据、解释澄清或可行修改，且同一冲突持续未解决，或可配置的调用／编辑预算耗尽，则输出待处理限制并停止。同一证据下纠正误读或提出新的可行实现仍可推进，不要求每次反馈都新增执行证据；也不得反复改写直到模型自称通过。已经满足的方案不为增加迭代而继续修改。

第二步的可检查产物包括：一份能说明依据与边界的初步方案、一份可追到实际文本的修改或明确停点，以及执行前保留的反馈修订记录。只有格式完整、没有具体决策依据，不算完成机制设计；这些设计产物也不等于已经实现或实证有效。

### 5.7 第五步：贯通跨轮更新的最小协议

本节把已有模块连接为一轮到下一轮的运行约定。默认采用一份固定的轮初状态、一条主 Candidate 构造路径和一份轮末发布记录；执行前允许有界反馈，执行后先结算观察与认识，再进入下一轮。协议用于保证学习链可追溯，不作为新的研究贡献，也不要求增加调度 Agent 或庞大的状态机。

#### 5.7.1 一轮的边界与两种持续状态

轮初读取最后一次有效发布的 Skill \(S_t\) 和 Memory \(M_t\)。同时绑定本轮允许使用的任务／来源、环境与执行配置、反馈权限、采用协议，以及剩余预算。轮次编号、Skill 版本和 Memory 版本不是同一个编号：一轮可以只更新其中一种状态，也可以两者都不变。

| 持续内容 | 在本轮中的作用 | 进入下一轮的条件 |
|---|---|---|
| 已采用 Skill \(S_t\) | 当前 Parent，所有主候选 diff 的比较起点 | Gate 给出完整采用决定并完成轮末发布后，才切换到实际 Candidate；否则保留原版本 |
| 当前 Memory \(M_t\) | 已有作用认识及来源，供本轮判断适用性 | 允许学习的证据经过处理，形成有效增量或明确无需修订，再发布相应引用 |
| 执行与决策档案 | 原始观察、各版要求、实际候选、采用决定、认识修订和处理错误 | 持续保存真实来源，未发布产物不能冒充当前状态 |
| 任务接触与成本记录 | 区分首次接触、复用、重试、额外比较及累计资源消耗 | 即使本轮失败或未发布也继续累计，不能随恢复或新轮次清零 |

这四类内容是职责划分，不规定四套存储系统。轮末发布记录同时指明下一轮使用的 \(S_{t+1}\) 与 \(M_{t+1}\)，不要求它们同时发生内容变化。

本轮 Parent 的新执行 \(O_t^{\mathrm{pre}}\) 可以直接参与当前 Diagnosis，并在 Fusion 中反驳不再适用的旧认识；固定 \(M_t\) 不意味着忽略这些新证据。它们在本轮作为带时间与来源的当前信息使用，轮末再写入认识修订，不能先暗中改写 Memory 后仍声称本轮只读取了原版本。

默认每轮构造并评价一个主 Candidate。任务可以是一项或一批，具体批次由环境协议决定。结束一轮不等于必然产出修改；没有候选、语义暂缓或明确未获采用资格也有合法出口。处理错误是否已恢复、证据是否已经结算，需要另行明确，不能用“轮次已结束”掩盖。

#### 5.7.2 常规信息流与模块交接

~~~mermaid
flowchart TD
    A["读取已发布的 Skill 与 Memory、任务协议和剩余预算"] --> B["Parent 执行或复用可比观察"]
    B --> C["紧凑经验摘要与一次全局分类；冻结决策结构"]
    C --> D["Diagnosis：保存目标、认真初稿与当前依据"]
    A --> F["Fusion / Compiler：读取适用历史并形成更新要求"]
    D --> F
    F --> E["Editor：构造实际 Candidate 与 diff"]
    E --> R["绑定执行前预期，Replay 获取允许的反馈"]
    R --> G["Gate：形成采用决定"]
    G --> L["行为解释与 Memory 增量，保留 Gate 来源"]
    L --> P
    P --> N["下一轮从已发布的 Skill 与 Memory 开始"]
~~~

图中是新阶段有主候选的正常路径：先 Replay 机械事实、再 Gate、再正式 Memory。Gate 与 Memory 职责独立，但不再画成可并列结算的两条分支；08 采用公开原生结果的程序 Gate，随后一次后处理解释行为并更新认识，不增加重复分析。采用状态不是 Effect 质量标签。无候选及错误的一般分支见第 5.7.4 节；08 的严格停点、零返工和全批采用判据以[独立协议](GROUPED_TWO_ROUND_PROTOCOL.md)为准。

| 交接 | 必须保持的对应关系 | 允许的结束或返回 |
|---|---|---|
| 当前执行 → 摘要／分类 → Diagnosis | 精确 Parent、全批可见经验及冻结决策问题；参考执行与本次运行身份分开 | 一次全局分类形成语义结构，Diagnosis 再形成初稿或合法停点 |
| Diagnosis → Fusion／Compiler | 原始 \(G_t,u_t,H_t\) 先留存；当前证据与所读取的 \(M_t\) 来源可区分 | 变换、原样保留、处理独立部分，或带依据返回诊断 |
| Fusion／Compiler → Editor | 当前有效要求、方向与范围、联合依赖、保留行为及相对初稿的变化 | 在要求内实现；实质偏离返回形成要求的环节 |
| Editor → Replay | 实际 Parent／Candidate、真实 diff、要求与编辑对应、执行前预测 | 可执行时进入评价；无新增修改或构造限制不能伪造 Candidate Replay |
| Replay → Gate → Memory | 实际执行、冻结分组、配对条件和原生结果先支持采用决定，再与实际编辑一起支持响应学习 | 采用状态与响应真值分开，局部未知不伪装成无影响 |
| 轮末 → 下一轮 | 实际保留的 Skill、已处理的 Memory 状态、来源与累计成本 | 完整发布后才启动新的自进化构造；异常按恢复规则处理 |

已经被诊断解决的局部问题直接复用，不因跨模块交接重新生成一套解释。历史线索若引出新的目标，先按第 5.3.1 节形成有来源的目标与初步方案，再进入构造；不能借轮次调度直接把旧建议变成编辑义务。

当本轮没有任何可执行方向时，跳过 Editor、Candidate Replay 和候选采用比较；有 Parent 新观察仍可进入相应的认识处理。某个方向无需编辑或被暂缓，不自动取消其他已明确、可独立落实的方向。

#### 5.7.3 执行前反馈、执行后学习与比较变体

**执行前的修订留在本轮构造中。** Editor 的表达和位置问题在要求内修复；策略、范围、顺序或依赖改变返回 Fusion／Compiler，涉及目标或事实解释再返回 Diagnosis。每次修订保留初始方案和前版要求，明确受影响部分，不重新做无关分析。纠正误读或找到新的可行实现可以继续；同一问题持续未解且没有新依据、澄清或可行变更，或预算到限时停止。

**主 Candidate 一旦执行，实际版本与执行前预期不再覆盖。** Replay 反馈可解释本次变化、修订 Memory，但不能倒写本轮初稿或将一次未成功的执行重新标成修复后版本。依据这些反馈继续修改主 Skill，常规安排是先完成本轮结算，再在下一轮重新形成要求和候选。

第 5.5.5 节的有界局部比较仍可以在本轮进行。每个比较变体有独立实际版本、完整依赖、运行身份和预算记录；其结果进入相应观察与认识，不因表现较好就替换本轮主 Candidate 的身份。初版协议下，拟采用比较变体时，在下一轮把它作为有来源的候选方案重新绑定当前 Parent，并走完整的采用要求；先前执行只有满足第 5.5.2 节的条件才能复用，不能把已见案例当作独立新证据。

必要原始修订对照也作为明确比较对象保存。不能把未经 Editor 落实和执行的 \(u_t\) 当作已测基线；构造成本、实际 diff、执行差异与选择过程都计入机制评价。

#### 5.7.4 轮末状态、无修改与失败分支

令本轮有效学习输出为 \(M'_t\)，它可以是带新来源的修订版，也可以确认为 \(M_t\) 不变。Gate 的采用决定只选 Skill；下一轮状态由完整发布记录确定。

| 本轮结果 | Skill 的处置 | Memory 与后续处理 |
|---|---|---|
| 主 Candidate 获准采用，学习处理完成 | 发布 \(S_{t+1}=C_t\) | 发布有效 \(M'_t\)，无新增认识时可以保持原版 |
| 主 Candidate 被正常评价后拒绝 | 发布 \(S_{t+1}=S_t\) | 处理被拒分支的允许证据并发布 \(M'_t\)；该分支不记成部署效果 |
| 无需修改、Editor 确认无新增修改，或无可行候选 | 保留 \(S_t\)；08 完整核验 Parent 后记录 RETAIN／no_change，缺省 Candidate 比较成绩 | 处理已有 Parent 新观察；只有构造限制时记录限制，不创造编辑效应 |
| 证据不足或构造语义冲突，经有界处理仍未解 | 保留 \(S_t\)，明确本轮未落实范围 | 保存未知及相关线索；其他认识不被无依据重写，可在合法结算后继续接收新任务 |
| Candidate 正常执行但任务失败 | 按既定采用协议评价，不能自动视为基础设施失败 | 保留真实行为与任务结果，允许其中有局部支持或反例 |
| 执行中断、覆盖不足或预算使评价未完成 | 没有完整采用依据时不采用；可明确结算为“本轮未获采用资格”，不是已测定劣于 Parent | 对可确认的部分观察完成有限学习并标明未覆盖；证据采集错误未能界定时转恢复处理 |
| Memory 明确无需修订，或关键未知已有来源和处理说明 | 按有效采用决定处置 Skill | 这是正常结果，可发布；保留未知不要求强行改认识 |
| Gate 技术失败、Memory 处理／校验／写回失败，或来源身份不明 | 保持最后已发布状态，不把错误冒充拒绝或无修改 | 暂存已完成产物，有界恢复；未恢复时停止新的自进化轮次 |
| 发布过程中中断 | 先查是否已有完整有效的发布记录 | 已发布则直接使用，不重复提交；未发布则补齐所缺步骤，不推测两个版本已经一致 |

以上是一般机制分支；08 的冻结协议更严格：缺失或不匹配的必需执行导致 Gate 输入校验失败，不发布也不进入下一轮，且不使用自动恢复或额外调用。

“评价不充分”是有证据边界的语义结果，“本应执行的处理发生错误”是恢复问题。前者可保留真实限制完成结算；后者不能靠填入“未知”伪装处理成功。合法的不确定结论仍须经过必要证据核对，相关已知反例及来源可以在后续读取；未处理的新反例不能被静默排除。

部分方向可独立执行时，必须先形成范围明确且依赖完整的要求，实际候选与评价也绑定该范围；不能在轮末才删去未完成项以声称完整通过。有限语义暂缓不代表永久放弃问题，被拒也不代表所有局部方向无效。

#### 5.7.5 统一发布与中断恢复

本节采用如下设计约定：**采用决定与认识更新分别形成，下一轮入口统一发布。** 这是对第五步提交边界的具体选择，存储格式和事务技术仍可在实现阶段确定。

1. 保存本轮不可变的实际版本、来源、运行与决策产物。Gate 的“可采用”此时是待发布决定，不等于已经替换当前 Skill。
2. 完成允许学习证据的处理，校验 Memory 增量，或给出有依据的合法不变／未知结论；技术失败不转换为合法不变。
3. 核对预期起点仍是本轮绑定的已发布状态，核对选择的 Skill、Memory、必要来源、未决范围及累计成本。
4. 发布一份完整记录，指向实际的下一轮状态及其依据。新的自进化轮次只读取这份记录；恢复时重复处理同一记录不能新增尝试、来源支持或版本切换。

可以用不可变产物及一个有效入口引用表达上述关系，无须原地同时覆盖两个大文件。若发布时发现 Parent 或当前 Memory 已被其他更新替换，不直接套用旧 patch 或覆盖新认识，应停止该次发布并重新核对来源和适用性；并发演化的合并策略不作为当前默认路径。

Memory 处理失败时，即使 Gate 已建议采用 Candidate，也先保留旧的已发布 \((S_t,M_t)\) 和本轮待完成材料。修复欠缺处理后再发布；预算耗尽则结束本次运行并保留恢复点。当前草案不以“旧 Memory 暂时凑用”为由继续自进化，避免尚未处理的反例在下一轮消失。带滞后认识继续运行属于后续可选扩展，需要另外定义证据传递规则。

恢复优先复用已完成且身份可验证的产物。已经完成的真实执行不因写回失败重新运行，重读也不增加独立支持；只有记录不完整、环境状态或比较条件不再有效等具体原因，才按预算与协议补跑。对外部状态不明的中断执行，不能假设重复调用无副作用或环境已重置；由环境适配确认可恢复点，不满足条件则保留运行限制。

技术重试和重新生成语义内容也需要区分：前者恢复同一产物，后者若改变要求或解释，保存新版本及原因。已消耗资源和任务接触记录均继承，不因重新启动进程、恢复检查点或改变轮次编号而重置。

#### 5.7.6 调用组织、预算和连续停滞

沿用四段常规语义工作：Diagnosis、Fusion／Compiler、Editor、Replay 行为解释与 Memory 更新。四段是职责组织，不是每轮必须四次调用；程序承担来源装配、版本和显式关系检查、可直接提取的反馈与成本记录。任务执行本身的模型与工具调用另行计入总成本。

| 情境 | 默认组织 | 何时追加或停止 |
|---|---|---|
| 正常形成一个 Candidate | 各段处理相关内容，语义编排与已有后处理合并，复用可比 Parent 执行 | 当前上下文不足以完成必要判断时有界拆分，不通过超长调用强行合并 |
| 无候选或无新增修改 | 跳过候选构造后的执行与采用比较；有可用新证据时保留相应学习 | 无新信息则不为凑流程重新分析 Memory |
| 执行前反馈 | 局部返回受影响模块，保留未变部分 | 同一未解问题没有新澄清或可行方案，或预算到限时停止分支 |
| 额外比较 | 先说明待区分问题与可能改变的决策，再按第 5.5.5 节运行 | 比较不可辨识、不能改变判断或剩余资源不足时保留未知 |
| 技术恢复 | 核对并复用完成的产物，重试有身份、有成本 | 到达恢复上限或全局预算耗尽时保存进度并结束运行 |

预算至少覆盖本轮构造、必要执行与评价、后处理和发布，以及连续运行的累计消耗。开始昂贵候选执行前，为完成必要评价、证据保存和后处理保留资源；这是一项资源安排，不保证事先精确预测 token 或运行时间。实际超支或失败仍按真实成本记录，不隐藏失败尝试。

每轮额度由连续运行的剩余预算分配，换轮、补跑、重新命名尝试不能无限刷新额度。可以在有新任务、新证据或新的可行解释时继续；若相同证据下相同未决方案反复出现，且没有回应已知限制，则停止该分支或等待新信息，不把循环重试当持续学习。具体额度和停滞阈值是后续配置，当前不冻结数值。

#### 5.7.7 跨轮不变量与完成条件

贯通后至少满足以下约定：

- 每次真实执行绑定精确 Skill、任务与环境条件；被执行版本和原始观察不被后续修复覆盖。
- 本轮读取的历史、当前可见证据和执行后新认识有明确时间边界，当前证据可以推翻旧认识。
- 采用不认证知识，被拒不抹去证据；未部署 Candidate 的反馈不冒充当前 Parent 的效果。
- 初步方案、变换要求、实际 diff、执行观察和认识增量可对应；共享来源不重复计算为独立证据。
- Skill 与 Memory 可以分别不变，但发布的状态及来源必须一起可解析；技术失败与合法不变有不同出口。
- 恢复不重置成本，不把已见任务重新标为首次接触；最终测试不进入更新或采用反馈。
- 下一轮应能说明某项认识为何适用、怎样改变或保持实际要求；不能只记录“已参考历史”。

第 6.5 节以连续三轮构造走查检查这些接口。走查能发现身份、时序与分支矛盾，但不能证明模型会稳定执行这些判断，或证明预条件化优于同信息、同预算的直接历史辅助编辑。

## 6. 如何避免退回普通历史辅助编辑

需要明确的不是更多阶段，而是初步修订到实际修改之间的具体变换。设计应支持回查以下关系；它们不是现在就要冻结的字段表或新增调用流程。

| 要回答的问题 | 必须能找到的内容 |
|---|---|
| 最初准备怎样改 | 当前目标、原始修订意向、依据及未知 |
| 为什么需要变换 | 当前分析或历史响应揭示的作用偏差与关联 |
| 实际改变了什么 | 方向替换、条件和尺度调整、组合协调等具体决策 |
| 怎样进入 Skill | 更新要求与实际 diff 的对应，及落实时的实质偏离 |
| 执行支持了什么 | 目标与非目标行为变化、联合效应及仍未知的作用 |
| 怎样影响下一轮 | 新反馈修正了哪些作用认识，后续据此怎样更新 |

这些关系应在执行前后分别留存，不能在看到结果后补写一份看似合理的变换解释。记录结构只能使机制可检查，本身不证明变换规则已经有效或具备新颖性。

### 6.1 第二步的完整构造推演：有效空结果、重复与恢复

本例只检验 Diagnosis 与 Editor 的机制是否能贯通，不调用模型或工具，不代表真实轨迹或实验成绩。工具状态和条款均为示意，不是针对某个 benchmark 冻结的实现。

**给定输入。** 假设使用只读查询工具；公开反馈可以区分有效空结果、正常结果和明确可重试的暂时故障。执行器提供本轮相关查询历史，已有任务预算与停止要求。对于路径或历史不明的情况，先沿用输入中已有的信息不足处理要求；若原要求也未覆盖，Editor 应返回缺口，不能将未知直接判成不存在。Parent 中有：

~~~text
P1：查询无结果时可以继续重试。
P2：避免重复调用。
~~~

修改前提供三个带来源的示意片段：

| 片段 | 可见事实 | 不能据此断言的事 |
|---|---|---|
| A | 查询有效返回空结果；已有任务信息支持另一条尚未尝试路径；Agent 直接结束 | 另一条路径一定成功 |
| B | 相同查询连续有效返回空结果，期间没有观察到相关新信息 | 相同查询在任何时候都无效 |
| C | 工具明确报告可重试的暂时错误；在既有预算内再次查询后得到正常结果 | 所有错误都应该重试 |

**Diagnosis 的具体判断。** A 与任务所需的信息获取不充分相联系，B 提示无效重复，C 提供需要保留的恢复行为。核对 P1／P2 后，可以提出“无结果、执行故障和重复的适用边界不明确”的解释；临时执行差异等其他解释尚未被排除。缺口位于查询结果后的下一步决策，不是缺少一句“更加努力”。

这里选择澄清结果分支与下一步路径的策略，而不优先增加统一重试次数：增加次数不能区分 A、B、C，也不能处理 P1／P2 的冲突。若当前 Parent 实际已明确这些分支，则应撤回这一缺失判断，转查是否有具体执行或表达问题，不重复添加规则。

Diagnosis 形成目标 \(G_t\)：减少有可见替代路径时的过早退出、减少缺少新信息的无效重复，保留正常结果处理、合理恢复与预算内结束。首选初步方案 \(u_t\) 的行为要求如下：

| 要求 | 初步策略与边界 | 依据及未决项 |
|---|---|---|
| U1 | 有效空结果后，根据当前可见信息检查其他有依据且尚未覆盖的路径 | A；不承诺其他路径一定产生结果 |
| U2 | 历史能确认同一路径已有效返回空结果，且未见相关新信息时，避免直接重复 | B；不把未知历史当成已尝试 |
| U3 | 明确可重试的暂时故障按已有工具规则与任务预算恢复 | C；不适用于所有故障 |
| U4 | 正常结果仍按原有要求处理；当前可见信息足以支持没有合理替代路径，或满足已有停止条件时，允许说明限制并结束 | 当前任务与执行约束；路径未知不能直接当作不存在，不创造持续搜索义务 |

U1—U4 是本例的展示标记，不是固定字段或预设的编辑维度。Diagnosis 已通过对 C 的检查给 U2 留出恢复边界，不故意生成一个“禁止全部重复”的弱初稿供后续修复。它同时记录：这些方向存在条件协调关系，预期仍需执行验证。

**Editor 的读取与构造。** 本步原样传递 \(\widetilde u_t:=u_t\)。Editor 读取 P1、P2、已有预算／停止要求、工具公开反馈定义和查询历史可用性。发现只在末尾增加“继续探索”仍会留下 P1 与 P2 的冲突，因此将两条一并纳入相关修改范围。

在上述输入假设成立时，可以构造以下文本差异示意：

~~~diff
-P1：查询无结果时可以继续重试。
-P2：避免重复调用。
+P1：查询成功完成但无结果时，根据当前可见信息检查有依据且尚未覆盖的其他路径；存在且预算允许时切换路径。当前信息足以支持没有合理替代路径，或满足已有停止条件时，说明限制并结束；路径未知时沿用已有的信息不足处理要求。正常结果沿用原有处理要求。
+P2：结合当前可读历史判断重复；已确认有效返回空结果的同一路径，在未见相关新信息时不直接重复。明确可重试的暂时故障按已有工具规则和任务预算恢复；相关新信息出现时可以重新考虑原路径。
~~~

这是尚未执行的文本构造，不是已生成算法产物。将来实际 diff 必须由保存的 Parent 与 Candidate 得到。U1／U4 主要映射到 P1，U2／U3 主要映射到 P2；两处共同处理继续、重复与恢复的关系，不能分别宣称独立效果。

**Editor 的边界核对。**

| 检查情境 | 要求实际文本允许或要求什么 | 能暴露的问题 |
|---|---|---|
| 有效空结果，仍有可见信息支持其他路径且预算允许 | 考虑并切换到该路径 | 若仍立即结束，U1 未落实 |
| 已知同一路径有效为空，未见新信息 | 避免直接重复该路径 | 若仍统一重试，P1 的旧缺陷未解决 |
| 第一次暂时故障，第二次相同查询可能成功 | 在工具规则和预算允许时保留恢复 | 若一律禁止同文本查询，U3 被阻断 |
| 当前信息足以支持没有合理替代路径，或满足已有停止条件 | 允许说明限制并结束 | 若必须一直寻找新路径，则产生新义务；不能把路径未知直接判成没有路径 |
| 出现相关新信息 | 允许重新考虑旧路径 | 若永久禁止历史空查询，则范围过宽 |
| 关键历史记录缺失 | 不能推断此前从未尝试或已经有效为空 | 若构造需要完整历史但运行时没有，必须反馈限制 |

前几行检查条件分支的含义，最后一行检查给定能力假设。核对未发现冲突时，Editor 交付 Candidate、实际 diff 对应方式、前述边界以及待 Replay 检验的预期；不能将表格填写完成称为执行验证通过。

**一条确实需要反馈的分支。** 若初步要求写成“环境状态没变时不重复”，Editor 查到运行时只能看到工具反馈，应指出：两次查询之间未见新消息，不足以证明环境没有变化。将它直接替换成“未见新信息”会改变适用条件，不能作为普通措辞修改。

Editor 将这一情境、不可观测条件及可见替代建议返回 Diagnosis。Diagnosis 可以根据实际证据形成限定在可见历史与明确空结果上的修订版，并记录对动态环境适用性的未知；若缺乏依据，则保留待证据结论。只有修订要求在执行前明确后，Editor 才继续构造。若运行时连必要历史也不可读，则进一步返回缺失能力，不假定写入 Skill 就能获得持久状态。

**无需生成修改的分支。** 若只提供 C，且当前 Skill 与工具说明已经正确支持恢复，没有新冲突，则 Diagnosis 没有理由新增去重或路径探索规则。若提供 A，但关键记录被截断到无法确认是否还有路径，则返回待证据，不能把早停直接归为 Skill 缺陷。

上述分支检查了正常构造、要求修订、无需修改和输入不足。真实 Replay 后续还要观察目标与保留行为、原生任务表现和成本；效果依然未知。此例没有使用历史响应模型或 Fusion 变换，因此不能证明预条件化收益。普通强 Editor 也可能产生同样文本，后续方法贡献仍需独立验证。

### 6.2 空 Memory 与证据不足

没有历史时，Diagnosis 仍可利用当前失败与成功行为、相关条款及可见工具条件，形成目标和局部作用假设；Fusion／Compiler 和 Editor 仍能调整初步修订。必要探测是可选手段，不是冷启动的强制前置条件。

必须区分当前观察、推断和未知，不能伪造历史响应来完成流程。Memory 的增益在于跨轮积累、修正与复用，使后续构造更有依据。已有历史不适用时，也应回到当前证据，而不是机械继承旧作用关系。

### 6.3 第三步构造推演：同一初稿如何随作用信息改变

以下均为人工构造的输入、历史与方案，不是运行记录或已测结果。它用于检查第 5.3 节规则能否产生可落实的变换，并与第 6.1 节的原样传递路径区分。

**固定初稿与目标。** 假设任务是在只读资料中找到符合指定对象及范围的依据。当前工具允许普通查询与索引查询，相关调用历史可读取；某些工具会公开返回对象标识或规范化检索路径标识，但并非所有情境都提供。缺失字段不能靠推测补齐。

Diagnosis 根据本轮信息形成认真推导的初步方案：

> 有效查询为空后，在预算内采用保留任务约束的查询改写或其他尚未覆盖的相关路径；避免直接重复已确认无效的路径。明确暂时故障按工具规则恢复，正常结果满足任务要求时结束。

这份方案已经考虑身份约束、恢复与停止。下面的历史提供此前尚未确认的作用信息，不通过故意制造一个明显错误初稿来展示 Fusion。

**适用信息改变决策。** 保持 Parent、目标与上述初稿不变，分别考虑以下输入条件：

| 新提供的信息 | 适用性与作用判断 | 应产生的要求变化或停点 |
|---|---|---|
| 没有新的适用历史，当前关联也已被处理 | 没有支持进一步调整的偏差 | 保留初稿；不为展示机制修改措辞 |
| 有实际编辑与轨迹支持：在当前这种公开精确标识可用的条件下，按标识进入索引能到达目标；普通改写在相关案例中反复未到达该入口 | 支持把索引路径作为当前条件下的替代机制，仍不能保证所有新任务成功 | 方向：有可用且与任务对象一致的标识时优先索引；其余条件保留有依据的改写或其他路径 |
| 历史中的普通描述改写有用，但对某些看似描述性的专业限定词改写后，返回了另一范围的对象；当前也出现这些限定词 | 揭示了原“保留任务约束”在这些情境中的具体影响边界 | 尺度：将这些限定词作为本情境下必须保留的查询约束，仅在其余可解释部分改写；不一律禁止改写 |
| 当前工具公开提供规范化路径标识；相关实际编辑与执行表明，表面不同的表达可能进入同一路径，继续探索和故障重试会重复触发 | 两类更新共享调用对象，但有效空结果与未完成调用的含义不同 | 关联：按可见路径身份协调覆盖判断和路径切换；仅成功完成的查询可形成相应覆盖证据，暂时故障仍走恢复分支 |
| 名称相似的旧任务有上述结果，但当时依赖的索引或标识当前不可用 | 作用条件不匹配，不能照搬 | 不据此新增精确索引义务；保留仍可行初稿，或将未决能力问题返回 |
| 历史只给出整包分数差，没有实际编辑对应和局部行为观察 | 不足以支持某个方向的精细效应判断 | 不能推出某个限定词应固定或某项编辑有效；保留整包限制与未知，必要时补读相关来源 |
| 支持与反例相互冲突，区别条件不可观察 | 尚不能构造运行时可判断的分支 | 不制造条件；保留有依据的初稿、形成有明确边界的待检验方案，或暂缓确实无法协调的部分 |

表格说明“同一初稿、不同证据应怎样影响要求”；每项历史是否足够适用仍要按第 5.3.2 节核对。找到有用索引的观察不能被升级为普遍因果规律，联合反馈也不能被拆成各项独立效应。

**形成一份联合要求。** 若方向、尺度和关联三类信息都适用于当前条件，Fusion／Compiler 可以把工作方案重构为：

| 联合要求 | 相对原方案的具体变化 | Editor 的落实边界 |
|---|---|---|
| 公开精确标识可用且与任务对象相符时，先采用对应索引；不具备此条件时继续采用有依据的其他路径 | 将原先未明确排序的路径选择，细化为标识条件满足时优先索引 | 条件必须可见；索引失败后仍需按实际反馈区分空结果、错误和未知，不能推断对象不存在 |
| 在受相关历史支持的情境中，保留已识别的身份和专业范围限定，仅调整其他有依据的描述部分 | 收紧改写影响的字段范围，同时保留探索能力 | 明确哪些词承担范围含义及依据；不能将这份局部清单泛化到所有任务 |
| 不同表达映射到同一可见路径时，复用其有效查询覆盖记录；只有未覆盖的相关路径才计为新探索 | 协调改写、路径选择与去重要求，改变它们的组合执行方式 | 缺少路径标识时不能自动断定路径不同；回到已有可支持的判断，必要时标为未知 |
| 未完成的暂时故障不写成“有效空结果已覆盖”；恢复仍按工具规则和任务预算进行 | 为覆盖判断与重试建立明确的前置关系和例外 | 禁止以去重规则抹掉恢复分支，也不无限恢复 |
| 正常结果满足原任务要求时结束；其他停止与信息不足情形沿用已有有依据的处理 | 保留原始目标与有效边界 | 不降低结果核实要求，不新增必须找到答案的义务 |

这里的“复用记录”仅指执行器实际能提供的历史，并须绑定对象、查询约束及可支持的有效条件。相关新信息可能改变结果时，应重新检查记录适用性；不能将一次空结果变成永久去重依据，适用性未知时沿用有依据的未知处理或返回澄清。若需要新状态能力，必须明示依赖并返回核对。索引优先、条件化改写和覆盖／恢复关系作为联合方案交付，不能分别生成编辑后再盲目拼接。

Compiler 保存原始方向到联合要求的对应，组织共同条件与依赖，并绑定已检查的相关条款。对“已覆盖”的判断必须以有效查询反馈为前提；如果结构中把恢复分支同时标成禁止与必需，应返回具体冲突。程序能检查显式关系，语义上是否真的表达一致仍由 Fusion 与 Editor 分别核对。

Editor 随后选择修改哪些现有路径选择、去重和恢复条款，并生成实际 diff。若原文无法表达条件，或历史截断使覆盖判断不可落实，就按第 5.3.7 节返回；不能静默删除该依赖后声称完成方案。

**执行前留下可反驳预期。**

- 标识条件满足时，是否采用索引并找到符合原要求的依据；若索引反复无效或遗漏必要其他路径，应修正方向认识。
- 固定范围限定是否减少错对象结果，同时仍能找到正确结果；若约束过窄导致可行查询被阻断，应修正尺度。
- 表面不同但路径相同的查询是否减少无效重复；路径标识不可靠时，这一关系不成立，不能继续沿用。
- 第一次暂时故障、第二次相同请求成功的恢复是否被保留；如果去重阻断恢复，组合要求仍有缺陷。
- 缺少相关标识、所有可支持路径已尝试或预算耗尽时，是否仍能按原边界处理，而不是出现新循环或无依据结论。

这些是联合方案的观察需求，不能保证隔离出每个操作的独立贡献。只有真实比较原方案与变换方案的执行，才能讨论变换是否更合理；只展示文本差异不构成效果证据。直接历史辅助编辑的强基线也应能看到同样的适用证据，后续验证需区分变换机制与更多信息、调用、回放的影响。

**无历史也可工作的情形。** 若当前 Diagnosis 分别提出“继续覆盖未尝试路径”和“对已成功查询的同一路径去重”，而尚未处理它们与故障恢复的依赖，Fusion 可根据当前工具语义组织上述覆盖／恢复关系。若初稿已完整处理，则原样保留。该能力支持冷启动，但不是跨轮 Memory 收益的证据。

### 6.4 第四步构造推演：从联合观察到可修订认识

本节延续第 6.3 节的索引、条件化改写、覆盖判断与恢复案例。以下全部是假设性的机制推演，不是运行数据、Gate 结果或 V22 实验结论。用多个情境说明信息怎样流动，不预设真实 benchmark 必须提供这些工具或反馈。

**执行前与实际版本。** 假设完整 Candidate \(C_1\) 落实了“适用标识下优先索引、按有效查询复用覆盖记录、暂时故障保留恢复”的联合要求，Editor 已保存实际 diff 和对应关系。执行前预期分别是到达正确入口、减少无效重复、保留故障恢复；这些预期在看到结果前保存，不据结果修改。

**Replay 可能取得的观察。**

| 假设观察 | 可写入的事实与限制 | 不能跳到的结论 |
|---|---|---|
| 可比情境 A 中，Parent 未到达目标入口；\(C_1\) 使用可用标识进入索引并取得符合要求的依据 | 在这份联合 Candidate 下观察到不同路径和目标结果；保留两侧实际执行 | 索引编辑单独造成了全部收益，或任何有标识任务都应只走索引 |
| 可比情境 B 中，Parent 在明确暂时故障后恢复成功；\(C_1\) 却把已发起的请求当作已覆盖而提前退出 | 恢复要求虽然写入，实际执行未遵循；存在与覆盖判断相连的路径变化，需保留原始事件 | 去重方向独立有害、恢复已被删除，或“恢复未触发所以没有信息” |
| 情境 C 没有标识，也没有暂时故障 | 保存正常路径的行为和结果，标记相关条件没有被检验 | 索引与恢复作用均为零 |
| 另一次运行外部数据已改变，无法与已有 Parent 对齐 | 保留当前版本的单侧观察和不可比原因 | 把两次结果差作为这次编辑的效果 |

情境 B 不会因 Candidate 仍有一些成功任务而被省略。如果只有整包分数而缺少上述事件，就只能保存整包结果和局部未知，不能生成这张表里的细粒度认识。

**第一次认识更新。** 假设 Gate 按预先声明的开发协议保留 Parent，Memory 仍可形成有来源的联合认识：

> \(C_1\) 的组合在 A 的标识条件下伴随索引入口与目标行为改善；B 中覆盖判断伴随恢复丢失，实际执行违背了“未完成调用不得作为有效覆盖”的要求。索引方向仍值得在适用条件下继续研究，覆盖与恢复的衔接需要复查；单项贡献尚未分离，未覆盖条件仍未知。

这里保存了可用方向和具体限制，而没有把被拒 Candidate 切成“已证明有效的索引 patch”与“已证明有害的去重 patch”。事实记录、认识修订和 Gate 采用决定各有来源；下一轮 Parent 没有包含 \(C_1\)，Memory 不能把它当作已部署效果。

**下一轮如何使用。** 当前 Diagnosis 仍须根据当轮可见证据形成认真初稿。若再次涉及路径探索或恢复，Memory 返回上述支持与反例，并核对当前 Parent 中的相关条款和工具返回含义。Fusion 可以据此：

- 保留有依据的索引探索方向，避免因整包拒绝一并否定；
- 核对“发起请求”与“取得有效查询结果”是否在实际要求和表达中被清楚区分，必要时限定可复用记录的范围；
- 将覆盖登记与恢复安排为需要共同落实的要求，防止去重先于调用结果分类而抹掉恢复；
- 如果当前初稿已准确处理这些限制，原样保留，不为展示 Memory 收益再次改写。

这些是重新构造要求的依据。尚不能确定 B 源于表达歧义、执行遵循还是其他共同修改时，应保留竞争解释，由当前证据决定能提出什么修订；不能仅将“加强恢复指令”作为通用答案。

**是否增加比较。** 如果“覆盖判断是否在当前组合中阻断恢复”会改变一个重要修订，且环境可重置、预算允许，可以比较两份完整候选：只改变有争议的覆盖／恢复分支，其余要求尽量相同并核对依赖。若修改分支的版本恢复正常，而原分支对照仍出现恢复丢失，可以在可比性与随机性限制下加强对该分支在当前组合和条件下的作用判断；不能证明索引的独立效果。若两份候选没有可辨差异，则保留未能区分的结论，不据此证明有效、无效或等价。没有必要或无法有效比较时，联合认识足以保留，额外执行不是本例完成的前提。

**已采用后出现新反例。** 再假设后续完整候选 \(C_2\) 修正了有关要求，并在开发协议下被采用。采用记录不删除 \(C_1\) 的问题，也不永久认证覆盖策略。若后来在 \(C_2\) 的真实执行中出现“对象相同但查询范围已改变，仍沿用旧空结果”的行为，应保存新的范围条件、实际决定和结果：

- 若证据支持区分查询范围，修订当前认识为“覆盖复用依赖对象、查询约束及其有效条件”，并指出此前对范围变化的处理不足；不得只按相同路径合并。
- 下一轮 Fusion 可据此细化失效与重查条件，Editor 协调查询构造、覆盖记录及停止条款；这体现尺度与关联的调整。
- 若区别信息运行时不可见，不能把事后知道的范围写成可部署判断；保留限制，并在可用信息下构造方案或暂缓。
- 若只是工具语义已变化，则先标明相关依赖改变，重新检查迁移；不能据此改写 \(C_2\) 当时的观察。

上述修订是对新行为和原要求之间缺口的处理，并不证明“增加条件必然有效”。新的 Candidate 仍需实际执行；已经包含旧规则的 Parent 新观察不是再次施加旧编辑的收益。

本例还要求保留几个停点：重复读取 A 不增加独立支持；没有新增认识可以只关联来源；构造失败不生成虚假 Replay；无历史时从实际观察形成局部认识；信息冲突且无法区分时保持未知。第 5.7、6.5 节进一步贯通这些接口的多轮调度与恢复设计，持续效果仍待真实验证。

### 6.5 第五步连续三轮走查：学习怎样进入下一次实际修改

本节沿用第 6.3、6.4 节的搜索、覆盖与恢复任务类型，单独固定一个连续走查的起点。所有观察和采用结果都是**构造假设**，不是已运行的实验；三轮只是检查接口的长度，不是算法轮数、评价阈值或默认预算。工具标识、结果状态和任务约束均假设在相应情境中真实可见，缺失时不能补造。

设初始 \(S_0\) 有通用探索、重复限制和错误恢复说明，但在有效空结果后的路径选择与几项要求的执行组织上仍有可诊断缺口；\(M_0\) 为空。下文 \(S_1,S_2\) 表示发生内容变化的 Skill 版本，\(M_1,M_2,M_3\) 表示相应认识版本，不要求它们与轮次编号同步。每轮保留实际 diff、来源、执行前预期和消耗，不将示例假设写入真实 Memory。

| 轮次 | 轮初状态 | 本轮主问题与构造结果 | 假设的轮末发布 |
|---|---|---|---|
| 第一轮 | \((S_0,M_0)\) | 形成完整联合候选 \(C_1\)，有目标改善线索，也出现恢复退化 | Candidate 未通过既定采用协议，发布 \((S_0,M_1)\) |
| 第二轮 | \((S_0,M_1)\) | 据旧反例调整执行组织，基于真实 Parent 构造 \(C_2\) | 评价允许采用且学习完成，发布 \((S_1=C_2,M_2)\) |
| 第三轮 | \((S_1,M_2)\) | 新的可见范围变化暴露覆盖复用问题，构造 \(C_3\) | 假设评价允许采用且学习完成，发布 \((S_2=C_3,M_3)\) |

表中 Gate 结果仅用于走查不同分支，不从这些假设反推具体评分或采用阈值。即使假设采用，Memory 也只能保存相应证据范围内的认识。

#### 6.5.1 第一轮：空历史下构造，被拒后保留可用认识

**当前依据与初稿。** \(S_0\) 的可见执行显示：有效空结果后有时过早结束，也会重复已完成的等价查询；另有暂时故障后恢复成功的行为需要保留。Diagnosis 核对当前工具支持的入口与条款，形成 \(G_1\) 和认真推导的 \(u_1\)：有效空结果后在预算内使用保留任务约束的其他路径，可用且匹配的对象标识可用于索引；复用已完成有效查询的覆盖信息，暂时故障按工具规则恢复，保持结果核实与停止边界。

这些策略来自当前证据和可见工具能力，不来自尚不存在的历史响应。它们的有效性仍是假设。若当前 Diagnosis 已处理可见的局部关系，Fusion 可令 \(\widetilde u_1=u_1\)，不强制创造冷启动收益。

**实际候选。** Editor 相对 \(S_0\) 形成 \(C_1\)：修改路径选择、覆盖复用与错误恢复的相关条款，保留三者共同依赖的任务约束。实际文本采用“路径与覆盖规则＋恢复例外”的组织方式，语义核对认为要求已落实；这不保证 Agent 在运行时正确遵循。

**假设观察。** 可比情境 A 中，\(C_1\) 经索引到达了 \(S_0\) 未到达的目标入口；情境 B 中，\(S_0\) 会在明确暂时故障后恢复，而 \(C_1\) 停止，可见说明把“已经发起请求”当作覆盖依据。其余行为和原生结果按真实来源分别保存。不能仅凭 B 证明覆盖条款独立造成退化，也不能把写入恢复例外当作实际恢复已发生。

**认识与出口。** 假设既定开发协议未允许采用 \(C_1\)。后处理形成 \(M_1\)：保存这份组合的索引路径观察和恢复反例；提出“当前组织方式可能使覆盖判断先于结果分类”的待检验解释，并保留其他执行遵循解释。索引方向仍有继续研究的依据，但尚无单项独立效果证明。发布 \((S_0,M_1)\)，没有把 \(C_1\) 的条款部署到 Parent。

#### 6.5.2 第二轮：将被拒分支的认识变成联合更新要求

**当前初稿仍认真形成。** 新一轮在 \(S_0\) 上取得允许的当前观察，仍存在类似探索与重复问题。Diagnosis 独立形成 \(u_2\)：按结果选择探索或恢复，保留任务身份与范围约束，复用有效已完成查询，暂时故障可以按工具恢复。这个初稿已经保留恢复行为；不能为了展示 Fusion，把它故意写成一律禁止重试。

**历史究竟改变什么。** Fusion 读取 \(M_1\) 的联合反例及相关实际条款，确认工具反馈含义和 Parent 依赖仍适用。\(u_2\) 的目标与分支原则可以成立，但在这些条件下，历史提示“并列规则配例外”的落实方式仍有被误用的可能。因此 \(\widetilde u_2\) 明确一组程序要求：

1. 每次得到工具反馈后，先区分有效完成、明确暂时故障及未知状态。
2. 暂时故障进入有界恢复，不以“已发起请求”登记有效覆盖；恢复要求不得被路径去重提前截断。
3. 只有有效完成的查询才为相应对象、查询约束和路径产生可复用的覆盖依据，再决定结束或转向其他相关路径。
4. 标识适用时仍可使用索引，原有核实、预算与信息不足处理继续保留。

本次具体变化是把独立陈述的覆盖与恢复要求重组为有先后依赖的执行程序，明确覆盖登记的证据条件。它主要体现关联与行为尺度调整，不把索引观察升级为普遍最优策略，也不把“更强调恢复”当成唯一答案。替代组织尚待执行检验；若 \(u_2\) 已明确给出同样程序，就应原样保留。

**实际 diff 与执行。** Editor 必须以当前 \(S_0\) 为起点构造 \(C_2\)，不能把未部署的 \(C_1\) 当 Parent。实际修改把路径选择、覆盖登记和恢复分支共同组织起来，保存各处 diff 到 \(\widetilde u_2\) 的对应。假设可比执行中 A 的路径行为得到支持，B 保留了恢复，已覆盖的其他情境未暴露相应退化，既定采用协议允许采用。

**认识与出口。** \(M_2\) 保存 \(C_2\) 的新联合观察与未覆盖条件，特别记录这批覆盖复用观察只涉及查询约束稳定的情境。不能用 \(C_2\) 的结果洗掉 \(C_1\) 的反例；\(C_2\) 对 \(S_0\) 的差异是这份完整修改的比较，也不能自动当作 \(C_2\) 对 \(C_1\) 的隔离对照。学习处理成功后发布 \((S_1=C_2,M_2)\)。

此轮的跨轮链可以逐项核对：第一轮 B 的可见行为 → \(M_1\) 的联合限制与组织假设 → \(\widetilde u_2\) 的结果分类前置和恢复／覆盖依赖 → \(C_2\) 的实际程序修改。只把 \(M_1\) 附在 Editor 提示后，而不形成这些要求，不算完成该走查。

#### 6.5.3 第三轮：已采用方案遇到新条件，修订尺度与配套关系

**新反例先作为当前证据使用。** 轮初是 \((S_1,M_2)\)。假设 \(S_1\) 的新执行中，任务的可见查询范围发生变化，Agent 仍使用上一次构造的查询条件查覆盖记录，以同一路径已有空结果为由跳过查询。这里不是故意去掉第二轮的约束：\(S_1\) 要求按查询约束复用，但当前条款未清楚安排“先按最新任务信息重建查询约束，再检查覆盖”的时序，轨迹暴露了这个实现缺口。

Diagnosis 应核对上述缺口是否真的存在；若当前原文已经清楚规定该时序，不能重复补同义规则，应继续检查执行遵循与其他解释。本走查假设证据支持时序澄清，形成 \(u_3\)：可见范围变化时更新查询并重新检查相关目标，范围不变时仍避免无效重复。初稿已有明确边界，不采用无条件清空所有历史的弱方案。

**Memory 与当前证据共同作用。** Fusion 可在本轮直接使用新的 \(O_3^{\mathrm{pre}}\) 检查 \(M_2\)，无需等到写成 \(M_3\) 才承认反例。\(M_2\) 提供稳定约束下覆盖复用的支持、第二轮恢复依赖及未覆盖范围；当前证据则指出先后关系的缺口。由此把 \(\widetilde u_3\) 组织为：

- 在任务条件发生相关可见变化时，先刷新本次查询的对象与范围约束，再进行覆盖匹配。
- 仅对条件不再匹配的记录停止复用；其他仍有依据的覆盖记录可保留，路径标识相同不能替代查询条件相同。
- 协调查询构造、覆盖检查与停止判断，避免新查询尚未形成就被旧“已覆盖”结论提前截断。
- 继续保留暂时故障的恢复顺序、原生结果核实及预算边界；条件不可判断时使用已明确的未知处理。

这使“范围改变后重查”的初步策略落实为有依赖的条件更新，尺度也限定到失效记录。历史支持用于约束哪些有效行为应保留，当前反例用于发现缺口，不能把全部决策都归功于 Memory。若当前初稿已经覆盖上述要求，仍允许不变。

**实际修改、认识与出口。** Editor 相对 \(S_1\) 形成 \(C_3\)，协调更新查询构造、记录适用性检查与停止条款。假设 Replay 在可比条件中观察到范围变化后正确重查，同时保留稳定条件下的去重和故障恢复；这些仍是组合观察，不能分配为各条编辑的独立功劳。

后处理形成 \(M_3\)：保存 \(S_1\) 的新反例以及 \(C_3\) 的条件化观察，细化“覆盖复用依赖有效查询条件及其及时更新”的认识。旧版本与旧条件下的支持继续保留；反例不再被宽泛的“已采用且有效”描述掩盖。假设采用协议通过、学习完成，发布 \((S_2=C_3,M_3)\)；若拒绝，则应发布 \((S_1,M_3)\)，学习链同样可以成立。

仅有三轮文本和假设结果不能证明收益来自预条件化。直接历史辅助编辑的强基线也应获得同等信息和可比预算；真实比较需要核对认真初稿的实际实现及执行，不能从这个构造案例得出优越性。

#### 6.6.4 复用既有搜索案例，走查实际变换与反馈撤回

真实材料未覆盖的变换分支，用第 6.3–6.5 节已有的搜索案例检查。**以下条件、对照和反例均是假设，不是 ALFWorld 观察，也不是新增实验。** 不新增一个明显有缺陷的初稿，而固定第 6.3 节已经认真形成的方案：

> 有效查询为空后，在预算内采用保留任务约束的查询改写或其他尚未覆盖的相关路径；避免直接重复已确认无效的路径。明确暂时故障按工具规则恢复，正常结果满足任务要求时结束。

固定 Parent、目标、初稿及允许工具，只改变提供的适用作用认识；工具能力在此构造环境中真实可用，包括公开标识、可读调用记录及相应的路径身份。分别检查三条变换，最后才检查组合。对每个分支，只有该分支描述的历史资料被提供，不能暗中借用其他分支结论。

**方向分支：让响应改变下一条路径的选择。** 假设在这种公开精确标识可用的情境中，历史实际修改后的标识索引路径到达了目标入口，而普通改写在相近条件下仍未到达；其他变化与比较限制已知。Memory 可形成“在此条件下优先尝试索引有依据”的局部认识，而非索引普遍最优。规则 D 将初稿的未指定路径顺序改为：**公开标识与任务对象匹配且索引可用时，先按该标识查索引；其他情境保留原有改写／探索。** 未经执行不能保证新任务收益。

可观察的区别是同一决策机会下先走哪条路径、是否在相同预算内得到满足原范围的依据。单次索引未得到结果只反驳“索引足够”的过强主张，不直接否定优先顺序，因为后续改写仍可补全。若假设的可比顺序比较进一步显示：在相同可见条件下，优先索引消耗了必要预算，使原顺序能取得的目标结果反而遗漏，才应撤回该条件下的优先依据，保留索引为备选或研究更窄的适用条件；不能靠增加索引重试维护旧结论。撤回该认识或其依赖不再满足时，原来未指定优先的初稿仍有依据，则取消这项优先变换。原初稿若已明确同样的优先规则，新增历史不再制造新编辑。

**尺度分支：让响应限定改写究竟能改什么。** 假设历史在相近条件下的局部分支比较支持：普通描述改写仍能返回目标对象，而改动某个看似描述性、实际承载专业范围的限定词时，返回范围发生漂移。Memory 将“改写可能有用”细化为“当前可识别的范围限定需要保留”，同时保留比较与迁移限制。规则 S 将抽象的“保留任务约束”具体化为：**在这类条件下固定承担身份和专业范围的限定词，只改其余有依据的描述；保留其他路径。** 这是缩小语义改写范围，不是一律禁止改写或减少文本长度。

预期区别是改写后的查询保留这些限定、错范围结果减少且仍能找到目标。若后续执行显示固定方式过严而屏蔽必要的合法同义表达，就修订认识为需要保持含义而非该字面形式，再设计条件化替代；不能为了保持旧规则牺牲目标。若仅有一个整包总分或根本无法确定哪些词承担范围，不推出此固定规则，也不按任务 ID 列例外。扩展到其他限定词需要相应依据，不能因本例未见副作用就自动推广。

**关联分支：让响应改变去重与恢复的共同判定。** 假设历史轨迹表明表面不同的表达会进入同一公开路径，且某联合候选把“请求已发起”记作已覆盖，暂时故障后因去重而丢失恢复机会；相关工具语义与调用记录可核对。Memory 保留共享路径及恢复被阻断的联合认识，不将全部损失归给某个独立方向。规则 C 将“已确认无效”的抽象要求组织为：**先区分有效结果与未完成的暂时故障；只有满足相同对象、约束及有效条件的已完成查询才参与覆盖复用，故障不按已覆盖跳过；改写、路径选择与恢复共用这一判定。** 这改变实际执行条件和顺序，不能仅追加“注意保留恢复”。

预期区别是等价路径不因换表达被重复探索，同时暂时故障仍能按预算恢复。若后续同一对象但查询范围已改变时，旧空结果仍阻断了新查询，首先检查：这是违反已写明的“相同约束”要求，还是要求没有交代清楚约束更新与覆盖判断的顺序。仅发现未遵循，不能直接收窄作用认识或重新增加一遍相同要求。沿第 6.5 节的假设，若轨迹和实际条款进一步支持“比较使用的仍是变化前的查询约束”，则修订“当前组织已足以保证比较使用最新约束”的假设，并提出规则 C 的有界新方案：先根据当前任务信息刷新查询约束，再做覆盖复用判断；是否解决问题仍需执行。若已有同样的明确顺序却未遵循，应保留执行／表达等竞争解释，不把它伪装成已学到的新关系。区别条件不可见时，也不能伪造失效判断。仅观察两个修改一起成功，不足以推出上述联合机制。

**组合与冲突走查。** 若三条认识同时适用，采用第 6.3 节的联合要求：条件化索引优先、受约束的改写、按有效查询覆盖且保留恢复。新增索引请求也必须受同一任务范围和故障分类约束；不能给新方向豁免，也不重复引入初稿已有的停止要求。假设“固定某个限定词”与工具要求的合法查询表达发生冲突，应重新判断如何保持范围含义，不能以检索分数投票删除任务约束；没有可落实表达时暂缓相关改写，其余独立路径仍可使用。

| 固定初稿下的输入变化 | 应得到的决策 |
|---|---|
| 三类新作用信息均没有，当前关系也已处理 | 恒等保留；不凭空生成上述三个变换 |
| 只有方向依据适用 | 只改变相应路径优先顺序，不顺带冻结限定词或新增覆盖规则 |
| 只有尺度依据适用 | 只细化改写边界；不能推断索引优先 |
| 只有关联依据适用 | 改写／去重／恢复按共享条件协调，不虚构独立收益 |
| 有整包分数但缺少相关行为证据 | 只保留整包判断和未知，不能补出以上细粒度变换 |
| 支持与反例对应同一可见条件、区别原因未明 | 撤销被反例否定的过强解释；保留可行原案、明确探索或暂缓，不能声称分支已解决冲突 |
| 初稿已完整包含某项处理 | 该项保持，不把重新表述算作新变换 |

这些输入变化检查的是“相同初稿是否对作用认识有选择地响应”，不是性能测试。三个分支都给出了对当前要求的实质差异、未执行边界和反馈修订；它们不证明实际模型会遵循规则或变换后更有效。

#### 6.6.5 本次走查交付与尚未完成部分

真实案例检查了联合认识、未知、恒等保留、过强主张撤回以及能力修复的边界；既有构造案例检查了方向、尺度、组合的非恒等变换，以及新反例如何修订变换依据。两类材料没有混为同一种证据，没有新 Candidate、Memory 版本或采用结果。

该次走查提出的下一项现已形成第 4.5 节及 [最小接口设计](MINIMAL_INTERFACES.md)：只保留完成“适用认识 → 作用偏差 → 实际变换 → 可反驳观察”所需的信息。后续落实这些接口，再选一条证据足够的规则贯通真实闭环。无需先把辅助模块做成全覆盖的通用审查系统，也不能跳过会改变决策的真实输入／语义错误。仍待实现和验证的是可靠的语义匹配与认识粒度、具体序列化、冲突下的有界探索策略，以及与同信息基线比较的实际收益；不冻结阈值、矩阵、全局关系图或每轮调用数量。

## 8. 可选技术路线及数学边界

本节保留仍有价值的探索，但不指定默认方案。应先明确更新表示、作用信息如何获得、怎样变换和落实，再结合公共环境选择技术。编辑维度、行为维度、关系结构、求解器和超参数均未冻结。

### 8.1 非数值或混合的局部更新构造

第 5.3 节已经给出语义更新构造草案：用条件化方案表达方向，用证据支持的局部关系说明影响重叠、冲突和依赖，再按明确规则变换并编排要求。其具体数据结构和模型实现仍是技术选择。也可在部分可靠观测上估计响应，把估计结果与语义判断共同用于构造。

两者都需要落实第 5.2、5.3、5.5 节的学习与变换规则；不能只用“让 LLM 综合考虑方向、尺度和关联”的提示替代这些机制，也不要求因此建立全局编辑图或庞大状态系统。

### 8.2 局部响应模型与残差纠偏

只有当共享编辑表示、行为度量和可靠响应估计成立时，才可考虑原方案的局部建模。令 \(u\) 为初始方案，\(d\) 为可执行编辑，\(r\) 为目标响应，\(\widehat R(d)\) 为预测响应，可探索：

$$
\min_{d\in\mathcal D}
\|\widehat R(d)-r\|_W^2+\lambda D_{\mathrm{edit}}(d,u).
$$

这只是候选目标。若另有明确的局部向量坐标，采用 \(\widehat R(d)\approx Jd\) 和平方欧氏距离，且 \(W\succeq0,\lambda>0\)，忽略离散约束时可得：

$$
d^\star=u+(J^\top WJ+\lambda I)^{-1}J^\top W(r-Ju).
$$

这提供一种解释更新变换的数值方式，但不定义整个 V22。固定步数、投影、候选枚举、正则到零或原始意向，均留作该路线下的后续选择。

保留以下边界：

- 任意自由文本不能直接相减或视为连续坐标；条件范围变化也不天然等于指令的倍数。
- \(J^\top WJ\) 表达代理目标下的响应重叠，不等于原任务 Hessian，也不自动证明非加性交互。
- 未知响应不能填零。正则到原始意向时，零响应估计可能直接保留该意向，不能因此声称稳健。
- 一般非线性模型的局部残差应基于其实际预测，不能无说明地用 \(Ju\) 替代。
- 连续解经投影或文本落实后，不保证仍是原问题的精确最优解。
- 若未来比较恒等、对角、完整预条件器，需区分固定预算的更新过程与对同一目标的精确求解；不能把相同目标的最优解变化归因于优化器。

上述公式是标准代理建模，不是创新点。其适用性、成本和必要性仍需与更简单的构造方法比较。

## 10. 后续验证要回答什么

以下包含当前机制问题与后续方法评价问题，不是已经冻结的测试矩阵、运行数量或正式配置。当前 08 优先验证一条完整的持续更新主线，移除 Direct，也不另做旧任务回归验证或 Selection／Test；具体任务、预算和停点以两轮协议为准。

后续若要证明方法相对优势，再考虑普通当前诊断、直接历史辅助编辑和完整预条件化更新的对照。届时需尽可能匹配模型、可用任务、反馈权限、历史内容与总预算，并允许强基线保留其关键能力；这些对照不是当前 08 必须同时建设的分支。

在代表性机制案例中，固定当前 Parent 和初步修订，检查作用认识如何改变实际更新；通过执行比较确认这种变化是否合理。持续实验再允许各方法形成自己的历史，区分单次变换作用与长期状态积累的收益。

| 维度 | 需要区分的解释 |
|---|---|
| 方向 | 修复策略改变是否有用，还是只增加理由文本 |
| 尺度 | 行为覆盖调整是否减少干扰，还是仅缩小文本预算 |
| 关联 | 协调更新是否优于独立生成后拼接，还是只增加候选数量 |
| 历史 | 响应认识的积累是否优于直接读取相同历史；空历史时机制是否仍可运行 |
| 反馈学习 | 新执行是否修正错误作用认识，并改变后续更新 |
| 效率 | 收益是否来自额外诊断、模型调用、搜索或回放 |

模块或维度消融根据实际采用的技术设计，不预先限定为矩阵消融。只选择信息性强的局部或组合比较，不要求每轮运行所有候选和所有编辑子集。

评价应同时考虑原生任务表现、目标行为改善、有效行为保留、下一批首次任务与旧任务新实例表现、更新活跃程度及实际成本。行为解释和文本 diff 只能辅助理解，不能替代原生任务评价。

所有探测、历史构建、失败调用和回放计入预算。训练、开发和最终测试按所选环境划分；需要重复运行时记录随机性，不把不同初始状态的结果差直接当作编辑效应。

| 第三步：Fusion／Compiler | 紧凑路径已实现要求原→新变更、来源继承、观察去向、程序装配与一次有界上游返工；允许有依据的恒等，具体运行不能被预先宣称为非恒等或有收益 |
| 第四步：Replay 与 Memory | 紧凑路径已实现稀疏发现、未决问题、认识增量及来源绑定，操作内认识可被后续 Fusion 消费；结构核验不能证明认识正确。追加比较未实现；08 已完成真实两轮，第二轮通过独立Memory恢复发布；结构通过不证明全部语义正确 |
| 第五步：跨轮闭环 | 已形成轮初状态、交接时序、正常与失败分支及预算约定；08 已接通真实 Parent／Memory 继承、不可变发布和单主线两轮运行器，现有327项离线测试通过；真实两轮含明确恢复已发布，历史预条件化的独立收益仍未证明 |
| 当前收敛：最小更新规则 | 第 5.3.4 节将作用认识修订与 D／S／C 变换配对；紧凑实现用条件化要求增量承载这些判断，不用字段数量或强制变更证明规则有效 |
| 当前收敛：最小共享表示与接口 | 已新增 compact_learning、compact_update、compact_cycle 及测试、计划和独立真实验证；旧 v0／v1 协议保持原样，代码、实际产物和语义验收分别记录 |

第 5.1、5.4、5.6 节及第 6.1 节保留第二步机制与原样传递案例。第 5.3 节及第 6.3 节给出第三步变换与对照推演。第 5.2、5.5 节及第 6.4 节补全第四步的观察、学习和复用。第 5.7、6.5 节贯通第五步的跨轮流程。第 4.3 节的调用与成本约束适用于所有步骤。

### 12.2 第三步交付怎样检查

第三步采用有证据约束的语义更新构造：在一份工作方案上直接调整策略、作用范围和关系，形成 Editor 可落实的要求。模型负责适用性与作用判断、语义变换、联合编排及边界检查；程序适合负责版本、来源、显式关系和实际 diff 检查。两者均不构成效果证明。

| 检查点 | 草案给出的具体答案 |
|---|---|
| 为什么需要 Fusion | 消费会改变当前方案的作用信息，处理尚未解决的共同影响；已解决的诊断不重复重做 |
| 什么信息可以影响更新 | 对齐实际编辑、Parent、条件、响应来源、归因范围与反例；不适用和未知分别保留 |
| 怎样改变方案 | 给出保留、方向替换、尺度调整、关联协调及撤回的触发依据与行为要求，不能只附历史或分数 |
| 多个方向怎样共同落实 | 按受影响行为检查局部关系，保持目标覆盖、前置条件、分支与配套要求，避免独立编辑后盲目拼接 |
| Compiler 怎样参与构造 | 联合组织条件与依赖、绑定相关条款和原方案去向；语义编排复用 Fusion 调用，程序核对显式结构 |
| 异常时怎样处理 | 目标与解释问题返回 Diagnosis，策略与范围偏离返回要求形成环节，缺证据或无法协调时有限暂缓 |
| 如何控制成本 | 一份工作方案、共享证据装配、必要时局部补读、无重复 Review 的常规路径，以及总成本记录 |
| 怎样避免纸面自证 | 同一初稿在不同适用证据下允许变化或不变，预先记录反驳条件，实际效果留待执行比较 |

初步方案必须认真形成，不能刻意弱化 Diagnosis 以制造变换收益。第三步交付是具体机制草案，不能视为经过证明的预条件器。

### 12.3 第四步交付怎样检查

| 检查点 | 草案给出的具体答案 |
|---|---|
| Replay 测试的是什么 | 精确实际 Candidate 与 diff，绑定执行前要求和预期；未执行的初稿不冒充已测对照 |
| 怎样获得可用观察 | 选择目标与保留行为范围，核对参考执行可比性，分别观察落实、机会、行为、响应和原生结果 |
| 怎样处理未触发与失败 | 区分外部条件未出现、Candidate 改变路径、未遵循、工具／基础设施问题及反馈缺失，不统一记为无效 |
| 什么时候进一步比较 | 未知会改变重要决策、存在有效可比方案且预算允许；优先已有证据，追加后仍可保留未知 |
| 怎样修订认识 | 根据实际来源补充、限定、拆分、替换或保留冲突；事实与历次解释不被覆盖 |
| 怎样保留方向与关联 | 认识粒度不细于证据；无法隔离时保留编辑组、局部线索和依赖，不分摊整包结果 |
| 怎样在下一轮复用 | 按目标行为、策略、条件和关系读取，连同关键反例与 Parent 依赖交给 Fusion；适用性再次核对 |
| 三项历史目标如何兑现 | 被拒候选可保留局部方向线索，已采用方案照常接受反例，重试必须回应失败限制 |
| Gate 和学习有什么区别 | Gate 决定版本采用；允许学习的事实支持认识修订，最终测试不进入这条反馈链 |
| 怎样保持轻量 | 一次相关后处理可共同完成观察解释和 Memory 增量，只维护受影响记录，不固定增加逐编辑回放或多个分析 Agent |

完成标准是能追溯“预期—实际编辑—执行观察—认识修订—后续变换依据”。现有文档具体到了操作、条件和停点，但来源验证不等于语义正确，构造推演不等于真实跨轮效果。V20/V21 已有证据学习和历史保留能力继续作为基础，不作为本步新贡献。

### 12.4 第五步交付怎样检查

第五步以第 5.7 节的跨轮协议和第 6.5 节的连续三轮走查，将已有模块连接到明确的下一轮入口。正常流程、必要分支、调用组织及恢复均已有具体约定；这表示机制设计草案已经贯通，不表示运行器或持续效果已验证。

| 检查点 | 本步给出的具体答案 |
|---|---|
| 一轮从哪里开始 | 读取最后已发布的 Skill／Memory，绑定任务、当前证据、执行与采用协议及剩余预算 |
| Skill 与 Memory 是否必须同时改变 | 分别决定；拒绝 Candidate 仍可发布新认识，无候选时也可处理 Parent 新观察 |
| 当前信息何时能用 | 当前 Parent 新观察可立即参与诊断和适用性判断；执行后反馈不倒写初稿，轮末修订认识 |
| 执行前后怎样返工 | 执行前有界局部反馈；执行后主候选版本不覆盖，实质修改常规进入下一轮，比较变体单独留存 |
| 何时进入下一轮 | Gate 或明确无候选／未获资格的处置、认识处理及来源检查完成后，统一发布状态 |
| 无修改、未知与错误怎样区分 | 合法不变或有来源的未知可以结算；技术失败保留旧入口和待完成材料，停止新轮构造 |
| 中断怎样恢复 | 先判断发布是否完成，再复用可验证产物、补齐欠缺步骤；不重复证据、版本切换或首次任务计数 |
| 调用和预算怎样约束 | 四段语义工作可跳过、合并或按需拆分；所有补读、比较、维护及重试累计，恢复与换轮不刷新总预算 |
| 学习怎样实际作用于后续修改 | 三轮走查对应历史反例、条件化认识、联合要求与实际 diff；允许初稿已经合适时不变 |
| 这些约定证明了什么 | 可检查设计中的版本、时序与分支一致性；不能替代真实模型、原生评价或机制对照 |

第五步没有另增归因、调度、总结或审批 Agent，也不把统一发布与恢复作为方法新贡献。创新假设仍是作用认识能否改善实际方向、尺度和组合，并带来同等条件下的执行收益。

### 12.5 机制草案贯通后，尚待确定什么

[环境入口](ENVIRONMENT_INTERFACE.md)、[无历史更新](NO_HISTORY_ROUND.md)和旧 [Editor／Replay](BEHAVIOR_FEEDBACK.md)为实现基础；后续按[紧凑接口](MINIMAL_INTERFACES.md)新增 [COMPACT_CYCLE](COMPACT_CYCLE.md)。最小运行器在既有 No Skill Parent 上学习历史 Candidate 的作用认识，独立形成当前初稿，交由 Fusion／Editor 构造后续更新，再执行并修订认识。旧 Candidate 未采用，不能把这条操作内链路称为已部署 Skill 的连续发布。

在此基础上，[有效认识与固定初稿消费](FIXED_CONSUMPTION.md) 实现了具体的收敛步骤：以有来源的退役操作隔离错误限制，保留未知及原始证据；Fusion 在一次响应内完成“对齐具体决定—检查初稿已有覆盖—构造有界方向／尺度／关联变换—保留可反驳观察”。不新增逐维自证字段，不因单项因果未识别而一律禁止探索，也不强迫非恒等。独立入口冻结完整初稿与当前证据，比较空 Memory 和有效 Memory 的实际构造；完整共同目标仍被冻结，需要改目标时允许返回 Diagnosis。调用失败、真实要求变化及其边界见[本阶段报告](../../../experiments/methods/v22/04_fixed_consumption/reports/REPORT.md)，没有新增环境执行或采用。

后续[通用条件化规则](CONDITIONAL_TRIAL.md)将旧案例暴露的问题收敛为更新决策约束：Diagnosis 区分共同目标与实现策略；Fusion 仅在历史响应支持的可见条件下放宽义务，同时保留其他状态下已知有效的完成／恢复路径，并协调相关要求。保留紧凑输出，不增加逐维自证字段。相同完整 Memory、当前证据与认真初稿分别进入普通历史辅助 proposal 和显式预条件化 proposal，再由同一个 Editor 落实。这是同信息、同结构、同调用上限的提示策略对照，不能预先称为算法优势。

该协议预先选定三个未用 Train 任务与覆盖六类的六个未用 Selection 任务；候选、要求、认识、代码和观察问题在 Selection 前冻结。Selection 不回流本轮更新器，也不用于修改后重跑。旧照明／清洁只用于理解通用规则，不再充当新验证的主要样本。实际构造、失败、费用与独立执行见[本阶段报告](../../../experiments/methods/v22/05_conditional_trial/reports/REPORT.md)。

2026-10-15 按研究范围重新收敛：暂不扩大 Diagnosis 去研究效率优化、成功程序提炼及复杂更新价值判断，优先从已有 No Skill 失败的 Train 任务继续同信息对照。06 选择旧原生检查中两项完整失败，分别通过当前入口复跑一次；不根据复跑结果换题，Selection 仍使用先前预选且未执行的六项，不按失败筛选。两条新 Train 均在 50 步上限结束，形成认真初稿与两侧原始候选；Direct 根据当前证据改变要求，Conditioned 恒等，两者均未引用 Memory 作为变更依据。该停点需要如实区分“历史已提供”和“历史改变了更新”，不能强迫非恒等来制造方法贡献。构造的定位错误、评价前单独声明的零调用格式处理、原文冻结及独立执行结果见[失败 Train 对照报告](../../../experiments/methods/v22/06_failure_trial/reports/REPORT.md)。本次不修改核心语义提示或增加模块字段；研究中心仍是作用认识如何改变实际决定。

06 最终完成 18 次 Selection 尝试：Direct 成功 4/6，Conditioned 3/6；No Skill 两项成功、两项失败、两次连接中断为未知。双物体任务出现 Direct 成功而 Conditioned 失败；加热成功执行又违反了两份文本中的绝对来源禁令。这些现象要求分别核对初稿、要求变换、Editor 实现和实际行为，不能把局部成功或总分当作预条件化作用证据。本批评价没有验证核心学习假设，不据此采用候选或回流更新器。

2026-10-15 后续调整以 [07 计划](../../../experiments/methods/v22/07_train_response/config/plan.json)为准：暂不扩展模块，先以 06 两份原文不变的 Candidate 各一次 Replay 原 `train:0021`、`train:0034`；根据真实 Parent／Candidate 行为分别学习带条件、限制、未知和 Candidate 来源的联合响应，再以同一新 Memory 支持下一轮同信息更新。原照明／清洁认识继续保留，但不存在经过核对的适用关系时不能强制迁移。Keep 不能直接判为机制失效；非恒等也不能直接判为收益。

下一轮预先固定三个未用 Train 实例做一次 No Skill 筛查，只将其中完整失败交给独立 Diagnosis；成功和技术中断保留，不扩展效率提炼、不换题补足失败。两侧候选冻结后只在这些失败 Train Replay，检验目标行为、范围和干扰。已有 Selection／Test 不进入此次构造或学习，也不新增泛化评价。两次分臂学习和共享 Parent 不等于独立重复实验；完整候选效果不得拆成未经验证的单条规则因果贡献。本轮仍以 No Skill 为下一轮 Parent，验证的是更新器所学响应的跨任务复用，尚非已采用 Skill 的连续发布。实际结果另见 [07 报告](../../../experiments/methods/v22/07_train_response/reports/REPORT.md)。

07 已完成 11 次新 Train 执行与 7 次语义调用：原 CD 的 Conditioned 修复、下一轮 Bread 的 Direct 修复构成具体 Skill 更新正例。五条真实响应进入后续两侧相同信息；Direct 据历史增加的目的地检查没有实际触发，Conditioned 识别短窗口限制后 Keep，仅增加观察问题，因此历史预条件化收益仍未验证。07 结束时提出研究“相关历史已表明原策略不足时，保留还是提出有界可执行替代策略”的决定条件，并区分历史支持与待测探索；不因该轮结果扩张模块、强迫非恒等或继续调同一案例到成功。

当前优先级进一步调整为[08 统一算法与两轮协议](GROUPED_TWO_ROUND_PROTOCOL.md)：先用共同决策结构贯穿紧凑要求、Effect、变换与反馈，再补齐真实 Parent 继承和 Replay → Gate → Memory 的连续入口。首步已完成两轮任务、预算、Gate、失败出口与固定分类 Prompt 的设计，随后修正整体成功率晋级、轮间任务不重复和单一主线；当前已补齐共享接口、实际 Parent 继承与运行器，真实两轮已通过明确恢复完成共同发布，原分类、Fusion和Memory失败保留；上述局部更新问题纳入该框架研究，不另建围绕单案例的调优流程。

- **认识的事实可靠性。** 保留完整可见输入仍可能被模型漏读；来源可解析不等于结论有支持。将能精确计算的事实交给程序，不通过增加自证字段解决语义问题。
- **更新规则的实际使用。** 分别核对历史被提供、具体要求变更引用历史、Candidate 落实和行为差异。允许保持，但不能将每次保持都算作历史学习贡献；联合观察无需独立因果证明才能提出有边界的探索。
- **最小表示与调用成本。** 当前本地协议和一次可选构造返工只是实现起点。认识读取、持久化、未知处理和传输恢复仍需结合真实问题改进，不扩张为全维检查系统。
- **选择与持续发布。** 已有预声明、冻结、隔离且不采用候选的小规模 Selection 入口；它不等于正式 Gate。发布指标、持续状态发布与跨轮恢复仍待接入。
- **机制与持续效果。** 当前先按 08 核对跨轮真实继承、历史作用认识、具体更新决定及执行反馈，完整记录失败与不变。后续若开展第 10 节的比较，再区分单次构造与跨轮积累并匹配信息／预算；当前单一主线的小样本不能替代相对优势或泛化证据。

数值响应模型、连续坐标、层级更新和具体超参数仍为候选。本次规则规定作用知识怎样约束决策，尚未解决所有语义匹配、迁移和探索取舍。若真实变换只来自当前诊断或静态能力修复，或者只得到不同措辞、更多拒绝和更长解释，就还没有展示跨轮作用学习的贡献。完整更新器与机制实验仍待开展。

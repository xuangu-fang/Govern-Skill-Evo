# v27.16 · 用局部提案留下的重复失败形成新的修改

本版沿用 v27.15 的四模块接口。唯一变化位于 [Diagnosis](prompts/diagnosis.md) 对重复失败的处理。v27.15 要求在提出改动后说明哪些错误仍被允许。v27.16 进一步要求回到这些余下的任务，检查它们是否卡在同一个作答决定上。若训练记录支持另一项可复用的动作，就将两个提案放回相同的错题和相关正确题，说明两者会在哪些题上产生不同的指令，再提交有依据的修改。部分改善和证据不足都是有效结论。

作答动作必须依赖新题上可用的信息。用参考答案审查历史后果，不能把排除一个错误当成已经选对。两种草案可以在原有的 reason 中比较，各条独立更新沿用原 JSON 协议。Preconditioner、Editor 和 Replay 采用 v27.15 的原文。

## 冻结输入对照

以 v27.14 已保存的 R02 Parent 和 11 道父版作答为共同输入，分别调用 v27.15 和 v27.16 的 Diagnosis。比较六道原先已处在旧规则范围内的漏选题，同时核对两道范围外漏选和相关正确样例。评价具体提案的适用范围、旧错误是否仍可提交、是否需要参考答案才能执行。该历史对照用于检验提案行为，实际答对题数需另外执行 Actor 才能测量。[回放程序](../../../experiments/analysis/v27_15_vs_v27_16_r02_frozen/replay.py) · [结果对照](../../../experiments/analysis/v27_15_vs_v27_16_r02_frozen/结果对照.md)

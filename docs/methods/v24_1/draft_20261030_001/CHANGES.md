# v24.1 四模块逐项差异说明

四模块共同保持“观察、解释、拟议改变、实际改变、经验结论”的区别。这是判断关系，不是新增字段、强制分析顺序或独立模块。Diagnosis 可以探索，Preconditioner 可以发展方案，Editor 保留方案含义，Replay 保留观察及解释的边界。

当前版本已完成第二次审阅；[复审说明](SECOND_REVIEW.md)记录探索边界与去重修订，含 RD、RP、RR 编号。下文 D、P、E、R 编号记录最初迁移意图，完整逐行 diff 已更新为当前草案对 v24 的差异。

下文以实际使用的 v24 反馈版 Prompt 为基线。条目编号仅供人工审阅；未加入模型 Prompt。v25 参考为 Diagnosis v5、Preconditioner v7、Editor v2、Replay v4，不采用已退回实验状态的 Preconditioner v8。

## Diagnosis

完整文本：[草案](prompts/diagnosis.md) · [基线](baseline/diagnosis.md) · [逐行 diff](diffs/diagnosis.diff)。

| 编号与位置 | v24 原有设计 | 草案处理 | 理由与保留空间 |
| --- | --- | --- | --- |
| D1 开头职责 | 一批形成一个 Plan，不要求每个 Group 一条 Update | 补充允许多个合理 Updates，不设固定数量、不按失败任务凑数量 | 借鉴 v25 的数量边界；保留多项修复，不把减少 Updates 当成方法目标 |
| D2 §2 已有规则与行为 | 区分未覆盖、未遵循、条件不可判断、遵循但未解决；证据不足时不强迫因果解释 | 替换最后的因果说明：合理修复假设不必先证实原因或效果；连接观察、Parent 和行为改变，说明不确定性 | 借鉴 v25 的探索许可；缺事实只在阻止合理选择时阻止该方向，不枚举推测性解释 |
| D3 §3 Update 组织 | 一个 Update 对应连贯问题，必要依赖放在一起 | 合并为明确问题、必要依赖与保护边界；独立修复分开；不顺带增加最佳实践；通过任务要求和行为关系泛化 | 允许跨物体、跨任务复用前置关系；不把某处找到目标变成普遍搜索顺序；不设案例数量门槛 |
| D4 §3 Update 正文 | 策略、范围、强度、依赖和保护要求进入 text | 补充 reason 或 Check 中的限定不能约束 Editor 收到的指令 | 强化跨模块交接，不增加字段；这在 Preconditioner 已有，Diagnosis 同样需要说明 |
| D5 §3 恢复与进展 | 恢复应对应具体问题，必要时才重访有效工作 | 替换为从已改变的环境状态继续；主策略和替代策略都保留任务要求；保护进展但允许解决阻塞所需的回退 | 针对 ALFWorld 的状态延续；不迁移 SpreadsheetBench 的从原文件重新开始，不将保护进展变成禁止回退 |
| D6 §3 成功与 Plan 结束检查 | 保留成功行为，允许关联 Updates，不故意削弱初始 Plan | 明确认可环境成功是当前实例成功，但不证明每个前置动作必要；合并整体重叠、冲突、依赖检查 | 借鉴 v25 的跨项一致性，不把成功行为自动写为新规则，也不依赖 Preconditioner 补全无依据内容 |
| D7 §4 Checks | 问预期响应、恢复效果和保护进展，不要求覆盖矩阵 | 替换为区分采用、目标问题变化、有效行为保持；重要假设用有用的 Check 支持或挑战；局部动作成功与任务完成分开 | 不强制逐条 Check；Checks 可空或覆盖多个 Updates；减少步数和更多观察都不自动算改善 |
| D8 §4 决策 | revise、no_change、need_evidence 三种决策 | 替换为 revise、no_change；无合理修订时说明原因与关键缺失事实；无更新不代表 Skill 无问题 | 与 v25 对齐决策语义，并明确 ALFWorld 中的解释；一个方向受阻不抹掉其他独立修复 |
| D9 §5 输出说明 | 三种 decision，reason 简述证据 | decision 只列两种；reason 连接更新与问题，区分事实、假设、不确定性和重要未解决方向 | 唯一拟变更的外部结构契约是 decision 枚举；reason 仍是字符串，没有增加分析对象 |

保留 Parent、command_sets、runs、grouping 输入；不加入历史 Memory。保留原证据引用、Group 与成员证据关系、多行 Update、`goal/updates/checks` 和格式错误反馈。最近两组历史、时间先后、命令候选与合法性、缺失列表不等于空列表等边界保持；重复的可见性提醒已合并。额外观察采用有依据的信息价值与成本判断，不要求证明不可或缺。

草案中 `revise` 的 JSON 示例只说明结构，沿用原例，不是基于真实任务生成的修订。当前 v24 校验仍接受旧枚举；真正实施时必须同步新版本校验与调度，旧结果不能直接改标为新版本。

## Preconditioner

完整文本：[草案](prompts/preconditioner.md) · [基线](baseline/preconditioner.md) · [逐行 diff](diffs/preconditioner.diff)。

现有 v24 已经具备完整 KEEP、局部修改、方向发展、强度判断、进展保护和整体一致性。本草案不把这些能力记作新增。初稿局部替换四处，复审进一步合并历史作用与正文条件的重复说明。

| 编号与位置 | v24 原有设计 | 草案处理 | 理由与保留空间 |
| --- | --- | --- | --- |
| P1 §2 历史与响应 | 整体成功不证明每条规则有效，联合修改限制归因 | 局部替换，先承认环境成功是实例成功，再限制它对动作必要性和规则普遍性的支持 | 不照搬表格评分覆盖不全的语境，不以谨慎为由否认 ALFWorld 成功 |
| P2 §3 Scope | 可收窄、放宽、强化或换条件；注意强度与可见性 | 替换该段：按任务要求、前置条件和行为关系泛化；无案例数量门槛；明确触发、强度、阶段、前置与完成条件的变化是实质选择 | 原紧邻段落已禁止允许变优先、优先变强制，因此不重复堆叠；能力保留需进入具体调整 |
| P3 §4 探索 Checks | 看原问题与成本，不只看遵循；无逐项配额 | 局部替换，加入有效行为保持，以及重要时区分有依据的竞争解释 | 保留探索，允许空 Checks，不要求证明每条有效，也不增加审查阶段 |
| P4 §4 整体一致性结尾 | 条件写入正文，保护任务与有效进展，遵守可见状态 | 替换该段：按当前状态下替代/恢复策略会允许什么行为来判断；保留任务要求和必要回退；局部操作成功不等于完成 | 借鉴 v25 对替代结果的判断，改写为 ALFWorld 状态与阶段；不加入公式、文件有效性或评分工具要求 |

保持原职责：历史可以纠错，也可以将合理方案发展为更有前景的方案；当前具体缺陷不必有 Memory 才能修正。保持 D/S/C 作为互相影响的判断维度，不变成三个独立步骤或代理。

整个 KEEP 判断、对反例的具体回应、无历史不自动 KEEP、效果未验证不自动撤回、部分修改保留有效要求、跨 Update 协调均不变。未来操作不应仅因“谨慎”就收窄方案，也不应为显示使用了 Memory 而改动足够好的要求。

§5 补丁协议、§6 引用和 Checks 契约、§7 输出与示例逐字保留。仍使用反引号内的 `M1`、`P1:1`、`R1/diff` 等原引用，不引入 `Memory:` 或 `Evidence:`。Grouping 仍不进入模型输入；历史原始轨迹仍不可检索。

此模块原文中的“no full-text fallback”是补丁执行机制，不是禁止 Actor 的行为替代策略；该机制保持不变。Preconditioner 原本没有合法的 `need_evidence` 输出，其相关说明也保留，不应与 Diagnosis 枚举变化混淆。

### 行动机会的比较边界

假设 Parent 找到目标并完成后续操作，而 Candidate 改变搜索行为后耗尽预算，未进入后续阶段。该情境只供解释设计，不是从现有实验抽取的事实。

- 可以确认的内容取决于轨迹：双方到了哪里、执行了什么、何时终止、哪一方进入后续阶段。
- Candidate 未进入后续阶段，不能据此宣称它在该阶段的策略无效。
- 需要关注的前序差异不能因“后续规则未触发”被略去；可以分析搜索如何延迟机会，并结合证据形成解释。
- 单独是哪条 Skill 修改造成差异、另一条未执行路线是否会成功，仍需相应依据；多个同时变化和采样差异可能限制归因。

### 没有迁移的表格专用内容

不加入工作表、单元格、公式缓存、程序分支实际执行推断、从原始输入重启、提交文件即结束、代码重复表示、共享初始消息或附加比较输出。程序和输入能支持的条件机制分析，不自动成为 ALFWorld 轨迹的证据能力。

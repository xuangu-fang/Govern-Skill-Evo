# v29.7 Preconditioner 设计稿

本版研究一个问题。对同一份 Original，Preconditioner 能否根据 Parent 找到确有必要的行为变化，再根据当前证据和 Memory 限定这个变化在什么条件下适用？期望的收益是定位题能保留有效步骤，答案范围题能避免错误截断或多答。成功率是待验证的结果。

基线取自新方案 v29.6 的正式训练归档，包含已适配的 DocVQA 指南、`parent_memory_delta_v1` 和配套 Editor。归档的四份 Prompt 与当前 v29.6 设计、运行时副本逐字节一致。v29.7 仅有一个实验变量，即 Preconditioner 的两处职责文字。独立训练与最终 Test 入口已完成离线验收，正式实验尚未启动。[接入与离线验收](IMPLEMENTATION.md)

## 一、D/S 如何改变提案

| 位置 | v29.6 的判断 | v29.7 的具体判断 |
|---|---|---|
| D，方向 | 识别值得促进、改变或停止的行为，逐项审查附带决定 | 找出答案与问题之间应满足的关系，再与 Parent 比较。若是定位问题，写明如何用题目限定在候选对象之间作选择。若只涉及表示差异，只修正相关表示。 |
| S，范围 | 用当前证据限定适用条件和强度，防止将局部改善推广为普遍编码或截断 | 对删减、补全、格式化或提高优先级的提案，找出 Actor 可见的区分线索：什么情况下这样做满足题意，什么情况下会删去所问内容或多答？将证据支持的触发条件和动作写入有效 text。 |

两者配合解决方向相反的错误。若证据支持“同时匹配两个限定”，就允许该动作适用于多种布局，具体位置由 Actor 根据文档判断。若证据只支持“当前问题明确只要复合字段的一项”，则将删减动作限定在这个条件下。版式、顺序、符号或位置本身就是题目明确要求时，仍然可以写成具体规则。

**候选 Effective text 示例，仅用于审阅。** 对已经提出“按时期和字段定位金额”的 Original，可考虑：“当问题同时指定时期与字段时，用两项限定定位同一条目，再读取与之绑定的值。按文档实际布局确定绑定关系；若该位置为零，保留零值。”这个修改有可执行的动作，也允许时期出现在行、列或标签中。假如 Parent 已充分表达这一动作且缺少受支持的进一步变化，处理结果可以是 WITHDRAW。

## 二、Memory 怎样决定可迁移的范围

v29.6 已要求按机制比较历史。v29.7 进一步指定比较的依据：**历史 Update 要求做什么，Knowledge 实际观察到什么变化，当前题有哪些可见线索，使同一动作在这里也适用？**

| 当前与历史的关系 | 对 Update 的影响 |
|---|---|
| 同一决策线索得到支持 | 在历史支持的范围内复用动作；先核对 Parent 是否已覆盖。 |
| 线索仅部分重合 | 迁移有依据的部分。把新的适用范围、强度或优先级交回当前证据判断。 |
| 只有答案都变短或得分都提高 | 将相似结果作为待考虑的解释。单靠这种相似性不足以扩大提案。 |
| 关键线索取决于未提供的图像 | 可交付由 Actor 依据问题与文档执行的条件规则。reason 区分“Actor 可检查此条件”与“历史或当前样本确实满足它”。 |
| 有相关反例、混合结果或缺少适用历史 | 按条件保留局部收益、收窄或撤回风险方向；历史没有可用支持时，用 Parent 与当前证据独立判断。 |

沿用 `{target, action, text, reason}`。Original 本身已满足上述判断则 KEEP；仍有支持的增量、但关系、触发条件或历史迁移边界需要调整则 REPLACE；去掉无依据的假设后已无有意义的增量则 WITHDRAW。Editor 只看到有效 text，需要它落实的条件必须出现在 text 中。C 段继续负责必要的旧规则处理、有效分支与多 Update 协调。没有额外输出字段、决策配额或推理阶段。

## 三、设计依据

下表记录 v29.6 训练中促成此次设计的四个案例。原图用于事后分析；训练时 Preconditioner 使用获准的文本投影、Parent、Original 与 Memory。

| v29.6 训练案例 | 观察到的问题 | 对 v29.7 设计的启示 |
|---|---|---|
| R08/u2，季度金额 | v29.6 的修订指定“季度列”，训练原图的季度实际在行标签上 | 保留同时匹配时期与字段的动作，避免把未经证实的轴写死。 |
| R06/u2，职位 | 问题只请求复合字段中的职位。一次去掉机构后得分提高，对通用职位截断的支持有限 | 判断 Original 的“独立 affiliation”条件是否真正区分被问成分与完整条目。必要时收窄，并保护完整字段原本合理的分支。 |
| R07/u2，职位经验用于品牌 | Memory 的局部收益来自职位与机构的分离；当前修正要区分品牌和描述文字 | 说明当前问题为何支持同一种分离动作。若只共享“答案更短”，品牌边界和优先级应由当前证据决定。 |
| R11/u3，发票单位 | Parent 已有表格单位规则；Memory 提供历史局部收益，得分变化本身不能定位符号来自哪里 | 保留有依据的合并能力，同时核对是否确需扩展到另一类字段。若没有剩余增量，允许撤回；若有独立支持，把扩展条件写进 text。 |

## 四、正式实验安排

后续正式运行使用 [v29.7 配置](../../../experiments/configs/v29_7_docvqa_optimization160.json)，按新方案 v29.6 的参数直接开展一次完整实验。

1. **正式训练。** 从同一初始 Skill 和空 Memory 开始，按原顺序完成 160 道优化题、11 批训练。归档实际加载的 Prompt、配置和最终选中的 Skill。
2. **最终 Test。** 训练成功完成后，用该次训练导出的最终 Skill 运行完整的 374 题 Test。
3. **结果比较。** 以已完成的新方案 v29.6 为基线，比较正确题数、Hard、ANLS 及逐题新增正确和回退，并结合本次训练轨迹解释差异。该 Test 已用于失效诊断，结果按回归比较解读。

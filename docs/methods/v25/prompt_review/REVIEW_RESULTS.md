## 2. 两题贯穿案例

这是一组缩小的**人工构造**案例，不来自优化集或 Test，也不是正式 15 题批次。

- P1 输入第一行是说明，第二行是表头，第三、四行是数据。假定 Parent 固定循环从第二行到 `max_row` 之前，并跳过非数字行：输出文件有效，但漏掉最后一个数据行。构造评分为 1/2 个目标单元格正确，hard=0。
- P2 输入第一行是表头，第二行是数据，第三行是尾注。同一 Parent 程序恰好完成目标，构造评分为 1/1，hard=1。这是必须保留的边界，不能只看失败题就规定“总从第三行开始”。
- 假定 Effective Plan 要求根据任务表头确定起点、包含末尾数据行、保留说明和尾注。示例 Editor 补丁只替换相关 Skill 规则；构造 Q1/Q2 均正确。它们使用原始输入及独立消息，没有 Parent 程序或评分反馈。

| 模块 | 具体材料 | 走读结果 |
|---|---|---|
| Actor | [首次请求](actor_initial_messages.json)、[运行异常后请求](actor_retry_messages.json) | 使用原始初始 Skill。第二份消息只追加一次 KeyError 和剩余 29 轮，不含事后错误坐标 |
| Grouping | [输入／示例输出](grouping_example.json) | 两个任务围绕数据起止边界比较，保留说明行和尾注差异，不输出根因或更新 |
| Diagnosis | [输入／示例输出](diagnosis_example.json) | 同时引用 P1 失败和 P2 保留条件，形成一个含完整条件的 Update；不读取 Memory，不要求等评分后修复 |
| Preconditioner | [输入／示例输出](preconditioner_example.json) | 空 Memory 下整体 KEEP 合法；理由不冒充历史学习收益；继续 Editor |
| Editor | [输入／示例输出](editor_example.json) | 精确补丁只实现 Effective Plan；保留不相关段落；未生成题目程序代替 Skill |
| Replay | [输入／示例输出](replay_example.json) | 同时看 P1/Q1 改善和 P2/Q2 保留；注明联合修改及两题范围，未推断独立因果效应 |
| Verifier | [输入／示例输出](verifier_example.json) | 对故意植入的“Parent 先看到评分错误坐标”给出 CONFLICT，依据实际请求和评分时间，而非仅因缺证据 |
| Repair | [输入／示例输出](repair_example.json) | 只改授权 Knowledge，纠正评分可见性，保留实际失败事实及来源；不改 Skill，不增加第二次语义核验 |

示例 JSON 的 `illustrative_output` 是人工填写的一个合理输出，不是模型返回值，也不是唯一正确措辞。Verifier／Repair 案例故意加入错误 Knowledge，是用于检查纠错边界的分支，不是假称前面的正常 Replay 生成了该错误。

## 3. 20 个边界案例

完整输入条件与预期在 [boundary_cases.json](boundary_cases.json)。下表为按定稿 Prompt 与方法规则完成的语义走读；程序层尚未实现的路径只检查预期，不标作集成测试通过。

| 案例 | 条件 | 确定的预期与检查结论 |
|---|---|---|
| C01 | 程序异常后修正 | 允许有限运行反馈；保留完整消息；新尝试从原始输入开始。模板一致 |
| C02 | 有效工作簿，评分失败 | Actor 已在评分前结束；不能追加纠错轮次。停止语义一致 |
| C03 | 公式合法但没有缓存，目标值非空 | 不额外重算；评分读取保存值并按空值规则比较；不将缓存问题反馈给 Actor。公式说明一致 |
| C04 | 15 题 hard 均为 10/15，单元格均值从 73.33% 提升至 93.33% | 现有 Gate 纯函数返回 RETAIN；Replay 可以记录局部改善，不能改变接受规则 |
| C05 | Knowledge 声称 Actor 收到评分坐标 | 实际消息与协议明确反驳时 CONFLICT；授权定点修正，不复核所有历史 |
| C06 | 只有程序文本，没有内部执行分支记录 | 合理限定的陈述不能仅因缺少轨迹被判冲突；SUPPORTED 保留有限含义 |
| C07 | 当前有效行为充分且无新更新依据 | Diagnosis no_change；不生成 Candidate、Gate 或 Replay，不强迫修改 |
| C08 | Preconditioner 全 KEEP | 更新仍有效，继续 Editor；不将 KEEP 误判成 no_change |
| C09 | 全部合法撤回 | 无 Effective Plan，Checks 必须有效清空；不启动 Candidate |
| C10 | Editor 空串与 null | 空串是已满足更新，null 是实现阻塞；两个分支不同，不反复采样以改变决定 |
| C11 | P1/Q1 编号相似但 task_id 不同 | 配对构造阶段必须拒绝；不能靠 Prompt 或 Gate 成功数计算补救身份错误 |
| C12 | 仅有历史 Knowledge 引用 | 不展开历史原文、不推导邻近 ID；整条修订时保留仍有效的旧经验 |
| C13 | 总预览恰好 100,000 或 100,001 字符 | 前者通过长度检查，后者请求前报错；不截断后继续 |
| C14 | 3,500 字符错误、已用一轮 | 仅取前 3,000 字符并标记，剩余 29 轮；不附评分结果 |
| C15 | 请求重试、只剩 7 秒、恢复执行 | 重试不加代码轮；进行中操作受剩余时间约束；恢复不重新发放预算；服务中断另记 |
| C16 | 已提交但评分器故障 | 仅补评分，不重启 Actor；未知指标不能记为零凑齐 Gate |
| C17 | 输出可打开但缺少目标表 | 先结束 Actor，再评分计错；评分器发现的缺表不作为运行错误回传 |
| C18 | 完整响应没有代码块 | 消耗代码轮，`executed=false`，不计程序执行；有预算时仅反馈格式错误 |
| C19 | Replay 为空；Repair 想删最后一项 | 空 Replay 合法；删除导致条目结构无效则校验失败，不生成填充经验，不影响其他项 |
| C20 | 优化集／Test、Parent／Candidate 可见性 | 优化任务事后评分用于学习；Test 仅报告；所有 Actor 无评分纠错、无直接 Memory，Candidate 不读 Parent 轨迹 |

# 程序执行与生成请求的独立预算

新训练显式采用 `actor_profile.attempt_budget_policy=program_executions_v1`；缺少该字段的历史配置仍按原 `responses_v1` 语义解释。不得拿新源码恢复旧冻结 campaign。

- 最多 30 次实际程序执行，包括最后成功提交的一次。每次执行仍从原始工作簿开始。
- 生成每份可执行程序最多 6 次 API 请求，包含第一次。网络错误、输出截断、完整响应格式错误共用该额度；只有完成一次实际程序执行后，下一份程序才获得新的 6 次额度。没有 SDK 或外层倍乘重试。
- 网络错误和 `finish_reason=length` 保持输入不变；完整响应的格式错误保留上一输出并附加格式反馈。等待仍为 2 × 请求编号秒。
- 截断响应完整归档为独立证据事件，但 `response_in_history=false`，不加入 Actor 后续请求。连续时间线按该标记逐轮还原；证据 ID 仍按原始响应事件顺序编号。模型响应、执行代码、执行日志、Actor 实际反馈和最终评分保持区分。
- `code_attempts` 统计已启动的程序执行，`program_executions` 统计已保存执行结果的次数；完整轨迹中两者相同。`generation_responses` 统计返回的响应事件，`api_requests` 包含无响应的请求。未知执行结果禁止重跑。
- 六次生成请求耗尽时保存 `status=generation_incomplete`、`termination=generation_budget_exhausted`，不调用评分器、不写成功完成轨迹。所在批次暂停，已开始的其他任务允许保存产物；不跳过该题、不缩小统计分母、不把未完成算作答错。恢复不重置次数，自动监控不能绕过耗尽的预算。
- 30 次实际执行均未提交有效工作簿仍是执行额度耗尽；按既定评分规则记录任务失败。首次有效工作簿提交后终止 Actor，即使最终得分为零也不提供评分纠错反馈。
- 继续关闭整题累计时限（0），保留 API 单次 300 秒、程序单次 600 秒、Actor 输出 32768、并发 4。思考强度及其他 API 参数保持原配置，未额外开展模型配置试验。

V25 与 SkillAdam 使用同一个 Actor。此次只重启正在运行的两组训练，旧目录及修改前源码保留，新目录从原始 initial Skill 开始，不迁移旧结果。No Skill / initial Skill 的旧测试产物仍属于旧预算条件，不能直接当作新规则下的完整对照结果。

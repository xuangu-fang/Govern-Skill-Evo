# Diagnosis v5：修订范围、修复假设与两种决策

2026-10-28，当前 Diagnosis 升级为 `v25_diagnosis_evidence_scoped_updates_v5`。
英文正文位于 [diagnosis.md](prompts/diagnosis.md)，与运行资源逐字同步。
本次没有调用模型、重跑 R05/R06、启动训练或测试集评估。

## 修改范围

| 位置 | 修改 | 解决的问题 |
|---|---|---|
| 开头与 Update 组织 | 一份 Plan 允许多个独立且有依据的 Update，不设数量上限，也不按失败题或分组凑数量 | 不把减少更新数量当成减少规则膨胀的替代方案 |
| 问题识别 | 连接任务要求、实际行为与目标差异；区分语义风险、错误解释、观察与假设 | 不把可疑实现直接说成当前错误的原因 |
| 跨任务比较 | 成功案例支持可行性或假设，迁移时保留匹配、身份、顺序、位置和交付要求的差异 | 不把不同语义任务当作受控对照 |
| Update 文本 | 每条围绕明确问题，保留必要依赖与边界；不附带无依据的归一化、排序或回退 | 限制单条修订扩张，而非限制每轮 Update 数量 |
| Plan 整体检查 | 检查重复、共享条件下的冲突及依赖，合并冗余但保留独立修复 | 避免多项更新互相矛盾或重复 |
| 成功经验与实现 | 成功不自动意味着必须新增规则；更强文字或更多检查不证明能力更可靠 | 区分有效目标与实现可靠性 |
| Checks | 分开观察采用、目标错误变化、保留行为；不从整体改善推断每项有效 | 为尚未确认的修复假设提供检验方向 |
| 决策与 reason | 仅 `revise`、`no_change`；reason 说明依据、假设、不确定性和重要未解决方向 | 保留探索能力，同时统一无可执行修订时的处理 |

去掉重复的“构造一份 Plan”和 Editor 可实施性要求，合并条件可见性表述；把数量、单条范围、
跨项关系和修订策略分别集中表述。执行可见性、原始输入重启、提交即结束、
直接引用、多行 text、公式及 fallback 仍须满足任务要求等边界继续保留。
不新增字段、模块、历史 Memory 输入、额外工具或 Gate 规则。

## 决策规则

- `revise`：至少存在一个有依据且可执行的修订，包括尚未确认原因或效果的合理修复假设。
- `no_change`：当前证据无法形成任何有依据的可执行修订，`plan=null`。若关键事实缺失，
  在 reason 说明缺口；不是因为无法预知效果就弃权。
- 某方向缺少关键事实时，其他独立合理修订仍可进入 Plan；必要依赖不能被省略。
- 当前输出不再接受 `need_evidence`。新模型若返回该标签，按既有输出契约错误处理；
  合法 `no_change` 不因结果不理想而重采样，沿用 Parent/Memory，是否继续下批由原配置决定。
- 调用、格式、输入损坏等技术错误仍单独处理，不能包装成 `no_change`。

reason 承载修订依据与假设；text 承载可实施的条件化行为，不能只把适用边界写在 reason。
结构验证器只核对形状、决策和引用，不声称能判断自然语言因果解释是否准确。

## 对 R05、R06 的预期

这些是审阅目标，不是已运行的新实验结果。

- R05：文本匹配假设与数值边界可以同时提出。没有观察到的文本差异应标为假设，
  不附带已存在的数值解析和容差。公式成功例可证明局部可行性，不能仅因 Parent
  未写该流程便自动扩写；Diagnosis 仍不能引用未提供给它的历史失败。
- R06：锚点与合并可以同时修复。表头锚点保留明确的题目条件，合并聚焦无依据跳过来源。
  完整标识符的语义依据与 H12/H13 的错误解释分开，额外日期排序作为具体竞争解释检查。
  原输入未显示的行值不能凭 prompt 获得。
- 现有训练和测试未隔离每轮 Update 数量的效果，不据此宣称多项更新有害或单项更新更优。

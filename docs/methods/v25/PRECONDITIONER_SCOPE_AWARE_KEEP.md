## 四处局部修改

| 位置 | 替换后的判断标准 | 对应问题 |
|---|---|---|
| §1 事实与不确定性 | 效果未知仍可支持合理修复；证据未确立的前提可以通过允许的协议定位或检查，但不能当成已知事实；已识别的语义区别交给 Scope 判断 | 避免把效果、前提和适用范围的不确定性都当成可直接原样保留的“未验证方案” |
| §4 Explicit Keep | 保留依据须支持整个 Update 当前的范围与强度，而不只支持核心方向或局部成功；只聚焦实质行为扩展和语义区别 | 避免“方向合理／没有反例”自动授权宽泛默认；不要求逐句证明有效 |
| §3 S 与 §4 衔接 | 同样审查继承的 Original 与自己的修改；已识别的任务语义区别要求不同动作、现有条件却不能区分时，调整相关条件或动作，不必等待已发生的失败 | 避免把 Diagnosis 已提出的范围默认视为成立；保留有依据的泛化，推测性风险不自动要求收窄 |
| §3 保护条件、§4 Checks | 检查保护条件是否真正覆盖扩展行为的风险；Checks 看问题改善、有效区别保持及成本，必要时帮助区分竞争解释 | “未匹配项不改”不能保护被扩大匹配错误纳入的项；逐项检查是否执行新策略不等于验证解释 |

在 §4 合并原来的“未验证不等于有缺陷”“需要说明合理 tradeoff”表述，明确允许
多个有依据的修复假设共同保留，但每个实质行为变化需要与其作用、范围和强度相符的依据。
“同时覆盖多种可能原因”不单独授权额外默认规则或更宽适用范围。

KEEP 的判定集中在 Explicit Keep；§3 负责具体范围判断，避免两处重复展开。
Checks 不能替代 Update 必要条件的说明统一保留在 §4，§6 继续规定结构、引用和
正文条件传递给 Editor 的要求。未改动 fallback、保存／终止、自检边界的既有要求。

## 保留的探索与泛化空间

- 不要求先确认根因或证明修复有效；合理假设可以留待 Candidate 检验。
- 不设置 Update 数量、最低案例数、Memory 引用次数或逐句审计要求。
- 允许根据任务语义、可迁移机制和相关历史经验扩大范围；同样允许多个假设共同保留。
- 推测性风险不自动触发收窄；范围调整针对已识别、与任务相关且会改变正确行为的区别。
- Checks 仍可为空或覆盖多个 Updates，不要求每项探索单独增加 Check。

## 预期判断变化，尚未通过模型验证

- **R05 文本匹配：** 可保留文本／数值两种修复假设，但不能仅因覆盖两种原因就保留普遍子串默认；应判断该范围是否由匹配语义支持，以及“不改未匹配行”是否真正保护误匹配风险。
- **R05 数值约束：** 继续允许定位边界并修复分配；不把“完整表里一定有边界值”写成事实。具体数值及来源仍然缺失，Prompt 不会补出这些事实。
- **R06 答案位置：** 对已识别的表头起点与数据起点区别，调整相关条件或动作，同时保留当前任务的有效布局修复；不要求先拿到另一个失败案例。
- **R06 排序与必需公式：** 保留合理且可检验的排序修复，以及不能用直接值取消必需公式的边界。

不将上述预期写成已改善结果；此前两个未被 DeepSeek 原输入覆盖的争议也不会因本次
Prompt 修订自动获得验证。

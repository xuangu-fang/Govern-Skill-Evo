# Replay v3：条件下的行为比较与 Knowledge 概括

2026-10-28。默认学习 Prompt 更新为 `v25_replay_conditional_comparison_v3`，输入视图继续 `v25_replay_pairs_knowledge_only_v4`，Preconditioner 默认 v7。本次仅修改 Replay 学习 Prompt、版本选择、未来配置和相应文档/测试；不跑模型实验。

## 依据与边界

[DeepSeek R05 / R06 的 v2 Prompt、v4 输入对照](../../../experiments/methods/v25/replay_view_v4_deepseek_r05_r06_clean_20261028_001/reports/README.md)表明输入明显缩短后，两项重要程序差异仍遗漏：R05 残差符号与加减动作反转、R06 item 名称与代码的优先级变化。新输出还将混合实现概括为 Parent 全部直接值、将两项改善纳入全部同分集合。

v2 已提出程序比较、证据区分及主张核对；本次将这些要求重排并具体化，不重复追加一套审查阶段。不能仅由输出确认模型内部推理过程，也不能把所有错误归为 Prompt 缺陷。两次输出均为新增 Knowledge，没有验证历史 Memory 替换的保真性。

## 四处局部调整

| 位置 | 实施内容 | 对应问题 |
| --- | --- | --- |
| §3 行为比较 | 先在相同任务条件下比较两侧动作、共同行为和结果，再关联实际 Skill 修改；按解释需要检查谓词、对象/键、方向、优先级、边界和回退 | 防止只提取符合条款的差异；保留符号映射、键优先级和 Parent 已有分支 |
| §1 Observation | 程序规定条件行为，已知输入可确定分支；日志支持其报告的事实但不自动成为独立验证；评分不能确定未知执行路径或独立原因 | 区分 R05 未知实际边界与 R06 已报告追加行数；不强制额外分支日志 |
| §4 Knowledge | 以有条件的行为关系组织经验；每个合并案例分别核对行为和配对结果，保留重要条件、例外和竞争差异 | Candidate 路线相同不推出 Parent 路线相同；Candidate 全对不推出与 Parent 同分 |
| §6 主张检查 | 核对身份、条件、方向、数量、结果与范围；对 all/both/unchanged/only/newly added 逐一核对所覆盖案例，并检查条目间一致性 | 防止“全部”概括与反例冲突，以及任务/工作表身份误写 |

§1 的输入说明改为核心证据字段，并指向所选视图附带的共享解码说明，避免将 v4 误描述成严格六个顶层字段。输入构造和解码实现没有变化。

## 合并与冲突检查

- 证据强度集中于 §1；§3 引用该边界，不再次展开整套日志规则。程序比较放在条款适用性和归因之前，保留联合干预及重要正反对照。
- §4 合并原分组和精简要求，明确精简不能删掉改变经验含义的分支、例外或竞争差异；不要求每个任务各产出一条，也没有固定句式、数量或额外字段。
- 不同结果可以保留在同一条经验中，只要差异本身是该理解的一部分；不能为形成整齐分组而抹平结果。
- 保留有依据的机制假设、合理跨任务泛化、无需最低案例数或独立因果证明等原有空间。未知量只约束对应主张，不抹去已知改善、退步及未测得收益。
- §6 负责最终主张核对，不重复 §3 的整个比较过程。因果保留语不能修补事实错误，但无需穷尽追踪无关实现细节。
- §2 全批次调查、§5 完整 MemoryEntry 替换规则、§7 输出契约及 Current pairing view 原文保持不变。当前程序比较要求不扩展为重读未提供的历史源码。

正文按空白分词从 2,707 增至 2,839 词（+132，约 4.9%）。没有把 R05/R06 任务名称、具体单元格或正确答案写入 prompt。

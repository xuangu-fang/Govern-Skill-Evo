# Preconditioner 事实与更新边界的局部修订

2026-10-28，当前版本为 `v25_preconditioner_evidence_decision_boundaries_v7`。
v7 只标识本次局部 Prompt 修订，不代表重新设计模块或新增流程。
输出契约仍为 `v25_explicit_references_v2`。

## 修改依据与范围

依据是 DeepSeek 原调用、GLM 独立对照和 GLM 新链路实际发送的输入核对，而非
用后续 Candidate 结果倒推模块当时知道什么。六项争议的可见事实与缺失信息见
[核对结论](../../../experiments/analysis/preconditioner_visibility_audit_20261028_001/findings.json)，
原请求路径、摘要校验与解码文本位置见
[证据索引](../../../experiments/analysis/preconditioner_visibility_audit_20261028_001/manifest.json)。

| Prompt 位置 | 修改及解决的问题 | 保留的空间 |
|---|---|---|
| §1 输入事实 | 区分代码允许的行为、输入能确定的事实和执行记录确认的事件；运行事实缺失时，不把评分解释成确定的执行经过 | 根因未证实时，仍可基于题意、代码结构和历史提出可测试修复 |
| §3 S | 根据可迁移的行为关系泛化；改变身份、匹配、排序或完成语义时，说明依据与保留的有效区别；未匹配、空值和未改项可能本来正确 | 允许扩大范围、替代方案和强度调整；不要求多案例数量门槛或逐条因果证明 |
| §4 fallback | 按触发后实际交付的结果判断，而非看主策略是否仍写在文本中；历史成功或高分不能使遗漏必需属性的方案变得等价 | 保留任务允许的替代实现，只调整冲突部分 |
| §4 保存与终止 | 按实际协议推演会提交什么；探查、准备或文件有效不能单独充当任务完成；合并原 §6 自检范围说明 | 保留协议内有用的探查与恢复，不要求完整正确性证明，不追加推测性失败分支 |
| §4 KEEP / Checks、§6 正文条件 | 主方向成立不自动支持附加匹配键、fallback 或终止条件；重要不确定性对应的 Check 应帮助区分解释；必要条件进入 Update 正文 | KEEP 无需逐句证明有效；Checks 可为空或覆盖多个 Updates，无新增字段和检查数量配额 |

采用替换和合并原段落的方式：泛化与强度分别放在 S 相邻段落；自检范围并入
保存／终止判断；Editor 不接收 reason 的限制统一放在 §6。保留历史经验的积极作用、
D/S/C 协调、整个 Update 的 KEEP 判断和任务要求边界，不增设独立审查阶段。

Preconditioner 仍针对每个 Original Update 返回恰好一项 Adjustment，这是既有
映射契约，不限制一轮 Update 数量。没有增加“先证明修复有效才能修改”、固定案例数、
一项探索对应一个 Check、未知事实一律撤回等要求。已有输入足以确认的要求冲突，
不能仅以“待 Candidate 验证”为由保留；尚未确定的修复效果则允许作为合理假设检验。

## R05、R06 预期判断变化（尚未验证）

- **R05 文本匹配**：承认错行原始文本、金额与实际分支不可见，保留有依据的匹配修复假设；不宣称已确认子串是根因，也不因未验证就否定所有归一化。
- **R05 查找回退**：仅 GLM 新链路 Preconditioner 收到对应 Update。已知 102 个未匹配、总计 4 个错格，至少 98 个未匹配结果原本正确；新增二级键须解释为何保持题目匹配依据，不能只以提高覆盖率为由保留。关键查询行仍缺失，修订不能补出真实根因。
- **R05 公式回退**：GLM 独立对照曾在必需公式条件下加入字面值 fallback；按实际结果检查应发现它会丢失必需公式，保留兼容缓存方案并调整该 fallback。DeepSeek 同输入已保留公式，是正面对照。该 GLM 独立输出未进入新链路，不能用它解释新链路缓存退步。
- **R06 合并来源**：可根据可见 Jack 标签及条件跳过代码提出修复，但不能用错格推断所有来源都没追加；Henry/Richard 的实际追加情况仍需额外运行事实。GLM 新链路已保留竞争解释，应保留这点。
- **R06 排序**：题意与 `(issued, requested, line, row)` 足以支持排序修复假设，无需先证明两格错值必由排序导致；也不能无依据认定 FIFO 已正确。GLM 新链路已展示这种利用现有输入的做法。
- **R06 探查也保存**：仅 GLM 新链路收到相应 Update。其输入和输出理由均包含首次正常保存可打开文件即终止的协议；应消除“仅探查也可以完成提交”的歧义，同时保留允许的探查与恢复行为。

这些是修改目标，不是模型效果结论。尤其不要求 Prompt 解决当次未提供的单元格、
实际分支、完整来源集合等信息缺口，也不把只有一个模型接触过的 Update 视为跨模型共同失败。

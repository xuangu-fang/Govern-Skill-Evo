# V25 Actor 与证据协议草案

2026-10-27 实现更新见 [执行历史协议](EXECUTION_HISTORY.md)。新协议将生成失败与临时格式修复保留在原始归档、排除于正式历史和自进化证据之外。下文是早期协议草案；其中累计时间、格式失败计数及完整请求展示的旧约定不适用于新协议。

本协议定义 SpreadsheetBench 任务如何交给 Actor、程序如何执行、结果如何评分，以及自进化模块可以使用哪些证据。已确认首版所有 Actor 执行均不接收标准答案纠错反馈，并复用 Parent 轨迹用于诊断和 Gate。数据条件与已确认预算保持不变；Actor 能力与停止语义以[共享执行上下文](SHARED_EXECUTION_CONTEXT.md)为准，具体数值推荐集中列在其中。当前没有生效的 v25 运行配置。

**一、任务与方法边界**

| 项目 | 已确定内容 |
|---|---|
| 数据 | SpreadsheetBench Verified-400；每题一份输入工作簿和一份标准答案工作簿 |
| 优化任务 | 80 Train＋40 Selection，共 120 题；保留原始划分标签，明确 Selection 已参与优化 |
| 批次 | 每批 15 题，完整遍历为 8 批；顺序及遍历次数在正式配置中明确 |
| 最终评估 | 280 Test；不用于修改 Skill、更新 Memory 或选择配置 |
| 初始 Skill | SkillOpt 的 SpreadsheetBench 初始 Skill 原文；不运行额外的初始 Skill 生成阶段 |
| 初始 Memory | 空；不导入 ALFWorld 经验 |
| 评分 | 相同评分器；主指标 `hard`，辅助指标 `per_cell_pass_rate` |
| 方法 Gate | 无评分反馈条件下，Candidate 在同批任务上的成功数严格高于 Parent 才 ACCEPT；否则 RETAIN |
| 学习与比较 | 同一 Parent 执行用于诊断和 Gate；Candidate 独立执行；两边均无标准答案纠错反馈 |

三种方法进行对照时，共享任务、Actor Prompt、Skill 注入位置、输入预览、执行环境、反馈范围、评分器和 Actor 预算。各方法保留自己的优化器规则。共享 Actor 后的结果应标明实际运行设置，不直接称为上游论文的原样复现。

**二、推荐的 Actor 协议**

推荐首版采用完整 Python 程序生成模式。Actor 模型没有单独的 shell、文件浏览或交互式工作簿工具；生成的程序能够读取完整输入工作簿。模型只直接看见实际放入请求中的任务、预览、代码历史及反馈。

| 输入位置 | 内容 | 明确边界 |
|---|---|---|
| 固定系统说明 | 输入输出约定、允许的库、程序执行方式、反馈范围和停止规则 | 不放进化模块指令或额外的人工解题策略 |
| Skill 区域 | 本次 Parent 或 Candidate 的完整 Skill；建议接在系统说明后的固定位置 | 每个任务内保持不变；不直接注入 Memory |
| 初始用户消息 | 指令、任务类型、答案区域及所属工作表、输入工作簿预览 | 不提供标准答案、评分结果或其他任务的经验 |
| 输入预览 | 各工作表名称、尺寸、带坐标的有限单元格内容；标明截断范围 | 预览未展示不等于工作簿中不存在；不默认追加评分器发现的结构 |
| 程序可用文件 | 当前任务输入工作簿及本次输出目录 | 不开放标准答案、其他任务结果或历史运行目录 |
| 后续消息 | 当前任务此前的完整代码响应及允许的反馈 | 不继承 ALFWorld 最近两步历史；不混入其他任务消息 |

预览推荐每表前 5 行、前 20 列，单元格文本最多 40 字符。已确认总预览完整生成后采用 100,000 字符检查，超过则在 Actor 请求前明确报错，不截断继续；具体规则见共享执行上下文，三种方法保持一致。每份实际请求均保存最终渲染的文本；超过上下文容量不得暗中删除中间尝试或切换预览策略。

建议模型返回单个 Python 代码块。执行器负责保存代码、绑定 `INPUT_PATH` 与 `OUTPUT_PATH`、运行程序和提交工作簿。固定说明中应明确：Skill 中“探索、执行、确认”等动作，在这个协议下通过生成程序及执行器实现，不代表 Actor 另有交互工具，也不代表它可以读取标准答案。

SkillOpt 初始 Skill 中含路径赋值示例，执行器不能任由占位路径覆盖实际任务路径。建议仅对独立、简单的顶层 `INPUT_PATH`／`OUTPUT_PATH` 赋值做明确的路径绑定适配；原始模型代码和实际执行代码均保存。复杂的重新绑定应返回协议错误，不进行猜测性代码修复。不能原样照搬可能误删其他语句的文本替换规则，也不能顺便修改解题算法。

初始 Skill 原文还包含 `openpyxl.save()` 的表述，而其代码示例使用 `wb.save(...)`。按已确认的初始条件保留原文，不在迁移时默默修正；后续如需清理，应将其列为单独的初始条件变更，并让对照方法使用相同版本。

**三、Parent 复用及单次任务顺序**

每批首先执行 Parent，结束后评分，再经过 Grouping、Diagnosis、Preconditioner 和 Editor。产生 Candidate 后，使用原始输入独立执行 Candidate 并评分；Gate 直接比较已完成的 Parent 和 Candidate，Replay 使用同一批配对轨迹。经验核验发布完成后进入下一批。

| 运行角色 | Skill | Actor 能否收到评分错误反馈 | 用途 |
|---|---|---|---|
| Parent | 本轮开始时的 Parent | 不可以 | Grouping／Diagnosis 的依据、Preconditioner 引用来源；同一结果复用于 Gate 和 Replay |
| Candidate | Editor 生成的 Candidate | 不可以 | 与 Parent 配对比较，供 Gate 和 Replay 使用 |
| Test | 最终已发布 Skill | 不可以 | 最终评估，不更新 Skill 或 Memory |

原 Train／Selection 标签不改变 Actor 反馈权限。120 个优化任务均参与 Skill 学习和本批 Gate；没有额外划出独立验证集。Test 不参与优化。

一批完整流程共 30 次任务执行：15 次 Parent、15 次 Candidate。no_change 或停止分支尚未形成 Candidate 时，不执行 Candidate 或配对 Gate。Parent 的完整归档结果原样复用，不重新抽样、选择历史最高分或只截取首轮结果。复用以任务、原始输入、Parent Skill、模型和执行／评分配置一致为前提。

单次任务按其角色执行：

1. 从任务清单读取输入、任务元数据和答案区域。准备独立的任务目录，记录实际 Skill 和运行条件。
2. 使用原始输入生成固定预览并构造 Actor 请求。标准答案由独立评分过程持有。
3. 接收完整代码响应，检查输出格式，保存原始代码及路径适配后的实际程序。
4. 在新的尝试目录运行程序。每次尝试都使用原始输入副本，不读取前次失败留下的输出或临时文件；模型消息历史仍按协议保留。
5. 检查程序退出结果、输出是否存在及是否可打开。存在错误且预算允许时，提供对应运行反馈，请求完整修正程序。
6. 首次获得正常退出且有效的工作簿后，结束 Actor 并固定最终提交；即使还有代码轮数或时间额度，也不根据评分继续修正。
7. 按统一公式处理策略对最终提交评分。首版推荐不自动重算，直接读取保存值；将来启用重算时另存评分副本。优化任务的结果供方法模块分析和 Gate 比较；Test 评分仅供最终报告。评分不追加到 Actor 消息，不能把事后评分伪装成当时收到的反馈。
8. 达到代码轮数或正常任务预算仍没有有效输出时，形成有记录的任务失败。接口、环境或评分故障按技术中断处理；不能为获取更高分重跑已完成任务。

Parent 和 Candidate 分别从相同原始输入开始，Candidate Actor 不读取 Parent 的程序、评分或产物，只使用 Candidate Skill 和自己的任务消息。两边代码尝试数可以自然不同，但上限、反馈权限、执行条件和评分方式相同。Gate 复用 Parent 的保存结果，不继续执行它的模型会话或程序。

执行器只向程序提供任务输入和本次输出空间。共享上下文推荐使用仅提供当前输入及尝试目录的独立执行容器，具体依赖版本在实现时固定；仅换工作目录或移除环境变量，不能证明程序无法访问宿主上的标准答案。这是 benchmark 输入边界的实现要求，不是新的方法模块。

**四、反馈与预算**

已确认首版不启用标准答案纠错反馈。Parent、Candidate、Test 都可以根据格式、程序异常及输出文件错误修正代码，但都不能根据答案比较结果继续尝试。任务结束后的评分仍用于 Skill 自进化：Diagnosis 分析 Parent 的结果，Replay 分析实际修改与配对结果。优化模块的评分视图与 Actor 的运行反馈分别保存。

| 反馈类别 | 是否返回 Actor | 处理建议 |
|---|---|---|
| 输出格式不符合约定 | 是 | 给出具体格式错误，不附带任务策略 |
| Python 异常、程序执行超时 | 是 | 返回有长度上限的真实错误及退出状态，不自动解释根因 |
| 输出文件缺失或损坏 | 是 | 返回真实产物检查结果，允许在预算内重试 |
| 标准答案对照后的错误坐标、缺失工作表 | 否 | 优化任务结束后供方法模块分析；Test 仅供最终报告 |
| hard、单元格正确率、预测值 | 不作为评分反馈返回 Actor | 指标供方法分析和报告；预测值仍可存在于自身代码或实际运行日志中，不由评分反馈追加 |
| 标准答案值及答案文件 | 否 | 仅评分器使用，不放入模型请求或错误文本 |
| API 超时或服务错误 | 不作为解题反馈 | 按请求重试规则处理；不告诉模型“算法失败” |
| 自进化模块 JSON、补丁或引用错误 | 仅返回发生错误的方法模块 | 沿用 v24 的输出校验反馈，不混入 Actor 的工作簿反馈 |

反馈长度限制应在运行前固定。已确认执行错误详情保留前 3,000 字符，短于上限则原样，过长时标注截断；完整 stderr/stdout 和事后评分记录保留。优化模块评分摘录推荐最多 100 个错误坐标和 100 个缺失工作表名称，准确计数另列，不作为 Actor 纠错信息。成功执行后的 stdout 不单独开启探索轮次。模型通过故意异常获取信息仍消耗代码尝试预算，不能改记成免费观察。程序自行触发的 KeyError 等运行异常可以回传，但评分器根据标准答案发现的缺失工作表不能回传。

必须分别记录以下预算，不能统称为“重试次数”：

| 预算 | 计数单位 | 草案状态 |
|---|---|---|
| Actor 代码轮数 | 一份完整代码方案或一次需要纠正的完整格式响应 | 推荐上限 30，不沿用 ALFWorld 的 50 个动作 |
| 单轮模型请求尝试 | API 发送及重试，包括首次请求 | 已确认沿用 v24，最多六次总尝试；统一外层与 SDK 计数，不能叠加隐藏重试 |
| 单次 API 请求时限 | 一次模型请求 | 已确认 300 秒 |
| 程序执行时限 | 每次执行的墙钟时间 | 已确认 600 秒，参考 SkillAdam 主结果配置 |
| 任务总时限 | 一次 Parent、Candidate 或 Test 执行的请求、等待、程序执行等累计时间 | 已确认 600 秒；推荐覆盖输入准备到提交检查，事后评分单独计时；进行中的调用受剩余时间约束，复用 Parent 不增加额度 |
| Actor 输出额度 | 每次请求 | 已确认 16,384 tokens |
| 方法模块输出额度 | 每次请求 | 沿用 v24：Preconditioner／Replay／Verifier／Repair 为 32,768，其余为 16,384；API 时限 300 秒，请求最多六次总尝试 |
| 输入容量 | 每次请求的上下文容量 | 正式配置明确保存，禁止失败后自动扩大 |
| 并发 | 同时运行的任务／执行进程数 | 首轮功能验证推荐 1，后续实验统一固定；不是每题预算 |

API 重试不应自动重新执行已完成程序。完整但格式错误的输出按代码轮次处理；未完成的响应不作为可执行程序，重试请求的消息不变。300／600 秒均为预算上限，不保证每次请求或执行都能用满；推荐强制裁剪进行中的请求和执行时限，具体计时起止、技术中断及恢复边界见共享执行上下文。

**五、评分与任务完成状态**

评分器按指定答案区域比较值。每题 `hard` 为 0 或 1；全部指定单元格正确时为 1。`per_cell_pass_rate` 保存每题正确单元格数除以应比较单元格数；总体对任务取平均，不能把所有任务单元格混在一起计算。保留整数计数，展示时再舍入。

日期、数值、空值及答案区域解析沿用选定的基准比较语义，并用固定样例验证。值比较不等于完整验证格式、公式文本或非目标区域保持情况，报告不能扩大评分器的实际覆盖范围。

首版推荐关闭自动公式重算，评分使用 `data_only=True` 读取保存值，与本地参考路径一致。有效公式没有缓存时可能被按空值判错，不能因此追加 Actor 反馈或默默启用重算。将来统一引入重算时，需固定引擎版本与调用条件，并分别保存 Actor 原始产物与评分副本；引擎故障为评分中断。两种条件不能混算成绩，不能手工填入标准答案。

下表中的 Gate 纳入条件适用于 Parent／Candidate 的完整记录。同一 Parent 成绩既供诊断，也作为 Gate 基准；两边使用同一无标准答案纠错反馈协议。

| 情况 | 任务结果 | 是否进入当前批次 Gate |
|---|---|---|
| 有效输出，答案区域全部正确 | 已完成，hard=1 | 是 |
| 有效输出，答案区域部分或全部错误 | 已完成，hard=0，计算单元格正确率 | 是 |
| 超出代码修正上限仍异常／无有效输出 | 已完成，hard=0，单元格正确率按 0 计 | 是，保留失败原因 |
| 缺失目标工作表，但工作簿可评分 | 已完成，相关指定单元格计错 | 是 |
| 接口重试耗尽、依赖环境异常、进程被中断 | 技术中断，指标未定 | 否；暂停批次，不能用剩余题替代完整批次 |
| 标准答案损坏、答案区域无效、评分器或重算服务故障 | 评分中断，指标未定 | 否；先解决协议或环境问题 |

Test 出现技术中断时报告已完成数和未完成数，不把缩小后的分母写成完整 280 题成绩。若故障修复涉及评分规则或执行条件改变，需要重审所有受影响结果，不能只修复表现差的任务。

**六、证据记录与引用草案**

保留普通版本、任务 ID、路径和实际内容即可。运行原始记录与模型输入视图区分保存，不建立额外的通用事件平台。以下是概念字段，最终字段名由实现阶段确定。

| 记录 | 必要内容 | 可以支持的判断 |
|---|---|---|
| 任务与协议 | 原始任务 ID、划分、运行角色、评分反馈权限、指令、类型、答案区域、输入来源、Actor 条件、实际 Skill | 两次执行是否对应同一任务及同一条件 |
| Actor 请求 | 每次实际消息、参数、原始响应、完成原因及用量 | 模型在生成代码时真正看见了什么 |
| 代码尝试 | 尝试序号、原始代码、实际执行代码、输入来源、退出状态、stderr/stdout、实际回传反馈 | 编写了什么、执行是否结束、哪些反馈被看到 |
| 提交产物 | 输出路径、可打开状态、工作表及选定范围的确定性摘录 | 保存了什么结果；未摘录区域仍属未知 |
| 评分 | 最终提交所属尝试、评分器条件、比较区域、正确／总单元格数、hard、错误坐标及缺失工作表 | 记录事后评分及其覆盖范围；不当作 Actor 执行时的信息 |
| 配对 | task_id、Parent run_id、Candidate run_id、双方完成结果和协议 | 同一 Parent 记录贯穿诊断和 Gate；按任务及实际运行身份配对 |
| 实际修改 | Parent 全文、实际 Candidate、实际 Diff、Effective Plan | 区分修改意图与真正应用的 Skill 修改 |

不记录不存在的内部逐行执行轨迹。代码中出现一个分支不证明运行时走过它；输入文件可读也不证明模型在生成代码前看过其中所有单元格。程序读取能力、模型请求可见信息、评分器的事后信息必须分别描述。

建议保留现有引用的简洁形式，改变其领域语义：

| 引用示例 | v25 建议含义 |
|---|---|
| `P1`／`Q1` | 一次 Parent／Candidate 执行；双方均无评分反馈；同一 P 引用用于诊断、Gate 和 Replay |
| `P1:0` | 初始任务、预览及 Actor 协议；不是整个工作簿已经被模型读取 |
| `P1:1` | 第一次代码尝试的实际请求、响应、代码、执行结果及回传反馈；不是代码行号 |
| `P1:outcome` | 最终提交、评分视图、终止原因，以及代码尝试／执行／请求的分别计数 |
| `diff` | 当前实际 Skill Diff 与必要的 Parent 上下文 |
| `G1` | Grouping 的分组对象；不能单独证明行为事实 |
| `R01/P1:1` | 已归档上下文中的原始引用；保留完整历史前缀 |

同一代码轮次内的网络请求重试保存在请求列表中，不伪装成多次程序执行。没有执行的格式失败也要记录 `executed=false`，不能因保留 `P1:1` 这样的外形就默认执行过。

Plan 的 basis 指向实际 Parent 证据 P，Replay 的 `runs/pairs` 使用同一 P 和独立 Candidate Q，不需要额外学习记录字段或引用前缀。引用编号本身不证明配对，仍需核对任务、输入、Skill 与执行条件。一次配对差异不是稳定因果证明；同批结果参与修改和选择也不等于独立留出验证，最终 Test 用于评估泛化。

删除 `command_sets`／`commands_ref` 及动作合法性菜单含义，不用工作表列表冒充动作候选。若为了复用现有验证器保留内部 `steps` 数组，应明确其单位是代码尝试，模型输入和报告使用清晰的尝试／执行／请求计数。

**七、模型可见证据范围**

推荐优化模块接收确定性的评分视图：指标、正确／总单元格数、错误坐标和缺失工作表；不接收标准答案值，不从评分器追加预测值。已有输出摘录或实际日志中的自身输出仍属于执行证据。错误坐标和缺失表列表按共享上下文的上限展示，保留完整机器记录并标注展示数量和总量，不由 LLM 先行总结替代原始事实。

| 模块 | 当前任务证据 | 历史材料 | 不提供的内容 |
|---|---|---|---|
| Actor | 任务、预览、当前 Skill、自己的代码历史和允许的运行反馈 | 无跨任务历史 | 标准答案、答案对照评分、Memory、另一侧记录 |
| Grouping | 本批全部 Parent（P）允许证据及事后评分 | 无 | Candidate、历史 Memory |
| Diagnosis | 同上＋Grouping | 无 | 未执行的 Candidate 结果、历史 Memory |
| Preconditioner | Parent、原 Plan、用于原计划引用核对与计划审查的完整 Parent 执行（P）；不提供 Grouping 内容 | 全部活跃 Knowledge Only 视图 | 未提供的历史原始轨迹；尚不存在的 Candidate 结果 |
| Editor | Parent、Effective Plan、统一 Actor 协议 | 无直接历史输入 | 执行原文、Preconditioner 理由、额外解题答案 |
| Replay | 实际 Diff、Plan、全部当前 P/Q 配对及允许证据 | 活跃 Knowledge Only 视图 | 未提供的历史原始轨迹、未执行的比较 |
| Verifier | 待核验 Knowledge、实际修改和其引用的原始证据视图 | 程序按被引用 ID 取出的历史证据 | 自主检索额外题目或主动扩展证据 |
| Repair | 被授权修复项、Verifier issues 和限定的原始证据 | 仅输入中已有历史证据 | 其他项的自由编辑、外部补证 |
| Gate | 完整 P/Q 配对任务的 hard 结果及执行条件检查 | 不需要 | 用辅助指标改变既定接受规则；择优重跑 Parent |

这里的“完整执行”指完整代码尝试序列及其允许的证据字段，不意味着把整个输入、输出和标准答案工作簿全部展开进模型上下文。

历史 Knowledge 的证据 ID 仅保留出处。Preconditioner 和 Replay 不能因为 ID 存在，就宣称重新读取过历史原文；Verifier 可以由程序按既定引用恢复原始记录，但不增加额外的探索调用。

Diagnosis、Preconditioner 和 Editor 都需要知道 Actor 不接收答案对照反馈。事后评分的错误坐标可以帮助诊断，但不能因此把“等待评分器指出错误后修复”写成 Actor 具备的能力。Verifier 按实际请求核验可见信息；方法模块能够读到评分，不代表 Actor 曾经收到它。

**八、贯穿案例与反例**

以下是构造案例，不是实际实验结果。某输入表第一行是说明、第二行才是表头；Parent 代码固定从第二行开始把所有内容当数据，执行成功，但部分目标单元格评分错误。

| 阶段 | 合理处理 | 不成立的跳跃 |
|---|---|---|
| Actor | 首次有效工作簿后结束，再评分 | 根据评分错误坐标继续修正，或将评分追加到此前的 Actor 消息 |
| Grouping | 以表头与数据起始位置的识别问题组织可比执行 | 仅因任务失败就认定缺少某条 Skill |
| Diagnosis | 同时引用显示说明行／表头的预览、实际代码、评分；提出可从输入检查的起始行规则 | 只凭错误坐标断定具体循环根因；要求永远从第三行开始 |
| Preconditioner | 结合历史 Knowledge、当前相关证据与执行条件，审查和发展原更新的方向、范围及协调关系 | 将历史单次成功提升为所有表格的固定规则 |
| Editor | 将通过调整的规则写入通用 Skill，保留单表和多表等边界 | 生成本题专用修复程序，或加入题号及标准答案 |
| Candidate 与 Gate | Candidate 从原始输入独立执行；复用完整 Parent 结果，按整批 hard 成功数决定接受 | 重跑 Parent 挑选成绩；单元格正确率提高就绕过严格 Gate |
| Replay | 比较真实代码、输出及配对结果，记录改善和反例，并注明修改可能是联合影响 | 仅凭得分变化证明某条 Skill 独立导致提升 |
| Verifier | 若 Knowledge 把第二行错写为第一行，可据已有预览纠正 | 为每项经验要求完整因果证明 |
| Repair | 只修正被指定项中的错误及依赖该错误的推断 | 借机重写整份 Memory 或改动 Skill |

必须补充以下反例：Parent 已正确且无新更新依据时允许 no_change；程序语法错误各阶段均可反馈重试；有效输出评分不通过也不能继续 Actor；预览没展示实际表头且无其他记录时不能假定模型见过；Gate hard 持平但单元格正确率改善仍 RETAIN；服务故障不能当作正常算法失败。

**九、实施前待定项与离线验收目标**

无标准答案纠错反馈、Parent 复用与已有数值预算已确认；共享执行上下文已定稿能力、历史、停止和评分边界，并给出代码轮数、预览、评分摘录、公式处理及时间约束的集中推荐值。完整 Actor／模块 Prompt 及构造案例已在[定稿包](prompts/README.md)完成；下一步需把参数写成明确配置，完成路径适配语法、环境版本和后端实现。以上条件不能在实验中临时修改；当前没有完成运行验收。

离线验收应覆盖：Parent／Candidate 从相同输入独立执行；Parent 完整记录在诊断与 Gate 间原样复用；失败尝试之间无产物残留；路径适配不改变算法；标准答案和评分纠错信息不进入任何 Actor 请求；事后评分正确提供给优化模块；评分边界及公式处理；预算计数和异常归类；P/Q 引用及历史前缀；恢复不重复已完成调用。

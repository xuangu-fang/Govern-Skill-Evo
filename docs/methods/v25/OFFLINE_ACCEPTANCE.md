## 实现范围

1. **Actor 与评分器**：完整代码生成、独立 Docker 执行、原始输入重置、当前任务完整历史、预算与请求重试、首次有效工作簿提交、提交后的独立评分。标准答案路径不进入 Actor 消息，标准答案文件不挂载到程序容器。公式不额外重算，评分读取保存值。
2. **方法迁移**：Grouping → Diagnosis → Preconditioner D/S/C → Editor → Candidate → 严格 Gate → Replay → Verifier／可选一次 Repair → Memory 发布。Parent 同时用于诊断、Gate 和 Replay；历史只以 Knowledge Only 视图进入学习模块，Verifier 按实际引用取证。
3. **恢复与隔离**：中断恢复复用同一 Actor 执行状态；预算不归零；已保存响应、程序结果、提交和评分不会重复执行。Test 评估入口不执行方法模块、不写训练 Memory。运行时无需导入旧版本、ALFWorld 或参考仓库实现。

正式配置保留 80 Train＋40 Val 共 120 个优化任务，明确 Val 参与优化；8 批，每批 15 题，原 Train 顺序后接原 Val 顺序。280 Test 仅最终评估。初始 Skill 与 SkillOpt 原文逐字一致；14 份运行 Prompt 与已审阅定稿逐字一致。

模型、代理地址、调用参数、输出额度、重试预算与输入容量均核对既有候选配置。SpreadsheetBench 的代码执行、预览和评分参数独立列明，不声称与 ALFWorld 的环境行为等价。

## 离线验收结果

完整测试共 **176 项通过，0 失败、0 跳过**：v25 为 76 项，v24 回归为 100 项。最终结果以保存的 JUnit 文件为准。

| 关键路径 | 已覆盖内容 |
|---|---|
| Actor 停止边界 | 首个有效但答案错误的工作簿直接提交，不追加评分反馈或纠错请求 |
| 错误与历史 | 格式错误、截断响应、运行错误、缺失或损坏文件；前 3,000 字符错误详情；完整历史 |
| 预算 | 30 次代码尝试含无效响应；单轮六次 API 请求；重试不重置；剩余总时间约束程序 |
| 恢复 | 响应已保存、程序结果已保存、已提交、评分已保存；评分故障不重新调用 Actor；发布前后恢复 |
| 程序隔离 | 真实 Docker 执行、文件不可见、无凭据、网络与外部命令限制、程序超时 |
| 方法分支 | ACCEPT、RETAIN、no_change、need_evidence、全部 Update 撤回、空 Editor、输出校验重试 |
| Preconditioner | D／S／C 修改的确定性应用，Update 身份和 Checks 保留 |
| 经验发布 | 历史引用、定向 Repair、只验证一次、非法删除最后一条 Knowledge 阻止发布 |
| Gate | 15 题严格成功数比较；成功数相同保留 Parent，辅助分数不改变决策 |
| Test 边界 | 合成 Test 任务仅评估、禁止混入优化、不运行优化模块、不修改训练状态 |
| 评分 | 数值与文本、空值、布尔、日期时间、多个区域、缺失工作表、公式缓存、错误坐标摘录 |
| 配置与依赖 | 划分 ID／顺序、继承参数、原文 Skill／Prompt、无旧版本或旧环境导入 |

评分比较使用本地 SkillOpt 和 SkillAdam 源码中的函数，正常值转换和有限区域样例的 hard 一致。辅助指标保留精确比值；与 SkillAdam 对比时单独核对其四位小数显示。没有以真实 Test 输出运行评分。

15 个合成任务的完整流程使用预设模型响应和真实程序执行器，完成 **15 次 Parent＋15 次 Candidate＝30 次程序执行**。同一 Parent 未重跑；完成全部七个模型阶段，其中 Verifier 和 Repair 各一次；发布后恢复没有新增 Actor 执行。预设 Parent 代码故意漏掉末行、Candidate 修正末行，因此 Gate 为 ACCEPT；该结果仅验证调度与决策，不能用作效果提升证据。

程序镜像实际为 Python 3.10.22、openpyxl 3.1.5、pandas 2.2.3、numpy 2.2.6；宿主依赖记录另存。测试中 API 传输检查只请求本机 HTTP 桩，不访问模型服务。

## 本轮检查后的修复

- API 请求耗尽总预算且未获得响应后，恢复继续保留技术中断，不生成评分或完整轨迹，不把服务故障纳入学习／Gate。恢复时先读取已保存响应，避免将已取得响应的任务误判成 API 故障。
- Test 汇总从 Actor 的 `termination` 读取实际终止原因；有效但答案错误的提交和预算耗尽即使同为零分，也能区分，恢复后保持一致。
- 新增 4 项回归用例，覆盖首次请求阶段超时、已有代码尝试后超时、截止时已保存响应的恢复，以及 Test 混合终止原因的汇总和恢复；另强化已有程序预算耗尽测试，确认恢复不会重跑或重评。
- 新增用例中的两种 API 中断和 Test 汇总问题已先在修复前复现失败；修复后针对性 36 项、完整 176 项均通过。候选配置、预算、Prompt 和评分规则未改变，已同步独立代码副本与新离线记录。

## 数据元信息发现与未验证范围

预检只读取任务元信息、文件存在性和工作表名称，不读取标准答案单元格。120 个优化任务全部通过区域和工作表对应检查。400 个任务中有 397 个通过，剩余三个均属于 Test：

| Test ID | 问题 | 当前处理 |
|---|---|---|
| 60-7 | 四个表名合并在一个 `answer_sheet` 字段，无法唯一确定目标表 | 保留原始任务并登记，等待统一评分配置明确处理 |
| 283-32 | 整列范围缺少有限行边界 | 保留原标注，不自行选择行数 |
| 73-45 | `BD2:308` 的右端缺少列名 | 保留原标注，不自行补写范围 |

最终 Test 评估在这些问题解决前会明确停止。任务没有被排除，Test 数量仍为 280。需要让三种方法采用同一份明确修正后的 benchmark 配置，再准备后续候选。

此外，训练任务 `170-13` 的不规整边界引号按参考方式兼容解析；`130-9` 的工作表名本身含逗号，v25 保留完整表名，不把它拆成多个区域。这些处理不更换目标区域。参考实现对边缘标注的处理并不完全相同：SkillOpt 对 `BD2:308` 可产生空单元格列表，SkillAdam 报错；简单按逗号切分还会误拆合法表名。因此不能把“正常样例评分一致”解释为所有异常标注行为完全一致。

尚未验证真实 API 的模型上下文容量、真实任务成功率、学习增益和总成本。未知程序执行结果的中断会保留技术停止，不自动重跑。上述限制不计为普通任务失败，也不转换成学习证据。

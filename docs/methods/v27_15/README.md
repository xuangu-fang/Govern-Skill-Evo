# v27.15 · 检查提案能解释哪些错题

v27.14 的 Diagnosis 能发现一组重复错误，也能在一道代表题上说明改动。v27.15 只修改 [Diagnosis 提示词](prompts/diagnosis.md)，把同一个提案放回它引用的各道错题，检查修改父版后哪些具体动作发生了变化。Preconditioner、Editor 和 Replay 取自 v27.14 本次训练的冻结版本，输入、输出、Gate 和 Memory 协议沿用原设计。

## 如何判断提案的作用

Diagnosis 在现有的 `reason` 里按实际情况合并说明。对照同一道题和同一份作答前信息，找出按新指令操作会排除的旧错误、只改变操作但仍可能交出旧答案的情况，以及原有指令已经适用或新提案仍解释不了的失败。用题面事实说明差异，参考答案只用于事后核对。再检查相关的正确作答是否仍然可行。影响判断的正例和边界样例通过原有的 `basis` 转发。

排除一个错误选项并不能预测模型一定答对。部分有效的提案可以保留；对剩余失败也可以如实记录证据不足。训练提示词不指定希望得到的策略，不要求所有错题由同一个提案解决。

## 冻结 R02 验收案例

v27.14 的 R02 父版在 10 道目标题中选对 2 道，漏选 8 道。原 Diagnosis 提出了扩大题型范围和细化检查。P4、P10 分别问等价条件和数量估计，扩大范围可以使原先漏掉的题型进入检查，但检查本身仍允许选具体答案。P1、P2、P6、P8、P9、P11 原先就明确问最强陈述，单靠扩大范围解释不了这六次漏选。P3、P7 是相关的正确样例。[R02 原提案](../../../experiments/campaigns/v27_14_lmb53_20261124/rounds/R02/diagnosis/attempts/001/parsed.json) · [父版逐题记录](../../../experiments/campaigns/v27_14_lmb53_20261124/rounds/R02/parent_runs/records.json)

行为验收固定 R02 的 Diagnosis 用户消息，用新版系统提示词生成原案。如果新提案仍是扩范围，应能区分上述两类漏选；若提出其他有依据的修改，应按其实际作用重新分组。验收看解释和提案是否相符、是否能指出尚未解决的错题，以及是否核对相关正确样例。接受有依据的部分改善或 `no_change`，不预设候选规则或具体措辞。此案例属于设计样例；要评价跨批次效果，还需从相同初始 Skill 和原题序开展独立训练。

本版本为独立设计。加载器与归档输出可以离线检查接口兼容性；模型回放及完整训练属于单独实验。

## 行为改动

将原来的“检查证据、构造规则”组织为有先后关系的三个判断，并在构造 Update 时落实强度：

1. **偏差是什么。** 区分对象／关系错误、答案边界及参考形式差异；允许混合和不确定情况。先判断边界修正能否保持原对象与关系，关系切换必须有自己的依据。
2. **改变什么决策。** 对照 Parent 和基础协议，说明触发后选择或表述行为的具体增量。失败不自动表示缺少指导；如果只是重复已有要求，必须找到实际的条件、行为或协调变化。已有规则过宽时明确修订相关条款。
3. **为什么能迁移。** 可见条件不自动是有区分力的条件；存在重要竞争解释时，说明输入中哪些信息支持拟改变的关系或粒度。题面形状、同主题、出现关联实体，以及单题参考形式偏好，都不能单独确立通用规则。
4. **用多强的指令。** 不要求事先验证成功或多例证明；允许有依据的条件偏好。范围扩张、优先级、强制顺序与 fallback 分别需要依据。不能用 reason 中的“不确定”给 Update 中的无条件命令兜底。

这些判断进入已有 reason、Update text/basis 和 checks，不增加分类标签、置信度字段或独立审核阶段。Update 文本承担最终行为条件；reason 解释依据；basis 保持原证据引用规则；Checks 观察决策增量及重要的保留边界。

## 保持不变

- 输入仍为 `parent/runs/grouping`，Diagnosis 不读历史 Memory 或 Candidate 执行。
- 输出契约和原 JSON 示例逐字保留：`decision/reason/plan`、`goal/updates/checks`、`id/text/basis`、`id/update_ids/question`。
- SearchQA 执行／证据边界、Actor 基础协议和 32,768 输出预算说明逐字保留。
- `revise` 和 `no_change` 均保留；没有新增 need_evidence。
- 不设 Update 数量、Skill 长度或支持案例数量门槛；多个合理更新可以同时提出；Checks 仍可为空。
- 无新增工具、Actor 调用或评分反馈纠错。Checks 面向正常流程未来产生的配对执行，不要求 Diagnosis 提前获得 Candidate。
- 不添加哈希或 SHA256 门槛。

## 语义审查

下表是对指令含义的人工审查，不是模型执行结果；不使用真实 Test 题作为 Prompt 示例或验收夹具。

| 情形 | 新版要求 | 防止的误用 |
|---|---|---|
| 对象和关系已合适，仅答案带有多余类别词 | 先修正答案边界，另行论证任何关系改变 | 从删词升级成另一种答题关系 |
| 裸标题同时关联创作者和来源作品 | 题面形状仅提示候选解释，检查决定关系的可见条件 | 仅凭某关系在上下文出现就赋予优先级 |
| 同一机构存在两种名称，当前参考偏好其一 | 区分参考形式与对象错误，不自动扩展为机构命名通则 | 将单题形式偏好普遍化 |
| Parent 已明确要求某行为，但执行仍失败 | 判断是否存在具体增量；允许 no_change 或其他合理修正 | 重复追加同义指导 |
| 单例支持一个合理但尚未验证的方向 | 可以提出有依据的条件性更新，不要求多例或因果证明 | 过度保守导致几乎停止学习 |
| 旧条款覆盖过宽，与当前修正冲突 | 明确相关旧指导及替换行为，保留适用范围外的能力 | 不断叠加例外和覆盖顺序 |

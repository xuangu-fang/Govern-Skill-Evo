# v28.1 两个 Prompt 的联合差异审查

日期：2026-11-03。第四步完成。结论：完成三处措辞澄清后，未发现阻碍进入独立配置与离线验收步骤的文本或契约冲突。此结论来自差异阅读、接口代码阅读和静态核对，不代表模型行为或测试收益已经通过验证。

审查对象：[Diagnosis](prompts/diagnosis.md)、[Preconditioner](prompts/preconditioner.md)，分别对照本目录保存的 v28 实际运行 Prompt。完整差异见 [diagnosis.diff](diagnosis.diff)、[preconditioner.diff](preconditioner.diff)；本次审查产生的三处修订单独见 [prompt_review_changes.diff](prompt_review_changes.diff)。

## 实质变化与已有要求的区别

| 审查点 | v28 已有要求 | v28.1 的实际增量 | 判断 |
|---|---|---|---|
| 发现失败后是否补规则 | 失败不证明 Skill 缺陷，要求相对 Parent 的增量 | Diagnosis 按偏差性质、决策增量、迁移依据依次判断；明确区分边界修正和关系切换 | 有实质判断差异，非仅重复“谨慎泛化” |
| 泛化条件 | 条件必须 Actor 可见 | 可见性之外，要求说明条件为何支持拟改变的对象、关系或粒度；题面形状只提示候选解释 | 针对条件缺乏区分力的问题 |
| 参考答案形式 | 禁止将参考专属拼写普遍化 | 明确覆盖简称、名称形式、拼写与词序，防止把形式偏差误判为对象／关系错误 | 扩展到已识别的错误性质，未加入具体答案补丁 |
| 范围和强度 | 区分许可、偏好与义务，警惕单例泛化 | 明确分开支持方向、扩大范围和新增优先级的依据 | 在两个不同职责的模块中保留相同边界，属于提出与审核的呼应 |
| 历史解释 | 保留联合编辑归因不确定性，区分未采用、无改善和不可观察 | 将这些区别落实到 KEEP／修改／撤回；不以没有反例扩大范围 | 不改变 Memory 或 Replay 格式 |
| 审核动作 | KEEP 涵盖整个 Original，修改要落实 patch | 修改、保留、撤回分别规定理由与文本动作；单改 change/reason/Checks 不算改变行为 | 强化已有要求的执行含义，不是新阶段 |
| 旧规则协调 | 不保留冲突，Editor 忠实实现 | 要求在相关 Original 中明确修订过宽 Parent 条款；新增优先级本身需要依据 | 与原 Editor 角色兼容，不把有效性判断推给 Editor |
| 学习空间 | 允许未验证提案及 no_change | 明确保留单例合理假设、条件偏好和多个独立更新；不设数量、长度或撤回配额 | 没有加入证明成功或多案例的硬门槛 |

## 发现并修订的三处歧义

1. **Diagnosis 的合理路径保护可能被读得过于保守。** 原新增表述要求偏好不能 suppress other reasonable paths，可能被理解为任何偏向都不允许。改为允许条件性偏好优先考虑某条合理路径，但不能将可见证据仍支持的其他路径无条件排除；仍需说明依据与限制。没有改成“存在歧义就必须更新”。
2. **只在 Diagnosis reason 中引用的证据不会传到 Preconditioner。** 原文说明 Plan 引用决定可见 runs，但没有直接提醒 reason 不会转发。补充要求将决定范围的支持或反例的直接引用放入相关 Update basis。依据是现有 `preconditioner_input` 仅从 `diagnosis.plan` 提取执行引用，而模型输入不含 Diagnosis reason。没有增加字段或强制复制全批证据，也不把理由正文塞入 Skill。
3. **联合编辑归因不确定可能成为 KEEP 的笼统借口。** 将“为什么仍合理”明确为指出仍支持当前范围与强度的依据，并说明不确定归因本身不是 KEEP 的理由。这不意味着联合编辑记录中的每个反例都必须导致撤回。

三处修订分别收敛过度保守、证据传递遗漏和审核动作落空的风险，不引入新算法变量。

## 接口与职责审查

阅读了现有 [SearchQA 证据投影](../../../src/skill_evolution/v28/benchmarks/searchqa/evidence.py)、[Update 编译](../../../src/skill_evolution/v27/update_patch.py) 和 [基线 Editor Prompt](baseline/prompts/editor.md)，确认：

- Diagnosis 只接收 Parent、当前 runs 和 grouping；历史 Memory 的使用仍归 Preconditioner，没有新增 Candidate 或历史读取要求。
- Preconditioner 接收 Plan 所选 runs 和 Knowledge 视图，不接收 Diagnosis reason，也不能自行扩大历史证据权限。basis 的新增提醒符合此输入路由。
- 调整 patch 的对象是 Original Update 文本。修改 Parent 的要求可以写入该文本，由 Editor 实现；不需要新增 Parent patch 字段。
- `normalize_update_patches` 对 Update 文本应用修改并编译有效计划；Editor 模型输入只有 Parent 和有效 Plan。两个 Prompt 均要求行为条件进入 Update，Checks 只用于未来观察。
- 原 Editor 已要求共同实现所有有效更新、修改冲突 Parent 文本、保留无关指导、且不将编辑说明写进 Skill。因此新版不依赖额外的 Editor 有效性判断。
- KEEP、部分修改、部分撤回、全部撤回及 Checks 的继承／清空契约保留；Goal 和 Original ID 的边界不变。

这里只检查了代码路径与文本含义，未执行完整编译链或恢复流程；运行级验收留到第五步。

## 合成情形的人工推演

以下是指令应导向的处理，不是模型实测结果；没有使用真实 Test 题作为示例或夹具。

| 情形 | Diagnosis 应如何提出 | Preconditioner 应如何审核 |
|---|---|---|
| 对象与关系正确，仅多出类别词 | 形成边界修正；不附带通用关系选择规则 | 删除无独立依据的关系切换，保留有依据的边界修正 |
| 同一名称有多种合理表述，只有参考偏好其一 | 区分形式差异；无可迁移条件时允许不提出该方向 | 不把单题 EM 不匹配当作通用名称优先级依据 |
| 只有一例支持合理条件性偏好 | 可提出尚未验证的更新，交代范围和强度 | 可以 KEEP；不要求多例、撤回或额外 Actor 验证 |
| 历史方向有效，但新提案扩大到整个题型 | 原提案仍须说明扩张依据 | 缺少依据时实际收窄 patch，不仅修改理由 |
| 相关反例与联合编辑混杂 | 不要求 Diagnosis 获取该历史 | 依据 Knowledge 判断是否修订；保留必须说明仍适用的支持，不靠“无法归因”兜底 |
| 当前输入没有证明指导缺失，Parent 已有相同要求 | 需要具体决策增量，否则可 no_change | 不将重复指导留作无效新增；不为保留提案发明独立修复 |
| 旧 Parent 条款过宽而多个新 Update 受影响 | 明确需要修订的相关指导和必要边界 | 协调相关 Originals；Editor 通过现有有效计划完成修改 |
| 多项更新分别合理、相互兼容 | 可同时提出多个更新 | 可以全部 KEEP，不人为压到固定数量 |

## 范围、冗余与泄漏检查

- 新增规则集中于判断顺序、迁移依据、强度及动作落实。保留了一些跨模块相同原则，因为 Diagnosis 负责提出，Preconditioner 负责用不同输入审核；没有为消除文字重复而削弱任一模块的边界。
- 没有新增实例名称、具体答案映射、任务 ID、测试措辞补丁或需要运行时读取测试数据的条件。裸标题／口号／作品列表是用户要求约束的通用形状，文本不规定它们应回答某个固定关系。Actor 协议中的原有示例保持原样。
- 不需要额外工具、Actor 调用、评分反馈补答、输出字段或执行阶段；不增加哈希门槛。
- 不要求必须修改或撤回；不设 Update 数量与 Skill 长度上限。合理但未验证的规则与 no_change 均保留。
- Diagnosis 从 1,669 增至 2,227 个空白分隔词（约 +33.4%）；Preconditioner 从 2,470 增至 2,990（约 +21.1%）。这是 Prompt 文本规模，不是模型 tokenizer 结果或最终 Skill 长度。新增篇幅有对应判断用途，但可能增加遵循负担；本轮没有用长度门槛压缩它，实际影响待实验观察。

# v27.14 · 从失败任务提出并复核 Skill 更新

当前版从父版答错的任务出发，检查训练中提出了什么修改、历史证据怎样影响复核、最终文字是否准确表达提案。相对 v27.13，本次修订涉及三个模块。各模块的数据接口、编译器、Actor、Gate、Memory 和训练预算沿用原设计。[v27.13 参照设计](../v27_13/README.md)

| 模块 | 当前指令 |
| --- | --- |
| [Diagnosis](prompts/diagnosis.md) | 对照错题、实际提交、参考答案与父版，找出可由同一修改改善的任务。在代表题上说明作答时能做出什么改变，再用同批正确题和其他相关记录检查适用范围。 |
| [Preconditioner](prompts/preconditioner.md) | 依据提案本身复核。核对历史收益或回退具体支持哪个动作，区分规则缺陷与重复提案，并用证据说明任何改写。 |

| [Replay](prompts/replay.md) | 沿用 v27.13。按逐题作答变化记录归因及其不确定性。 |

## 复核怎么做

先在同一道题、同样可见的信息下比较 Parent 和 Original：什么条件触发，允许选什么，何时可以提交，什么发现允许改选。用当前作答记录核对这个差异。一个错误字母可以说明交卷结果；只有当 Parent 的措辞、范围和优先级都已经明确时，才有理由判定再写一遍同样的动作属于重复。仅凭字母无法知道 Actor 是否做过某项检查。

读 Memory 时，将历史更新中的每个分支和实际观察到的作答变化对照。沿用有增益的动作，遇到有依据的回退则调整适用范围。若更新同时包含默认动作和改选例外，默认动作的增益不能同时充当恢复例外的依据。联合候选和只有 EM 翻转才形成的记录，都限制了历史归因。

| 裁定 | 依据 | 传给 Editor 的内容 |
| --- | --- | --- |
| KEEP | 新旧规则在适用场景下确实导向不同动作；原案有证据支持，已交代关键边界。 | Original 原文。 |
| REPLACE | 某个动作或条件存在具体缺陷，能以当前样例、历史转变、题目明确要求或实际规则冲突说明。只修复必要分支。 | 完整的新指令。范围与优先级写在正文中。 |
| WITHDRAW | 父版已在同一范围、同一时机要求相同动作，或证据无法支持该问题内可复用的变化。 | 该提案退出本轮有效计划。 |

若 Original 有意修订旧条款，Editor 可以在原处替换。若新旧指令相遇时仍给出冲突动作，Preconditioner 应在有效指令中明确谁先执行及何时适用。每个 Original 沿用原 ID 和 basis，裁定理由仅供审计。[现有编译实现](../../../src/skill_evolution/v27_1/preconditioner.py) · [Editor 指令](prompts/editor.md)

当前复核沿用第二版确立的两次比较。先比较 Parent 与 Original，判断提案有无实际变化；若拟裁定 `REPLACE`，再比较 Original 与复核拟写的正文。对每个新增、改写或删去的分支，理由应给出二者何时采取不同动作，并说明哪条证据支持改写后的动作。可以用本轮样例、历史作答变化、题干要求、另一条仍然有效的指令或从题面可验证的推导。原条款的存在只能证明提案改变了它。若原案有证据支持，复核只能设想某种情况下旧动作也许正确，则保留原案，把这种可能记在理由里。

## 三个行为验收案例

下列预期用于人工核对模块输出。案例、预期裁定及历史测试分数均置于方法提示词之外。

| 案例与提供给复核的证据 | 预期裁定及判断标准 |
| --- | --- |
| **历史 R05**。使用 [归档的复核输入](../../../artifacts/methods/v27_13/v27_13_lmb53_20261124/rounds/R05/preconditioner/input.json)，保留当时的 Parent、Original、转发执行和 Memory。Original 收紧了以具体选项取代默认答案的条件。相关历史增益出现在转向默认答案的方向。 | **KEEP**。理由应指出被删除的是哪项改选许可，以及历史样例实际支持哪个动作。检查编译后的正文是否逐字等于 Original。 |
| **历史例外，有记录的回退**（合成）。Parent 要求遵守题面指定的舍入方向，未给出方向时只要求比较两个邻近值。当前多道中点题未指定方向，参考答案均采用同一默认方向，Parent 在其中漏选。Original 提议一遇中点就采用默认方向。Memory 记录过一道明确指定相反方向的中点题，父版遵照题面答对，采用默认方向的联合候选答错，Replay 将翻转关联到这项修改。 | **REPLACE**。修改后的完整指令须优先遵照题面的方向，在未指定方向的中点才允许用默认。理由应引用该回退并保留对联合候选归因的不确定性。 |
| **父版已有明确动作**（合成）。Parent 要求两区间仅在端点有别时，提交前把端点代入原条件，以结果决定开闭。当前题的选项只在同一端点开闭上不同，Actor 交了错误字母。Original 用同样的范围、时机和动作重新要求代入该端点。 | **WITHDRAW**。理由应指出覆盖该动作的父版条款。可记录执行原因未知。 |

历史回放只替换复核系统消息，固定用户消息。后续若实跑 Editor 和 Actor，核对首个允许提交的位置、触发以外的原条款，以及 R05 同批 6 道触发题与 4 道普通题的逐题得失。Gate 只统计归因到更新的翻转，分组结果取全批记录，包括无法归因的翻转。

**前两版复核的 R05 回放。** 这些回放使用本次三模块修订之前的系统提示词。第一版裁定 `REPLACE`，恢复了父版的改选许可。第二版首次返回 `KEEP`，因 Memory 引用格式未通过校验，按原协议重试一次，再次返回 `KEEP` 并通过校验。有效计划与 Diagnosis 原案逐字一致。第二版引用的 M4–M6 是转向目标选项后的增益；M9 则是从正确目标选项切换到具体选项后的回退。该结果检验了此次复核，尚未测量 Actor 的作答变化。[第一版裁定](../../../experiments/analysis/v27_14_r05_frozen_20261124/preconditioner/attempts/001/parsed.json) · [第二版裁定](../../../experiments/analysis/v27_14_r05_preconditioner_v2_frozen/preconditioner/attempts/002/parsed.json)

## 正式比较

使用与 v27.13 相同的初始 Skill、初始 Memory、53 道优化题、顺序和五轮批次（11、11、11、10、10），按原 Gate 选择最终 Skill。逐轮追踪 Diagnosis 首次提出的改动及其错题依据、Preconditioner 的裁定和 Editor 实际写入的文字。冻结 R05 复核的输入已包含旧版 Diagnosis 原案，只能检验如何复核已有提案。训练模块从各自可见的训练输入学习；触发文字和目标答案都不写入模块指令。静态归档检查、模型复核回放、完整训练和最终测试分别记录。

冻结最终 Skill 后，按预先约定的复测次数，让两版本在相同的 Actor、预算和重试协议下作答同一批 124 题。逐次报告含目标选项的 53 题正确数，以及其余 71 题正确数、配对增益和回退。理想结果是各次均达到 53/53，且其余组的平均正确数至少与 v27.13 持平。另列未完成数与预算偏离，不能用一次全对或总体净增替代两项结果。该测试集已经用于方法分析，以上结论仅针对这批历史题。

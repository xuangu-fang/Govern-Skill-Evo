# V23.4 D/S/C 决策规则

- 更新日期：2026-10-21（Asia/Shanghai）。
- 对应契约：[v23_4_transformations_v2](INPUT_OUTPUT_CONTRACT.md)。
- 状态：第二步规则与人工案例；第四步已补齐[完整合成材料与离线走查](OFFLINE_REVIEW.md)。Prompt 源文件见 [preconditioner_prompt.md](../../../src/skill_evolution/v23_4/preconditioner_prompt.md)。未验证模型遵循率或行为收益。

## 1 决策单位与执行顺序

以每个 Original Update 为处理单位，以其中需要改变的行为要求为语义对象。每项只输出一条综合 Adjustment，不建立行级权限、候选池或额外 Agent。需要协调时同时考虑其他 Updates 和 Parent，但不重新开展整批 Diagnosis。

决策依赖为：当前要求及改善目标 → 可比较的实际编辑与响应 → D/S/C 判断 → change 与 reason → Patch。先决定要改变什么以及为什么，再写 Patch；不能先自由生成替代策略，再为结果补 D/S/C 标签。一次调用不能保证内部思考顺序，验收依据是这些环节的实质对应，而不是字段顺序或解释长度。

| 步骤 | 需要得到的判断 | 对输出的影响 |
|---|---|---|
| R1 明确当前问题 | Update 改变什么行为、为何需要、Parent 已覆盖什么、Goal 要保留什么 | 确定 target 对应的具体语义对象 |
| R2 对应历史响应 | 历史真正修改了什么、观察到什么、条件是否可比较、能否定位作用 | 决定哪些事实能支持、限制或仅启发当前变换 |
| R3 判断 D | 应继续推动什么行为方向，哪些方向需要重构或撤回 | 决定 change 的行为取向 |
| R4 判断 S | 哪些条件、许可、限制或强度应扩大、收窄或重构 | 决定 change 的适用方式 |
| R5 判断 C | 与 Parent/其他 Updates 存在什么冲突、缺口或重复 | 决定必要协调与保留边界 |
| R6 综合决定与保留检查 | 改完是否仍有改善作用，是否应 Keep，哪些实现仍是假设 | 每项一个 Adjustment，focus/change/reason 表达 D/S/C 决定，focus 仅列实际决定了变换的维度 |
| R7 实现与核对 | Patch 是否完整实现 change，是否额外引入新要求 | 一个对冻结 Original 的 Patch、撤回或显式 Keep，以及 Checks |

D/S/C 可以相互修正，不要求机械执行一次固定的 D→S→C 扫描，也不要求输出三段分析报告。发现协调冲突后可以重新考虑方向或条件，最终仍只提交一套变换。reason 给出简短可检查的决策依据，不要求披露完整推演过程。

## 2 R1 与 R2 当前问题和历史对应

先区分原始提议、Parent 已有指导、Editor 实际写入的修改和 Actor 实际行为。Original 尚未执行，不能把历史 Parent 或相似条款的表现直接当作它的执行结果。当前失败也不自动证明缺少规则，可能是未遵守已有指导、环境变化或技术中断。

历史对应遵守以下规则：

1. 阅读相关 Memory 的历史 Parent 与实际 Diff，再解释行为响应。knowledge 是可修订理解，若与可见来源不符，应依据来源校正该部分，不丢弃其他有效观察。
2. 比较行为决策、任务阶段、前置条件、可见信息、目标粒度、执行协议与预算。文本或任务名相似不足以迁移结果；会影响结果的差异必须进入 reason。
3. 正面与负面响应一起保留。任务成功不证明所有条款有用，失败不证明所有条款有害；局部改善与整体结果分开看。
4. 联合编辑只支持联合响应，除非来源足以区分单项作用；一次配对不证明稳定因果。没有显式可靠的配对信息时，不从 P/Q 编号或数组顺序推断配对。
5. 历史来源、动作、状态仅按实际模型视图使用；不得跨压缩缺口补状态，不把事后发现当作行动前知识，不把“未找到”当作“不存在”。
6. 无关历史不强制改变要求；证据不足可以保留合理提议或支持待验证探索。直接用当前事实纠正的问题必须如实说明，不能记成 Memory 独有贡献。

历史正面响应可以提供发展方向，负面响应可以暴露方向、范围或协调问题。它们不是自动加减规则：先定位问题，再决定变换。

## 3 R3 方向决定

D 判断原始要求试图增加或减少的行为，是否仍服务于 Goal，以及当前问题是否需要不同的行为方向。

| 证据与问题 | 可以支持的方向决定 | 不能直接推出 |
|---|---|---|
| 可比较的正面响应，当前仍有同类缺口 | 延续或强化有支持的行为关系；把有益行为表达得更明确 | 越强越好、所有条件下都应强制 |
| 同一方向产生混合响应 | 区分有益作用与副作用来源，保留有效部分或重构限制对象 | 删除全部方向，或无条件保留原实现 |
| 当前要求约束了错误的行为对象 | 将要求转向与改善目标更直接相关的行为 | 新对象的识别方式已经被验证 |
| 问题持续且旧方向未解决，存在具体替代动机 | 提出与 Goal 相关的新方向，并说明待验证部分 | 历史失败证明替代方向必然有效 |
| 方向有害、冗余或保证性主张无依据 | 修正或撤回，核对必要行为仍有覆盖 | 为规避失败而撤回所有探索 |

方向不变时仍可以进行 S/C 变换，不必为了填 focus 额外改变方向。仅把同一行为的触发条件改窄通常由 S 表达；如果限制对象本身改变，D 可以与 S 同时出现。标签边界不要求互斥，但每个所列维度都应对 change 有实际贡献。

## 4 R4 范围与强度决定

S 决定已选方向应怎样生效，既可以减少限制，也可以增加有支持的要求。

- **收窄**：原触发把有重要差异的情形混在一起，反例支持一个可观察的区分。保留真正改善问题的触发范围，不堆叠无依据例外。
- **扩大或解除限制**：原前提排除了有依据、合法且与目标相关的机会；可扩大许可或加入有用分支。允许一种行为不等于规定它始终优先。
- **调整强度**：证据可以支持优先、允许、避免或必须之间的合理调整，但单个成功序列不证明所有前置动作必需，也不证明强制程度越高越好。
- **重新确定条件**：原条件依赖不可恢复的全局状态，或划分本身不合理时，可以提出更合适的可观察条件。替代条件必须保留预期改善作用，不能把局部信息冒充完整历史。

新条件、阈值、排序和结束标准是策略的一部分。必须在 change 中声明，若属于探索则在 reason 中说明；不能让 Patch 在措辞落实时独立发明。历史缺少最优阈值不禁止合理探索，也不支持把任意常数当成历史结论。

## 5 R5 协调决定

C 检查所选方向与条件能否和其他指导共同生效。对每项拟议配套，问：若保持相关旧要求不变，主变换是否仍能实施，是否会破坏必要行为？

| 发现 | 可以采取的协调 | 边界 |
|---|---|---|
| 一项允许的行为被另一项无条件禁止 | 同步修改各自 Update 的条件或优先关系 | 两项 Patch 均针对各自 Original；不遗漏其中一项 |
| 主变换缺少必要前提、后续行为或原有能力保护 | 在相关已有 Update 内补齐必要要求 | 说明具体依赖，不借机发明独立策略 |
| 多项要求重复或累积例外遮蔽共同原则 | 在保留有效差异的前提下整合语义，必要时撤回冗余 Update | 第一版不创建新 ID 或结构拆合；不得把文字冗余直接当行为无效 |
| 配套只是可选改进，主变换不依赖它 | 有独立当前问题和依据时可纳入综合变换 | 如实称为独立探索，不能借主变换的证据冒充必要性 |

若 S 已解决冲突且没有额外协调变化，就不因“检查过协调”而把 C 写入 focus。若 Parent 已有必要指导且不冲突，可以保留它，不自动重复增加要求。

## 6 R6 综合变换与 Keep

合成前检查三个问题：是否仍针对原始改善目标？是否仍有可识别的生效情形与有用作用？是否保留必要行为？不以更少修改、更短文本或更多例外作为成功标准，也不要求为展示历史使用而强行修改。

每个 Original Update 直接对应一个 Adjustment，包含 target/focus/change/reason/to；不单独生成 Transformation 对象或增加生成阶段。同一个 Update 的多项变化写在一条 change 中，focus/change/reason 共同表达 D/S/C 更新决策，to.patch 落实具体修改。允许有根据的大幅重写、强化、扩大和探索。focus 只列实际决定了修改的维度；可以是一个或多个。语义维度存在重叠时，重在判断与 change 对应，不追求唯一标签组合。

Keep 必须是明确决定：`focus: [] / change: "KEEP" / to: null`。需要说明当前为何保留；若存在重要反例，说明它已被当前条件覆盖、与当前要求不相容，或不足以定位其作用。必须有具体差异，不能把所有反例都称为“证据不足”。没有适用历史时可根据当前问题保留 Original，不声称它已经被证明有效。

历史负面响应支持撤回旧要求，不自动证明替代策略；历史正面响应支持发展某方向，不自动授权新的终止条件。探索可以来自历史类比与当前问题，但与已知事实分开。必要能力唯一依赖某项要求时，撤回必须同时解决覆盖问题，不能仅靠 checks 补救。

## 7 R7 Patch 与检查

先形成具体 change 与依据，再编写 target 对应 Original 的 Patch。整项撤回使用 `to: []`；在原 Update 内新增行为要求可使用插入 Hunk。保持 Goal 不变，不编辑 Parent 正文，不引入新 Update ID。

核对两个方向：change 中每项实质决定都落实；Patch 中每个新增或改变的行为要求都被 change 覆盖。文字简化不必逐词记录，但改变触发、强度、顺序、退出标准或能力边界属于实质变化。若实现过程暴露出未考虑的行为选择，应重新作 D/S/C 判断并让 change/reason 与之保持一致，不能保留已经无依据的 Patch 再补装饰性标签。

checks 保留原表或完整替换，只引用存活 Updates。必要指令必须在最终 Update 中，不能只存在于理由或检查问题里。全部 Keep 仍进入 Editor；全部合法撤回才得到 null Effective Plan。任何技术错误不得修饰成 Keep。

本协议没有成功的弃权输出。已识别的不可消解 Goal 冲突或无法形成合法 Plan 的情况是失败，不能用 KEEP、全部撤回或旧 need_evidence 字段伪装。没有额外错误 JSON；未来运行与审查层负责保留失败事实。结构校验不能保证发现语义冲突，本步不实现自动语义审核。

## 8 人工案例走查

以下 8 例均为合成的设计材料，不是已有实验事实、模型输出、完整六字段运行 fixture 或唯一正确答案。每例假设所述编辑、前后行为与可见条件都已提供；若用于未来模型输入，必须补齐真实或明确标记的合成来源，不能把这里的叙述当作历史证据。案例编号不进入通用 Prompt。

### A1 局部反例支持收窄

- Original：任何失败动作都立即再试一次。Goal 是减少无效动作并完成任务。
- 当前与历史：在前提未变时，实际加入重试指导后出现重复失败；前提已修复后的重试出现成功。Actor 当前可见前提是否改变。
- D/S/C 判断：保留“恢复后继续尝试”的方向；S 区分未变与已修复的前提；没有额外协调冲突。
- 一种合理 change：前提未变且没有新反馈时不重复；前提可见地修复或新反馈支持时允许重试。focus 可为 S。
- 不可接受：所有失败永久禁止重试；或无依据地规定“恰好重试三次”。
- 证据敏感性：若反例实际发生在前提修复以后，不能继续用“前提未变”解释它，应重审触发条件。
- 改善作用：既减少无效重复，也保留恢复后的推进机会。

### A2 混合响应支持方向重构

- Original：禁止返回任何访问过的位置。
- 当前与历史：实际全局回访限制伴随空转减少，但必要搬运返回受阻；任务需要的目的地由当前观察可识别。
- D/S/C 判断：D 将抑制对象从“返回”转向“无信息、无任务进展的重复”；S 明确可观察触发与必要返回边界。若已不与交付要求冲突，不再额外增加 C 条款。
- 一种合理 change：避免当前及近期观察所支持的无信息重复，保留可见任务需要的返回；具体识别方式仍为待验证假设。
- 不可接受：不断追加各类任务例外却保留错误的总括禁止；或借此增加“所有类别查完才结束”。
- 证据敏感性：删除必要返回的负面观察后，不能再引用它作为重构依据；相同改法若仍由当前事实支持，应改写理由，而非强制改变结果。
- 改善作用：尝试形成覆盖更广的有效规则，而非把原规则逐步削到失去作用。

### A3 正面响应支持扩大许可

- Original：只有来源 A 可用时才获取所需信息，否则等待。
- 当前与历史：实际增加来源 B 的使用许可后，在 A 不可用且 B 当前可见、具有任务所需信息的条件下完成了获取；未观察到所有来源都可互换。
- D/S/C 判断：获取所需信息的方向不变；S 扩大到可见、适用的替代来源，解除对 A 的独占前提。
- 一种合理 change：A 不可用而有可见且适用的替代来源时允许使用它，保留信息有效性检查。
- 不可接受：永远优先 B，或允许忽略信息质量；也不能因为没有所有情形的证明就拒绝任何扩大。
- 证据敏感性：若 B 的正面响应来自不同质量要求，直接迁移理由不成立，可以保留为待验证类比。
- 改善作用：新增可推进任务的机会，不把 S 约等于收窄。

### A4 必要协调与配套新增

- Original：u1 要求准备完成后再次尝试；u2 要求发生任何失败就放弃该动作。
- 当前与历史：历史实际加入“修复后重试”时，保留的无条件放弃条款仍阻止重试；当前可见的反馈区分前提未满足与已修复。
- D/S/C 判断：D 保留修复后推进的方向；C 识别 u1 与 u2 的直接矛盾；S 重新限定 u2 放弃条件。如果修复可能改变就绪状态，还需在 u1 中补充尝试前重新检查当前前提的配套要求。
- 一种合理输出安排：u1 的综合 change 说明修复后重新检查并重试；u2 的综合 change 允许前提已修复后的重试。分别生成两项 Adjustment，原子化应用。
- 不可接受：只改 u1；或把恢复前提的依据用于新增与重试无关的全局调度策略。
- 证据敏感性：若 u2 原本已明确允许修复后重试，就没有同步修改它的必要，可以对 u2 Keep 并说明原因。
- 改善作用：让有希望的修复机制真正能生效，C 不只是删除冲突文本。

### A5 反例已被条件覆盖的 Keep

- Original：仅在前提未变且没有新反馈时避免重复动作，前提改变后允许再试。
- 当前与历史：Memory 的负面观察针对“任何失败后永不重试”，其中前提修复后的合法重试受到阻碍。
- D/S/C 判断：当前方向服务于减少无效重复；S 已排除该反例；与其他要求无新增冲突，因此不实施变换。
- 一种合理输出：focus 为空，change 为 KEEP，reason 指出“永久禁止”与“仅在前提未变时限制”的具体差异。
- 不可接受：只写“历史证据不足”；或为显示使用了 Memory 再加一个无关例外。
- 证据敏感性：若新反例发生在当前条件内部且确实需要重复，原 Keep 理由不再成立，必须重新判断。
- 改善作用：保留已经合理的规则，避免无效编辑；不把 Keep 当作已验证有效。

### A6 历史启发但未验证的新探索

- Original：始终耗尽当前可选分支后再切换。
- 当前与历史：实际扩展探索范围曾带来进展，但伴随遗漏仍有价值分支；当前轨迹也出现长时间停滞。联合编辑不能定位独立效果，没有证据支持最优顺序或阈值。
- D/S/C 判断：D 探索更及时地重新分配尝试方向；S 基于当前及近期无进展信息允许切换，同时保留有用分支的资格；不把一次采样当作完成证明。
- 一种合理 change：出现可见的持续无进展且有合理替代选择时允许切换，不要求先耗尽；具体切换判定是探索，需要在 change 中明确所选实现。
- 不可接受：声称历史证明某固定顺序最优；或因为新策略未验证而一律 Keep/撤回；也不能只写“持续”而让 Patch 私自决定新阈值。
- 证据敏感性：移除历史正面响应后，不能继续宣称历史支持扩展；当前停滞可能仍支持探索，但理由应相应变化。
- 改善作用：对未解决问题提出有边界的新方案，而非只保留已知安全小范围。

### A7 证据不足与未落实的编辑

- Original：提出对某类重复错误的改进。Memory 同轮包含多项意图，但 actual.diff 没有落实被指称有害的那一项；另一条记录还缺少关键状态详情。
- D/S/C 判断：不能将意图当作实际干预，也不能跨状态缺口证明条件相同。先利用仍有效的当前事实；可 Keep 合理提议，或作明确标为当前事实驱动的修正。
- 一种合理结果：解释为何该历史归因不能支持当前撤回，不宣称“历史证明无害”。若实际指导已落实但 Actor 未遵守，也不能自动把原措辞改得更强。
- 不可接受：仅因整体 Candidate 失败就删除当前要求；或者虚构缺失状态来完成理由。
- 证据敏感性：若提供了真正落实该要求的 Diff 与相关响应，应重新进入 D/S/C 判断，不沿用原来的排除理由。
- 空 Memory 边界：同样允许基于当前事实 Keep 或合理变换，reason 不引用虚构历史。

### A8 撤回与失败不能混同

- 合法撤回情形：Original 重复增加 Parent 已完整覆盖的要求，当前事实未提示其措辞或落实有问题；C 判断支持撤回冗余提议，reason 说明必要能力仍由 Parent 提供。to 为空数组，Checks 迁移按契约执行。
- 相反情形：该 Update 是必要行为的唯一覆盖；不能仅因收益未知而撤回，必须保留、修正或补齐覆盖。
- 无合法 Plan 情形：不可修改的 Goal 强制要求与必要修正矛盾，且不存在一致实现。人工语义检查应判失败，不输出旧 need_evidence，不把所有项伪装成 Keep 或撤回来逃避问题。
- 程序边界：最后一种冲突不保证被结构校验自动发现；失败保留与识别方式属于后续运行实现，本步不伪造成功响应。

# V25.2 优化方案草稿

版本日期：2026-11-01。状态：已按三项审查意见修订并完成静态与语义复审，尚未接入运行配置或启动实验。

## 目标与改动范围

V25.2 通过 prompt 提高 Update 的选择质量，减少 Skill 中低价值、重复和过度细化的要求。Diagnosis 控制本轮值得提出哪些修复，Preconditioner 改善修订方式，Editor 沿用 V25.1。

| 模块 | V25.2 处理 | 职责边界 |
| --- | --- | --- |
| Diagnosis | 主要修改：整批最多 2 个 Update，按独立价值筛选 | 不为覆盖所有失败而提出修复，不把多个独立修复打包绕过数量限制 |
| Preconditioner | 小幅修改：一处指导段落，要求有价值的行为增量，优先替换或合并 | 保留 D/S/C 与历史 Knowledge 的作用，不另做 Diagnosis、不增加数量筛选流程 |
| Editor | 与 V25.1 逐字节一致 | 忠实实现有效 Plan，沿用已有简洁、合并和去重要求 |

模块顺序、D/S/C、JSON/patch 合同、Gate、Memory/Replay、Actor、数据顺序、评估方式和运行预算均沿用 V25.1。不增加历史任务重跑、额外验证集、稳定性复测、程序数量校验、自动截断或新的重试规则。

本稿不修改 V25.1 冻结实验、当前运行源码或实验配置。

## 实验依据

本稿针对 Actor 对齐的 V25.1 与 SkillAdam 实验。完整测试分别通过 223/280 与 229/280；最终 Skill 按空白分词分别为 3,106 与 334 词。单次测试的准确率差距不能证明各模块的独立因果贡献，但 Skill 增长值得检查。

V25.1 八轮 Diagnosis 提出的 Update 数量依次为 **4、2、3、3、4、4、1、5**。被接受的 R03、R04、R05、R06、R08 分别含 3、3、4、4、5 个 Update；多方向同时进入 Plan 的问题首先出现在 Diagnosis。

Preconditioner 共处理 26 个 Update：11 个原样保留，15 个修改，没有撤回。15 次修改全部使文本变长；跨轮 Update 文本合计从 3,189 词增至 3,924 词，增加约 23%。这是提议文本统计，不等于最终 Skill 的长度增量；零撤回也不意味着必须设置撤回指标。

具体记录显示两类修订同时存在：

- **必要边界。** R03/u2 修正“所有目标单元格必须非空”的要求，允许任务预期的空值。该边界应保留，但可避免在多个条款重复展开。
- **重复扩写。** R06/u3 原文已经要求已有等价记录不影响继续追加；调整又追加一条完整记录不得抵扣的要求。其协调目的合理，更适合改写原条款并明确优先级。对应任务后来通过，但未单独比较原始与调整后的 Update，不能证明追加文字独立有效。

R04/u1 的静态值 fallback 还提示：补救策略必须保留任务要求。需要公式的任务不能仅为保证读回非空而降级为静态值。V25.1 Preconditioner 已有这一语义约束，本稿保留，不再追加一套重复要求。

## Diagnosis：控制提议数量与独立价值

1. **整批最多 2 个 Update。** 一个足够就只选一个；没有值得修改的内容时返回已有的 `no_change`。上限不是必须达到的目标。
2. **按价值筛选。** 综合当前证据与行为问题的联系、跨实例用途、增加的 Actor 指令和执行负担，优先选择值得尝试的修复。第二条需要自己的依据，不能借第一条的合理性进入 Plan；有独立价值的第二条仍可保留，不因它不是第一条的必要组成部分而删除。
3. **不打包绕过限制。** 一条 Update 对应一个清楚的行为问题，保留必要耦合要求，不塞入独立修复。不把未选中的要求放进 Goal 或 Checks。
4. **避免规则累积。** 去除单项修复内部重复、缺乏依据的附带要求；需要修复时优先修改或替换相关规则，并保留完整表达变更所需的边界。解释放在既有 `reason` 中，证据引用放在 `basis` 中，Update 保留可执行要求。

同步替换原文“不限制 Update 数量”和“不要仅因减少数量而省略修复”的要求，并使 `revise` / `no_change` 的选择表述与筛选原则一致。输出字段、引用格式和 patch 合同不变。

数量上限仅为 prompt 指令，没有新增程序强制保证。单例可以暴露可迁移缺陷；不要求每条修复必须有多例，也不要求在提出之前已经证明有效。

## Preconditioner：以必要修订代替重复追加

只替换第 4 节中的一段指导，保留其余模板与职责。新增到 Update 的行为要求需要说明：它使 Actor 做出什么不同的行为，以及为什么这项差异对当前 Update 有用。

- “更完整”“更保险”不足以单独支持增加行为要求，包括 Actor 程序内的验证步骤。
- 上述要求不用于 Plan 的观察性 Checks；它们仍可按原有规则观察效果、成本和不同解释，无需直接改变 Actor 行为。
- 避免无效重述，同时保留说明适用范围、优先级和保留边界所必需的最少文字；Parent 已有相关行为，不意味着 Update 不能明确协调边界。
- 歧义、适用范围或优先级需要修正时，优先替换或合并相关表述，避免追加平行规则。
- 支持理由留在 `reason`，必要的行为条件仍写入 Update，保证 Editor 能完整实现。

仍允许 Keep、修改和撤回，允许基于证据发展有潜力的方向。不要求每次都缩短、不设置撤回比例，也不为了短而删除必要依赖、适用边界或任务要求。不限制其使用历史 Knowledge，不增加新的输出字段或审查阶段。

这项调整约束修订方式，不能替代 Diagnosis 的源头筛选，也不能保证 Skill 每轮不增长。

## 2026-11-01 修改后复审

本次只修正三项审查意见：必要边界不受绝对去重禁令限制；新增行为要求与观察性 Checks 明确区分；单项修复内的无依据附带要求与独立成立的第二个 Update 明确区分。Diagnosis 同步将“较弱的伴随提议”改为“无依据的伴随提议”，避免把相对收益较低但仍合理的第二项误删。

以下为基于完整模板的语义审查，不是模型运行测试：

| 审查情形 | 修订后的处理 |
| --- | --- |
| 修改追加规则时，需再次明确保留已有行 | 允许保留界定作用范围和协调关系所必需的文字，不因 Parent 已有相关要求而删除 |
| 新增“是否增加执行成本”的观察性 Check | 沿用原有 Checks 规则，不要求它直接启用或阻止 Actor 行为 |
| 第二个 Update 与第一项无依赖，但有独立证据和价值 | 可在最多 2 条的约束内保留；单项修复内部的无依据附带条款仍需去除 |
| 历史 Knowledge 支持扩大适用范围或尝试新方向，但尚未证明成功 | 原 D/S/C 与合理探索条款保持原文，不增加必须已有成功证据的要求 |
| 修复需要补充必要依赖，文字因此变长 | 允许增加必要内容，不要求每次缩短或撤回 |

复审未发现此次修订新增的明确冲突或职责变化。Preconditioner 对方向、范围、协调关系的调整能力，历史 Knowledge 的利用，Keep/修改/撤回与观察性 Checks 的处理均保留。Editor 不变。

静态检查不证明模型遵守提示词，也不证明 Skill 已缩短或测试效果已改善。当前没有运行模型验证、正式训练或测试。

# 通用版 v24.9 定稿：学习任务尚未完成时的下一步

## 研究目标

给定训练轨迹，当 Actor 做了一个合理动作、任务仍未完成时，能否学出一条它下次仍能执行的决策规则？研究者允许提示模型优先检查停滞、折返和重复尝试。验收看规则改变了什么行为，以及整题是否因此获益。模型是否在零提示下首先发现了该瓶颈，不参与评分。

| 历史同题实验 | 成功题数 | 总步数 | 全程未取物 |
|---|---:|---:|---:|
| v24.6 → 换入 v24.1 搜索段落 | 104 → 118 | 2,919 → 1,919 | 22 → 9 |
| v24.7 → 只改搜索段落 | 115 → 123 | 2,147 → 1,873 | 9 → 8 |

第一组提示应追溯取物前的选择，第二组提示即使最终拿到了物品，早期决策仍可能消耗完成后续工作的机会。两次都同时改变了若干搜索偏好，无法分别估计每条偏好的贡献。这些结论用于设计研究问题。两次实验的 Skill、Test 轨迹、题号、分数和手工排序均不进入正式模块输入。[第一组结果](../../../../artifacts/methods/v24_6/v24_6_alfworld_v24_1_search_swap_test134_20261108_012501/summary.json) · [第二组结果](../../../../artifacts/methods/v24_7/v24_7_search_continuation_only_test134_20261108_102755/summary.json)

## 四个模块

| 模块与完整英文系统 prompt | 决策与交接 |
|---|---|
| [Diagnosis](../../../../src/skill_evolution/v24_9/general/prompts/diagnosis.md) | 看当前 Parent 批次。从合理选择之后的停滞找到一个可改变的决策，用可见证据比较 Parent 仍允许的动作。也允许其他有充分依据的问题。若反复任选导致重走，可以提出一种稳定且能从菜单重建的选法作为待检验假设。依据放入 basis，行为写入 text；无合适提案时用 no_change。 |
| [Preconditioner](../../../../src/skill_evolution/v24_9/general/prompts/preconditioner.md) | 在同一窗口比较 Parent 和提案，再把同一措辞应用到另一处真实选择。一次性规则只核对触发和退出。检查它会不会打断原本成功的路线，以 KEEP、REPLACE 或 WITHDRAW 决定哪段有效文本交给 Editor。 |
| [Editor](../../../../src/skill_evolution/v24_9/general/prompts/editor.md) | 只接收 Parent 与有效计划。在实际支配该选择的 Skill 段落写补丁，可涉及通用原则或适用的任务段落。每个 ID 独立应用于原 Parent，保留其触发、优先级和退出条件。冻结的 Actor 模板和既有逐 ID 补丁协议继续生效。 |
| [Replay](../../../../src/skill_evolution/v24_9/general/prompts/replay.md) | 对程序提供的同题事件，对照实际补丁及两侧轨迹，沿着“可见线索 → 实际选择 → 后续进展 → 整题成败或步差”归因。若只解释局部差异，或联合候选内多个补丁无法区分，保留事件并记 null。 |

四个模块沿用 v24.7 的 JSON 接口和每轮调用预算。Diagnosis 看不到 Candidate 或历史 Memory。Preconditioner 只能读取提案引用的当前轨迹与既有 Memory，故支持规则边界的成功片段也要进入 basis。Editor 看不到轨迹和上游 reason，执行所需的条件必须写进有效 text。Replay 只用非空、实际执行过的补丁归因。程序按原 Gate 计票：只有成败收益时保留，只有退步时拒绝，两者都有则暂缓；没有成败票时，至少一票效率增益且无效率损失才保留。效率事件须双方均成功且步差至少 10。[Gate 实现](../../../../src/skill_evolution/v24_6/gate.py)

## 实验边界与版本隔离

以 v24.7 的共同 Initial Skill、空 Memory 和 Actor 为起点。Pick Two 的取放、计数与交付条款保留原文，包括共享原则中规范这些行为的条款；其他修改也须保留这些行为的原有含义。其轨迹仍可支持通用决策改进。若主要问题恰在保护范围，Diagnosis 可在 reason 中如实说明。审核可保留混合提案中独立且合规的部分；Editor 无法忠实实现的有效提案按原阻塞协议处理。

通用版的方法标识为 `alfworld_v24_9_general_v1`。训练入口为 `python -m src.skill_evolution.v24_9.general train --campaign <独立训练目录>`，测试入口为 `python scripts/runs/v24_9/run_v24_9_general_test.py --campaign <独立训练目录> --evaluation <独立测试目录>`。编排器使用项目的 Python 3.10+ 环境，Actor 使用既有的 alfworld 环境。编辑器逐条核对各个补丁及联合候选中的受保护条款，Gate 发布时再与 Initial Skill 核对。共享措辞的语义影响由 Preconditioner 和 Editor 审核。[搜索专项版](../DESIGN.md)仍有独立入口。

## 验收与正式运行

1. 离线用真实训练侧轨迹生成提案与审核结果。让模型看到完整的正常模块输入，人工复核时单独重建当前目标、观察、菜单和最近两步。至少审阅一个反复决策、一个一次性动作或退出边界、一个可能干扰原有成功的例子。可以使用 R04 的折返轨迹与 R05 的成功、失败片段；只要求其输出确实落在可见动作上，允许有依据的收窄、撤回和 no_change。脚本夹具与可执行性检查不能替代这次语义验收。
2. 正式训练一次，六批题量为 10、10、10、10、10、7，每题上限 50 步。追踪原提案、有效文本、候选实际动作、归因与 Gate 发布，最后核对相关规则是否保留在 R06。
3. 用 R06 最终发布的 Skill 对 134 道题各跑一次。**成绩线为至少 117/134。** 报告相对 v24.7 原版的赢回、丢掉、共同成功题配对步数及总步数。另报全程未取物数、灯下检查与 Pick Two 分项，用于理解收益与回退。123 是手工改段的一次参照成绩。
4. 方法结果单独报告：哪条训练产生的规则在真实窗口中改变了可选动作的优先级，经过一次未完成的尝试后如何继续，何时退出，以及整题结果有哪些证据可归给它。分数过线和行为证据是否充分分别给出结论。

# ALFWorld v24.9 设计方案：只学习搜索续行

## 1. 实验问题与起点

当目标还没拿到，刚检查的位置也没有目标时，Actor 能否仅凭当前位置、当前可选动作和最近两步，选出下一站？规则要在同类地点之间可用，也要在离开一类、进入下一类后仍能推进。最终产物是六轮训练实际发布的 Skill。

按本次讨论，**方法基线是 v24.7，正式训练从它使用的共同 Initial Skill 和空 Memory 开始**。v24.7 最终 Skill 是 115 题的成绩对照，也是上一次手工换段的底稿。从共同起点训练检验的是完整的自进化过程。从 v24.7 最终 Skill 接着训练则会继承已经学出的目的地偏好与开放表面优先，属于另一个实验。共同 Initial Skill 自带的 Pick Two 取放、计数和交付文本保留原文；v24.7 最终版另有“已见另一件时可直接返回”的搜索例外，不能把它记成共同起点已经具备的知识。

手工只换搜索段落的版本为 123/134，原版为 115/134。同题赢回 9、丢掉 1；Pick Two 从 9/17 到 13/17，灯下检查保持 18/18。该实验同时给同类与跨类选择加了顺序，尚不能分开估计两者的贡献。**正式成绩目标是至少 117/134；123 是行为参照。** 手工 Skill、Test 轨迹、题号及其具体答案都留在训练输入之外。[换段结果](../../../artifacts/methods/v24_7/v24_7_search_continuation_only_test134_20261108_102755/summary.json) · [v24.7 对照](../../../artifacts/methods/v24_7/v24_7_alfworld_20261108_020254_test134/summary.json)

## 2. 只开放一个编辑位置

在原则 2「Systematic exploration」内设一个可独立换行的搜索续行段，初始化时沿用 Initial Skill 原文。允许学习的内容是查空后的同类下一站、换类时机、跨类下一站，以及这些偏好何时让位给既有任务步骤。开容器看内容是检查的前提。看见可取目标，或开始拿取、处理、照灯、交付时，控制权交回原规则。新段不能通过重新定义“目标”“完成”或“可取”来改变这些行为。

Pick Two 的题正常参与。拿到第一件之前，或按原任务流程需要找另一件且眼下缺少可直接获取的目标时，这些轨迹可以提供通用的搜索证据。物品编号如何计数、从目的地能否取回、两件放在哪里、如何返回交付，均不进入更新范围。Editor 按原有逐 ID 补丁机制产出候选。构造候选和发布所选补丁时，用普通文本比较核对搜索段外逐字一致；段内夹带取放或交付指令由 Preconditioner 和 Editor 在语义上检查。独立更新改不同句，互相依赖才能执行的一组决策放在同一 ID。

## 3. 怎样让训练自己发现顺序

| 模块 | v24.9 的具体工作 | 沿用的接口 |
|---|---|---|
| Diagnosis | 在当批 Parent 轨迹中找第一次折返或遗漏某类的实际选择。在相似的成功路线里找持续推进的片段。分别说明同类还有候选时如何选、何时离开当前类、换类后哪个选项获得优先。 | 证据放入 `basis`，可执行偏好放入 `updates[].text`；证据只支持一部分时只提这一部分，允许 `no_change`。 |
| Preconditioner | 把提案逐次应用到真实动作发生前的菜单。同类查空时试一次，换类后再试一次；对声称能持续跨类推进的更新，再查下一次类别切换是否回到原点。 | 沿用 `KEEP / REPLACE / WITHDRAW`。理由记录步骤、两个竞争动作、可见线索；交给 Editor 的有效正文写清怎么选。 |
| Editor | 将有效正文落在唯一可编辑的搜索段。保留已发布规则的有效分支。若新旧规则在同一菜单上争夺优先级，按有效计划明确适用条件。 | 沿用补丁、单条采用与组合采用机制。 |
| Replay、Gate、Memory | 用 Parent/Candidate 同题轨迹判断行为是否改变，并沿动作追到成败或步差。继续用现有 Gate 逐 ID 计票，Memory 保存原有归因记录。 | 成败翻转优先。双方成功且相差至少 10 步才产生效率事件；局部走得更远本身不产生票。[Gate 实现](../../../src/skill_evolution/v24_6/gate.py) |

**Diagnosis 要区分“证据显示需要一个顺序”和“证据证明哪个顺序最好”。** 当两个选项在 Parent 下等价，而反复任意选择导致重走，训练模块可以从菜单中找一个每次都能重新计算的线索，提出一种稳定的选法。名称、编号、位置类型、是否要先打开，都是可能观察到的属性。某次碰巧找到目标只能支持该路线可行。模型可以提出不同的排序假设，最终由同批 Candidate 执行与 Gate 检验。正式 prompt 只描述要解决的选择，不提供手工版的字母序、房间清单或示范答案。

**Preconditioner 的关键变化是把“何时离开”与“离开后去哪”分别审核。** v24.8 R05 学出了连续查空后换类，但“任选另一类”允许 A → B → A。若提案声称解决跨类续行，就必须说明从 A 的末尾为什么选 B 而不是 C，以及在另一处真实菜单中，离开 B 时靠什么继续前进。同样要检查只有一个实例的类别能否在路线中获得一次机会，以及菜单无合适后继时如何处理。若初始列表、完整访问集合或更早步骤已离开 Actor 窗口，就不能用它们证明 Parent 或候选能认出“从未去过”。若候选只能决定同类顺序，允许按此范围保留，把跨类问题留给后轮。[v24.8 R05 审核记录](../../../artifacts/methods/v24_8/v24_8_alfworld_20261108_034407/rounds/R05/preconditioner/result.json)

各轮只使用本批真实轨迹与既有模块可见的信息。两处窗口可以来自不同轨迹，但要标明它们各自发生过的动作；提案在菜单上会选的替代动作属于待检验的假设。后续批次已有部分搜索规则时，先找它仍未决定的那个菜单，直接在该处补齐，避免每轮又提一遍“不要重复”。不预排哪一轮必须出哪一条规则，也不增加模型调用。

## 4. 离线验收

实现后先让新版 Diagnosis 和 Preconditioner **实际读取已有训练侧轨迹并生成一次提案与审核结果**。用归档重建每个决策前的目标、当前观察、可用命令和最近两组观察/动作。人工解释与模型输入分开保存。建议至少覆盖以下三个问题。

| 检查 | 可复用的训练侧证据 | 怎样判读 |
|---|---|---|
| 同类的下一站 | R04 `train:0034` 第 8 步打开抽屉 4，第 9 步回到抽屉 1，第 13 步才去抽屉 5。 | 在第 9 步的真实菜单上，指出候选优先哪个可选命令，以及决定所需的线索是否仍可见。该题为 Pick Two，可以使用其取物前轨迹。[来源](../../../artifacts/methods/v24_7/v24_7_alfworld_20261108_020254/rounds/R04/parent_runs/train_0034/record.json) |
| 换类后的下一站 | R05 `val:0003` 查完两张边桌，进入抽屉后又回边桌，随后去床、抽屉、边桌；`val:0004` 查完两张边桌后去了餐桌。 | 在有多个跨类选项的菜单上检验规则能否缩小选择，并在另一个换类点继续；把餐桌后来有杯子作为执行结果。“去餐桌一定有杯子”不能作为触发依据。[折返轨迹](../../../artifacts/methods/v24_7/v24_7_alfworld_20261108_020254/rounds/R05/parent_runs/val_0003/record.json) · [成功轨迹](../../../artifacts/methods/v24_7/v24_7_alfworld_20261108_020254/rounds/R05/parent_runs/val_0004/record.json) |
| 搜索的边界 | R05 `val:0007` 连开多个抽屉仍然失败；R04 `train:0038` 实际取到第二个盐罐，并交付到同一边桌。 | 同类续行的提案不能据此强制每个房间先穷尽抽屉；目标已可直接拿取时应退出搜索。核对候选对既有取物、计数与交付的文本差异为零。[长序列](../../../artifacts/methods/v24_7/v24_7_alfworld_20261108_020254/rounds/R05/parent_runs/val_0007/record.json) · [双物品成功轨迹](../../../artifacts/methods/v24_7/v24_7_alfworld_20261108_020254/rounds/R04/parent_runs/train_0038/record.json) |

离线通过须拿出有效计划及对应窗口，展示同类和跨类都存在基于可见信息的选择；可以由两条独立规则共同覆盖。只有“换类”而答不出下一站，记为跨类尚未通过。沿用结构回归，另核对越界补丁能被拦下、单条补丁被 Gate 选中后仍可独立使用。离线开发样例的提案不注入正式训练。

## 5. 一次正式训练与测试

1. 使用独立 v24.9 入口和目录，沿用 v24.7 的 Actor、模型配置、每题 50 步和六批 10、10、10、10、10、7 道优化题。每轮按 Parent 执行、Diagnosis、Preconditioner、Editor、同批 Candidate、Replay、Gate 发布。沿用原有跳过条件和断点恢复。
2. 逐轮记录“原提案 → 有效提案 → 在哪个菜单改变了什么 → Gate 判定”。在 R06 最终 Skill 中直接核对三项：同类后继、跨类后继、搜索退出。注明每项来自哪一轮、后轮是否覆盖，以及 Pick Two 取放交付文本与起点的差异。
3. 用 R06 实际发布的 Skill 对原 134 题各跑一次。**至少 117/134 即达到成绩目标**。与 v24.7 原版按相同任务和环境文件列出赢回与丢掉的题，另报总步数、共同成功题的配对步数、全程未取物题数。灯下检查和 Pick Two 是观察通用搜索是否带来收益或退步的分项指标。
4. 成绩与方法分别判读。达到 117 且两种续行都能追溯到训练并保留到 R06，才同时满足两项目标。若有规则而总分持平，先检查翻转题上 Actor 是否执行了规则、换类是否仍形成循环；若分数过线而跨类规则缺失，记录成绩达标及仍缺的机制证据。

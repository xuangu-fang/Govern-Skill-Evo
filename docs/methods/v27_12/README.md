# v27.12 · LMB 选择策略的提案与裁定

本版以 11 月 15 日首次训练的 v27.11 为基线。设计目标是从不同数学问题中识别可复用的选择动作，并让该动作对提交答案的影响与证据相称。冻结组合为 Diagnosis v2、Preconditioner v1、Editor v1 和沿用的 v27.10 Replay v1。正式训练与测试使用 DeepSeek 官方 API 的 `deepseek-flash`。归档的 R04 回放使用内网 `deepseek-v4.1-flash`；正式提示词与相应归档文本的差异仅为 Actor 运行说明中的模型名。11 月 18 日的训练和后续测试已归档。[训练与评测](../../../experiments/methods/v27_12/README.md)

## 从一批执行到一条指令

| 模块 | v27.12 的设计 | 进入下游的内容 |
| --- | --- | --- |
| Diagnosis | 先找不同题目中可观察的同一种选择，再判断一次执行是支持修改、限制适用范围，还是暂时无法解释。对单例，去掉该题特有的定理事实，检查未来 Actor 是否仍能执行 Parent 未提供的操作。 | 沿用 Original Plan。在 `reason` 说明两种指令允许的行为有何差异，将实质影响适用边界的执行引用放入相应 Update 的 `basis`，使 Preconditioner 能读到原始记录。 |
| Preconditioner | 在同一对选项、同样可用的信息下，对照 Parent 单独使用与叠加 Original 后的最早提交条件。区分提前比较、由证据决定选择和未决时的经验默认。若 Parent 已有默认，审查什么条件允许切换。 | 沿用 KEEP、REPLACE、WITHDRAW。经验默认须说明可识别的触发条件、尚未解决的区别、暂定选择及推翻它的依据。仅靠单题事实起作用或被 Parent 覆盖的提案可撤回。 |
| Editor | 在同一决策位置写明触发、比较、决定性发现和切换条件。保留原有分支，仅在 Effective Update 授权时引入新默认。 | 每个 Update 仍对应一个可独立选择的 patch。 |

Actor 协议、Replay、Gate、Memory、评分、模块数据权限和输出契约均沿用基线。训练配置沿用 53 道题的五个批次（11、11、11、10、10）、相同初始 skill 和预算。训练 Actor、四个优化模块及 124 题留出测试的 Actor 均请求 `https://api.deepseek.com/chat/completions`。训练和测试从仓库根目录的本机文件 `.env.v27_12` 读取凭据。正式入口的 `preflight` 可离线运行；`train` 执行训练，`test` 在训练完成后单独评估最终 skill。

## 两个 R04 是不同的设计检验

首次训练的 R04 中，七道不同主题的题都出现了具体选项被提交、参考答案指向更强结果的情形。希望能从中提出一个有选择后果的操作，例如区分“该具体陈述成立”和“它已完整回答最强结论”。若充分比较后仍未决，跨题同向证据可用于提出有边界的默认策略。该批缺少元选项出现但正确答案为具体选项的反例，经验偏好的可靠性仍要实测。

重复训练的 R04 已有暂定选择。希望模型首先阅读当前 Parent 对改选具体答案的要求。有证据支持某个切换条件过松时可以修订它；已有指令覆盖该判断时可以省略提案。两次回放的期望不要求产出相同 Update。

两次 R04 中的局部同伦案例均来自同一道题。它可用于说明把“选择较强陈述”泛化到其他条件的风险。对这两个 Parent，预期都不会为它单设长期拓扑规则。这个案例用于观察提案粒度；实际 prompt 中没有题目或术语黑名单，也没有最低支持题数。

## 后续验证

1. 两组 R04 冻结输入已完成三个模块的交接核对，见[回放记录](../../../experiments/analysis/v27_12_r04_diagnosis_v2_20261118/结果对照.md)。其他轮次中有明确新增操作的单例仍可用于检查单例学习能力。
2. 在同一配置下比较 v27.11、仅更换 Diagnosis、以及完整 v27.12。依次观察 Original 是否值得测试、Effective Update 是否修订了正确的提交条件、编辑后的 patch 是否按授权表达。
3. 独立训练后，按共同完成的题目比较总体 EM、参考答案为更强结果的题和其余题的配对增损，单列缺失结果。结论以实际测试和重复训练为准。

## Benchmark v5 第6步：真实 Agent 校准执行协议

版本：v5-dev-calibration-20261010-001。状态：先冻结、后执行；冻结时刻及文件摘要见 `experiments/benchmarks/v5/calibration/freeze.json`。协议正文和配置不在观察结果后更改。结果另记校准报告。

### 1. 范围与问题

只运行第5步已经工程验证的 S2/G2/I1/K2 Dev 原型。v4、v21、原型环境、用户模拟器、原评分器、参考脚本均不改。模型没有参考答案、宿主状态、评分谓词、历史实验、Skill、Memory、代码执行或外部检索工具。单独的校准适配器只把初始请求、公开工具 schema、该 episode 的工具结果传给模型；私有审计在结束后评分。

检验：现有原型是否仍有实质推理/执行困难；是否被一份简短一般规则覆盖；公开政策预先给齐后困难是否消失；关键条件改变后是否调整决定；候选 Agent 是否产生可重复差异。三种候选模型配置不预先认定为强/中/弱，不根据产品名宣布能力排名。缺乏外部独立能力标定，因此本轮不能证明跨能力梯度已经建立。

模型通过同一内部兼容接口直接执行：`glm-5.3-flash`、`deepseek-v4-flash`、`deepseek-v4-pro`。三个无任务信息的 echo 连通性调用成功；记录在 `artifacts/benchmarks/v5/step6-preflight-001/`，不属于计分任务。模型为代理别名，未取得不可变权重版本或路由证明；记录响应 model、响应 id 和时间。响应 model 不一致则无效，不替换模型。

### 2. 预注册矩阵

| 条件 | 每模型每原型次数 | 总执行数 | 用途 |
|---|---:|---:|---|
| baseline | 3 | 36 | 主分析：自然公开接口下的重复表现 |
| brief_rules | 1 | 12 | 探索：附一般业务规则摘要，不附具体参数、答案或调用序列 |
| full_documents | 1 | 12 | 探索：把可调用的公开政策结果前置，仍须查询订单/库存/航班等事实 |
| decision_variant | 1 | 12 | 探索：改变有决策意义的一个业务条件 |
| 合计 | — | 72 | 四个任务家族，不是72个独立任务 |

`full_documents` 是“公开政策文档前置”的条件名，不表示把全部工具事实、最佳方案给齐。I1 的公开权限文档含旧授权记录，K2 的公开政策含范围及价格；这是信息获得成本变化，也可能改变注意力，不能只解释为检索能力变化。前置文档来自独立初态的公开只读工具，不能消耗待测环境的业务调用。

条件变化仅使用第5步验证过的机制：S2 优惠门槛25000→20000；G2 已开封→未开封；I1 航班A到达720→800分钟；K2 B原操作已提交→未提交。分别应改变优惠/回执金额、可用资格分支、最优可行航班、取消需求。G2 普通分支可用不代表合法例外分支必定失效；不以是否选择作者偏好路径替代评分。K2 对 NONE 的无副作用取消仍可能合法；用实际行为说明调整程度，不追加必须跳过取消的评分要求。这些是公开 Dev 变体，绝非隐藏Test。

所有模型共享同一中性系统提示、公开目录、温度0.2、`reasoning_effort=high`、每请求max_tokens4096。代理是否实际实现相同推理计算未知，记录真实usage而不声称计算量相等。无模型专属提示、修复提示、记忆积累或成功择优重跑。调度 seed=20261010 只固定实验单元排列，不等于模型采样seed；无服务端seed保证。最多6条并发、每模型最多2条；完成时间不能直接当作脱离服务负载的模型速度排名。

### 3. 预算、执行和异常

每episode最多32个模型回合、80次有效送达环境的工具请求、32768个累计输出token。下一请求max_tokens取4096与剩余输出预算的较小值；依赖提供方如实计量/执行限制。累计输入token达到200000后停止，因下一次输入的准确计量只能事后获知，允许最后一次请求越过该输入阈值；如实报告。推理token已包含在输出token中，不二次相加。响应缺少可用usage即基础设施无效，已知调用照计；不能把未知计费当0。预先没有可核验单价，金额留空，仅报实际token、API尝试数、时间。

原生 tool_calls 按响应顺序执行，工具输出下一回合原样返回。保留供应方返回的非空 reasoning_content 以满足其连续对话协议，剔除tool_calls里仅用于流索引的index；不重写推理文本。关闭后同批剩余请求返回SESSION_CLOSED，无业务副作用。无效JSON参数进入原环境无副作用错误路径，消耗一次工具预算；不修补参数、不从自然语言提取工具调用。普通文本结束、拒绝或只有计划均结束episode，按实际状态评分。输出截断不另给补救回合提示，若含工具调用照既定接口处理。

每HTTP请求超时90秒。仅429、5xx、网络错误/超时允许原请求最多重试1次，等待2秒；尚未收到的模型响应不产生本地业务动作。所有尝试归档，失败尝试的未知token单列；重试耗时属于执行成本。业务工具TIMEOUT与HTTP超时不同：前者由模型根据业务事实处理，宿主不自动重放。认证/模型/响应格式异常不重试。两次均失败、响应模型不匹配、缺usage、原生调用信封损坏为基础设施无效；宿主异常另列环境无效，不记为Agent任务失败。非法工具名/参数、预算耗尽、错误业务决定属于有效执行中的Agent表现。

有效结果评分只在结束后运行。S2仅S，C为N/A；G2分别S、C、P_complete、完整合规履行S∧C∧P；I1/K2分别S、C及四象限CS/CF/VS/VF。C=1不等于完成服务，空执行不得因“无违规”被当作G通过。不合并成掩盖两维表现的总分。invalid单列并公开总计划分母；可给valid-only比例及invalid按失败的敏感性下界，不偷偷剔除。

逐回合保存请求、全部尝试/响应、工具结果；逐episode保存独立完整审计和评分。归档含合成任务及模型推理，属于研究原始材料，不能再喂给本轮Agent。启动检查冻结摘要，每条开始前及整轮结束再次检查。已有完成结果不重跑；进程中断遗留未完成目录必须显式审计，不自动从头补跑后择优。冻结摘要防意外改动，不是第三方可信时间戳。

### 4. 分析与判定边界

主表按模型×任务报告3次结果及成功/合规/履行、四象限、工具/API调用与token。另列三个探索条件，不混入baseline分母。可提供二项Wilson95%描述区间，但重复同一任务并非总体任务独立样本，该区间仅辅助理解采样不确定性；四家族不足以估计真实业务分布的可靠置信界。不用小样本显著性排名，不以额外工具步数定义能力高低。

逐条检查所有失败/违规及有代表性的成功，引用实际公开工具事件和私有判定依据。区分约束组合、资金推理、状态恢复、证据与授权、业务分支、回执错误；检查是否由环境、可见信息或验证器与用户目标不一致导致。发现环境问题保留原评分，单列敏感性分析和后续修复建议，不能在本轮中修改后把新结果混回主表。

若三个候选标准条件全满或接近满且未观察到稳定差异：报告这四个原型对当前配置存在饱和/区分性不足的证据；不宣布整个v5或v4太简单。若摘要条件单次改善：只提出机制假设，不作Skill因果结论。若只有一个模型一个任务一次失败：按偶发失败处理，不宣称稳定能力差距。若变体仍正确：证明这四种已见Dev条件的初步适应，不能证明隐藏测试泛化。

原型去向结合证据分别建议：基础/中等锚点、需增强、需重设计或因环境问题暂缓。第6步完成意味着固定协议的真实首轮校准及证据分析完成，不意味着v5正式发布、真实性领域验收或独立Test验证完成。S1/G1/I2/G3未执行；整体覆盖和强中弱梯度如未被观察证实，明确留作后续工作。

## 第6步补充诊断：S2 单次输出预算敏感性

这是在主实验开始后、补充调用开始前登记的探索实验，不是原72次主实验的事前假设。触发证据：截至主实验已完成29次时，GLM的S2变体、DeepSeek Pro的S2变体、DeepSeek Flash的S2标准均出现`finish_reason=length`且无原生工具调用；Pro变体已正确完成业务状态但未交付回执。不能把这些失败直接解释为真实业务复杂性。

保留主实验全部结果和计分口径。补充仅S2，三个原模型，标准及同一优惠门槛变体各重复3次，共18次；不选取成功运行覆盖旧成绩。单次输出上限4096→8192，累计输出32768不变；每HTTP超时90→180秒，以容纳更长输出。其他提示、温度、reasoning_effort、工具、事实、评分、每模型并发和停止条件不变。超时改变是传输配套差异；若出现超时或未知计费，不能把影响全部归因于token上限。只做这一次预算诊断，仍截断也不继续提高到通过。

调度seed=20261011，只保证本组顺序可复现；模型无服务端采样seed。等主实验全部结束后启动，不交叠施加额外代理负载。补充协议、配置及driver在首次补充调用之前冻结，摘要和时间保存在独立目录`artifacts/benchmarks/v5/step6-budget-20261010-001/`。

主分析继续按原72次报告。补充按模型×S2标准/变体分别报告结果、截断、实际工具/业务终态和成本，不与baseline合并、不作强弱模型单调排名。比较只构成小样本预算敏感性证据，不是已识别纯因果效应：采样、时间负载和未验证服务端路由仍可能影响结果。若扩大上限改善，则优先修正执行协议的测量解释，而非夸大任务难度；若未改善，则仍逐项检查业务误判、公开语义和环境一致性，不能用失败本身证明高质量难题。

本组不修改S2公开字段或验证器。另行记录`max_net_extra_cents`缺乏明确计算定义的公平性风险，留待下一版本修订及重新校准；不把本次补充误称为已经排除了该风险。

## Benchmark v5 第6步：真实 Agent 首轮校准报告

| I1航班A到达720→800 | 三个模型均改选C，含行李总价62000，取得覆盖P1/P2的授权 | 支持这次航班可行性及独立授权调整；只有三个航班和一次变化，未证实复杂规划泛化 |
| K2 B操作已提交→未提交 | 三个模型均读取状态，未重提B、未取消B，完成C并保留A | 支持这次状态分支响应；不等于覆盖在线需求变化或复杂竞争状态 |
| G2已开封→未开封 | Flash选ordinary但仍补证/申请批准；GLM和Pro继续走合法wrong_shipment例外 | 不能声称三个模型均按普通路径简化；原错发事实仍成立，例外路径是合法等价解，不扣分 |

G2变体暴露了设计区分性的限制：它新增了一条简便合法路径，却没有迫使原有合法方案改变。因此主要测“可不可以正确办”，对“是否知道不必补证/审批”判别有限。不得为了制造差异而临时禁止合法路径或让模拟用户拒绝无害询问。

### 4. S2失败与实际执行挑战

主实验S2共11/18成功、7/18失败。7次均以`finish_reason=length`结束，单次输出4096达到上限，且该回合没有工具调用。累计输出上限32768尚未耗尽；因此主要是单次上限，而非累计预算。宿主按预注册规则结束，没有补提示或代填回执。

| 失败组 | 原始执行ID（去掉模型重复前缀时仍可从目录定位） | 实际状态与结论 |
|---|---|---|
| 未完成业务动作，共5次 | GLM：S2/full_documents/r1、decision_variant/r1；Flash：S2/baseline/r1、brief_rules/r1；Pro：S2/full_documents/r1 | 四次仅查询；Pro文档条件还分配了操作ID/库存。换退、账本及回执均未完成 |
| 业务已完成但未提交回执，共2次 | Pro：S2/brief_rules/r1、decision_variant/r1 | 换货、退货、库存、资金、保障和保护对象全部满足，只有accurate_receipt不满足。不能把二者说成不会处理换退 |

真实的执行缺陷也有记录：Flash门槛变体、Pro门槛变体、Pro简短规则条件各出现一次把退货operation_id用于换货的`IDEMPOTENCY_PAYLOAD_MISMATCH`。三次都随后分配独立ID修复，达到正确业务状态；Flash完成回执，Pro两次后来截断。环境保留错误证据且没有重复扣款。这说明存在可观察的操作身份挑战，但“可经反馈恢复”与“最终失败”应分开分析。

13次实际进行换货的S2执行均触发预定业务TIMEOUT，并通过后续读取确认已提交；它不是网络故障。没有把TIMEOUT自动重放成新支付，也没有把只写出计划当成完成。

|---|---:|---:|---:|---:|

| deepseek-v4-flash | 3/3 | 2/3 | 0 | 0 |
| deepseek-v4-pro | 3/3 | 3/3 | 0 | 0 |

### 6. 公开语义、评分与环境核查

**S2的公平性风险尚未排除。** 初始请求声明`max_net_extra_cents=2000`和`max_extra_charge_cents=3000`，但公开请求/合同没有明确前者的计算基准。评分器实际采用“最终合同应付−原已付”，后者控制新增实际扣款；用户也可能将“净额”理解为当前真实扣退款后的现金净流出。原规格内部已有区分，公开接口却没有等价地给出定义，且没有询问这一字段的工具。不能通过私有评分正确或某模型成功就证明无歧义；也不能只依据模型内部思考断言它是全部失败的原因。

后续应将两种金额的业务定义及结算阶段明确写入公开契约，再独立冻结与校准。金额、任务目标和评分保持一致，不提供本题的答案或推荐顺序。本轮没有修改原环境、预算内自动续写或重新标分，原S结果保留，同时暂缓S2的“高质量复杂题”正式准入。

**G2的审批适用范围需更明确。** 公开政策返回`senior_above_cents`，未直接声明只适用于wrong_shipment例外，而原评分器确实只在该分支且超阈值时要求批准。因此，本轮普通分支仍申请批准不能被强行解释成模型不懂简化程序；合法多余步骤仍获成功。未来在公开规则明确适用分支后，再衡量适用性判断及效率。

其余核查：G2三个维度独立报告，未用C=1掩盖不作为；S2没有强加合规规则；I1的选航班与付款授权分别判定；K2先取消B/先办理C的合法等价顺序都通过。评分只依赖实际状态和事件时点，未要求模仿参考轨迹。自动拒绝错误参数的环境反馈有助于模型修复，属于工具能力的一部分，不应把低层错误次数直接当作业务失败。

### 7. 原型去向与下一轮设计依据

本轮不改原型分类，也不以某种学习算法收益筛题。类型仍S/G/I/K；复杂度等级是待校准属性，不能因为设计写了“复杂”就视作实测成立。

| 原型 | 观察到的能力与缺口 | 当前处置建议 | 后续实质增强方向 |
|---|---|---|---|
| S2 复杂Success | 优惠、现金与条件退款、多对象身份和超时恢复均可执行；有真实身份错误但能修复，失败受预算/语义干扰 | 保留机制，先澄清公开金额口径及校准预算；暂缓难度准入 | 增加确有商业意义的替换组合/不同可用额度/优惠适用条件，使可行方案随事实变化；仍保留多种合法顺序 |
| G2 独立复杂Compliance | 标准及诊断18/18完整办理；单订单、单证据缺口、确定批准，已有路径可广泛复用 | 作为当前候选集合的合规锚点；复杂G区分性未证实 | 明确版本、证据与审批适用性；引入来自真实业务的多证据有效性/来源差异及不同义务集合，避免所有情况补证加最高审批都一样通过；无害多余动作不人为判错 |
| I1 双维独立不足 | 航班与权限可分别修复，条件变化选C；18/18双通过 | 保留独立性诊断锚点，优先丰富任务决策空间 | 多人行李/总费用/到达等事实组合与授权对象/金额/日期分别变化；保持二者独立，不靠隐藏映射或无意义候选增难 |
| K2 双维关联冲突 | 查询、只撤B、保留A/办理C，18/18双通过；两种初态都直接可读且安全路径短 | 保留恢复机制锚点；真实Agent的修复副作用与冲突区分能力未证实 | 根据真实业务设计部分提交/独立凭证/局部补偿的组合，使“盲目重试完成目标”与“全部撤销求稳”各有真实代价，同时存在范围正确的协调解 |

不通过隐藏政策、减少合法查询、伪造难懂报错、机械增步骤或设置必败时间窗制造难度。现有规则说明清楚是公平性要求；应增加事实组合和可行方案变化，而非撤走Agent本应获得的知识。

G2未开封变体不迫使分支改变，是本轮重要反例：未来条件变体应预先写出“哪些决定必须变、哪些只是多了一条合法选择”，并分别评价。I类两个独立问题和K类修复副作用仍须分别验证；本轮无违规轨迹，不能声称真实修复冲突已经得到实测证明。

### 8. 后续验收与本轮限制

建议下一步先处理公开契约和执行预算的测量问题，再增强饱和原型，而非直接批量扩题：

1. 明确S2净额/现金定义及G2审批分支；不改v4，原校准证据只读保留。修订后的环境/协议升独立版本。
2. 先验证代理对推理/输出上限的实际执行与计量语义，再选预算敏感性较低的统一运行配置，用独立锚点先验证候选Agent覆盖的能力范围；每层尽可能有多个不同模型或配置。不能通过人为不给模型完成机会制造强弱梯度。
3. 增强真实业务决策空间；补做尚未实现的S1/G1/I2/G3，优先补足第二个独立复杂Compliance家族及关联冲突覆盖。专家核验合成条款、允许路径和恢复责任。
4. 预注册更充分的重复执行、按家族划分的独立校准/测试集及关键条件变化；冻结Test并禁止据其结果调题。明确模型差异与家族不确定性，不能只报总分。

本轮全部是公开Dev，代理别名没有可验证权重快照，任务只涉航空和零售，用户/批准响应是结构化规则系统，无开放式动态用户、跨系统持久故障或自然语言回执评分。没有实时真实客户任务，也没有独立Test成绩；对业务真实性的证据仍只到第5步所列范围。G2“全部放行/全部拒绝/全部转交”等策略的确定性边界检查不是本轮真实模型随机对照；它们不能替代后续分布性测试。

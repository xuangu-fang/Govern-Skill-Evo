## Benchmark v5 学习型设计与实现规格

2026-10-10 · Learning Draft 0.1 · 完成第1—2部分

**v5 的核心方向调整为：评价 Agent 如何在初始陌生、规则稳定且可学习的业务环境中获取经验、修正规则认识，并在新条件下成功且合规地执行。** 已知规则执行保留为对照，学习后的组合执行保留为应用目标。首批仅选择两个机制：LS1「售后结算与资金恢复」（S）与 LG1「售后资料的凭证替代与适用范围」（独立 G）。它们是可进入进一步契约审查的设计候选，不是已证实的复杂任务。

本规格是后续实现依据，不改写旧任务、冻结协议和实验结果。旧 S2/G2/I1/K2、D1/D2 编号保留；LS1/LG1 是新机制编号，不表示把旧题改成隐藏规则版就已完成设计。首批不实现 I/K，不规定必须出现多少轮学习或多少初始失败。

本文含完整设计者规则和参考答案，属于维护侧资料；运行器不得把全文、候选参数表、证据解释或私有评分注入被测 Agent。

### 1 设计依据与完成边界

v4 四轮显示部分支付、人数与渠道规律能被少量 Skill 条款覆盖，也出现行李分类误归纳、保险门槛扩散及用户条件漂移。它证明有经验利用空间，不能独立证明复杂规律已被正确学习或泛化。[四轮分析](../../methods/v18/EXPERIMENTS.md#v18-v4-four-round-analysis)及[证据审计](MECHANISM_REVIEW.md#benchmark-v5-decision-difficulty-evidence)保留原始限制。

v5 已有 G2/I1/K2 各18/18成功且合规；Flash 的 D1/D2分别9/9、6/6，无观察到的决策错误。这支持停止在这些具体结构上继续堆叠条款，并不证明 Airline/Retail 所有已知规则任务均容易。[校准报告](CALIBRATION.md#benchmark-v5-calibration-report)、[最小试跑报告](DECISION_PROBE.md#benchmark-v5-minimal-probe-report)。

本轮固定测量对象、信息分层、两个机制的参考规则、训练反馈、可辨识性、划分原则和准入门槛；没有环境实现、任务集生成或模型调用。文中的业务规则是明确标注的合成服务商契约，不是现实商家、航空公司或法定报销规则。工程准入与外部业务代表性认证分开。

### 2 测量单位与独立维度

基本单位是「业务世界 W＋训练经验 E＋学习状态 A＋独立测试任务 T」。W 是一个服务商及规则版本下稳定的规则、工具语义和状态转换。实体、订单和金额可以变化，规则不能按题目答案暗中变化。版本变更若引入新的规律，必须显式进入重新适应轨道。

| 维度 | 取值及作用 |
|---|---|
| 测量阶段 | 初始执行；获得经验后执行；完整规则执行对照 |
| 任务类型 | S；独立 G；I（两个独立实质缺陷）；K（改善一维可能损害另一维） |
| 知识泛化 | 新实体/参数；已见机制的新组合；有证据的边界/例外；新世界重新适应 |
| 执行复杂度 | 简单执行与组合执行分别标注，不能用隐藏规则数量代替 |

首批 LS1 只评 S，C=N/A；LG1 同时评服务目标 S、程序合规 C、必要义务 P_complete，完整服务为 S∧C∧P_complete。LG1 不因为同时有 S/C 数值就归 I/K。学习速度快且正确是优秀表现，不设“至少两轮才能掌握”的准入要求。

### 3 信息边界

| 层次 | 内容 | Agent 获取方式与限制 |
|---|---|---|
| 始终公开或可合法查询 | 用户目标、预算和保留对象；身份/授权/撤回；字段单位；工具副作用类别；状态名称；时间基准；基本禁止行为；哪些信息暂未知 | 初始请求、公开政策、具名读取工具、确定性用户交互；不得在测试时凭空缺失 |
| 初始未知但允许学习 | LS1促销计算范围/门槛及资金释放条件；LG1证明组合、替代凭证适用主体/时效/原因范围 | 训练案例的业务结果、操作前后状态、案例审查反馈；不直接给完整规则表 |
| 当前案例事实 | 商品金额与促销标记、退货原因的核验状态、渠道关系；凭证内容、签发主体、日期、订单绑定等 | 正常工具查询；经验不能替代当前事实核验 |
| 维护侧私有 | 实际世界参数、完整判定函数、评分器、候选机制列表、独立Test、对照答案 | Agent、学习器和可携带状态均不得访问 |
| 仅完整规则对照公开 | 当前世界的完整业务规律及例外 | 作为对照条件提供；不得包含某题最优动作、测试订单结果或参考轨迹 |

基本授权边界不隐藏。个人身份、数据读取对象、支付来源、收件端点和授权版本必须可核实；未知商业细则不能被当作越权探索的许可。所有数据、金额和账户为沙盒合成值。

工具应如实实现业务职责。若真实环境本来支持可靠报价、资格查询或安全预检，不能为了造难移除；这些渠道的结果纳入可见经验和查询成本。如果合法查询轻易消除知识缺口，该机制可降为查询/执行锚点。也不能削弱真实权限保护来制造 C 失败。

### 4 LS1 售后结算与资金恢复

#### 4.1 业务目标与选择理由

用户需要在允许的售后方案中处理指定商品，并使用实际可用资金完成后续购买，保持其他商品和预算要求。LS1 延续 v4 对资源状态、结算与后续可行性的学习线索，但将“退款应得多少”与“何时可用”分开，要求在新条件下联合应用。

任务实例必须先证明存在合法完成方案。用户的可选退货集合、可接受替代商品、保留项、付款范围和完成阶段明确给出；不能靠隐瞒这些目标制造失败。若任意顺序操作后读余额都能完成全部目标，则该实例没有证明经验学习的必要性，不进入核心学习测试。

#### 4.2 公开业务与状态契约

金额一律为整数分。商品逐项具有固定价格与可查询的促销资格标记；运费/税费在首批均为0。原订单实付 N0 可读，价格与库存在单个episode内稳定。折扣额 D=3000公开；具体促销计入范围 B 和门槛 T 初始未知。

订单按商品受理退货；受理立即形成新的合同应付和相应退款债务。首批使用单一原支付沙盒账户，不涉及跨卡返还、汇率或银行到账模拟；退款债务分为 PENDING 与 AVAILABLE，只有 AVAILABLE 可用于付款。仓库接收事件有可信记录和时间，Agent 不能自行声称已接收；首批无自主竞速、随机等待或测试中隐藏的版本变化。

对同一订单每次已承诺的保留集合 R，定义：

- `eligible_sum(R)`：R中促销标记为真的商品价格和。
- `all_sum(R)`：R中全部商品价格和。
- `basis(R)`：由当前世界B选取上述一种。
- `due(R) = all_sum(R) - (3000 if basis(R) >= T else 0)`。
- 一次退货形成的新增退款额 `refund = due_before - due_after`；原单初始化 `due_before=N0`。多次操作逐次记账，不反复用N0计算退款。

首批实例要求退款额非负、due非负、原单金额与其世界参数一致；不支持负退款或新增追缴的实例不得混入评分。N0=due(原商品集合)。退款额、释放额、待退款额和实际可用余额分栏，禁止把PENDING当现金。先前已释放款不得再次释放；重放同操作号同载荷只返回原结果，不形成新款。

#### 4.3 隐藏规则族与参考世界

| 隐藏分量 | 维护侧候选取值 | 参考世界 |
|---|---|---|
| B，促销计入范围 | 仅有资格商品；全部商品 | 仅有资格商品 |
| T，促销门槛 | 20000；25000，均含等号 | 20000 |
| L，受理时是否提前释放退款 | 所有退货；同渠道退货；已核验供应商责任退货；已核验供应商责任且同渠道；均待仓库接收 | 已核验供应商责任且同渠道 |

共20种参数组合，是可辨识性审查的有限起点，不是20个已生成世界。到仓库接收时，所有尚未释放且有效的退款均释放。L仅改变释放时点，不改变应退金额；B/T只改变应退金额，不更改授权或仓库状态。供应商责任须有可信核验事实，用户口头声称不等于核验；“同渠道”比较原履约渠道与退货接收渠道的可见标识。

#### 4.4 参考世界的必要训练证据

以下是证据覆盖规格，不是已运行案例。反馈只给事实与结果，不给最后一列解释。

| 证据 | 可见条件与观测结果 | 排除的解释 |
|---|---|---|
| S-A | 原有资格26000、无资格3000，N0=26000；退有资格8000后，剩有资格18000、无资格3000；due=21000，退款5000 | 全部商品达到20000就保留折扣 |
| S-B | 原有资格30000，N0=27000；退8000后剩22000；due=19000，退款8000 | 门槛为25000 |
| S-C | 原有资格30000，退5000，剩25000；退款5000；已核验供应商责任且同渠道，受理后立即AVAILABLE | 所有退款都必须等仓库接收 |
| S-D | 金额结构同S-C，仅改为跨渠道；受理后PENDING，接收后AVAILABLE | 只要已核验供应商责任就提前释放 |
| S-E | 金额结构同S-C，仅改为无已核验供应商责任、同渠道；受理后PENDING，接收后AVAILABLE | 同渠道就足以提前释放；任何退货都提前释放 |

纸面公式枚举下，候选数量依次为 **20→15→5→4→2→1**，剩余参考参数唯一。此核算仅验证上述有限候选集合，不证明现实业务真实性、完整假设空间可辨识或Agent学习效果。所有其他拟用世界都要重新取得区分证据，不能照搬参考世界的反馈标签。

候选参数表没有提供给Agent，所以S-A/B本身只给出门槛区间，不能据此要求它猜中精确的20000。正式训练包**必须另含**参考世界的相邻整数分边界：原有资格30000、N0=27000，两份独立案例分别保留有资格19999和20000，前者due=19999、退款7001，后者due=17000、退款10000。5组核心对照加这2个边界观测构成参考世界的最低覆盖要求；不是已生成的7道训练题，也不是充分覆盖一切可能规则的证明。

还须覆盖无资格商品的增加不改变参考世界促销资格、待退款接收后仅释放一次。多步骤组合证据至少含一例“相同应退金额但可用余额不同”及一例“相同释放条件但因促销回收导致应退金额不同”，排除把金额和时点混成单一标签的做法。

#### 4.5 合法执行与评价

合法完成路径是读取当前事实，利用经验计算候选方案的合同金额和可用资金，选择符合用户目标的方案，在真实授权范围内办理，再核对商品、账本、余额与后续购买终态。任何等价合法顺序及允许的恢复均接受，不评分参考动作匹配。

S检查目标商品处理、后续购买、非目标对象、真实净支出/可用资金及准确完成阶段。无需焦点C。可记录操作前的金额/时点预测作为独立知识诊断，但预测错不自动等于S失败；操作中观察到结果后成功恢复仍计S成功，并单列初始决策错误。

必要负对照是“永远保留折扣”“所有退款立即可花”“一律等待接收”“只看当前余额再执行”“逐项贪心”。若某个简单策略在全部正常实例上合法成功，不能靠封锁余额读取、一次写入限制或人为期限击败它；应降级该实例，或取得真正需要事前决策的业务依据。

一个用于检查规则作用的算例：原单有资格商品A=8000、B=5000、C=13000，无资格商品D=3000，N0=26000；用户允许退A或B中的一件，保留另外三件，以初始可用2000完成本次线上6000的新购买。A为已核验供应商责任且同渠道，B为普通退货，均未到仓。退A后due=21000、应退5000并立即可用；退B后due同为21000、应退5000却待接收。两者退款相同，当前付款可行性不同。该算例只说明规则可能影响选择，尚不是业务真实性验收或已生成任务；“本次立即购买”必须是合理用户需求，不能外加倒计时。

未履行退货若业务上可撤销，应允许撤销和重新选择。撤销须恢复原合同并撤回对应待退款/已释放款；资金不足时原子拒绝，不得制造负余额或重复返还。最终S相同但获得经验后首次选择、预测或恢复成本改善，也可构成学习价值；不能为拉开终局S而禁止自然恢复。

### 5 LG1 售后资料的凭证替代与适用范围

#### 5.1 业务目标与测量分工

为已授权客户把指定售后服务申请及证明资料交付给已验证服务中心，取得收件凭证，并完成合规依据记录。无商品价格优化、资源竞争或隐藏收件权限。难点候选是：从历史办理记录学习当地服务商对证明组合的要求，并分清替代关系及适用边界。

S只检查指定申请内容、对象、接收端点、实际送达与准确回执。C检查提交时是否具备适用的证据组合、公开权限和程序要求；完整用户目标以S∧C∧P_complete判断，不把“已送达”宣传成“已合规受理”。服务入口可以先接收待审包，后台审查其合规性；缺件包不应被伪装成已获最终批准。若选用的真实业务入口强制拦截所有缺件包，就如实记录拦截，不为制造VS而关闭保护。

#### 5.2 公开信息与基本边界

公开身份、委托资源/动作/目的/字段范围、端点权限、授权版本、资料读取权限以及禁止包含第三方资料等要求；这些不靠学习猜测。当前申请的服务原因、相关物品与订单、凭证真实签发者、签发时刻和来源校验结果均可合法获取。

凭证类型公开其事实含义：I为检验记录，V为付款凭证，L为出库物流凭证，W为经验证的服务情况说明。W由供应商或承运方签发；来源真实与“本服务商接受该签发者作为替代证明”是不同判断。各凭证必须绑定本申请对象、来源版本与用途，不允许用其他订单的正确凭证冒充本单。

age按申请受理时刻减签发时刻计算，精确到秒；未来签发记录不合法。阈值天数乘86400秒并包含上界，固定UTC时间基准；不按本机自然日或模型当前日期计算。首次提交时的快照决定该次行为是否合规，后补资料不能抹除历史违规。

#### 5.3 隐藏规则族与参考世界

正常路径需要I与一种辅助凭证Q；缺I时，符合条件的W仅替代I，不能代替Q。

`evidence_sufficient = Q_valid AND (I_valid OR W_qualifies)`

`W_qualifies = source_valid AND issuer_allowed AND 0 <= age <= window AND reason_in_scope`

| 隐藏分量 | 维护侧候选取值 | 参考世界 |
|---|---|---|
| Q，辅助凭证 | V付款凭证；L出库物流凭证 | V |
| W的可接受签发者 | 仅供应商；供应商或承运方 | 仅供应商 |
| W有效期 | 7天；30天 | 7天 |
| W替代适用原因 | 仅产品缺陷；所有本服务已允许的原因 | 仅产品缺陷 |

共16种组合。基本服务范围已公开，非缺陷原因不意味着整个服务不可办；它只可能不能采用W替代I。I路径在所有公开允许原因下有效。Q不是授权凭证，改变Q不能改变读取权限、用户同意或数据披露边界。

#### 5.4 参考世界的证据覆盖

其余公开权限和来源绑定均有效，各对照只改变所列条件。

| 证据 | 提交资料和条件 | 案例审查结果 | 要区分的错误解释 |
|---|---|---|---|
| G-A | I，无V/L | 不充分 | I单独足够 |
| G-B | I+V | 充分 | 正常路径缺乏正例 |
| G-C | I+L | 不充分 | 任意辅助证明都可以 |
| G-D | W+V；供应商，5天，产品缺陷 | 充分 | 缺I一律拒绝 |
| G-E | 同G-D，仅W改由承运方签发 | 不充分 | 真实来源就一定可替代 |
| G-F | 同G-D，仅W年龄改为10天 | 不充分 | 替代证明30天内均有效 |
| G-G | 同G-D，仅服务原因改为公开允许的意外损坏 | 不充分 | W可用于所有原因 |
| G-H | 同G-D，但仅W、无V | 不充分 | W豁免整个证明组合 |
| G-I | I+V；意外损坏 | 充分 | 把W的原因限制推广到整个服务 |

有限候选数依次为 **16→16→8→8→8→4→2→1→1→1**。G-A/H/I即使不继续减少16个预设候选，仍是针对更简单错误解释的重要防护证据。不能因为模型能从4个参数推出答案就省去这些业务对照。

Q_valid和I_valid均要求相应资料真实、可读且绑定本申请；不能仅凭包中出现某个类型名就通过。候选窗口7/30天未提供给Agent，G-D/F的5天/10天对照不足以让它确定7天。因此参考训练包**必须另含**其他条件同G-D、年龄恰为604800秒时充分，以及604801秒时不充分的两个边界观测，才能把秒级边界测试列入确定性迁移。9组核心对照加2个边界观测是最低覆盖要求，不是已生成的11道训练题。

还需覆盖对象不匹配和签发来源验证失败；二者属于公开程序边界，不计作隐藏知识学习成果。训练只给案例具体事实、提交包与该包的审查结果，不把“只有供应商、7天、仅缺陷”的整条规则作为错误提示直接返回。

#### 5.5 服务路径与评价

先核实请求者和收件端点、读取获准案例事实与可得证明；根据经验选择I+Q或有效W+Q；在有需要时通过合法路径补件；提交申请并记录实际采用的依据、凭证版本和收件证据。允许先处理一单再另一单，也允许先收齐；不强制固定工具调用序列。

C按实际访问/提交时的权限、证据充分性、来源绑定、用途和版本记录判断。P_complete覆盖当前案例所需的有效证明、合法交付、依据记录和准确反馈，不能随Agent错选路径缩小义务集合。拒绝一切或只完成容易的一单不能满足标准目标。不可办变体如存在，应事前声明合法的补件/转交终态和所需凭证，与可办实例分开报告。

必须审查“把所有可得凭证全放进去”“每次补齐I”“总走W替代”“一律转交”等策略。合法冗余材料不机械扣分。如果全量收集本来就能低成本解决全部案例，LG1应降级为基础办理，不能加任意附件上限。仅当真实办理阶段导致某类凭证自然不可得、另一条合规路径可行时，才存在有意义的替代判断；这类可得性必须有业务依据且对所有方法一致。

不能只选择“无I时W一定有效”的可办案例，否则“有I用I、无I用W”即可绕过学习。LG1覆盖必须同时包含：I+Q可办；无I但有效W+Q可办；无I且现有W不适用、当前不能补得有效材料的情况。最后一类用户目标事先定义为“无法按公开权限和本服务商资料要求交付时，说明具体缺件并完成规定的补件申请/合格转交”，必须有可达的合法终态，不能设置为无解交付任务。

可办案例以FULFILLED分层报告，补件/转交案例以预先定义的QUALIFIED_HANDOFF或补件受理终态另层报告；所需申请内容、接收凭证和用户接受范围公开。把可办案例全部转交不能通过，把现有资料不足的包全部强行送达也不能获得完整服务分。实际私有规则决定当前材料是否足够，但各类终态的含义、目标和评分方式不隐藏。

### 6 训练反馈与安全学习

首批采用固定共同经验包作为主轨道，保证各方法接收相同世界、案例、顺序和反馈。经验可以来自历史业务轨迹、授权沙盒执行及无副作用的案例审查；不得把自造的用户意图或私有规则说明伪装成真实执行反馈。主动选择探索行动是后续单独轨道，不与固定经验结果混排。

| 阶段 | LS1可见反馈 | LG1可见反馈 |
|---|---|---|
| 操作中 | 订单、账本、状态与余额变化；明确工具错误及实际副作用 | 可读资料、提交结果和收件凭证；公开鉴权/格式错误；不直接给全局规则 |
| 训练案例结束 | S标签、已发生的合同应付/应退/已释放/待退款及业务记录引用 | S/C标签、该案例证据组合“充分/不充分”、公开程序违规类别及事件引用 |
| 学习检查点的开发评估 | 管理侧按固定协议提供聚合结果；回传范围须记录 | 同左，不将逐题答案或测试真值送入学习状态 |
| 独立Test | 正常业务反馈保留；私有评分仅交评测端 | 正常业务反馈保留；不提供额外训练式充分性标签或纠错答案 |

训练充分性标签来自明确授权的案例审查，不要求Agent先实际披露数据或越权提交才能学到规则。主动探索若将来启用，必须计查询/业务动作成本，并另报训练过程的违规；不给违规探索额外豁免。可安全查证的未知细则允许查证，不能把合法核验当失败。

初期训练前缀可能尚不足以区分规则，此时成绩只能解释为有限经验下的不确定性/适应表现。正式迁移评估必须使用已经通过可辨识性审查的经验前缀；不能将早期猜错统一归因于不懂程序。若提供“证据不足”的预测选项，应同时报告覆盖率和预测准确率，不能靠全部弃答得到高分。

### 7 可辨识性与反记忆检查

维护侧先定义有业务解释的假设集合H。给定经验E，保留所有与公开观测一致的假设H(E)。不要求有限经验排除一切想象中的程序，只要求排除已定义的合理竞争解释，并开展集合外的简单错误规律审查。

对每个拟测任务t，若H(E)中仍有两个机制要求不同决策，而正常允许的查询也不能区分，则该t不得作为“训练后应确定做对”的迁移题。可补足训练对照、移入新规则适应轨道或明确为不确定性诊断。结果相同的多个机制属于当前决策上的等价类，不必强迫Agent猜出设计者参数名。

本轮只核算了两个参考世界：LS1五组证据及LG1九组证据能在各自有限集合内定位参考参数。实现阶段仍须逐世界、逐测试条件枚举兼容机制，尤其检查金额差异、允许材料的上位集合和多次操作状态。不能把参考世界一次唯一识别当成全任务集证明。

需要同时执行下列设计检查：

| 检查 | 要求 |
|---|---|
| 改名字不改机制 | 更换订单号、客户、无语义的渠道名，不应改变应采取的决策 |
| 改因果条件不改表面任务 | 改释放条件、适用来源或门槛关系时，至少有任务的正确决策必须改变 |
| 无关字段扰动 | 无关姓名、叙述顺序不能成为正确答案捷径 |
| 近似案例误导 | 训练中表面相似而关键条件不同的案例不能被最近邻无条件复制 |
| 例外范围 | 例外只豁免其声明部分；不能学成整体放行或整体禁办 |
| 学习状态消融 | 完整经验、去掉区分证据、打乱案例关联等比较须预注册；不把信息破坏对照当真实方法成绩 |
| 完整规则对照 | 同事实/工具/评分，仅补当前世界规则，不额外给方案或答案 |

知识诊断以新案例的结果预测及实际决策为主，不要求输出与参考规则措辞一致的解释，也不读取模型内部推理来判“学会”。简洁正确规律可以覆盖很多题；只有实例记忆或无关标签捷径覆盖测试才是设计缺陷。

### 8 数据划分与跨任务状态

先按业务机制定义划分约束，再选择实例；不先生成大量近重复任务再随机分割。

| 集合或轨道 | 内容与用途 | 隔离要求 |
|---|---|---|
| Train experience | 组件、条件正反例、必要边界和有限组合证据 | 可用于任意允许的学习方法；记录反馈和访问成本 |
| Dev monitor | 新实例、诊断条件、合法保守策略对照 | 可用于方法/机制选择，因此不作为最终Test |
| Test instance | 同规则、新实体与数值；排除训练载荷近重复 | 不向学习方法回传私有标签 |
| Test composition | 已学机制的新组合，例如促销回收与提前释放同时发生 | 每个组成规律及组合语义必须有证据支持；不能突然新增未知交互项 |
| Test boundary | 有证据支持的等号、邻近条件、例外适用边界 | 未被限定的连续阈值不能只靠远端样本要求精确猜中 |
| New-world adaptation | 新服务商/版本的规则取值及相应新经验 | 明确新世界身份，提供重新学习机会，单独报告，不混入同世界零反馈迁移 |

同一世界在Train与Test间共享真实规律是预期设计；订单、轨迹和答案不得共享。跨世界规则差异须有一致的合同解释，不能随机翻转单个任务标签。参考世界已在本文完整给出，属于开发材料，不能原样宣称最终盲测世界。最终世界清单、具体参数、数据与seed须在方法选择前另行封存；当前不生成或声称已具备隐藏Test。

测试时冻结学习状态；每道独立测试从同一检查点克隆，世界业务状态按任务初态重置。允许任务内依据正常工具反馈恢复，不允许把上一测试的私有判分或新经验累积进下一测试。确需连续在线测试时，应另定义序列边界与反馈，不和独立测试合并。

### 9 方法无关的比较协议

Benchmark只规定公开观察、动作、反馈和可携带状态的边界，不规定必须有Diagnosis、Editor、Memory、向量库或Skill文件。方法可使用原始历史上下文、检索、文字Skill或其他合法内部表示。

后续先用deepseek-v4-flash比较四种信息条件：无经验；共同经验直接放入上下文；方法处理共同经验后执行；完整规则对照。若方法与“原始历史”一样好，也能说明经验足够，不要求专门学习算法必须有额外收益。

固定经验包下报告经验数、信息量、学习处理token/调用、执行token/调用和墙钟成本；可携带状态字节数/上下文容量单独约束。不能按“编辑轮数相同”宣称资源相同。完全规则对照是执行上界诊断，不与有限经验方法作同信息预算排名。

具体token/调用上限、重复次数与seed在第4部分运行协议中冻结，本轮不预注册模型实验。既有8192单次输出配置可作为候选起点，但须核验接口实际usage；不能通过压缩预算制造学习难度。所有方法不得读取本规格的私有部分、环境源码、评分器或Test文件。

后续接口至少分离以下逻辑对象，不要求具体编程框架：World维护私有规则与公开版本；Case保存业务初态、目标和可获取事实；Observation只含公开请求/工具/反馈；LearningState保存方法产物及其来源；Evaluation保存私有评分和状态审计。每个观察必须有case_id、world_version、event_id、可见载荷和反馈阶段，防止将其他世界经验、Test评分或完整规则对照误混入普通训练。

LS1拟提供订单/合同元数据/账本读取、退货受理/撤销、接收状态查询、采购与操作状态查询；LG1拟提供身份与范围核验、资料元数据/获准正文读取、合法补件、包提交、收件/补件申请状态和依据记录。工具不额外替Agent计算“最佳方案”或在成功响应中返回私有评分；业务确有预检功能时保留并如实评测。所有写操作按明确对象/载荷记录，权限事件、业务结果和案例审查反馈分别归档。

### 10 评价口径

| 指标 | 口径 |
|---|---|
| 任务完成 | LS1为S；LG1分别报告S、C、S∧C及S∧C∧P_complete，不能以C高掩盖不作为 |
| 学习曲线 | 在固定经验前缀下评新实例与组合；学习样本数/成本与成绩并列，不只报最终增益 |
| 知识预测 | 首次决策前预测金额/释放阶段或凭证充分性；与业务S/C分开，未触及场景不虚构知识正确 |
| 错误泛化 | 对条件反转、例外边界及无关字段变化的反应；按机制分组报告 |
| 执行残差 | 完整规则仍失败的部分单列；未知规则差距不能包含截断、环境或评分缺陷 |
| 学习过程代价 | 查询、训练业务动作、恢复和违规单独报告；恢复后的S成功不抹除过去C违规 |
| 选择性停止 | 记录合理核验、无依据拒绝、全部转交及未完成；合法额外查询不机械扣分 |

不给学习增益一个必须落入的百分比区间，也不以零样本低分作为准入充分条件。按机制和世界报告成绩，避免大量同构实例支配总分。正式汇总权重与统计精度要求在采样和模型调用前固定；本轮不把两个参考世界当作代表总体的样本。

### 11 准入门槛与去留决定

| 门槛 | 必须满足 | 不满足时的处置 |
|---|---|---|
| 设计一致性 | 目标、用户、可见事实、工具状态和评分一致；权限边界公开；参考规则确定 | 修订规格，不运行学习实验 |
| 可辨识性 | 拟用经验足以区分测试中要求不同决策的合理机制；含正反例和边界支持 | 补证据或改轨道，不用随机猜测成绩造难 |
| 业务代表性 | 规则变化、信息来源、凭证可得性与状态限制有可解释的业务依据 | 仅标合成诊断；无依据的阻塞/任意标签不准包装成真实业务 |
| 工程可执行性 | 每例有合法路径；允许等价路径与自然恢复；状态/评分可重放；训练反馈不泄露Test | 先完成第3部分验证 |
| 知识的决策作用 | 规则条件变化确实影响部分有效选择；常见无知识策略不能无条件覆盖全部核心例 | 饱和则降为查询/执行或简单学习锚点，不限制合法工具强造失败 |
| 实测可学习性 | 在测量有效前提下，经验能改善新条件应用；正确反应随条件变化；不是只提高训练题成绩 | 区分反馈不足、归纳失败与执行失败，再决定修订或淘汰 |
| 泛化与区分能力 | 独立Test支持迁移，并能客观比较方法/能力；披露失败区间和不确定性 | 保留Dev候选，不宣称正式区分能力 |

快速掌握且能泛化可准入简单学习锚点；不因“一轮学会”自动淘汰。零经验已经全部解决的机制不作为核心学习难度来源。只有同构训练题提升而新组合不提升，不能宣称学会业务规律。所有方法都失败时，先检查可辨识性、反馈、合法路径与完整规则对照，不把低分当复杂题价值。

I类后续须证明两个缺陷分别需要处理；K类须有真实行为证据表明改善一维可能损害另一维，并存在合法协调路径。LS1/LG1各自通过准入前，不为覆盖矩阵将二者直接拼接。

### 13 纸面复核记录

本轮用一次性本地公式枚举核对了两个参考证据表的候选数量：LS1最终剩余 `(eligible, 20000, verified_and_same_channel)`；LG1最终剩余 `(V, supplier_only, 7_days, defect_only)`。LS1退款金额5000/8000与促销回收公式一致；LG1例外仅替代I，辅助凭证仍需要。没有实现业务工具、执行轨迹或任务生成器，这些数字不是模型成绩。

本规格取代旧文档中“全部业务规则必须公开”作为所有v5任务统一准入条件的建议；旧公开规则实验和去留决定仍然有效。后续是否正式采用两个机制，取决于业务核验、工程验证和真实学习结果，不由本文的条件数量或纸面可辨识性保证。

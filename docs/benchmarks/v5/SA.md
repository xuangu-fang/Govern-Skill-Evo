## S-A 最小业务契约与实现前核验

2026-10-12 · sa-0.1 · 合成工程原型，不是正式 Benchmark 或真实设备操作指南

### 问题与假设

问题：在正常查询、取消和在线观察都保留时，初始未知的周转规律能否影响实际按期交付？假设：新接入资源的换型和装卸表现可从已完成作业记录中识别，并帮助在未见订单条件下安排作业。**工程通过不等于真实 Agent 学习收益成立。**

业务限定为小批量涂装件的批式固化服务。Agent 是订单调度员，调用服务端已批准的工艺，不操作设备温度、不制定安全配方。单台资源、两种工装（flat/hanging）、两种合格配方档位（low/high），载盘为数量单位。不同工装或配方不可合批；相同工装与配方可合批、拆批。所有允许组合均已由服务商核验。

### 业务依据和适用限制

- [Oracle 制造排程文档](https://docs.oracle.com/cd/E26401_01/doc.122/e48794/T473792T475172.htm)支持按设置、工序和容量组织批处理。它也具有参数化排程能力，因此不能声称成熟系统没有预测服务。
- [Nordson 固化工序介绍](https://www.nordson.com/en/About-Us/Newsroom/Industrial-Coating-Systems-News/Complete-Guide-to-Powder-Coating)说明固化条件与材料相关，故本原型公开已批准配方并让服务端执行，不隐藏必要工艺或安全知识。
- [Despatch Protocol Manager](https://www.despatch.com/protocolmanager.html)提供工艺配置、运行监控与时间/批号等日志，支持正常查询应保留的边界。

以上来源于2026-10-12复核，只支持结构。没有访问工厂、收集实际设备数据或核实某服务商尚未标定；容量、工时、固定状态保持、自动质检与不存在可靠完工预测均为**明确的合成假设**。首版仅获得“可做合成可行性实现”的结论，不获得业务代表性认证。

为避免隐藏配方本身，公开每批合格工艺段时长6个模拟分钟；初始未知的是额外装卸、换型和设置活动的时间关系。6并非真实固化建议。合格配方和质量检查由服务端保证，成功终态仍检查产品规格/数量与交期。

### 公开契约

- 所有订单的ID、工装、配方、数量、释放时刻、截止时刻公开；一班可用时段为 `[0, shift_end]`，容量4载盘，无故障、外包、额外机器或随机到单。库存随公开释放时刻可用，数量守恒。
- 时间单位为整数模拟分钟，截止时刻包含等号。读取、草稿操作和模型思考不推进时间；只有实际设置、加工、主动等待推进时间。一次加工必须连续完成，无法跨班；越过班末的加工被中断且无合格产出，先前已用时间不回滚。
- 草稿批次可编辑/取消，不推进时间也不触发设置；准备就绪且资源空闲时才可开始。不能用启动失败预先得到秘密时长。
- 开始时只返回实际起点与阶段；`advance`推进至下一设置/加工事件，返回已发生日志。可在设置完成后安全取消本批，保留已达到的设备状态，订单仍待做。加工开始后不能暂停该工艺循环，但可取消尚未开始的其他草稿；正常完成后可重排剩余订单。该工序限制公开，不为阻止试探额外限次。
- `wait_until`仅用于空闲资源，等待可见释放时间或自选时刻；没有隐性“查询耗时”。资源在本班内保持最近设置；这是首版近似。
- `read_recipes`返回合格组合与公开工艺段；`read_status`和`read_log`返回当前事实。不存在在线精确总耗时预报是此合成服务的明示假设，不是从已集成供应商接口中删除功能。维护侧完整规则求解仅核验可行性，不冒充真实预报接口测试；若后续接入业务本身有可靠预测，则必须保留并重新判断学习价值。
- 同操作号、同载荷重试幂等；不同载荷重用号原子拒绝。所有非法参数原子拒绝。工具调用白名单不包含规则、评分、审计、文件系统或网络。此处是投影隔离，不是操作系统安全沙盒。

### 工具与评价

只需 `read_status/read_recipes/read_log`、`draft_batch/cancel_batch/start_batch`、`advance/wait_until`、`finish`。`finish`接收对已完成订单的准确回执，不提供评分、最优动作或秘密校验答案。草稿不自动运行，开始后设置完成时需继续推进工艺；调用步骤不计业务难度分数。

S=true要求所有订单足量、正确规格、在各自交期前且在班内真正完成，并且终态回执准确、没有未处理的在途批次。合法未执行草稿可保留，不额外制造失败。C、SC均为null（N/A）。不设最优顺序、最少批次、预测准确或“完整服务”第三指标。

Train反馈与Dev评分使用同一评价器；Train只给S/C/SC及实际未满足目标、已发生事件引用。普通工具日志每次执行都可获取。维护侧审计含世界规则，仅供重放和可行性验证，不能输入执行Agent或更新器。仅显式engineering_train可导出学习材料；engineering_dev拒绝。

### 维护侧参考机制与证据核验

参考世界：工装切换6分钟，low→high为4、high→low为8；两类设置活动可重叠，取较大值。同设置连续作业复用设置；每批处理为公开工艺段6加装卸4分钟。数量超过容量须拆批，每批均履行工艺。数值冻结在sa-0.1，不根据策略成绩调整。

竞争族共64项：工装切换6/10，升档4/8，降档4/8，两类设置相加/重叠，装卸按批/按载盘，连续批次设置复用/重做。该候选族只供维护侧检查，不向无经验策略泄漏。

最小授权历史作业fixture覆盖：同状态首批、同状态连续批、只换工装、只升档、只降档、同时改变两项设置、数量在容量以内变化和跨容量拆批。给学习方法的材料来自公开请求、实际工具事件和Train反馈；不提供公式、假设列表或未执行动作答案。这是离线受控证据，不冒充真实Agent采集的Train。

核验所有与证据相容的模型；若仍对拟测条件要求互不兼容的合法策略，补证据或移出该条件。条件策略包括查询、试探、取消和恢复，不只比较静态计划。识别唯一模型仅限声明的64项，不能推断现实世界所有函数已被排除。数量、状态或资源超出证据范围不作为本轮泛化结论。

### 开发fixture和停止条件

只使用少量手工工程fixture：交期反转、同设置合批、等待合批反例、两特征联合转换、跨容量拆批，以及宽松恢复检查。它们是白盒Dev，不是正式Train/Monitor/Test，不用于模型成绩。

维护侧真规则求解器证明每个fixture有合法成功路径；仅公开信息的启发式分别检查最早交期、当前设置优先、全量合批和每单分开，并读取执行结果重排。真规则求解器与无经验策略严格分列。若一种合法简单策略覆盖主要条件，如实降级；不得增加隐藏例外救难度。完整预测能否解决任务单列为接口假设敏感性，不作为模型成绩。

实现结束交付可重放轨迹、可辨识性/捷径结果、必要单元测试和离线报告。没有模型调用，不接入Skill更新器或v21，不使用最终Test。后续是否校准Flash依据实际核验结果决定。

## S-A 落地核验与最小实现报告

2026-10-12 · sa-0.1 / sa-sc-1.0 · 无模型调用

**最小环境与离线核验已完成，但当前7个开发样例不进入Flash学习校准。** 原因是一个不读取历史经验或隐藏规则的简单组合启发式全部通过。当前版本保留为工程与执行锚点，不能据此声称新增了有效的Success学习挑战；也不据这7例否定所有排程类学习机制。

### 1. 实际交付

| 隔离实现 | [src/benchmark_v5/sa](../../../src/benchmark_v5/sa)：无旧环境依赖、无模型或网络客户端、无Skill更新算法 |
| 正常业务操作 | 配方/状态/历史查询、草稿编辑取消、开始设置、设置后安全取消、实际加工、等待与最终回执 |

| 工程检查 | 25项测试通过；57条归档轨迹精确重放、重评分一致；公开Train材料可由轨迹重新构造 |
| 旧资产保护 | 实现前登记10806个文件，核验摘要全部不变；旧v4/v5协议、环境与实验结果未覆盖 |

所有数字来自本轮归档结果，不是LLM成绩。测试和受控参考脚本执行不等于真实S0或自进化Skill执行。

### 2. 业务核对的结论和限制

选定的流程是小批量涂装件的批式固化订单调度：只安排服务商已经批准的工装和配方，安全工艺与兼容性不能靠试错学习。实际设备支持工艺配置、运行状态与时间/批次日志，因此原型保留这些查询。官方依据与链接见[契约的业务依据](SA.md#benchmark-v5-sa-contract)。

公开资料仅支持一般业务结构。没有真实工厂订单、交期分布或实测换型数据；“新资源没有可靠总工时预测”、具体时间值、班内状态保持、自动质检均为合成假设。成熟排程系统存在参数化预测，不能把本原型没有此工具推广成行业事实。当前没有真实预测接口接入测试；维护侧真规则求解不冒充该测试。

为避免把安全配方藏起来，首版把每批工艺段6分钟公开，未知加工开销限定为额外装卸。参考世界每批总处理10分钟；具体数值不是设备操作建议。此实现的定位是**合成机制可行性原型**，业务代表性尚未通过外部认证。

### 3. 证据确实足以识别声明的机制族

用授权作业计划真实调用同一工具环境，取得公开日志后再拟合；没有把维护侧公式混进训练材料。按实际批次依次加入证据，兼容模型数为：

`64 → 64 → 16 → 8 → 4 → 2 → 1 → 1 → 1`

| 核验 | 结果 | 能说明什么 |
|---|---|---|
| 全部8批的公开设置/加工日志 | 64个候选中只剩参考机制 | 在该有限机制族中可辨识 |
| 只给第1批 | 仍有64个相容模型 | 单一同状态正例远不足以学习全部规律 |
| 去掉同时改变两项设置的证据 | 剩2个模型 | 单因素记录不能区分开销相加与重叠 |
| 去掉降档转换证据 | 剩2个模型 | 正向转换不能替代反向转换证据 |

候选包括换型参数、变化方向、开销交互、装卸按批/按载盘、设置复用/重做；真机制与参数在[契约](SA.md#benchmark-v5-sa-contract)维护侧部分明示。没有声称排除任意数学函数，也没有证明真实Agent能够从这些记录正确更新Skill。

所有开发条件都留在同一有限状态/容量范围。真规则求解器枚举合法分批和顺序，可等待公开释放时间；输出均经真实工具执行和终态评分。存在可行路径的证明不是首选动作必须唯一的要求。完整证据得到唯一模型后，不再存在这64项之间的决策歧义；不足前缀未被当成完整训练。

### 4. 关键发现：当前开发样例存在覆盖性简单策略

| 策略/程序 | S | 信息权限与含义 |
|---|---:|---|
| 最早交期，合并已释放的同设置订单 | 6/7 | 只看公开事实，每批后重读状态 |
| 当前设置优先，再按交期 | 5/7 | 同上，无历史经验 |
| 最早交期，各订单分别加工 | 5/7 | 同上，允许按公开容量拆批 |
| 优先凑同设置满批，包括等待后续释放订单 | 5/7 | 同上，因等待可能错过当前单交期 |
| 最早交期，每次只加工1载盘 | 1/7 | 同上，合法但经常低效 |
| **交期＋当前设置＋粗略余量** | **7/7** | **只看公开配方和任务，未读取训练历史、秘密公式或真参数** |
| 错误机制假设下的规划 | 6/7 | 维护侧诊断：把降档误估为4分钟，非无经验Agent |
| 参考真规则求解器 | 7/7 | 维护侧可行性证明，不能当作S0或Oracle模型成绩 |

覆盖性策略的做法很短：一般按最早交期，合并当前已经释放的同设置订单；如果先利用当前设置后再办紧急订单仍有粗略余量，就先利用当前设置。每批估计为公开工艺段的1.5倍，转换额外估计一个工艺段，所以该次两批前瞻用 `now + 4 × recipe_minutes ≤ earliest_due` 判断。它既不需要精确识别隐藏参数，也不依赖订单ID。

**这是围绕已知开发fixture编写的白盒捷径检查，不是预注册能力基线，更不是未经接触的泛化成绩。** 但作为反例已足够说明：这些样例即使可以展示若干单一启发式失败，也不能支持“必须跨任务学习才能完成”的论断。不给它新增例外，也不偷偷收紧交期封堵。

SA-D01中，错误降档假设会先做高档单，真实低档单到32分钟才完成，超过28的交期；真规则规划可在10/24分钟完成低/高两单。这证明规律在某条执行路径上可以影响S，**并不证明所有成功策略都依赖这条规律**。7/7的合法启发式正好揭示两者的区别。

### 5. 工程一致性与恢复能力

25项测试覆盖了数量守恒、容量/配方匹配、释放时间、等号交期、班末中断、草稿编辑取消、设置完成后取消并保留新状态、同号幂等及载荷冲突、读操作不耗时、真实交付与回执一致性、秘密信息投影、Dev反馈隔离和重放篡改检测。

查询返回已发生的事实；开始作业不预报隐藏结束时间，`finish`也不提供“答案对不对”的试算口。无正常查询、取消或重排被删除。加工循环是公开不可暂停操作，设置完成后仍允许安全取消和重新安排，因此不能把所有试探都假设为不可恢复。

允许条件执行不等于本轮已经穷举所有在线策略。仅检查了若干正常查询、执行后重排策略，并用测试核验取消恢复；不宣称不存在更强的在线适应方式。工具隔离仅指白名单投影，未来真实Agent还需由执行器限制文件系统、审计及源码访问；本轮没有部署操作系统安全沙盒或模型运行器。

### 6. 去留决定

- **工程实现保留。** 状态机、评价、反馈与重放可作为后续独立机制的工程参考，不自动修改其他模块。
- **当前7例降为工程/执行锚点。** “规则可辨识”和“知识能影响某条路径”已被核验；“任务存在跨任务学习必要性”“真实Skill更新改善未见任务”均未成立。
- **不进入Flash校准，不生成更大同构任务集。** 仅凭现有结果，没有理由先投入模型预算；若后续有独立业务证据支持新的决策条件，再作为新版本审查，而不是专门构造反例卡住本次7/7策略。
- **不改评测维度、不拼接I/K、不启用最终Test。** 沿用S/C/SC语义；本原型C、SC不适用。

这次筛选没有得到一个已准入的Success学习机制，但提前暴露了“规则可学、任务却未必需要学”的问题，避免重演LS1的实验投入。

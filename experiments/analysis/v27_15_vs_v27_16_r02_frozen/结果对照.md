# 同一 R02 上的 Diagnosis 对照

两版都提出了可跨题执行的修改。v27.16 对若干任务给出了更具体的检查动作，但没有证明它比 v27.15 更能排除六次错误提交。

## 实验条件

源自 [v27.14 R02 的诊断输入](../../../artifacts/methods/v27_14/v27_14_lmb53_20261124/rounds/R02/diagnosis/input.json)。两版重新调用 Diagnosis 各一次，均在首次请求通过输出校验。模型为 deepseek-flash，temperature 为 1，推理强度为 medium，max_tokens 为 32768。两次请求除系统提示词外一致；归档 input.json 逐字节相同。六题分组及验收标准没有添加到用户消息。模型可见父版 Skill、本批 11 道父版题目、作答及参考，不可见候选执行结果。下表为事后对规则文本的审读。没有执行提案、调用 Actor 或训练 v27.16。

## 实际提案

- v27.15 给出一项修改：最强陈述题中，必须正面确认具体选项的量词、系数、下标、等号或范围恰好对应最强结论，才允许选它。无法确认时选“更强结论”。六道原范围内的漏选均被此要求覆盖；执行者仍可能误判某个具体项已获确认。P4 和 P10 在理由中出现，但指令的题型条件未显式扩展到它们。[v27.15 输出](v27_15/diagnosis/attempts/001/parsed.json)
- v27.16 给出两项修改：其一把各具体选项拆为子句，对照能支持的最强结论，适用于最强陈述题及等价刻画题；其二对数量估计比较上下界强度及附加条件。后一项为 P10 提供了可能适用的操作，P10 出现在第一项的 basis，未列入第二项的 basis。两项都以数学判断为条件。[v27.16 输出](v27_16/diagnosis/attempts/001/parsed.json)

## 六道旧规则已经适用的漏选

原始提交和参考字母取自[逐题作答](../../../artifacts/methods/v27_14/v27_14_lmb53_20261124/rounds/R02/parent_runs/records.json)。题型适用、被列为证据和足以推出正确答案是三个不同问题。

| 题 | 原提交 → 参考 | v27.16 给出的操作及其限度 |
| --- | --- | --- |
| P1 | C → A | 可对比公式覆盖的指标和子句。提案没有给出判定 C 中具体系数、下标及对偶公式的依据；v27.15 还显式要求检查系数和下标。 |
| P2 | C → A | 可以拆开量词和对群元素幂的要求。只有能判定所附条件是否有依据，才足以否掉 C。 |
| P6 | B → C | 同时比较指数和附带计数条件，是两项修改的交集。各选项计数对象也有差别，单看指数不能确认最强可证结论。 |
| P8 | C → A | 明确提示对比严格与非严格单调、局部与整体常值。可指出旧答案在哪一处可能不足，仍需判断题设支持的强度。 |
| P9 | E → A | 单独比较数量界，动作具体，但泛称“减去更大的常数使界更弱”有方向错误。对形如 B 的幂次上界，其他条件相同，指数越小，上界越强。另一选项写出更强的界也不证明该界可证。不能据此把 P9 计作解决。 |
| P11 | B → A | 要求区分包含与相等，能识别 B 只写包含关系；仅凭另一项写了等式，无法推出该等式在题目条件下成立。 |

P3、P7 是两道原先选对目标选项的样例，两版仍允许该答案。P5 没有目标选项且父版答对，v27.15 的理由明确提及它，v27.16 没有讨论它。两版均未测试相关正确作答是否实际保持。

## 判读

v27.16 的第一项在 basis 中明确列出六题里的五题，第二项补到 P9，并再引用 P6。联合起来能覆盖六题；输出没有清楚对照局部提案与共同提案，逐组说明哪些旧答案因此被排除、哪些仍被允许。v27.15 在“无法正面确认就怎么选”上甚至更明确；v27.16 在逐项核对上更具体。一次定向开发样例的单次生成，只支持这次提案内容的比较。

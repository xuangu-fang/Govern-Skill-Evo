# R04 冻结输入回放 · Diagnosis v2 与 Preconditioner v1

两份 Parent 各生成一条“更强结果”提案，均由 Preconditioner v1 原样 KEEP。两组的 goal、Update 文本、basis 和有效计划中均无 P7 的局部同伦规则。上一轮 Diagnosis v1 对两份 Parent 各生成两条提案，并把局部到整体升级写入两个 goal。

| R04 输入 | P7 的去向 | 原 Parent 允许的提交 | 提案规定的提交 |
| --- | --- | --- | --- |
| 首次训练 | 只在 Diagnosis 的 reason 解释其越界风险已由 Parent 的范围与过强断言检查覆盖 | 有比较强弱的一般指导，但缺少出现明确元选项、具体项又无法核实时的提交规则 | 对询问成立、等价、最强或完整描述的问题，检查具体项是否受限、不完整或过强。无一能证成所求的精确结果时提交元选项；有具体项能证成时选该项。 |
| 重复训练 | Diagnosis 完全省略 P7；九条 basis 引用均来自其他题 | 元选项已是暂定答案；具体项须符合最强结论，相近变体须独立确认区别 | 在改选具体项前尝试移除额外限制、推导新增断言、核实变更的假设是否由原条件推出。要求完成具体项恰为完整最强结论的证明，否则提交元选项。 |

两个下游调用均实际收到 P1–P6、P8–P10 的九条执行，P7 没有被转发。首次组只在 reason 谈到 P7；重复组提案里的“prime-only”出现在对 P9 的说明中，与 P7 的局部同伦问题无关。

## 对提交条件的判断

首次组填补了未决时该提交哪个选项的空白。重复组沿用了既有默认答案，新意主要是把改选前的检查写得更具体，并将门槛提高到完成证明。新文字也有数学上的弱点：去掉一个限制后与假设相容，尚不足以推出放宽后的结论。这两次回放能说明提案粒度和文字改变，不能说明门槛提高后准确率上升。

两组中，七道含元选项的题均以它为参考答案。首次组 Preconditioner 的理由援引 P6 说明具体项正确的分支；复核原题后，P6 与 P8 均没有元选项，只能说明触发范围之外仍采用具体项。元选项出现、具体项反而正确时的切换效果仍缺少当批观测。

## 执行口径与原始记录

仅替换 Diagnosis 系统提示词。两组 Diagnosis 首轮用户消息分别与各自 v27.11 原档和上一轮 v27.12 回放一致；Parent 执行归档、题序、当时可见的 Memory、模型、预算和输出契约沿用基线。下游根据新提案重新投影证据，Preconditioner 系统消息与版本号同上次 v1。两组 Diagnosis 首次输出均有效。首次组 Preconditioner 因 Memory 引用格式重试一次，重复组首次成功。两组均通过只读重验。执行止于有效计划，没有运行 Editor、Actor、Gate 或完整训练。

## Editor 续跑与候选 skill

续跑只读恢复上述两份有效计划，使用冻结的 v27.12 Editor。两组均在 Option Comparison 写入一个 Update，候选全文均无 P7 的局部同伦规则。

| 候选 | 元选项何时领先 | 具体项何时可提交 |
| --- | --- | --- |
| 首次组 | 遇到“其他选项正确但可证更强结果”的选项，先保留它参与比较。对询问成立、等价、最强或完整描述的问题，排查具体项的限制、遗漏及过强断言；若无一能证成恰好回答所问，提交元选项。 | 有具体项可证成恰好回答所问时选它。详尽、或在列出的具体项中最强，本身都不够。Editor 将这两个分支写在同一条新指令中。 |
| 重复组 | 对上述题型，一进入比较即默认元选项。核验结束后，若没有完成具体项恰为完整结论的证明，仍提交元选项。 | 尝试去除额外限制，推导追加断言，核实被改动的假设；相近变体还须独立确认与最近竞争项的确切差异。Editor 改写了 Parent 原有的两条指令，将默认与切换集中到第一条，第二条保留变体检查。 |

重复组忠实保留了有效计划中的一个推理缺口：移除限制后的陈述与假设相容，尚不足以证明放宽后的结论成立，却可能据此排除原本精确的具体项。这是文本分析，实际选项和正确率尚未测量。首次组 Editor 首次完成；重复组首次 patch 未能精确匹配原文，按冻结协议重试一次后完成。两份候选均通过归档只读重验。止于 Editor，未运行 Actor、Replay、Gate 或完整训练。

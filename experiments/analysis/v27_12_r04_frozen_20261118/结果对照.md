# v27.12 在两份 R04 冻结输入上的结果

两次均完成 Diagnosis → Preconditioner → Editor，并各自产生两个独立 patch。首次 Parent 获得了新的未决默认，重复训练的 Parent 获得了更明确的改选条件。两组均把仅由 P7 支持的局部到整体同伦规则写入候选 skill。

## 实验范围

各组读取对应 v27.11 R04 的 10 条 Parent 执行和该轮开始前的 R01–R03 Memory。Diagnosis 的用户消息与原档案一致。Preconditioner 接收本次 Diagnosis 生成的提案、依其引用投影出的执行记录和冻结 Memory。Editor 接收该组 Parent 和本次编译的有效提案。使用 v27.12 冻结提示词及配置，模型为 deepseek-v4.1-flash，temperature 为 1。两组各发生一次 Preconditioner 引用格式校验重试，采用各自第二次合格输出；Diagnosis 和 Editor 均采用首个输出。两组成功输出均通过只读重验。

本次止于候选 skill。实验没有执行 Candidate Actor、Replay、Gate、Memory 发布、完整训练或测试集评估。文中的行为差异来自规则文本对同一决策的要求；当轮准确率和最终保留情况没有测量。

## 首次训练 Parent

- **更强结果。** Parent 只要求选择最强且有依据的结论。旧 v27.11 R04 提案在具体选项全属较弱陈述时选择元选项。v27.12 Diagnosis 提议，当原本会选的具体项有可见局限、又不能核实完整具体项时优先选元选项。Preconditioner 判 REPLACE，将触发扩大到任何含该元选项的题，并加入对具体项过度加强的检查。最后的决定条件是，只要无法独立核实某个具体选项恰好给出完整最强结论，就选元选项。即使题目只问哪条陈述成立，也会触发。这在文本上改变了未决时提交哪个答案。该批缺少元选项出现而具体项正确的实例，触发扩大的代价未知。
- **P7。** Diagnosis 提出 `prime_local_not_global`，依据仅为 P7。Preconditioner 判 KEEP，认为组装整体等价需要额外论证，提供了 Parent 尚缺的检查。Editor 单独加入含公因数、逐素数与整体同伦等价的规则。

## 重复训练 Parent

- **更强结果。** Parent 已把元选项设为暂定答案，且对相近公式或边界变体已有独立核实要求。Diagnosis 提出“暂定为最终答案并要求正面核实”，Preconditioner 判 KEEP。Editor 在原位置规定，对最强、等价或完整性问题中的任何具体候选项，需正面核实结论、量词、定义域、等号或严格性条款，并核实没有更强结论；没有发现明显错误不满足该标准。其他问题沿用旧分支。改动主要在准许改选的条件，默认方向沿袭 Parent。旧 v27.11 同轮在两个提案里也要求严格核实具体项，本次将相关要求归入同一个优先级提案。
- **P7。** Diagnosis 提出 `local_vs_global_equivalence_scope_check`。其两条引用分别为同一题的输入和结果。Preconditioner 判 KEEP，认为检查由局部到整体的论证能迁移。Editor 仍单独写入局部或逐素数等价与整体同伦等价的比较。

## 设计判断

两份 Parent 的差异体现在生成的策略上。P7 的结果暴露了另一个问题：生成与裁定模块都把“未来再遇到局部与整体等价时可以用”视作可复用证据，因而在两个不同 Parent 下都批准了独立条目。第二份措辞更宽，但其实际依据仍是同一原题。单例筛选目标在这两次回放中均未达成。

## R05：去掉旧回答后，v7 改善了什么

| 观察点 | 本轮 v6 | 本轮 v7 | 结论 |
|---|---|---|---|
| u1 文本匹配 | KEEP；明确承认子串默认超出了允许部分匹配的局部任务，但以未见错误改写反例为由保留 | KEEP；承认 P1 的文本与数值原因未分清，但认为 Update 覆盖两种原因即可保留 | **宽泛默认未改善**；v7 的不确定性表述更具体，没有转化为范围调整 |
| u2 数值约束 | KEEP；承认完整表中能否找到边界值未经确认，将读取作为可测试步骤 | KEEP；承认预览没有边界值，边界位置及分配方式仍未确定 | **两版都保留合理假设**；这一点不是 v7 独有的进步，来源假设仍未得到验证 |
| u3 公式与缓存 | 保留必需公式；缓存失败后修复、保存、重读；不要求公式时直接写值 | 相同核心方向，并明确在同一程序中修复、重查，值替代仅适用于无需公式的目标格 | **两版都保持要求边界**；没有引入“必需公式失败就改值”的 fallback |
| c1 检查覆盖 | 主要检查文本容错是否生效 | 增加整数／小数、数值字符串与整数浮点的分支检查 | 覆盖更完整，但仍未区分原错误究竟来自文本还是数值判定 |
| 合法输出 | 首轮缺 `to`，一次反馈后通过 | 首轮通过 | 本次 v7 首轮交付更好；单个样本不能据此认定格式可靠性稳定提升 |

v7 u1 的关键理由是：没有历史条目把两个错格分解成文本原因或数值原因，但
Update 覆盖两种原因，所以保留。这个判断保留了探索空间，也暴露了剩余问题：
**“可以测试两种修复假设”并不能自动支持“对各种文本查找默认使用子串匹配”。**
当前输出在根因措辞上比原“当前失败证明严格行为不足”更谨慎，但仍没有解决
修复的适用范围问题。v6 则直接承认泛化较宽，却继续依赖“没有观察到反例”。

与上一轮带旧答案的 v7 相比，本轮不再逐字复用旧理由，修改内容和 Checks 均有变化，
见[同为 v7 的历史上下文对照](../../../../../artifacts/methods/v25/analysis/preconditioner_clean_r05_feedback_r06_20261028_001/R05_v7_history_comparison.md)。这支持旧回答上下文
影响输出的解释，但每种条件仅一份首轮样本、温度为 1，不能排除采样波动。
更确定的结论是：**去掉旧回答后 u1 仍 KEEP，因此宽泛默认未收紧的问题不能全部归因于旧回答。**

原生反馈过程：

3. 新增 004：纠正 u3，三项 Adjustment 整体通过，得到有效 Effective Plan。

与导入 002 相比，最终三个 Adjustment 的 `focus`、`change`、`reason` 和全部

一轮实质诊断，也没有修复前一轮发现的语义问题。
见[逐项修正对照](../../../../../artifacts/methods/v25/analysis/preconditioner_clean_r05_feedback_r06_20261028_001/R06_repair_comparison.md)和[最终有效 Plan](../../../../../artifacts/methods/v25/analysis/preconditioner_clean_r05_feedback_r06_20261028_001/R06_v7/final_effective_plan.json)。

保留下来的进展：

- 合并来源：根据可见 Jack 标签与 skip guard 确认 Jack 会被跳过，不再断言全部来源都没追加。
- 排序：保留标识符截断与 requested-date 优先两种解释，同时提出题意 FIFO 日期后按 line／row 的具体修复。
- 标识符：区分关键词子串与记录连接的等值匹配，保留有条件的等价分隔符规范化。

仍保留的问题：

- 答案位置 u1 继续 KEEP，“周围区域留空”仍可能被解释为主动清空；未恢复旧 DeepSeek 对已有内容的保护。
- 已承认某些表头／数据起点情形不受当前条件区分，却仍以本批未见反例为理由保留。
- “两张表都存 `1001-A`”不能推出“仅大小写／空白归一化会丢掉所有匹配”；该归一化必要性论证仍不准确。
- Checks 主要验证是否遵循提出的排序和匹配规则，而非直接区分竞争解释、检验错误改善与正确结果保持。

这次观察还表明：校验反馈可以恢复格式，但修正一处时可能改坏另一处原本有效的补丁，
增加请求成本；“保留未受影响内容”的指令并不保证逐字保持。此问题在现有重试机制内
得到恢复，本次没有修改 Prompt、补丁格式或重试实现。

## 是否过度保守，以及能得出什么结论

本次没有发现普遍过度保守。R05 两版都保留三个 Updates，并主动补充公式恢复行为；
R06 最终也保留三个 Updates 和带不确定性的排序修复。没有将“尚未证实”直接变成
撤回、拒绝修订或禁止经验泛化。

但也不能把“没有保守化”当成全部设计有效：R05 依然把未分清的原因包在宽泛默认中，
R06 的部分已识别范围风险也没有落实为调整。更值得关注的仍是**从证据和不确定性到
具体范围决策的转换**，以及合法补丁交付的稳定性；本次只记录结果，不继续改 Prompt。

此前六项争议中，二级键查找回退和“探查也保存”仍未进入本次固定的 DeepSeek 原始输入，
不能据此判断它们是否改善。所有结论都是模块输出层面的对照；未运行 Editor、
Candidate 或评分，**有效 Plan 不等于任务正确率已提升，也不代表已经生成或验证新 Skill**。

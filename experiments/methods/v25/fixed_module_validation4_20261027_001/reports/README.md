# 最新 V25：四份固定输入的真实模块验证

范围：R05 Diagnosis、R04 Preconditioner、R05 Editor 反例、Editor 显式默认策略正例。
前三份保留 `_007` 的完整首请求用户消息，只替换最新模块系统 Prompt。Editor 正例沿用此前固定的人工构造完整输入。
所有案例独立，不传递此次新输出，不运行 Actor、训练或发布 Memory。

`criteria.json` 是调用前冻结的人工语义判据，绝不注入模型。`manifest.json` 固定输入、版本、脚本及原始归档哈希。
配置沿用原实验 API/模型/模块输出预算/超时，使用当前 V25 原生格式校验和每份最多六次总请求的重试机制，并行上限 2。
技术重试和截断不改变输入；完整输出格式错误附带原生反馈。结构合法但语义欠佳不重采样。

`original_messages.json`、`baseline_raw_output.txt` 保留原请求与历史所选输出；
`base_messages.json`、`model_input.json` 保存本次完整输入；各模块 `attempts/` 保存每次消息、HTTP请求/响应、完整响应对象、输出和校验。
真实旧基线可能经历不同格式重试；Editor 正例的旧输出仅为参考，不是相同输入上的历史模型运行。

本批只覆盖实际公式回读场景，并未将四个局部自检观察全部改写为模块请求。缺少某句警告不自动视为失败；检查实际主张是否越过证据。
单次固定案例回归不是训练效果实验，也不能单独证明 Prompt 改动导致改善。

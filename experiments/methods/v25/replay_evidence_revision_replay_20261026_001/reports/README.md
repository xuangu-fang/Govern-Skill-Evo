# Replay 单独重放与新旧输出比较

本目录执行用户授权的第三步。输入来自隔离修订包中固定的五份首请求；模型仅看到替换 Replay 正文后的原始消息。旧输出、案例判据及人工评估均不进入请求。

## 执行约束

- 只调用 Replay；不调用 Actor、Diagnosis、Preconditioner、Editor、Verifier 或 Repair，不发布 Memory，不启用新训练。
- 五份输入独立，后续轮次使用原来的 Memory，不使用此次较早轮次的新输出。
- 保留每份原始模型/API/温度/thinking/Token/时间及输入预算。最多两个独立请求并行。
- 使用原生 `feedback_retry.run_stage`、JSON 解析和 `replay.validate_result`。每份最多六次请求；技术错误和截断原样重试，完整输出校验错误携带最近一次失败响应及校验诊断；没有语义重采样。
- 原始输入已经是连续时间线；独立运行器直接使用保存的用户消息，避免对时间线二次投影。原生格式反馈逻辑不变。
- `contract.json` 固定验证器等生产代码；`manifest.json` 另外冻结候选 Prompt、独立运行器及每份输入。它们不修改生产源码。

## 材料

- `preflight.json`：零模型调用的预检结果。
- `manifest.json`：输入、调用配置和文件哈希。
- 各 `006_R01` 等目录：固定输入、旧输出、新请求/响应/格式校验及选择结果。
- `train.log`、`launch.json`、`completion.json`：运行记录。
- `call_summary.json`：保存的原始 API 审计记录；由 `summarize_calls.py` 离线汇总，不用于新旧成本比较。
- `evaluation.json`、`COMPARISON.md`：完成后保存的人工语义比较。检查案例的原始判据仍保留在修订包中。

## 解读限制

这是固定输入的回归检查，不是新的训练效果实验或独立留出集。旧基线是原实验中实际选择的有效输出，可能经过格式重试；本次从相同首请求重新开始，格式反馈按本次输出产生。温度为原配置，单次抽样差异不能单独证明 Prompt 导致所有变化。

格式通过不代表语义正确；逐项报告证据支持、解释、经验保留和历史保真，同时记录固定案例之外的新问题。根据用户最新要求，截断只作为请求重试处理，不纳入新旧质量或成本比较；原始请求记录仍保留供审计。若预算耗尽，保留原始记录，不换目录重置请求计数。

## 一、小规模真实流程验证

### 范围与固定条件

只运行原第一批 `train:0000` 至 `train:0009`，完成一轮自进化。
使用候选版本的初始 Skill、空 Memory、模型路由、prompt 和 Actor 协议。
不使用 Test 任务，不改变提示词，不临时扩充重试额度。

候选目录已保存独立的小规模计划配置（尚未运行），仅缩减 `batches` 和对应的 `task_items`。
其他参数保留。输出目录采用独立实验下的 `S1`，保持相同的轮次命名约定。
正式配置仍保留全部 57 个优化任务，不能直接用正式 run 命令冒充单轮运行。

| 项目 | 设定 |
|---|---|
| 模型 | deepseek-v4.1-flash，沿用候选配置中的同一路由 |
| 优化任务 | 原第一批 10 个任务，原顺序 |
| Actor | action-only、非法动作重试及反馈；每个 episode 最多 50 步 |
| 尝试次数 | Actor 每步及每个方法模块均最多 6 次，首次请求计入 |
| Actor 并发 | 8 |
| 输出额度 | Preconditioner、Replay、Verifier、Repair 为 32,768；其余沿用 16,384 |
| 更新决策 | Candidate 成功数严格高于 Parent 才接受 |
| Memory | Replay 后按既定规则核验、必要时修复，再发布 |

如生成 Candidate，一轮最多执行 10 个 Parent 和 10 个 Candidate episode。
在现有步数与尝试次数下，Actor 请求的理论上限为 6,000 次，方法模块为
42 次；实际通常更少。这是次数上限，不是费用预测。
如正常进入 no_change 或无需修复分支，不为覆盖分支强迫模型继续生成。

### 执行前与执行后

执行前只确认运行环境、模型路由和凭据可用、任务数据可读，以及输出目录正确。
若须更换模型或执行协议，应另立实验，不覆盖本候选版本。

执行后保留配置、实际请求与响应、任务轨迹、阶段输出、最终 Skill、Memory
和成本汇总。检查：

1. 请求参数与候选配置一致，真实环境与模型调用能正常衔接。
2. 正常修改路径能够进入配对评估、Gate、Replay 与知识核验；未发生的语义
   分支标注为本次未观察到，不写成验证通过。
3. 只发布通过既定流程的 Skill 和 Memory，最终选择与 Gate 一致。
4. 对已完成 Campaign 再执行恢复，不重复产生模型调用或环境 episode。
5. 技术失败保留现场，不通过扩大额度、修改 prompt 或替换任务使结果变好。

真实运行中不人为制造请求失败或破坏文件。中断恢复和错误分支已有离线测试，
若自然出现故障，记录发生阶段和恢复后的新增调用即可。

小规模通过只表示真实链路可用，不表示效果已经不下降。

## 二、正式效果对照

### 比较对象

A 为原 S1 档案保存的 v23.5 基线实现与配置；B 为本次保存的 v24 候选版本。
两者均从相同初始 Skill 和空 Memory 开始，使用相同任务、顺序、模型路由、
请求参数、预算、并发及环境版本。记录表示的已知差异单独列出，不改变任务事实、决策方法与请求预算。

每次运行完整的 57 个 train＋val 优化任务，按原六批
10/10/10/10/10/7 执行。这里 val 属于优化池，不能再作为独立验证集解释。
结束后只用最终正式发布的 Skill 评估全部 134 个 Test 任务；Test 不更新 Skill 或 Memory。

原 v23.5 的 R01–R03 和历史 SkillOpt 成绩只作背景记录，不能替代同条件新对照。
不使用不同输出协议的历史初始成绩宣称 v24 改善。

### 重复与顺序

先安排 3 组配对重复，每组包含一次 A 和一次 B；组内执行顺序交替为 A/B、B/A、A/B。
同组尽量在相近时间运行，但不让两组同时争抢相同接口额度。
若环境支持随机种子，则组内使用相同种子并记录；不向不支持的接口额外添加 seed 参数。

如三组结果方向不稳定、无法形成判断，可在用户确认成本后补到五组；追加时
保留并报告全部已有结果，不挑选成功运行，也不边测边修改方法。
预算不足时，一组结果仅标为探索性结果。

### 指标与判断

| 指标 | 记录方式 |
|---|---|
| 主要指标 | 每组最终 Test 成功数、成功率，以及 B−A 的配对差值 |
| 稳定性 | 各组差值、均值与离散程度；按重复组保留任务对应关系 |
| 优化过程 | 各轮 Parent/Candidate 成功数、ACCEPT/RETAIN/no_change、最终轮次 |
| 资源成本 | Actor 与方法请求次数、已知 token、未知用量次数、墙钟时间 |
| 运行可靠性 | 技术中止、额度耗尽、恢复次数与额外调用；语义停止单独列出 |

目标是 v24 的平均最终 Test 成功率不低于 A，并且没有跨组一致下降或新增系统性失败。
小样本波动必须如实报告：观察均值不低于不等于已经证明长期效果相同。
如果要给出统计上的“不劣”结论，需在正式运行前另行约定可接受差值和样本规模。

比较发现下降时，先定位是否有配置、请求、环境或发布差异；无法确定的结果
写作不确定，不能用挑选轮次、挑选任务或只展示最佳重复来消除差异。

### 产出与停止条件

每个运行保留完整记录；汇总表同时展示所有配对重复及失败/未完成运行。
若出现数据混用、错误发布或真实请求条件不一致，停止后续运行并分析现有记录。
单次技术故障按原恢复规则处理，不自动重开整轮获取更好结果。

正式比较通过后，再将 v24 确认为 ALFWorld 正式基线，并单独开始 v25 的
SpreadsheetBench 适配。候选版本及本次结果继续保留，不用后续修改覆盖。

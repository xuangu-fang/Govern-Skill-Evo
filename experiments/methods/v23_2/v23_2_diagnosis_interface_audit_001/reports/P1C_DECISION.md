# P1-C：最低上游职责与下一阶段决策

**应把研究重心转回Memory与Preconditioner，但先清楚界定少量不可修改的Goal承诺及局部证据选取缺口。不应继续以“Diagnosis独立消除所有策略问题”为前置验收条件。**

这是接口与证据审计结论，不是模型纠正能力或行为性能的通过结论。本次没有Prompt修改、模型请求、环境执行或新策略生成。依据见[接口报告](P1C_INTERFACE_AUDIT.md)、[案例矩阵](P1C_CASE_MATRIX.md)、[原请求和静态输入核验](../results/interface_audit.json)。

## 1. Diagnosis是否还需要继续修正

需要考虑的最小范围是**解除已进入不可变Goal、又缺乏必要性依据的实现绑定**：

- R04：`by sweeping all receptacle types once`。若要允许不必覆盖所有类型即可利用已知剩余来源完成数量任务，不能只改Update而留下这句目标方法承诺。
- R06：`numbered receptacle names`作为规则必须依赖的实现线索，以及`at the open appliance`作为普遍温度操作状态。前者不同于合理的“Actor只能用当前／近期信息”，后者不同于合理的“必须完成heat/cool”。

要删除这些**Goal文本承诺**，现有下游没有改写接口；不能靠Checks、reason或Editor默默忽略来宣称修复。但这不意味着在它们存在时所有Update都不可改：编号策略仍可变换、回源边界仍可修；R04 `minimal microwave heat interaction`没有锁定open，其开门条件完全有下游调整空间。

R05 Goal已基本分离行为目标和具体算法，没有发现必须先修Goal才能调整类内穷尽、跨状态不重试等问题的证据。不要因u1/u2不完美而再次改整个Diagnosis。

程序没有Goal语义冲突检查，也没有Editor必须逐字复制Goal的代码。这一上游责任来自“Goal必继承＋Preconditioner必须保留Goal”的契约组合，不能夸大成已经证明任何相反Update都无法编译或任何Editor都必失败。全撤回／合法停点可避免发布，却不等于生成了修正后的目标。

## 2. 哪些具体策略可以留给Preconditioner

下游可改变方向、条件、范围、强度和具体方案，可合并／拆分／撤回关联Update，且没有最小改动限制。

| 可调整对象 | 不要求Diagnosis先做到什么 |
|---|---|
| R04无条件开门→依可用动作／必要访问条件限定 | 不必先独立证明最优温度流程；不能把完整成功链当必要性证据 |
| R04已访问来源／移走一件后的排除范围 | 不必自己生成完美回源规则；下游可依据剩余实例纠正 |
| R05编号推进、类内穷尽及换类强度 | 不必先证明类内或跨类哪种最优；可以是明确、可调整的探索方案 |
| R05Nothing happens后的重复限制 | 下游可把范围限定到相关状态与动作前提，不必为此重新设计上游全部职责 |
| R06未访问／consumed要求和近期启发式 | 下游可修条件、协调规则或撤回不具执行依据的部分；是否更有效另需行为证据 |
| R06温度备用方案、u1与u3回源关系、搜索及交付预算 | 可使用当前事实和Parent边界收窄／协调；不必先选出唯一实现 |

“可留给下游”不是认可所有原始策略正确，也不是让Diagnosis故意写差方案。它表示**这些缺陷正处在预条件化契约授权修正的对象中**。不能要求输入已经没有可调整的问题，才承认Preconditioner值得验证。

## 3. 下游证据是否足够

应给出四种不同答案，而非统一称“信息都有”或“上下文不足”：

1. **关键纠正事实已到达或静态可到达。** R04 early heat候选及P6/P8有效回源；R05循环／无效动作；R06温度前提及P6/P7数量行为。Parent全文和Actor两步窗口说明也在消息中。需要收窄必要性／范围时，不能把这些问题一概归为证据缺失。
2. **存在选择性原证据缺口。** P1-B R05漏选P2/P4/P5/P9全文，仅有部分Grouping摘要；P3慢路径对P4快速直接路径的原始对照不完整。R04 P10也未选。未传完整轨迹不等于描述完全消失，但摘要不能替代原始条件核查。
3. **Memory传输保真已核验，语义保真未由本次证明。** 各轮Active快照和所选sources实际正文一致，并未使用事后Memory。历史knowledge的因果／类别抽象是否准确、Active引用是否覆盖重要反例，仍属P2可核查对象。
4. **最佳策略的证据本来不存在。** 现有混合轨迹和联合编辑不能确定最优排序、切换尺度或独立因果收益。补齐请求不能凭空创造反事实结果。

Diagnosis.reason确实没有传入Preconditioner，只有完整Plan及其选中证据。若某假设唯一的动机／范围只在reason中，下游无法直接读取该解释；但也可能从Plan和轨迹自行判断。本次没有证明reason不传导致失败，不建议仅凭这一发现加字段或扩输入。原契约本来要求Update自足。

## 4. Diagnosis最低必要职责

在保持现接口时，Diagnosis至少需要：

1. 正确定义任务改善和保留边界，**不把不必要的探索实现锁进Goal**。
2. 输出结构合法、有直接执行basis、相对Parent且足够具体的候选Update；它可以含尚未验证的新策略。
3. 把实施所需的关键条件写在可调整的Update里，不能只留在生成解释中；目标与必要任务／能力约束不冲突。
4. 分清要保留的行为能力与某次成功路径中的伴随动作。必要约束可以具体，不应把所有动作词从Goal删除。
5. 给预条件化留下真实调整对象，不以“最优方案已确定”作为前提，也不故意削弱初始方案。

**不属于Diagnosis独立验收必须先证明的内容**：全部搜索策略最优、每个探索细节已有历史成功、所有可调整Update已通过历史反馈检验、最终行为性能已提高。原始策略有缺陷但Goal未锁死、关键证据可到达时，预条件化仍可开展；R05是清楚的例子，R04温度Update亦如此。

## 5. 当前主要剩余问题是什么

不是单一瓶颈：

- **已确认的上游接口约束**：R04/R06少量Goal实现绑定，无法通过Adjustment删除。
- **已确认的局部证据选取缺口**：R05等未被Plan直接引用的成功成员，仅摘要可见。
- **多数可调整问题的状态是D**：接口允许、主要事实在，但P1-B Original未真实交给Preconditioner；不能写成“下游又失败”，也不能写成“下游一定可修”。
- **Memory语义和策略效果仍需分别评价**：本次没有证明Memory是主要瓶颈，也没有证明架构缺少新的审核模块。

先前“P1-B总体未通过，所以暂不进入任何下游研究”的结论应缩小适用范围：它正确描述Diagnosis独立A—E未全过，却不能据此要求Diagnosis继续负责解决所有Update构造缺陷。**接口审计提供了重新分配研究责任的依据，不追改旧报告或历史验收记录。**

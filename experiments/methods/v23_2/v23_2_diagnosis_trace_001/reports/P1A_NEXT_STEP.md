# P1-A：P1-B 的最小修正建议（未实施）

P1-A已完成离线证据归因；P1语义验收仍未通过。建议下一阶段继续留在Diagnosis自身的证据到策略构造边界，**不要以这份分析作为进入P2或行为实验的通过证明**。本文不提供新Prompt，不改变任何字段、模块或默认配置。

## 优先级1：让“保留有效行为”与“复制成功动作链”分开

**已核实的问题。** R04 D1.Goal把P2/P3/P4的具体动作链列为应保留流程，u2将其设成无条件前置步骤；三个早期pre-action菜单已有heat候选，G1还明确P4有额外循环。见证据追溯04-1、04-3、04-4。

**应调整的已有职责。** Diagnosis“比较实际行为、识别应保留能力”与“提出条件明确的Update”之间的推导：保留完成任务所需的行为／状态关系，不能仅因某步骤伴随成功就认定其必要。应利用已提供的行动前可见选择、观察反馈和成功轨迹内部差异来界定要求的条件。

**为什么现有规则不足。** P1要求区分观察与预期、不要无依据附加强制要求，但没有在实际R04输出中阻止“真实发生过的成功链”成为必要链；这不是显式效果保证词的问题。泛泛强调“保留成功”甚至可能被错误落实为保留全部动作。

**如何保留探索。** 不要求反事实证明每一项新操作最优，也不禁止提出完整新流程。需要区分“有任务／状态理由要求这么做”与“值得验证的一种实现”。Goal仍表达效果与必要约束，Update可以具体且有力，但不得把未证明的必要性当事实。

**用P0如何验收。** 固定R04输入，分别核对早期heat可用状态、后续成功处理交付及P4循环差异；检查是否仍提出精确目标、必要处理和交付策略，同时避免无理由要求完整前置链。不能以删除全部温度动作作为通过。R06有条件直接heat/cool作为保留对照，不引入M4或其他历史Memory。

## 优先级2：保持证据的条件和完成单位，检查新规则的连带排除

**已核实的问题。** R04从“已查且无目标”扩大到“仅查未查”，可能排除已访问但仍有目标的来源；R05把receptacle变成category作为结束单位，前文又允许few／later return；未找到的分支直接转向use target。见04-5、05-5。

**应调整的已有职责。** 在构造Update的触发条件、范围、依赖与保留边界时，保持事实单位和条件语义一致；策略改变不应顺带取消必要获取、处理、数量和交付条件。不是规定哪个顺序正确，而是明确这次策略究竟改变了哪个行为、还有哪些行为仍须允许。

**为什么现有规则不足。** Goal里写“保留成功”不自动给Update留下例外；写“提高覆盖”不自动定义什么叫覆盖完成。已有Checks也不是Actor指令，不能代替Update的条件边界。

**如何保留探索。** 跨类、类内、分段、编号推进都可作为候选；不要求最小改动或历史验证成功。一个策略改变了搜索安排，不代表必须附加类别终止条件或绝对回访禁令；反过来，纠正类别结束歧义也不等于必须穷尽当前类才能切换。

**用P0如何验收。**

- R04 P6/P8：检查“到过但还有目标”的来源仍有合法处理空间；不要求Actor记住所有曾见目标，不强制某一步必须回源。
- R05：逐项区分单位置、部分类成员、全部类成员和全体合理位置；检查结束与未找到目标分支是否连贯，不预设breadth-first为标准答案。
- R06：核对新Update与Parent、旧Original之间的保留关系，确认必要处理和交付不被搜索指令排斥。检查预算依赖是否明确，**不要求任意固定预留步数**，也不把没有重述旧规则自动算作删除Skill。

## 优先级3：把已有可执行性要求作为边界，而非重启完整能力优化

**已核实的问题。** R06 P3:22证明“近期未出现”不等于“从未访问”；前段uninspected family与后段近期fallback仍有条件关系未明确。Parent/D0已有同类依赖，不能全部记为P1新错。见06-3至06-5。

**建议的范围。** P1-B若要修改Diagnosis，仍应落实原有“只用Actor可获得信息”的职责，不能把Diagnosis完整轨迹视野投射给Actor。近期启发式应按近期信息评价，不包装成全局进度事实。**不建议此时另起一轮全局搜索可执行性Prompt工程**，不改变Actor历史窗口、不增加记录状态或信息审核模块。

**为什么不一概禁止。** `few`并非固定2或3；有条件的局部换区、近期新颖性偏好可以在有限信息下形成有效候选。它们不能保证覆盖，但这不等于不可探索。未知全局状态应限制要求的适用性，而非迫使所有Update退化为“尽量提高效率”。

**用P0如何验收。** 对关键决策对照实际Actor消息，而非只读完整Parent轨迹；逐条区分即时可见、近期可恢复和不可恢复的累计状态。保持具体操作候选；不建立关键词黑名单，不把出现unvisited／few自动判错。若这一项仍未解决，应单独记录残留，不把Goal解绑或删除保证词当作整体通过。

## 暂时不应修复／不应预设的事项

| 暂缓项 | 理由 |
|---|---|
| 规定唯一搜索算法、全局类别顺序或固定批次 | P0没有隔离比较证明哪种更优。不能用现有失败现象反推一个强制标准答案 |
| 断言所有提前heat都必成功，或所有门操作都冗余 | 当前菜单与成功反馈能限定必要性，不能替代特定早期执行的反事实结果 |
| 为R04强制加入“永远记住剩余目标”的回源方案 | 需要区分保留回源机会和给予Actor不存在的持久记忆；当前两步窗口不支持全局目标清单 |
| 为预算问题增加固定早停或预留步数 | 未知不同任务路径和成本；现有数据只支持考虑后续必要处理，不支持统一数字 |
| 修改Memory、Preconditioner、Goal覆盖接口或新增审核模块 | 当前可纠正的问题已经出现在无Memory的Diagnosis输入输出中，不需要先改下游来证明 |
| 修复所谓“P1 Candidate实际退化” | 没有P1 Candidate／Replay。只能讨论文本风险，不能修补尚未观察的行为后果 |

## 后续验收应如何保持严格而不保守

继续使用P0既有A—E，不增模型字段或自动语义评分。各项输出须同时体现：

1. Goal承载行为改善、有效行为和必要约束，不把探索实现锁为目标。
2. Update有明确、可落实的策略。无历史成功证明可以是合理假设；与当前事实或任务条件冲突不能靠“探索”免责。
3. 强制要求的必要性、范围与状态前提有相应理由，不能仅凭成功整条链或失败现象成立。
4. 通过对照实际当前轨迹保留有效行为；区分“没写进新Update”“已在Parent”“明确删掉”“尚无Editor落实”。
5. 在原字段中诚实表达预期与待验证问题；Actor行为指导仍明确，不机械添加模糊词。

P1-B是否有效应看上述语义，不看字数、策略数量、是否含某个词或某轮是否选了指定顺序。一个具体候选可以仍需行为验证，而不被当作构造失败；一个明显越过当前证据的附带禁令，不能因候选整体有合理动机而通过。

**本次止于建议。** 没有生成新Prompt、没有重新运行P1、没有进入P1-B或P2。P1-A结论足以支持一次围绕“必要性＋条件／完成边界”的小范围Diagnosis修正研究；不足以承诺这种修正会稳定改善输出或执行表现。

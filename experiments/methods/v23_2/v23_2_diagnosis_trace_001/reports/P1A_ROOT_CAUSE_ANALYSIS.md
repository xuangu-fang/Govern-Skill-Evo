# P1-A：跨案例功能归因与证据边界

## 结论

**P1 改善了部分目标表达，却没有稳定约束“事实对具体策略到底支持到哪一步”。** 问题发生在Diagnosis内部从执行事实构造行为要求的环节：必要性、适用条件、覆盖单位和保留行为没有始终随事实一起进入最终Update。不是所有情况都缺少信息，也不是所有新策略都不合理。

- R04已有足够信息质疑无条件微波炉前置链，也已有有效回源的直接反例。这里主要是**可用信息未正确约束要求**。
- R05已有足够信息区分位置和类别，识别停止分支缺少目标；但没有信息证明某个轮换尺度最优。这里同时有**可纠正的构造错误**和**需要允许的策略探索**。
- R06完整轨迹与Actor局部窗口的差别已经明确提供。局部fallback承认了部分不确定性，但全局“未查类别”仍未充分落到可见状态；最优搜索安排仍无隔离证据。不能把前者的能力前提缺口归为后者的策略未知。

以上是输入输出层面可核查的功能归因，不是关于模型隐藏推理的确定诊断。完整证据链与逐项判断见[证据追溯](/Users/didi/Desktop/Govern-Skill-Evo/experiments/methods/v23_2/v23_2_diagnosis_trace_001/reports/P1A_EVIDENCE_TRACE.md)，原文件和字段见[索引](/Users/didi/Desktop/Govern-Skill-Evo/experiments/methods/v23_2/v23_2_diagnosis_trace_001/reports/EVIDENCE_INDEX.md)。

## 为什么 Goal 解绑仍不足

Goal—Update边界解决的是**策略放在哪个字段、下游能否替换策略时仍满足目标**，不是自动保证策略内容有依据。R06把ordered/memory-independent移出目标并删除穷尽／保证，表明这项修改在本例有作用；R05也没有把breadth-first写入Goal。但具体策略仍需决定覆盖单位、切换条件和完成分支，而这些决定可能继续越界。

R04甚至没有完全实现目标解绑。新Goal明确要求保留具体成功链，Update再落实该链。这里不是“Goal已经全部修好但Update失败”，而是**同一份输出中，目标边界和策略必要性一起失败**。

P1 Prompt原文已经要求：实现选择留在Updates；当前证据支持新策略；一个改善动机不自动支持附加强制要求。事实说明这些指令未在每份输出稳定实现，不能进一步推导“再把同一句话写得更严厉就能解决”。也不能把所有责任推给Goal不可修改：P1没有调用Preconditioner，这些偏差在Diagnosis输出时已经存在。

## 为什么成功动作会被当作必要流程

R04的显式解释是“heat-then-place未覆盖，成功执行揭示procedural pattern”。这是补充流程的一种合理问题认识，但它尚未回答：流程中哪些动作由任务／当前状态要求，哪些只是那次执行所采用的路径。

可观察的推导缺口有三处：

1. **结果成功没有分解步骤的必要性。** P2/P3最终成功不使move/close/open/take全部成为heat的必要前提。
2. **行动前可见替代未改变新规则的条件。** 三个早期heat候选已存在；D1仍要求完整前置链，并把“available时不重复”放在后句，未说明首次也可以跳过。
3. **成功组内部差异被抹平。** G1已标出P4长开关循环；D1.Goal仍将P2/P3/P4一起概括为short sequence。问题不只是没有反事实实验，还包括当前已有差异未约束总结。

“成功流程模仿偏向”“Grouping中的序列词形成锚定”都与输出相容，可以作为解释假设，但没有消融或模型内部证据。Grouping本身只问如何排列这些动作、并报告差异，没有断言必须执行完整链，不能把必要性错误全归给Grouping。

原始Actor三个open步骤的保存回答也自述“需要先开门”。这个更早的必要性判断没有传入Diagnosis：facts保留行为与环境结果，不保留Actor回答文本。因此，“Diagnosis新增无条件前置链”指相对Parent和D0的规范新增，不意味着“先开门才可加热”这种观念在整个执行系统中首次出现于Diagnosis；也不能据Actor的自述推断Diagnosis内部沿用了同一推理。此区分避免把行为证据和模型解释当成同一种来源。

## 为什么观察粒度会被扩大

R05证据的对象是**具体位置及其实际内容**。为了提出可复用策略，Diagnosis抽象成“类别”是允许的；跨类别安排也有问题动机。错误风险发生在进一步把类别层级用于“搜索已完成”的判定时：

> 某些位置反复检查、其他位置没到达 → 值得分散探索 → 先抽样不同类别 → 所有类别checked once就可结束。

前两次转换可以是合理认识与探索方案；最后一次需要额外的覆盖论证。当前输入没有给出“每个类别采样即可排除该类所有目标”的条件。尤其同一Update又承认还有remaining closed containers，说明“已触达类别”与“已完成类别”未被一致处理。

R04也有相似的条件压缩：事实是“已查且无目标的位置被无效回访”，最终条件变成“已查位置”。它丢失的是**无目标／剩余物体**这一关键谓词，而不是缺少搜索方向。这与R05的类别结束同属支持范围没有随抽象保留，但具体修正点不同，不能用同一搜索规则覆盖。

## 能力约束和保留要求为什么没有稳定进入最终Update

现有Prompt不是完全缺少约束：

| 已有职责／要求 | 输出中的落实与遗漏 |
|---|---|
| 用pre-action理解选择，不把后续发现归给此前决定 | 原始输入与候选装配准确；R04没有把早期heat可用性转化为必要性限制。不能把它归为菜单漏传 |
| 不假定完整执行记忆、全局visited集合、持久笔记；触发条件应可识别 | R06近期fallback部分落实，前段uninspected family仍缺明确可知条件；其他轮沿袭全局状态依赖 |
| 比较成功行为、保持有效能力；Goal或Update边界保留，不自动复制成新规则 | R04一面过度复制成功热处理链，一面未在u3边界保留有用回源；说明“保留成功”没有被一致细化到条件和行为 |
| Update相对Parent且完整、明确条件／依赖；Checks只观察响应 | R06没有重述旧后处理预算，Parent一般预算仍在；可以确认保留关系不清，不能把Check当实施保证 |
| 允许新策略，区分观察与预期；不得自动强化 | R05/R06仍有明确探索候选，R06删除保证。R04的强承诺不是显式“guarantee”，而是程序必要性；删保证词不足以解决 |

功能层面最有依据的共同解释是：**从事实生成可执行规范时，没有稳定保留“哪种状态下、对哪个对象、为哪个行为后果”这组条件关系，并检查新规则是否改变了其他必要行为。** 合法basis引用只能保证引用存在、来自相关执行，不能证明它支持某个子要求的必要性、覆盖范围或强度。原`validate_diagnosis`明确只校验结构与引用，不校验自然语言含义；这是契约的既定边界，不是本次要修的程序bug。

仍不能证明的内部原因包括注意力分配、训练偏好、推理捷径或特定措辞的因果作用。每轮仅一次P1随机输出；本报告不能把这些功能现象提升为稳定模型内部规律。

## 缺信息，还是缺把信息变成更新的能力

**对当前可纠正错误，信息并不主要缺失。** R04热处理菜单、有效回源，R05实际位置列表与遗漏，R06Actor协议、原有后处理需求都已在Diagnosis输入中。问题是没有把这些信息用于限制某些具体承诺。追加历史Memory不是纠正这些错误的必要条件，也不能因Memory不在Diagnosis就解释为历史被忽略。

**对策略优劣，信息确实不足。** 当前材料无法隔离证明类内穷尽、跨类轮换、编号推进或某个切换尺度更优；也未执行P1新Skill。这里需要承认假设性，而非逼Diagnosis只输出历史已证实的方法。类似地，菜单提供直接heat足以否定“没有其他可见选择”的认识，但不提供独立的早期heat反事实成功率。

**Actor的信息不足和研究者的因果证据不足也不同。** 前者决定某个规则能否在决策时判断条件；后者决定一个可执行的新策略是否有效。不能用“值得探索”豁免不可获得状态，也不能用“尚未证明更优”否定所有可执行探索。

## 对P1-A研究问题的回答

1. **确认存在从轨迹事实到过强要求的转换**：R04必要前置链、only-uninspected范围扩大，R05类别级结束；证据足以定位文本越界或歧义，不证明新行为已经失败。
2. **主要共同缺口在策略构造及条件保持，而非单纯事实传输**。R04还存在对成功组内部差异的过度概括；R06的目标解绑和近期fallback是反例，表明并非所有判断都无效。
3. **下一步宜优先约束“从观察到必要性”的推导及新规则的条件／完成边界**，继续允许有明确问题动机的探索。不是再列举每类搜索错误，也不是让Diagnosis只生成模糊建议。

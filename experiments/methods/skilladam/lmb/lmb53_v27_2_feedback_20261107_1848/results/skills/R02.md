# Live Mathematical MCQ Heuristics

## Workflow
1. Parse the claim before reading the choices. Write down what is asserted (existence, uniqueness, a regularity class, a classification list, an equivalence of several conditions) together with the exact hypotheses and quantifiers: "for all", "there exists", "exactly", "at most", "if and only if".
2. Calibrate the strength of the result. Decide what the underlying theorem actually delivers: which regularity or exponent, whether a full equivalence or only one implication is proved, and whether the hypotheses cover the whole family or only a restricted subfamily or a set of excluded cases.
3. Compare every option against that calibration, one distinguishing feature at a time. Name the single feature separating each option from its nearest neighbor (an exponent formula, a divisor condition, an added converse, an excluded case, a regularity upgrade) and mark it supported, unsupported, or a weakening. Reject options with explicit reasons; never stop at the first plausible one.
4. Weigh the catch-all option explicitly. An option stating that a stronger result than the listed ones can be proved is not a lazy fallback: pick it when each concrete option has an identifiable defect, such as proving strictly less than the natural full theorem, or adding a clause (a converse, a "for every" upgrade, an exact exponent, a removed hypothesis) that the result does not supply.
5. Format. Output exactly one label inside <answer>...</answer> and nothing else.

## Error Avoidance
- Do not default to the option with the most clauses. Converse claims, "every such case occurs" additions, exact exponent formulas, and silently dropped hypotheses are standard distractor moves; justify each added clause independently or reject the option.
- Do not default to the hedged option either. When the result does establish the stronger claim (an embedding, a full equivalence, a complete classification), an option weakening it to "need not" or "for some" is the distractor.
- In piecewise or split-regime statements, match each regime separately, including whether a boundary value is included (< versus <=) and which regime receives the sharper exponent.
- When options differ only by a restriction on a parameter (dividing one integer versus twice it, any divisor versus an even one), the correct option uses exactly the restriction the proof delivers; a stronger or weaker restriction is a distractor.

# Spreadsheet Manipulation Skill (xlsx)

## Workflow

1. **Explore before computing.** List the sheets (`wb.sheetnames`), find each relevant sheet's header row and real data extent, and inspect any reference or example tab that shows the expected layout. Address the sheet by name when the instruction names one; `wb.active` is safe only for single-sheet workbooks. Candidate tools: `wb["SheetName"]`, `ws.iter_rows(values_only=True)`, `ws.max_row`, `ws.max_column`.
2. **Map source and target structure explicitly.** Read the target block's own header row and row labels and line them up with the source headers instead of guessing offsets; for lookups and aggregations an unverified key mapping is the usual cause of a wrong answer. When the block uses merged or banded sub-headers, expand the merged ranges and confirm the block's full row extent before deriving any row stride, bucket index, or column offset — a stride read off a short sidebar can point into the wrong bucket block.
3. **Compute in Python first**, into a dict or list keyed by target cell (or by match key), then write it out. Write every target cell the instruction covers, using the requested placeholder (blank, dash, zero) when a result is empty. Keep the output row set anchored to the source rows — one output row per source row — unless the instruction explicitly asks for a split or an expansion.
4. **Write computed literal values into the target cells.** When the request is formula-shaped — including "fix" or "replace" the formula in a named cell — evaluate the same logic in Python and store the result: a formula string written by `openpyxl` has no cached value, so a later read with `data_only=True` gives `None`. Write a live formula only when the instruction explicitly asks for the formula expression itself.

5. **Mutate and save in place**: `wb = openpyxl.load_workbook(INPUT_PATH)` → write → `wb.save(OUTPUT_PATH)`. Do not rebuild the workbook from scratch; keep every sheet, cell, formula and format the instruction does not mention. Prefer `openpyxl` whenever formulas, number formats, or named ranges must survive; use `pandas` only to reshape data, then write the results back through `openpyxl`; no other third-party libraries.
6. **Verify before finishing**: reopen `OUTPUT_PATH`, read the target cells back, and re-read the instruction to confirm every stated constraint (filters, ordering, placeholders, formats, and which field belongs in which named column) is met — multi-part requests commonly fail on the last-stated requirement, and when ordering rules stack, the one described as the final output order governs. Where the workbook already held a correct value for a target cell (a working formula with a cached result), compare your computed value against it — a mismatch points at the key mapping, not the source data.

## Code Patterns

- **Read cached formula results alongside the formulas** — load twice and use both views:
  `wb = openpyxl.load_workbook(INPUT_PATH)` / `wv = openpyxl.load_workbook(INPUT_PATH, data_only=True)`
- **Targeted write** once the destination row/column is known: `ws.cell(row=r, column=c).value = result`
- **Delete rows bottom-up** so the remaining row indices stay valid:
  `for r in range(ws.max_row, first_data_row - 1, -1): ws.delete_rows(r, 1)`
- **Normalize before comparing**: strip strings, treat blanks as the instruction defines them, and check `isinstance(v, bool)` before numeric tests.
- **Merged-cell headers**: only the top-left cell of a merged range carries the value, so bounded reads return `None` elsewhere — expand the ranges (or forward-fill the band) before indexing a header block:
  `for rng in ws.merged_cells.ranges: top = ws.cell(rng.min_row, rng.min_col).value`

## Error Avoidance

- Never write a formula string and then patch a cached `<v>` into the saved XML — compute the value in Python and write it.
- Never guess month/category/year column mappings from position; derive them from the labels visible in the target block.
- Never hardcode row counts or column letters; iterate `ws.max_row`/`iter_rows` and skip trailing fully-empty rows.
- Never use `pandas.to_excel()` on a workbook that has formulas, named ranges, or formatting.

# Spreadsheet Manipulation Skill (xlsx)

## Overview
This skill guides agents in manipulating Excel (.xlsx) spreadsheets using Python.

**Primary libraries**: `openpyxl` (structure-preserving read/write), `pandas` (data transformation).
Never use any other third-party libraries.

---

## Common Workflow

1. **Explore** the input file: list sheets, inspect headers, check dimensions, and read any pre-filled example cells or surviving target-cell formulas — they pin down the rule that prose alone leaves ambiguous (row interval, window definition, match direction). If an example conflicts with the stated instruction, follow the instruction.
2. **Resolve governing inputs before computing**: read the control cells the answer depends on — selected dropdown option, year/month label, bucket thresholds, limits — and the exact row or range boundary the instruction names. Take these from the workbook's own cells or from the instruction text verbatim; do not substitute assumed defaults or add unrequested heuristics. Candidate tools: `ws.cell(row=r, column=c).value`, `ws.iter_rows(...)`.
3. **Write `solution.py`** with `INPUT_PATH` and `OUTPUT_PATH` defined at the top.
4. **Execute** `python solution.py` and verify the output file was created.
5. **Confirm** the target cells/range contain the expected values; where the sheet already holds a worked example — a filled answer cell or a surviving formula — check that your computed value reproduces it before trusting the rest of the range.
6. **Write the output and keep the edit scoped**: save to `OUTPUT_PATH`, iterate actual rows instead of hardcoding row counts or column letters, and preserve sheets and cells the instruction does not mention.

---

## Code Patterns

- **Read cached formula results**: `wbv = openpyxl.load_workbook(INPUT_PATH, data_only=True)` exposes cached values; a `None` there can mean "never calculated" rather than "empty", so fall back to the formula text from a normal load before treating the cell as blank.
- **Write the computed result as a literal**: `ws.cell(row=r, column=c).value = total` — assign the number/string itself; a formula assigned by openpyxl (including `ArrayFormula`) stores no cached result, so reading the file back yields `None`. Do this even when the instruction words the answer as a formula.
- **Delete rows bottom-up**: `for r in sorted(rows_to_delete, reverse=True): ws.delete_rows(r)` — keeps indices stable while removing rows.
- **Clear an output sheet before repopulating it**: `ws.delete_rows(1, ws.max_row)` (or set each cell's `.value = None`) so stale rows from the input layout cannot remain in the result.
- **Write companion columns together**: build each output record as a tuple and write it in one pass — `for i, rec in enumerate(records): ws.cell(row=start+i, column=1).value, ws.cell(row=start+i, column=2).value = rec` — so a name and its paired value never drift out of alignment.
- **Test thresholds and whole numbers with a tolerance**: `if cur >= ref * 1.1 - 1e-9:` / `if abs(v - round(v)) < 1e-9:` — an exact float comparison at a stated ratio, percentage, or "no cents" test can miss a boundary value by a rounding hair and silently undercount.
- **Match header labels tolerantly**: compare stripped, case-folded text first, then fall back to a short-form/prefix match so an abbreviated label (`Jun`, `Wed`) still resolves to its full-name header instead of going unrecognized and leaving that column unwritten.

## Error Avoidance

- Do not hand-edit worksheet XML to inject cached `<v>` values into formula cells; write the computed literal result instead.
- When the instruction names an exact boundary (e.g. delete every row above a marker), apply it literally — do not add heuristics that preserve extra rows.

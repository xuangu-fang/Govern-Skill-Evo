# Spreadsheet Manipulation Skill (xlsx)

## Overview
This skill guides agents in manipulating Excel (.xlsx) spreadsheets using Python.

**Primary libraries**: `openpyxl` (structure-preserving read/write), `pandas` (data transformation).
Never use any other third-party libraries.

---

## Common Workflow

1. **Explore** the input file: list sheets, inspect headers, check dimensions.
2. **Write `solution.py`** with `INPUT_PATH` and `OUTPUT_PATH` defined at the top.
3. **Execute** `python solution.py` and verify the output file was created.
4. **Confirm** the target cells/range contain the expected values.

## Existing Examples and Expected Results

Before bulk-writing a target range, inspect the cells already present and any adjacent block explicitly labeled as an example, expected result, reference, or check. When such a block or target cell is presented as a filled example rather than a placeholder or stale output, treat it as an executable specification: compute your proposed result independently for that example and compare it with the stored value before overwriting anything. If they disagree, do not bulk-write or overwrite the example; revise the matching key, rounding or age rule, row or column orientation, or formula logic and re-check. Use the example only to validate the derivation, not as permission to copy reference values into every target cell when a formula is required. If the existing target values are merely old results that the task asks to recalculate, do not treat them as authoritative. After repair, retain any required formula and apply the cached-result verification in the Cached Formula Results section so the saved formula and its readable data_only result both agree with the validated computation and the examples.

## Deleting Row Blocks Above a Marker

Interpret `delete all rows above the first occurrence of X` as a block deletion from row 1 through `marker_row - 1`. Find the marker by scanning the full search column with the stated case sensitivity. Then delete that complete block, for example with `ws.delete_rows(1, marker_row - 1)`. Do not start at the first non-empty row or preserve leading blank or title rows unless the instruction explicitly says those rows are outside the deletion.

After deleting, verify the marker now occupies the first row of the remaining block or the instructed position. If it does not, delete any rows still above it. Preserve content below the marker and all content outside the deleted block.

## Residual Allocation Sign and Direction

When balancing ordered unit columns against a residual, determine the sign convention from the task wording and any visible check or example before modifying cells. Under the usual wording that the residual is the amount still needed, a positive residual is a deficit: add from the first unit column toward the last, increasing nonzero cells within their minimum and maximum bounds. A negative residual is an excess: subtract from the last unit column toward the first, decreasing nonzero cells within the bounds. Do not reverse these directions for the opposite sign. Leave zero-valued unit cells unchanged. After allocation, set the residual cells to the requested final value, such as zero. If a workbook explicitly defines residual as actual minus target, or an example or check row shows the opposite convention, follow that workbook evidence instead of the default. Verify at least one positive and one negative residual before saving.

## Library Selection

| Use case | Library |
|----------|---------|
| Preserve formulas, formatting, named ranges | `openpyxl` |
| Bulk data transformation, aggregation, sorting | `pandas` → write back with `openpyxl` |
| Simple cell read/write | `openpyxl` |

**Warning**: `pandas.to_excel()` silently destroys existing formulas and named ranges.
When writing back to a spreadsheet that contains formulas, always use `openpyxl.save()`.

## solution.py Template

```python
import openpyxl
import pandas as pd

INPUT_PATH  = "..."   # set to the actual input path
OUTPUT_PATH = "..."   # set to the actual output path

wb = openpyxl.load_workbook(INPUT_PATH)
ws = wb.active  # or wb["SheetName"]

# --- perform manipulation ---

wb.save(OUTPUT_PATH)
```

## Output Requirements

- Save the result to `OUTPUT_PATH`.
- Do not hardcode row counts or column letters — iterate over actual rows in the workbook.
- Preserve sheets and cells not mentioned in the instruction.

## Consolidation and Appending Source Records

When a task asks to consolidate or append records from source sheets into the first available blank rows of a destination, determine the first write row from the destination's actual used range. Write every qualifying source row once, in the sheet or source order the instruction specifies or in workbook order if none is stated. Do not use an identical existing destination row as a reason to skip a source row, and do not deduplicate against existing content unless the instruction explicitly asks to remove duplicates. Existing rows are not a filter for new source records. Keep each source row in its own destination row and set any requested provenance column consistently. Before saving, verify that the first appended row corresponds to the first qualifying source row and that the appended count equals the number of qualifying source rows, not the number left after matching existing rows.

When duplicating or expanding source rows into a destination block that reproduces the source table, preserve the source header row as the first row of the output block when the source table has a header and the answer block starts at the top of a blank sheet or empty destination. Write the duplicated data beginning in the row immediately below that header; do not shift the data up into row 1 or omit the header. Determine the header from the source's first populated row and from any existing destination labels, not from a fixed row number. Verify that the block's top row matches the source header and that the first data row corresponds to the first source data row, then that each source row appears the requested number of times in order.

## Cached Formula Results

When a task requires formulas and the saved workbook will be read with `data_only=True`, a formula cell without a stored result is not sufficient because `openpyxl` does not calculate or refresh a cached value. For every requested formula cell:

1. Compute the intended result independently from the source data using the task's criteria.
2. Write the required formula when formula text is required.
3. Store the computed result as that same cell's cached value, without replacing the required formula text. Do not rely on a blind in-place XML string patch as the final step.
4. Resolve the worksheet part through `xl/workbook.xml` and `xl/_rels/workbook.xml.rels`. Normalize the relationship `Target` by converting backslashes, stripping any leading `/`, and handling relative parts; do not assume `xl/worksheets/sheetN.xml` from sheet order.
5. Preserve each target cell's `<f>` element and add a correctly typed cached `<v>` for the independently computed result: use `t="str"` for text results and clear the type for numeric results.
6. Do not rely on `fullCalcOnLoad` to populate the cache.
7. Treat a legitimately blank result as blank, not as a missing cache.

If the task permits a literal value instead of requiring a formula, write the literal result. After saving, reopen the output both normally and with `data_only=True`; using the `data_only=True` view, require every requested formula cell to return the independently computed value, including a legitimate blank. When formula text is required, confirm the required formula is present. If any target does not match the independent computation—missing, `None` when a value was expected, or wrong—repair that cache and re-check. If the task explicitly requires formula text, never replace the formula with a literal; if only values are required, a computed literal is an acceptable fallback. Do not treat a successful `wb.save()` as evidence that the cached result is readable. If the required check still fails, raise an execution error that names the affected cell and the discrepancy.

## Threshold and Band Tables

When a result is assigned through a threshold or band table, read that table's band labels from the workbook; do not hardcode them or assume a shared label set. Keep each dimension's own label set: a grid may have different boundary values in different columns or rows, such as a boundary-label row whose entries differ by column. Resolve a value on each dimension using the labels at the position where that value actually lands, not by copying one row's labels or assuming the labels are uniform.

Assign a value to the band whose lower label is the greatest label less than or equal to that value. Use inclusive comparison at every boundary; for example, do not use a strict `>` for the top band while using `>=` for lower bands. If the table has a row at the top threshold, a value exactly equal to that threshold belongs to that row. Honor an explicitly stated exclusive bound or `more than` wording for a particular band as the stated exception. Resolve the band on the other axis with the same inclusive rule.

Before saving, check at least one exact boundary value and one interior value for each dimension against the table.

When a task uses an "increases by at least N%" condition, treat it as an inclusive threshold and compare at the boundary without binary-floating error. For integer percentages, compare exact or scaled values—for example, use `Decimal` or compare `value * 100` with `reference * (100 + N)`—rather than an unguarded `value >= reference * (1 + N / 100.0)`. A value exactly N% above the reference must qualify, and the next value below must not. Keep the instructed scan and restart point unchanged. Before saving, test one exact-boundary value and one just-below value; if the workbook has visible progress or check cells, compare the qualifying positions with them.

## FIFO Stock Allocation

For FIFO stock allocation, sort candidate order lines by the date field the instruction identifies as the FIFO date, earliest first. When multiple lines share that date, order them by explicit order-line number or, if absent, by workbook row order. Do not use requested delivery date or another unmentioned date as a tie-breaker. Allocate cumulatively down that ordered list, filling each line up to its requested quantity and leaving later lines at zero once stock is exhausted; do not exceed the group's available stock. Verify at least one multi-line group where requested delivery dates and line order disagree.

## Period-End Open Status

When a task asks whether records are open at the end of a period, count a record only when it was created before the start of the next period and its close date is blank or is on/after the start of the next period. A record closed inside the period is not open at the end and must not be counted merely because it was open on the first day. Use the start of the next period as the cutoff so date-times are handled correctly. The end-of-period result label controls over an informal first-day description when they conflict. Verify at least one record closed inside the period and one closed after it; if the instruction explicitly asks for records open at any time during the period instead, apply the stated first-day condition.

## Lookup Criteria and Tie-Breakers

Resolve each lookup using exactly the criteria the instruction names. Do not add an unmentioned column to the required key when that can leave an otherwise matching row unfound or select a different record. Use extra columns only to break ties among rows that already satisfy the named criteria. If the task states no tie-breaker, choose deterministically in workbook order and apply the same choice consistently across all derived rows and columns.

## Explicit Output Block Starts

When the instruction names an explicit starting cell or row for an output block, treat that named position as the first header and the top-left cell of the block. The supplied answer region may extend one or more rows or columns above or left of that named start to include unchanged or blank cells; do not shift the block upward or leftward to fill the top of the answer region. Read the cells in and around the answer region to confirm there is no contradictory label, but if they are blank, the explicit start position controls. After writing, verify that the named start cell holds the first header and that the next row or column holds the first result; if not, move the block back to the named anchor.

## Locating Off-Preview Answer Ranges

When the supplied preview does not show the answer range or shows only blank cells, do not infer the table's orientation from the preview or from fixed row and column guesses. Read the actual cells in and around the stated answer range from the full workbook, identify the header row and the row and column labels, and decide whether years, categories, or other criteria run across columns or down rows from those labels. Then map the source amount, date, and code columns to those labels. If an existing total or check cell is present, compare the computed result with it before saving.

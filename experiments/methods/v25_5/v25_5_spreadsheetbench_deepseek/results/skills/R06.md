# Spreadsheet Manipulation Skill (xlsx)

## Overview
This skill guides agents in manipulating Excel (.xlsx) spreadsheets using Python.

**Primary libraries**: `openpyxl` (structure-preserving read/write), `pandas` (data transformation).
Never use any other third-party libraries.

---

## Common Workflow

1. **Explore** the input file: list sheets, inspect headers, check dimensions.
2. **Write `solution.py`** with `INPUT_PATH` and `OUTPUT_PATH` defined at the top.
3. **Execute** `python solution.py` and verify the output file was created.
4. **Confirm** the target cells/range contain the expected values.

---

## Calculated and Formula Targets

Derive the comparison rule from the instruction's own wording and apply it identically to both sides of the match. When the instruction says to find, look for, or search for text in a column, or states that partial matches and numeric or text prefixes/suffixes are allowed, test case-insensitive containment of the keyword or phrase in the trimmed cell text instead of requiring equality, so prefixed, suffixed, or differently-cased variants are not silently skipped; use equality (case-insensitive at most) only when the instruction says a cell's value must match or equal another value. When the instruction supplies, or asks to repair, a lookup formula, reproduce that lookup's semantics: the same key column, the same return column, exact match with first-match-wins order, and only the single normalization the instruction names (for example trimming) applied to both sides — determining those columns from the actual headers and cell values rather than copying example coordinates, and not adding further tiers such as case folding or deleting all spaces that would return a value where the specified rule finds no match. Once a row matches, evaluate the paired condition on the value actually stored (for example whether the amount carries a fractional part), reading numeric cells at face value, and decide explicitly what a blank or unparsable counterpart must produce instead of letting it fall silently into one branch; apply that decision uniformly to every matched row.

For calculated ranges or formula deliverables, derive each result from the source rows/blocks named by the instruction or from the contiguous source table whose headers match the destination labels; resolve destination row/column labels, control selectors, and criteria from actual cell values instead of assuming coordinates from an example formula. When a designated target cell must show a value derived from other cells, read the sources through a `data_only=True` view of the input (keeping a separate formula-preserving workbook for writing) and derive the target value from the source rows rather than copying a formula string or inventing a number. If a source read comes back None while the writing view of that same cell holds a formula, resolve the value from the cells that formula references or from the source table's own values, and keep 'unresolved' distinct from 'zero': a blank or unresolved source produces a blank target, never a fabricated 0 or empty string, while a genuine numeric 0 in the source stays 0. Compute each designated readable result independently from the source data, preserving the expected type (number, text, date) and allowing a legitimate blank result. If the task requires formulas, write the formula at the intended writable cells and ensure the saved cached result matches the independently computed value; if it requires values, write the computed values. Writing to those intended cells supersedes any prior value or cached result there. Never wrap the save, the cache-filling step or the archive patch in a bare `try/except` that discards the error: a silently skipped patch leaves uncached formulas that read back blank, so either let the exception surface or handle it with a real recovery. After `wb.save()`, reopen the output with `openpyxl.load_workbook(OUTPUT_PATH, data_only=True)` and compare each designated cell's readable result and required formula presence with the independently computed/expected result, treating a required value that reads back blank as a failure. If a label or control is blank or unrelated, a target cell is unexpectedly unwritten, or a cached value is missing or inconsistent, search for the correct label/range or use the explicit answer region and fix the source selection, formula, or cache. If one differs, repair the fill or cache and save again, or, where the deliverable may be a plain value rather than a formula, write the computed value, save and recheck a second time. After fixing, save and recheck the final saved output; if the same check still fails, raise an execution error naming the cell and the expected and observed behavior rather than submitting a silent heuristic guess.

## Library Selection

| Use case | Library |
|----------|---------|
| Preserve formulas, formatting, named ranges | `openpyxl` |
| Bulk data transformation, aggregation, sorting | `pandas` → write back with `openpyxl` |
| Simple cell read/write | `openpyxl` |

**Warning**: `pandas.to_excel()` silently destroys existing formulas and named ranges.
When writing back to a spreadsheet that contains formulas, always use `openpyxl.save()`.

## solution.py Template

```python
import openpyxl
import pandas as pd

INPUT_PATH  = "..."   # set to the actual input path
OUTPUT_PATH = "..."   # set to the actual output path

wb = openpyxl.load_workbook(INPUT_PATH)
ws = wb.active  # or wb["SheetName"]

# --- perform manipulation ---

wb.save(OUTPUT_PATH)
```

## Output Requirements

- When the instruction identifies a destination range, answer sheet, or output sheet for the result, treat that region as authoritative. When the instruction names the cell where the answer begins (for example 'put the answer from I3 with the headers ITEM and Qty'), anchor the first written row there rather than at the top-left cell of the designated answer region: when the instruction's answer includes headers, the header row occupies the named start cell and the data rows follow it, and any cell of the designated region above or beside the used block is written as an explicit blank. When no start cell is named, anchor the first written row at the region's own first cell. Fill the region by clearing or blanking the whole designated region first and writing the values on top; never run a clearing pass after writing, because a clear whose range covers rows already written erases the program's own headers and first data rows. Compute the complete intended output from the source data, then write every required cell in the region in order and explicitly write a blank for any unused target cell; overwrite stale, example, or partial values already inside the region. Do not skip writing or keep existing content just because the region is populated, because existing values look plausible, or because they do not prefix-match the newly generated sequence. Use pre-existing content only to resolve labels, formats, or genuinely ambiguous layout questions, and preserve cells outside the designated region. If a worksheet example or the region's existing layout plainly shows a different anchor, reconcile it with the instruction's wording before writing.
- Save the result to `OUTPUT_PATH`.
- Do not hardcode row counts or column letters — iterate over actual rows in the workbook.
- Preserve sheets and cells not mentioned in the instruction.

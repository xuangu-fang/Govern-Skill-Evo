## 研究问题与预先声明

**Question：** 当前证据、认真初稿、有效 Memory 与调用上限相同时，显式利用更新作用认识调整方向、尺度及组合，能否形成更合理的条件化更新，并在独立任务中表现出来？

**Hypothesis：** 将历史响应对齐到具体更新决定，仅在有支持的可见条件下放宽义务，同时保留其他状态下有效的完成／恢复路径，可能减少无依据的强化与跨状态干扰。允许恒等、没有收益、需要修订或回归，不预设一定产生变换。

配置在第一条新轨迹前保存：[plan.json](../config/plan.json)。[方法说明](../../../../../docs/methods/v22/CONDITIONAL_TRIAL.md)解释规则和对照。原始记录位于 `artifacts/methods/v22/conditional_trial_20261014/run/`；[summary.json](../results/summary.json)保存实际阶段、来源和费用，[verification.json](../results/verification.json)保存离线核验结果。

## 已实现的变化

- **更新规则：** 新 `conditional_update.py` 将目标与策略区分开；根据作用认识定位具体决定，条件化方向／强度／范围，并协调相关要求。替代成功不能跨状态取消已知的完成或恢复路径；事实计数纠错不等于编辑收益。沿用原紧凑 Plan、增量和 Editor 输出，没有新增逐维自证字段。
- **同信息对照：** direct 是普通胜任的历史辅助 proposal，conditioned 使用显式预条件化 proposal。二者读取逐字相同的用户证据视图、同一完整有效 Memory、同一初稿，再由同一个 Editor 落实；两侧各最多两次调用。普通组也允许合理的条件化和协调。此设计比较提示策略，不等同于隔离出的数值优化器，也不代表对所有直接编辑方法的优势。
- **冻结与隔离：** 新 `conditional_trial.py` 和 `bounded_evaluation.py` 组织预声明任务、真实 Train、共享 Diagnosis、独立构造、候选冻结、val/selection 执行与核验。冻结绑定要求、文本、输入、调用、代码和来源；评价后不再调用更新模块或改候选。相同继承 watch 只做确定性去重，原始输出保留，实质内容不修复。
- **失败与停点：** 不重复语义调用、换题、重跑 episode 或覆盖失败；技术失败与合法停止分开记录。没有可执行候选时，不以历史候选替代。正式 Gate、自动采用和持续发布没有接入。

原始模型提示、历史代码与产物保持不变。旧灯光／清洁材料只用于通用规则走查，不是本次新样本。

一次真实 Diagnosis 返回 `decision=no_change, plan=null`。其理由是三条任务全部完成，P3:3 的非法动作属于对已有合法动作要求的未遵守，当前没有得到具体的 Skill 可修复缺口。原始调用与输出没有改写。

按预声明停点，运行状态为 `no_change`；没有调用 direct/conditioned proposal 或 Editor。有效 Memory 已作为固定快照绑定到操作，但没有进入本次实际语义消费。没有初稿或候选可以冻结，因而没有启动 Selection。预声明协议和源码已绑定，不等于已生成 `freeze.json` 候选冻结记录。

对诊断理由的离线复核保留以下限制：

1. 三次成功和 P3:3 是唯一列表外动作，都有轨迹支持。模型的“立即纠正”只能解释为下一步恢复合法行动；第二件物体实际到第 9 步才取到，不能写成当场完成或立即修复了同一条命令。
2. P1 的重复访问是实际效率线索，Diagnosis 没有明确讨论。第 5 步 Actor 只能看到第 3、4 步的短历史，首访已不在其输入中；因此不能直接补一条依赖完整访问记录的规则。
3. “违反基础协议”不能普遍推出“Skill 无法帮助”。可见条件下的执行程序可能减少选择歧义，但当前单次观察没有证明它有效。这里记录的是本次模型的保守停止判断，不是证明所有可复用 Skill 都无价值。
4. 成功轨迹也可能提供可学习程序或成本问题。三条成功不能证明该批没有更新空间，更不能证明预条件化有效或无效。

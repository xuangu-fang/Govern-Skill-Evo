# V22 紧凑接口：真实反馈学习与后续更新构造

日期：2026-10-14。对应[实现说明](../../../../../docs/methods/v22/COMPACT_CYCLE.md)、[初始计划](../config/plan.json)、[连接失败恢复计划](../config/plan_recovery.json)及[末尾反馈修复计划](../config/plan_feedback_completion.json)。完整原始材料在 `artifacts/methods/v22/compact_cycle_20261014/`，三个操作独立保存，不覆盖失败。

## 1. 研究问题与实现范围

**Question：** 紧凑接口能否从实际 Skill 修改及执行反馈形成作用认识，让这些认识参与独立当前诊断后的更新构造，并从新执行继续学习？

**Hypothesis：** 相关 Replay 与 Memory 共用一次后处理，Fusion 交付要求变更，Editor 落实有效 Plan，可以形成可核对的学习构造链。历史是否改变要求、是否带来收益必须分别观察，不预先要求非恒等结果。

本次已新增紧凑学习、Diagnosis／Fusion／Editor 接口、运行器及离线核验。初始真实反馈形成两条操作内认识，参与一次后续 Fusion 判断，并生成、执行了新 Candidate。**Fusion 实际选择恒等，没有变更要求；因此本轮没有展示历史响应驱动的非恒等更新，也没有证明预条件化收益。** 最终反馈首次失败后，按独立计划修正消费视图并仅补做一次末尾学习；补充结果见第 6 节。

## 2. 固定协议与数据边界

- 来源为旧无历史轮次的完整 Train 执行，任务固定 `train:0000`、`train:0012`。旧 Candidate 仍为 staging，当前 Parent 明确为 No Skill；复用原两条有效 Parent，不重新执行或重复计费。
- Diagnosis 只读取 Parent 轨迹、当前能力和基础协议，不读取旧 Candidate、旧初稿或 Memory。Fusion 才读取历史作用认识；Editor 只接收有效要求实际引用的认识。
- 每个新 Candidate 任务执行一次，最多 50 步，seed 42，不按表现重跑或中途改 Skill。全程没有 Selection／Test、正式 Gate、采用或全局 Memory 发布。
- Actor 请求及返回模型为 `deepseek-v4-flash`；语义调用请求及已返回模型为 `deepseek-v4-pro`。temperature 请求值 1.0，thinking enabled，reasoning effort medium，max_tokens 请求值 16,384，stream false。计费按返回 usage，未知用量另计；请求值不当作已证实的总 completion 硬上限。
- Git HEAD 为 `7d4749541dab04397ea146e56dc762a26ba81a3b`；各操作 manifest 记录实际源码 hash。运行环境与原 Actor 适配器保持一致；两项执行的已记录条件均匹配，仍有模型随机性和未观测漂移。
- 原计划常规五次语义调用，Editor 明确返回构造问题时至多一次 Fusion／Editor 返工；实际未发生返工。第一次连接失败只按预存恢复计划增加一次操作；后续修复仅增加一次反馈调用，不重做构造或环境执行。

## 3. 学习怎样进入后续构造

| 阶段 | 实际产物与判断 |
|---|---|
| 初始 Replay／Memory | 4 条 finding、3 条 open、2 条认识增量；15 个从旧冻结材料重建的 watch 均有去向。重建问题不冒充旧执行前已保存的问题 |
| 认识 m1 | 旧照明 Candidate 在灯旁放置→use→take 成功，避免了旧 Parent 的部分重复尾段；仅支持局部联合观察，不证明必要性或单项贡献 |
| 认识 m2 | 动作定位收益尚未独立建立；其中“Parent 只有一次非法动作”错误，实际是第 4、7 步，输入未遗漏第 7 步 |
| Diagnosis | 独立形成 u1–u5：合法动作选择、可见容器处理、对象定位、fixture 状态操作和最终放置；正确识别两次非法动作，并以 w1 保留照明收尾歧义 |
| Fusion | `changes=[]`、`watch_changes=[]`，理由认为历史主要提供联合归因限制，现有 watch 已保留不确定性。初稿和有效要求一致 |
| Editor | 一次生成新 Skill，逐组定位五项要求；无上游返工。有效要求无 Memory basis，因此 Editor 没有直接读取认识 |

这条链路证明历史认识被供给、被提及并参与保留判断，不能据此说它改变了方向、尺度或组合。Fusion 的不变理由也有局限：未隔离单项因果不应自动排除基于联合观察的条件化探索；u5 的通用最终放置与照明任务的不同收尾没有被改成条件分支。无需强行制造变更，但这提示核心规则的实际使用还需完善。

初始 m2 的错误未被抄入有效要求或 Candidate，不等于该认识正确。初始 Replay 也没有主动指出所有旧静态实现缺陷，不能称为完整语义复核通过。

## 5. 失败与具体修复

第一次 `run/` 的初始学习请求在收到响应前 ConnectionError，耗时约 148 秒，用量未知，未形成认识。按独立计划创建 `recovery/`，其初始学习、Diagnosis、Fusion、Editor 与两项执行均完成。

`recovery/` 的最后学习返回了 JSON，但 f1/f3 引用不存在的当前 `C2:8`，并将新清洁轨迹误写成旧八步轨迹及额外 look，被引用检查拒绝。其 f2 正确识别照明替代成功路径；这些仍只是失败响应中的内容，未被人工抽取成有效最终 Memory。原报告保持 `status=error`、`active_stage=learn_final`。

该故障揭示消费接口的歧义：历史 Memory basis 与当前轨迹都使用裸 `C2:…`，虽有完整 context/run ID，模型仍混合了两个运行。新增独立 `compact_learning_view`：

- 当前引用保持当前范围；历史引用改为 `H1::C2:8`，通过目录还原完整 context，历史解释中的相关别名也限定范围。
- 程序计算动作数、非法动作与 look 步骤；完整当前轨迹保留，不让模型重新数这些事实。
- 历史事件去重，消费视图去掉重复的完整合法动作列表与 fingerprint，保留实际动作、观察、条件、静态证据和全部限制。完整持久 Memory 不变。
- 发现旧认识错误时要求明确 replace；新限制说明哪些继承限制已被纠正。旧依据不删除，仍需关注继承文字与新认识是否一致。

`feedback_completion/` 只对同一已完成 Candidate 的末尾反馈调用一次模型；全部输入来源绑定，零新增环境执行、零新构造。没有去掉错误引用来放行旧输出，也没有放宽引用校验。未来默认计划使用独立 scoped profile，旧计划缺省 legacy，保证旧调用可逐字重建。

## 6. 补充反馈结果、成本与核验

补充操作返回 `feedback_ready`，形成 3 条最终认识；独立核验通过。初始操作的错误和原恢复操作的 `cycle_complete=false` 保持原样。这里是**通过独立补充完成末尾反馈**，不是把失败原报告改成成功。

补充输出正确使用新清洁 7 步、无 look 的轨迹，记录照明持物直接 use 的替代成功路径，并通过 `replace` 明确修订 m2 的非法动作计数。m1 也被修订且保留旧 basis；其一句“以前关于当前 Candidate 的说法不受支持”仍有措辞混淆，应理解为区分旧、新 Candidate 和限制外推，不能说旧历史事实被推翻。

Memory 写入仍机械继承旧 limits，因此最新 m2 同时保留旧“single invalid-event”文字和新的纠正说明。模型已经纠正正文和计数，但失效限制尚未被干净隔离；后续不能把两句等价消费。`feedback_ready` 不是全部认识语义正确的认证。

## 7. 下一步

优先把行为响应转成更明确的条件化更新决策：区分“联合观察足以支持有限探索”和“单项效应尚未证明”，检查初稿是否已处理该关系，再决定保持或改变实际要求。固定同一认真初稿，比较当前诊断、同信息历史辅助编辑与完整变换；不通过削弱初稿或反复生成候选制造非恒等。

同时继续收敛作用认识的修订和消费：准确区分旧事实、当前事实、错误限制和新反例，避免修订后仍把失效限制当作当前判断。完整证据保存与消费视图分离已经实现，但本次不代表 Memory 检索、长期容量或语义可靠性问题已全部解决。

# V23.3 P1：后续验证计划

此文件是后续协议设计，不是执行授权或行为结果。先完成 P2 离线实现与契约验证，再冻结模型实验配置。已完成 [P0 的既有测试](V23_3_EDITOR_PATCH_AUDIT.md)和 [P1-R 的多行纯函数兼容验证](p1r_multiline_001/P1R_PATCH_COMPATIBILITY.md)，均不是模型或任务表现验证。

## 1. 验证层次与判定标准

| 层次 | 必须观察什么 | 不足以通过的结果 |
|---|---|---|
| 表示粒度 | 独立行为要求分行后，能只修改选定要求并精确保留其他行；触发与动作仍完整 | 行数更多、机械按句号拆分、夹具中悄悄纠正旧策略 |
| 工程 | Patch 精确应用、错误拒绝、真实 raw→Adjustment→Effective→Editor handoff 可重载，Goal/未改项保持 | 单纯能解析 JSON；用手填最终 text 绕开 Patch；伪造旧归档 |
| 算法决策 | 最终 Update 改变与实际历史响应及其条件对应；合理纠错/探索保留，无据附带承诺减少 | reason 提及 M6、解释变长、修改变少或全部 Keep |
| 行为 | 同条件 Candidate 比 Parent/旧机制改善任务表现且保留必要能力 | 单次成功、5/7、一个 rescue、仅类别覆盖增加 |

语义评价使用冻结标准、盲化方法标签的人工独立标注；分歧保留并说明，不增加运行时审核 Agent。允许多个合理策略，没有“必须跨类”答案键。

对每个输出核查：修改对象；来源实际编辑与响应；条件迁移是否成立；当前纠错/历史方向/独立假设的区分；必要配套的反事实理由；未支持的新增强制条件或出口；未解决的 Original 问题；保留能力；新策略是否可执行且可检验。以**整体最终 Plan**评价，避免只改一处或 Keep 通过“零新增”获得虚假优势。

## 2. 三类主对照

| 实验 | 冻结项与变量 | 主要结果 |
|---|---|---|
| A 更新构造机制 | 固定 Original、Parent、实际选入 facts/menus/Grouping、完整真实 Memory、Actor 背景、模型版本/参数、上下文与输出预算；V23 自由 to.text 对 V23.3 响应条件化 Patch | 有依据的变化、无据新增承诺、未解决问题、有效探索、语义冲突、格式/编译失败；比较最终 Effective，不只比较 reason |
| B Memory 增量 | 固定 V23.3 同一完整 Prompt 和其他全部输入；只切换 `memory={entries:[],sources:{}}` 与冻结真实 Memory | Update 方向、触发范围、强度及关联的实际差异，以及其历史依据；同时记录两组共同可由当前事实纠正的部分 |
| C Candidate Replay | 相同 Editor Prompt/模型、相同 Parent、任务实例、reset、执行协议、预算和 Actor；分别落实预注册候选 | 成功率及配对修复/退化、位置级覆盖、重复/非法动作、发现/获取/处理/交付步数、能力保留 |

A 同时改变决策程序和输出表示，只能证明整体方法差异。若要归因于“响应决策”而非 Diff，增加两项离线构造消融：**旧决策 + 同一 Patch 表示**、**新决策 + 完整 text 表示**，构成 2×2；输入和评价不变。没有这项拆分证据，不声称收益专由算法或 Patch 引起。

P1-R 再明确区分**文本分行方式**与**输出是 Patch 还是全文**，它们不是同一个变量：

- 表示对照固定策略语义、事实、Memory、模型和决策规则，比较单行与人工审核的多行表示下 Patch 的实际作用范围、未选要求的保留、行内附带承诺及格式错误。人工副本仅用于开发表示对照，不能作为真实 Diagnosis 输出统计。
- 响应决策对照与有/无 Memory 对照，在各组使用同一份多行 Original；不能一组用旧单行 Diagnosis、另一组用重新生成且策略也变化的多行 Diagnosis，再归因于 Memory。
- 自然生成多行的遵循率另测：触发/动作完整性、独立要求粒度、语义遗漏、Goal 实现绑定；只是输出有换行不算合格。当前未调用 Diagnosis，不能预先确认遵循率。
- 无据附带承诺与最终行为仍分别评价。一行替换也可能夹带类别一次结束，新增行不因格式独立而有证据；表现改善不能全部归给分行或 Memory。

为控制实验规模，可先固定多行表示完成原 A/B，再单独做表示对照；不要求立即开展全因子大规模实验。每次对照冻结 representation 版本，保留原始单行来源和人工组织差异。

B 的有/无 Memory 差异也包含上下文长度变化。不同不等于因果已隔离；可后续独立比较相关来源消融或等预算证据，先不同时压缩 Memory。M6 正反证据、M10 正确 summary 与原 summary 的消融是诊断性实验副本，不修改历史条目、不假装是主 A/B。

## 3. 样本、重复、选择和污染控制

- R04/R05/R06 仅开发回归。明确每个 Original 来自正式 V23 还是 P1-B，R05 必须使用成功重试；最终 P3-B 采用同 Prompt 的 A_format/B_format。
- 初始构造阶段建议每个固定输入/条件 **3 次独立生成**，完整保留全部样本。固定模型、temperature、输出预算和可用 seed；若服务不支持 seed，记录该限制，不伪称可精确复现。三次只观察波动，不足以证明泛化。
- 在新调用之前，另选未参与规则设计的 **Train 批次**，冻结 IDs、游戏实例、Original、Memory 时间截点、选取依据与样本数。对照既有开发清单、V23/V23.2 实验来源及 Memory sources 排除已暴露实例；不能仅因文件名含 train 就认为未见过。
- 独立验证任务不得进入 Diagnosis、候选选择、Prompt 修改或 Memory 更新。每个被冻结 Candidate 在同一验证清单上评价；不能看验证失败后补规则再继续称同一次验证。
- 正式 V23 已将 Train 与 Selection 拼成优化池，R05/R06 的 `val:*` 也已用于更新。该 Selection 不能直接充当 V23.3 的独立验证集。参见[现有数据协议说明](../v23/v23_alfworld_formal_001/README.md)与 [selection 清单](../v23/v23_alfworld_formal_001/data/selection.json)。
- 旧 V23 Test 汇总已公开在 README；不把它称作未暴露数据。最终 Test 仅在方法/候选选择规则冻结后使用，不用于调参。真正独立的新保留集必须在后续清点中确认；本轮不虚构现成名单或承诺已经隔离。
- 预注册完整的样本数/重复数/成本上限后再开始新模型实验；不能根据第一次输出临时改输入或增加有利重复。预算不足时报告不确定性，不缩减分母选择性报告。

## 4. Candidate 选择和失败处理

所有结构有效且进入预注册执行范围的样本按相同规则进入 Editor；不凭预想收益挑选“最好”的 Patch。若预算只能执行子集，预先固定每例每条件的生成序号或随机规则，不能看文本质量后选。语义问题单独标注，不从结果分母删除。

Editor 输出 `""`/null 分别报告 no_change/needs_revision；Preconditioner no_change/need_evidence 与技术失败分开。无 Candidate 的样本仍计入端到端产出率，不能只在成功生成 Candidate 的子集上宣称整体提高。

网络/解析/超时/补丁错误完整归档，重试上限和允许的技术恢复在实验前冻结。不得只给某组改策略 Prompt、修补 Diff 或补发有效输出。未知成本记未知；环境中断不记为行为失败，也不静默排除，按预定同条件重试并保留中断。

Goal 绑定导致的案例阻断单列。若需修改 Diagnosis Goal，形成单独实验版本，两个对照共享该版本；不能一边修 Goal 一边保留原文后归因于预条件化。

## 5. 行为指标的操作定义

| 指标 | 计算/解释要求 |
|---|---|
| 任务成功率 | 同任务、实例和执行条件配对；报告 Parent→Candidate 修复与新增失败、分母、按任务类型结果；重复时按任务聚类而非把同实例多次当独立任务 |
| 有效位置检查 | 按具体 receptacle ID，只有观察确实揭示该位置/容器内容才计入；到达闭容器未打开不算内容检查。类别数只作辅助，不替代位置数 |
| 无信息重复 | 同一位置/动作在相关状态未变且没有新信息的重复；有新目标、任务阶段改变或合法回源不算。机器可计候选事件，语义边界需轨迹核验 |
| 无效动作 | 分开统计不在当时可见候选中的动作和环境无效反馈；菜单缺失不当空菜单，Nothing happens 不一律视为所有未来状态都无效 |
| 时间/预算 | 目标首次可见、实际获取、必要处理成功和交付各自步数；未获取者记删失/未发生，不伪设为第50步获得。报告获取后剩余预算及未完成比例 |
| 能力退化 | 原成功任务新增失败；单列精确类别、处理前提、交付、灯具、数量与有效回源。Update 中文字保留不是行为保留证明 |

在 Actor 端维持两步历史。评价器可以用完整轨迹统计重复和覆盖，但不得将事后集合反馈给 Actor 作为新能力。对重复获取/多实例任务按阶段和实例记录，不混成单目标首见。

重复执行建议使用预先固定的多个环境种子/模型重复配置，并对每个条件成对使用；预算与 reset 由原 `verify_pair` 核查。报告配对差及不确定区间；若样本不足或区间跨越零，结论保持“未证明稳定收益”。本轮不指定一个无依据的成功率提升阈值。

## 6. 决策机制的反例测试

进入行为实验前，离线人工夹具至少包括：

1. 仅正例与正反混合响应：是否限制结论强度，而非一律放大跨类偏好。
2. 相同任务名但不同作用条件：不能自动迁移历史响应。
3. summary 与 actual.diff 冲突：应使用真实改动；单侧来源不足时不捏造配对。
4. 修改调度与无关停止条件同时出现：Patch 可通过，语义评价必须识别额外承诺无据。
5. 大幅有据重写：不能因文本长或 Hunk 多拒绝；多个 Update 的必要协调可表达。
6. 无 Memory：当前事实纠错仍可进行；未验证探索不自动 need_evidence。
7. Goal 与必要修正冲突：结构编译可通过不等于应发布，不能偷偷改 Goal。

上述夹具测试设计规则的表达与工程边界，不证明模型会遵守。只有 A/B 实际输出与 C 的真实行为证据才能支持方法增量。

# 紧凑 Memory：有限真实格式验证

本轮由用户授权真实模型验证输入理解。先验证格式，再在通过后进行一次实际 V23.3 生成。不是新增在线检索阶段，不增加后续正式 Preconditioner 的模型调用次数。

## 输入与调用预算

- 固定 `memory_evidence_view_v1`、±2 窗口及原活跃 Memory；使用前一离线实验已生成的 R05、R06 紧凑 payload。两例覆盖共享历史 M6/M7，并由 R06 覆盖 M10 概括冲突。没有加入 Test 或未来记忆。
- 两次格式探针保留完整紧凑 payload（含当前证据），使用专门格式检查系统说明及固定问题，**不使用生产 Preconditioner Prompt**。用于证明指定读取任务能否正确完成，不用于评价策略优劣。
- 两次探针全部通过后，才发第三次请求：原 P3-B 的紧凑 messages，原 V23.3 方法 Prompt 加既有 MODEL_FORMAT 说明；不附探针问题、参考答案或本轮回答，不重新生成 Diagnosis。
- 最多 **3 次逻辑调用、3 次 HTTP 请求**，每项只发送一次，无自动/技术/语义重试。失败或截断不补采样。R05/R06 各独立检查；任一未通过则不发生产生成请求。
- 内网 `deepseek-v4.1-flash`，temperature=1、thinking enabled、reasoning_effort=medium、stream=false；连接/正文发送及读取超时 `(60,300)`，禁重定向，不使用环境代理。
- 探针 max_tokens=16384；生产生成 max_tokens=32768。生产上限是为这轮新验证预先增加的独立预算，不能声称与旧 16384 结果形成方法优劣对照。最多 65536 completion tokens 的配置上限，不含输入，不保证服务端会执行/计费所有额度。
- 保存实际请求、字节数、socket 发送超时、HTTP 原文、模型 response、finish_reason、usage 和错误堆栈。不输出或归档认证头/密钥。费用按实际返回记录；货币费用未知时不估填。

## 探针与通过条件

发送前从完整归档及紧凑视图交叉核验参考答案，并把问题、答案、请求与本协议冻结归档。模型只收到问题，不收到答案。

探针覆盖窗口起点与窗口内状态重建、局部 C ID 到全局命令表的解析、跨来源命名空间、动作合法性前提、缺失状态不可恢复、完整动作序列、配对正反结果、窗口覆盖与不完整来源集合。R06 另检查 M10 的位置/类别区别、实际修改限定与“未找到不能证明不存在”。

每题要求指定结构的简短事实答案。JSON 解码后的字段、类型与值逐项精确比较，不根据内部 reasoning 打分，不用第二个 LLM 作裁判。不要求输出推理过程。所有题通过且正常 finish=stop 才通过该探针；技术失败/截断记未取得有效验证，不能记理解错误。

问题是已知开发案例上的定向测试，不是随机/未见样本。探针通过仅支持这些格式和边界的读取能力，不证明所有输入都理解正确，也不证明与完整输入语义等价。

## 生产生成与后续结论

第三次请求若执行，必须正常结束、可解析、满足原 Patch 契约，并以保存的原始 full payload 完成规范化及 V23 编译；紧凑 view 不冒充原完整 Memory。手工核对最终内容中的历史依据是否为实际提供的证据，是否跨越缺失状态、是否把 Memory 概括当事实、是否破坏 Goal/必要行为。

正常 keep/no_change/need_evidence 是合法输出，但没有实际 Patch 时只能称输出契约/停点验证，不能称非空 Patch 生成成功。程序编译成功也不能证明策略正确或未来行为收益。

- 探针通过且生产输出通过契约、证据边界核查：建议作为**可选输入方式**接入后续有限实验，原完整模式保留。
- 任一必要检查未通过：不宣布整体通过、不默认接入，归档具体失败原因。
- 无论结果如何，最多执行上述调用后停止。无 Editor、Actor、Replay、Memory commit、完整进化、正式 A/B 优劣结论或 Test。

既有源码与所有历史归档保持不变。本轮只新增本目录文件，不提交或改写默认配置。

## 接入决策与下一步建议

**当前决策：保留离线原型和全部失败记录，不将 v1 视图升级为正式默认，也不启动后续生产 A/B。**

值得继续研究的方向是减少模型需要执行的间接解引用：

1. 详细步骤直接带原始 step ID，并显式携带该步 before/after，减少从窗口起点和 after 数组下标反推状态的工作。
2. 详细状态直接引用全局唯一命令表 ID，减少“历史来源 → 局部 C ID → 全局 menu ID → 命令列表”的多级查找。来源映射保留用于审计，不混淆同名 C ID。
3. 来源数量、窗口步数等程序可准确计算的元数据直接给出，避免把计数负担交给模型。

这些只是基于失败现象提出的下一版候选设计，**尚未实现或重跑**。它们仍可保持一次 Preconditioner 调用、不新增检索 LLM，但会增加部分明确状态字段，必须重新测量 token 成本。没有全文/紧凑同题受控对照，不能证明当前错误由压缩单独造成，更不能保证上述修改一定修复错误。

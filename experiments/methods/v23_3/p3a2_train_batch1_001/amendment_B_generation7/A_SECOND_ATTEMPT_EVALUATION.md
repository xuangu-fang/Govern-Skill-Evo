# A 追加生成独立评价

A2 为用户在 A1 引用契约失败后授权的第二次同输入生成，非首次输出。ready，两项一对一替换，checks=null，原编译器与 load_a 重新解析通过。它是本组首次合法结果，未按策略优劣择优。

## 模型明确理由与事实核查

模型称两个 Update 都依赖完整 visited-set，M3/M6 记录 anti-cycle 未可靠执行，因此改为当前观察/最近两步和当前候选驱动。这个问题动机有依据，但其当前证据描述有明确错误：

- 称 P3:6、15、19 反复到 fridge 却未打开。实际依次为 `open cabinet 3`、`go to cabinet 3`、`go to cabinet 6`；P3 全程没有 `go to fridge 1`。
- 称 P3 漏查 countertop 2/3 与 shelves；这些实例/类别不在本任务初始列表中。P3 的 diningtable 1 和 fridge 1 确实可见且未访问，必须与虚构候选区分。
- 称 P6 漏查 tvstand；本例初始列表没有 tvstand。sidetable 3、sofa、armchair/ottoman、diningtable 的漏查则可核验。

原输入提供了真实轨迹与菜单，故这些不是当前证据未传入造成的缺失。可能发生了历史/当前案例混淆，但无法从输出确认生成来源。详见 `runs/A_retry_001/current_evidence_fact_audit.json`。

## 实际变换

u1 从覆盖所有可达候选位置的首轮，改成覆盖当前观察中的每个 distinct receptacle type 一次即可结束首轮。它是**类别级首轮结束条件**，不能误写成模型要求“立即终止整局”；但它确实弱化了原位置级覆盖，同类剩余实例可能被遗漏。当前/历史证据支持扩大范围，M6 反而包含同类实例遗漏的反例，并不足以支持这个附带停止条件。

u1 改为闭合容器才必须 open，修正了 Original 把所有 candidate 一概“open it”的风险，并保留精确目标/多目标数量文字。选择当前可执行动作更具体，但“每种已检查一次”的计数仍不能由最近两步稳定还原；对 current observation 的范围也有歧义。

u2 把回返禁止收窄到刚离开/前一步位置，使用可见局部历史，新增不要空手重复 inventory（当前 P6:34/43/50 可支持）。仍含“未检查过的类型”条件，且“换不同类型”不是所有有效回返的必要条件；它需要被限定在无目标搜索阶段。保留 checks=null，原 c1 对继续同类检查的负向措辞未被纠正。

## 历史与评价边界

M3/M6 被明确用于 anti-repeat 可执行性动机，不能说历史完全未参与。模型将 M3 的联合编辑收益归为扩大范围救回任务，因果表述比单次联合编辑证据更强；无 Memory 消融也不能证明历史增量。

结论：有局部可执行性改写和避免不必要开门的改善意图，但新增类别级首轮终点、保留全局状态需求，并有当前事实错误。工程有效不等于策略质量有效。后续按协议照常交给 Editor/Replay，不修正、不追加生成。

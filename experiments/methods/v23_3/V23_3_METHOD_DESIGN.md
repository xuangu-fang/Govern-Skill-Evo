# V23.3 P1：统一方法设计

## 1. 研究对象与新增机制

以同一个行为决策问题贯穿 Diagnosis、Memory、Preconditioner：在什么可见条件下，Agent 应选择什么行为；修改该指导之后实际发生了什么。

V23 已有历史响应、范围调整、拆合/撤回等概念和权限。V23.3 **不把这些已有能力重新宣称为创新**。本设计新增的是一套有明确分支和可反驳条件的变换选择程序：

1. 对照历史**实际 Diff**与条件相容的响应，确定当前哪条行为关系受到支持、反例或不确定性约束。
2. 分别决定纠错、方向探索与无关要求保留；混合响应不再作为整段策略的统一背书。
3. 只有“不改会矛盾、不可执行或破坏必要行为”的要求进入必要配套；其余新增改变必须有独立问题动机。
4. 将所选变化映射到多行 Update 中对应的完整行为要求，直接构造 Patch，由程序得到完整 Update 与原格式 Adjustment。不能先自由重写全文再反向生成 Patch，也不能另交完整 text 覆盖补丁结果。
5. 用实际行为差异检验并修订历史认识。

决策规则见[算法](V23_3_PRECONDITIONING_ALGORITHM.md)；工程载体见[集成](V23_3_PATCH_INTEGRATION.md)。它是待检验的方法设计，尚未证明比 V23 更稳定，也没有优化器的数学收敛性质。

## 2. 模块职责与立即修改范围

| 模块 | 本方法中的责任 | 是否立即改实现 |
|---|---|---|
| Diagnosis | 从当前 Parent/Grouping/执行提出改善目标、可调整的策略假设、保留能力与可观察 Checks；不读取 Memory，不必独立选出最优策略 | P1-R 不改现有代码、Schema 或正式 Prompt；未来 V23.3 直接生成多行 `Update.text`，每行尽量为可独立判断的完整行为要求 |
| Memory | 保存真实编辑、混合行为响应、观察条件和联合编辑/单次执行的归因限制；knowledge 是可修订认识，sources 是核查依据 | 不重写、不压缩、不修补历史档案。M10 的错误在使用时依据 sources 限定；后续可独立比较修正 summary |
| Preconditioner | 根据条件化响应选择 Keep/收窄/放宽/替换/撤回，检查可观测条件、协调必要关联，并明确探索的可检验预期 | P2 仅实现这一决策契约及 Patch 衔接；一次模型调用，不加审核 Agent |
| Editor | 落实 Effective Plan 到 Parent Skill；不再重选策略 | 复用现有接口和实现核心；只适配上游归档加载 |
| Replay/Memory commit | 测量真实 Parent/Candidate 差异，将收益、反例和限制继续写回现有 knowledge/evidence | 沿用闭环，实验阶段再运行 |

P0/P1 原先冻结 Diagnosis；P1-R 仅修订未来输出的文本组织，不改变职责、Schema 或历史 Plan。触发条件与动作同处一行，依据不同的调度、回访、完成等要求尽量分行，不按标点机械拆分。原单行档案保持；人工表示副本与策略修改分开。详见 [P1-R 表示规范](p1r_multiline_001/P1R_UPDATE_REPRESENTATION.md)。

这不等于认可所有历史 Goal。遇到 Goal 实现绑定，必须单列兼容修正与上游阻断；不能给 Preconditioner 暗中改 Goal 的权力。如果后续反复出现此障碍，再做独立 Diagnosis 对照，不把它混入预条件化收益。

## 3. 三种修改关系，不增加三种字段

**目标修改**：有当前行为问题或明确要求错误，历史响应帮助确定修改方式。例如放松“类内穷尽后才能换类”。

**必要配套**：保持旧关联句会直接否定目标修改、要求不可得状态，或破坏必要任务前提。例如同一 Update 另一句仍禁止未穷尽时换类，必须同步协调。理由应指出旧句与新选择的具体冲突。

**独立探索**：有自己的问题动机和可观察预期，但效果未知。例如对状态未改变的重复无效动作另行限定重试，而不是借搜索覆盖收益新增永久禁令。

用既有 `basis/reason/checks` 说明这些关系，文字可指出相关 Update/原句；无需 role、依赖 ID、D/S/C 字段或长期状态。程序不解析 reason 来决定编辑顺序或验证“必要”。

允许大幅变换、多处修改、多个 Update 同时协调。边界是行为依据，不是字符预算。未修改要求也可能错误；不能把“默认保留”当作正确性证明。

## 4. 输入与可见性约束

先复用 V23 当前证据选择与完整 Active Memory。不新增检索、摘要或响应评分调用。“获取相关历史响应”指同一次 Preconditioner 生成中的语义匹配，不是 P2 另建 Memory 选择器。

历史支持的迁移单位是“指导改变—适用条件—实际响应”，而非任务名称、ACCEPT/RETAIN 或总体成功率。方向比较至少看实际 Diff；没有双方来源或受控配对证明时，只能作为单侧观察/类比。不同实例成功链能否定某条路径的普遍必要性，不能当作同条件提速实验。

局部历史、当前候选只能支持局部判断。任务已完成、目标不存在、全位置已访问之类全局命题，不能由短历史或类别采样构造出来。有限预算是约束，不能据此猜固定预留步数的最优值。

## 5. 贡献与验收边界

P1 交付的是明确决策规则、真实案例推演和工程方案；不是模型已遵守规则的证明。若后续只有 reason 更长、Patch 格式变化，而实际 Update 仍夹带无据结束条件，方法验收失败。

应区分多行表示带来的编辑粒度、确定性应用、响应驱动的决策质量及真实任务收益。未修改行由程序保留，但一个被替换行仍可能夹带多个无据承诺。表示收益不能归为 Memory 收益，工程通过也不能替代语义或行为验证，见[验证计划](V23_3_VALIDATION_PLAN.md)。

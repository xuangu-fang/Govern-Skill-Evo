# 显式步骤状态与全局菜单引用：验证结果

**离线等价验证通过；两项目标读取错误本次均未复现，但模型读取整体门槛仍未通过。** R05 存在一项真实的跨历史来源动作混淆；两组还各有两项完整 ID 与局部 ID 的输出契约差异。建议保留两项设计改进，先统一 trace 的来源标识与题目输出契约，再考虑后续生产生成验证。

本轮仅新增本实验目录。没有接入正式默认输入，没有执行生产 Preconditioner/Patch 生成、Editor、Actor、Replay 或 Memory commit。2 次逻辑调用、2 次 HTTP，无重试、无追加生成。原有失败结果与评分均保留。

## 两项实现

1. 每个选中的详细步骤直接包含 `step/before/action/after`，step 使用完整来源 ID，例如 `S1_R03/Q4:13`。不再根据窗口内 after 数组下标推导 before。
2. 状态中的 `commands_ref` 直接指向全局 `command_pool`，取消模型视图中的局部 `C1 → menu_*` 映射。同内容、同顺序的命令列表仍共享；原局部映射只存入审计文件。

全部 active entries、历史来源集合、±2 窗口、原始观察、命令内容、完整动作/反馈 trace、结果、Diff 和缺失范围保持与 v1 相同。没有新增检索 LLM，也没有加入预计算的来源数量、窗口步数或题目答案。完整 trace 本轮仍保留局部 step ID，这与详细步骤的完整 ID 形成了两套表示，后续结果暴露了该问题。

实现见 [compact_v2.py](compact_v2.py)、[格式说明](MODEL_FORMAT.md)；局部映射见各 case 的 `audit_menu_aliases.json`，不发送给模型。

## 原有两项错误的结果

两组的 `inside_window` 与 `menu_namespaces` 均通过：

- 正确读取 `S1_R03/Q4:13` 的 diningtable 动作前观察及对应全局命令引用。
- 正确区分两个目标历史来源的命令列表，没有把不同来源的同名局部菜单当成同一张表。

R05 上轮的窗口详细步数与来源数量错误，本轮也通过；没有添加计数答案提示。R06 的实例/类别、实际 Diff 与缺失证据边界检查继续通过。

这是本次已知案例上的正面结果。两项修改同时发生，且模型有随机性；上轮 R05 reasoning_tokens=0，本次为8,587，客户端无法解释后端行为差异。因此不能声称这两项表示修改已被单独因果验证或能稳定消除错误。

## 剩余一项事实错误

R05 的 `omitted_precondition` 查询 `S1_R03/Q6:26`：

| 字段 | 原始事实 | 模型答案 |
|---|---|---|
| action | `go to cabinet 3` | `examine cabinet 4` |
| action_in_admissible_commands | false | true |
| 未提供的 before / 完整命令表 | null / null | null / null |

模型正确保留了缺失状态的 null，却读错了明确提供的动作与反馈。核对输入发现，错误答案的动作与合法性**恰好等于 `S1_R02/Q6:26`**；另一个来源 `S1_R04/Q6:26` 又是不同动作。由此可推断仍存在跨来源的同名局部步骤混淆，但不能从最终答案确定模型内部过程。

此次详细步骤已完整限定来源，完整 trace 仍只有 `Q6:26`，依赖外层 source 定位。省略详细状态的步骤只能查 trace，故这条路径仍有歧义风险。不能把问题解释成被压缩掉了动作：原动作和反馈在模型输入中完整存在。

## 四项引用格式差异与测试契约问题

两组的 `whole_trace` 与 `action_order` 均因同一原因被严格评分拒绝：

- 参考答案：`Q2:25/Q2:30/Q2:36`、`Q4:13/Q4:15/Q4:17`。
- 模型答案：相同的来源和步骤位置，但使用 `S1_R03/…` 完整前缀。
- 动作位置、顺序、trace 长度、结果等其他字段全部相同。

这四项**不是事实位置或顺序错误**。新格式说明要求引用完整来源 ID，而沿用的题目只要求 step_ID_strings，严格答案仍使用局部 trace ID。格式说明与评分契约没有完全统一，是本次验证设计的缺口；不能将分数直接解释为读取能力退步。

为保留预注册记录，本轮未修改评分器、未事后改判通过，也没有再调用模型。严格门仍未通过；即使统一这四项引用格式，R05 上述真实动作/合法性错误仍然存在，不能据此宣告整体通过。

逐题期望与实际值：[R05 评分](runs/R05/evaluation.json)、[R06 评分](runs/R06/evaluation.json)。最终回答与原始 HTTP 响应已分别归档；没有用内部 reasoning 内容评分。

## 结论与下一步

**保留显式 before/after 和直接全局菜单引用；暂不进入正式默认或生产 A/B。**

下一项最小修改应是把完整 trace 的 step ID 也统一为 `source/step`，详细步骤与 trace 使用同一身份；来源关系由程序确定，不需要检索 Agent 或额外 LLM。同时明确所有题目的步骤输出契约并在调用前冻结对应参考答案，消除局部/完整 ID 的评分冲突。

该修改尚未执行或调用模型。之后仍应先离线核对全部动作、反馈、顺序和来源绑定，再检查相同事实，尤其保留本次出错的 `S1_R03/Q6:26`。当前证据尚不支持“可稳定理解所有历史”“策略质量改善”或“生产 Patch 生成通过”等结论。

最终检查：冻结文件 SHA-256 一致，4,005 个既有相关文件 size/mtime 未改变，见 [保护记录](results/protection.json)。完整机器可读结果见 [summary.json](results/summary.json)。

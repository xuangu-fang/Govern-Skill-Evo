# 明显事实错误筛查：判定边界 v1

目标是减少明显、重要、当前输入能够识别的错误进入 Memory，不证明整条 Knowledge，也不保证所有错误均能发现。本文件和 Prompt 在新版模型运行前冻结；本次不运行模型。

## 拦截门槛

同时满足：能用当前输入指出具体问题；影响被保存的事件事实、决策机会、结果比较、规则适用条件或重要解释；不需要补读轨迹或复杂因果分析。具体引用的动作/对象/位置错写属于重要事实错误，即使删除该错误例子后总体经验仍成立也应修正。对没有具体事件绑定的概括性措辞，结合它是否改变关键经验判断重要性，不机械挑词。

| 情况 | 本版处理 |
|---|---|
| 指定步骤的动作、对象、位置、身份、结果被写反或写错 | 有明确原始记录时拦截 |
| 已提供的前后状态明确揭示时间关系错误 | 拦截；不把 after 内容自动当成 before 已知 |
| 声称对象出现在某条观察中，但该条完整可见对象列表未包含它 | 拦截可见性断言；不声称对象在环境中不存在 |
| 只有任务描述出现对象名，或仅动作候选中没有 take | 不能据此认定对象可见/不可见；缺少观察本身不拦截 |
| observation 为 null、被截断、只说 Nothing happens，或对应时刻未提供 | 不能作为对象不可见的直接反证 |
| 重要的“从未/全部”结论被输入中明确例子反驳 | 拦截，不再审计其他完整轨迹 |
| 只有部分过程，没有反例 | 不因 first/only/all/never/identical 缺少覆盖而拦截 |
| 实际 Diff 同时修改多处，却称实验只改了一处、已控制其他改动 | 拦截与实验设置直接矛盾的描述 |
| 有限案例的伴随改善、保留不确定性的经验或假说 | 不要求证明唯一因果或普遍适用 |
| 错述明确的规则触发条件 | 若会误导后续经验使用且直接与 Diff/协议不符，拦截 |
| 轻微措辞或可合理理解为正确的概括 | 不作为决定性错误；审阅歧义单列 |

## 输出语义

继续使用 `results → target / verdict / issues` 和原严格 JSON/位置/引用校验器。`SUPPORTED` 是兼容旧协议的“本次未发现明显重要错误”，不是证据充分认证；`CONFLICT` 指明确需要修正的问题，不再包含单纯缺证据。永久 Memory 和 Replay 输出 Schema 不变。

支持通过的条目不输出逐断言证明、覆盖矩阵或缺证据清单。冲突反馈短而具体，只说明当前证据能证明的部分。仅依赖 context 的问题可按现有 Schema 使用空 evidence，但需指出具体字段；当前输入存在相应 diff 引用时优先引用它。

以下仅用于边界说明，不放入真实模型输入，不是模型实测：

- 原记录显示 go to rack，陈述却将该步写成 go to bin：CONFLICT。
- 陈述说从未开过盒子，已提供一个 open box 的动作：重要行为结论被反驳，CONFLICT。
- 同一陈述只附几次无关移动，未提供反例：SUPPORTED；没有证明其真实。
- 前状态明确门关闭，动作是开门，后状态才显示内部物品；声称开门前的该条观察已显示内部物品：CONFLICT。
- 只给开门后的状态、前状态未提供：不能仅凭缺少前状态拦截。
- 声称某次完整观察列出钥匙，该观察实际只列出书和杯：CONFLICT；不能延伸为房间内无钥匙。

## 本轮评价约定

基准仅根据即将给模型的去重输入及其恢复的等价记录决定应否拦截，不让模型负责识别未提供的反证。旧审阅和旧输出已可见，因此本版是前瞻冻结的开发集参考，不是盲评或独立人类金标准。旧版基准及指标不改写，也不回算旧输出宣称性能提升。

每条保存原 Knowledge、预期标签、理由、检查到的记录、接受的局限、旧标签与变更原因。明确问题另保存原文片段、真实字段值和检出判据；泛泛返回 CONFLICT 不自动算命中具体错误。基准说明和答案不进入 messages。

R01 `[0,3]` 的 stayed in drawers/shelves 可理解为主要搜索模式，也可理解为完全排他；Q6:2 的 before 已显示 desk 1，不能说输入没有任何相关反例。R03 `[0,4]` 的 needing a further open / no task-level benefit 也有动作记录与必要条件、成功率与步数的解释歧义。二者预期按宽松边界通过，但预先列为 `review_only`，不进入主检出/误拦截指标；以后无论模型输出如何，均须展示，不得临时改变归组。若人类确认应严格拦截，应另建基准修订版。

后续若运行：先报有效输出覆盖率，再在 `primary` 项上统计判定与具体问题检出。缺失/截断响应不计为漏检或正确；`review_only` 单列。通过项包含“证据不足但允许通过”，不能把通过项计数称为已证实事实数。当前没有新版运行结果，不计算检出率或模型改善幅度。

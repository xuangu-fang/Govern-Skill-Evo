# 有限反馈真实小规模验证结果

本轮 6 次真实请求全部结束，均为 `finish_reason=stop`，无截断或传输失败。两组完整校验通过均为 **0/3**；重复原先首个诊断的次数为原样组 **2/3**、反馈组 **1/3**。反馈在两个案例中帮助越过原错误，但尚不能认为它已解决重复失败或人工重启问题。

| 历史失败 | 原样续试一次 | 带反馈续试一次 |
| --- | --- | --- |
| JSON 正文不是合法 JSON | 再次出现同一 JSON 解析错误 | JSON 可解析；随后因 `u1.reason` 把 `step_limit` 加反引号失败 |
| 引用格式：动作命令被加反引号 | 再次把 `heat apple 1 with microwave 1` 当作引用 | 原引用错误消失；随后 `u3` 补丁 Hunk 1 零匹配 |
| schema：Adjustment 缺少 `to` | 必需字段齐全；随后 `u3.reason` 的 `P6` 缺反引号 | `u1`–`u3` 仍缺 `to`；再次报 `Adjustment: unexpected fields` |

引用案例的补丁零匹配并非反馈引入：原响应已经包含完全相同的补丁，单独对原始 Update 应用同样得到零匹配。反馈保留了全部非 reason 的 Adjustment 字段；另将 c1 Check 中 heat/cool 的反引号改成普通文字，未发现该处实质含义变化。不能把越过第一处失败后暴露的下一处失败统称为新错误。

schema 案例暴露了反馈内容的具体不足：`Adjustment: unexpected fields` 没有指出哪个 Update 缺少哪个字段。反馈结果只给 u4 补上 `to`，其余三个仍遗漏。当前证据支持优先完善这类诊断的定位，再做一次小验证；不能据此确定模糊诊断就是失败的唯一原因，也不支持现在堆叠 Prompt、放宽校验或扩大重试预算。

这只是 3 对历史失败续试：每组各生成一次，全部使用相同当前精简 Prompt、Knowledge Only 输入、模型和 32,768 输出预算。历史失败源于较早 Prompt，当前事实与原输入按解析后的内容核对一致。原样组不带旧响应，反馈组按生产函数加入旧正文和诊断，因此比较的是整套反馈消息的作用，而非单独诊断文字的作用。没有检验新 Campaign 的自然错误率，也未运行 Actor 或评估任务成功率。校验器仅报告首个失败，不能将未报告的后续错误视为不存在。

实际发送的 6 份请求均已核对冻结 messages 和输出预算，未使用独立推理字段作为反馈，未追加第七次请求。完整响应、HTTP 档案、校验结果和 usage 均留存。现有生产代码、Prompt、旧实验保持不变。

# Replay 条件性认识候选设计

基于 P4 `v23_4_replay_multi_knowledge_v1`，候选命名为 `v23_4_replay_multi_knowledge_conditional_v2_candidate`，只存在本隔离实验目录。完整主 Prompt 为 replay_conditional_learning_v2.md；Actor/Memory/Pair 说明仍使用原程序拼接内容。

## 真正改变的决策要求

| 决策 | P4 已有内容 | 候选的重组 |
|---|---|---|
| 先决定比较什么 | 识别实际编辑、survey all pairs、再检查相关轨迹 | 明确由实际行为要求及其范围定义比较对象；全局任务数字用于发现材料，不作为 Knowledge 的组织骨架 |
| 如何解释行为相同或不同 | 列机会、遵循、局部与整体、归因限制 | 用编辑相关条件组织响应，再分别判断适用性、可观察执行、是否新增收益；不把这三件事压成有效/无效 |
| 什么值得形成 Knowledge | 独立、有范围、有证据、适当粒度 | 先从支持的响应建立条件性关系，再判断其对未来修改的方向、范围、交互或能力保持有什么参考价值；仍不输出 D/S/C 标签或更新指令 |
| 如何保留历史 | 全数组替换、逐项审视、保留有效比较 | 先确定当前证据带来的新支持与限制，再对旧认识协调；将保留历史观察与保留其旧解释分开，输出完整最终数组 |

这不是声称 P4 没有这些原则。P4 已要求实际 Diff、作用范围、机会不对称、局部结果、校准历史和独立 Evidence；候选把散布的学习和复核要求合并到形成认识的顺序中。唯一更明确的推断边界是：没有违规不能证明全局规则未使用。它是跨领域的适用/执行/收益区分，不针对某个对象。

## 保留与合并

- 保留 Diff 优先于 Plan、真实 Pair、独立时间轴、当前完整证据、历史详细窗口边界、实际反馈与技术中断的区分。
- 保留局部响应与总结果、联合编辑的归因限制及重要不对称比较。
- 将 P4 Knowledge 粒度/独立性/条件/泛化约束合并为“Form useful conditional understandings”；未来价值作为选择认识的依据，而非要求生成更多条目。
- 将历史逐类列表、新建/修订/不更新列表和重复 completeness 提醒合并为主题协调与完整替换。
- 保留证据支持、双侧引用、未来窗口作用及引用格式。主 Prompt 不新增检查表输出。
- 输出契约从 P4 原样复制；Memory Schema、验证、存储、压缩和算法未改变。总主 Prompt 由 16,084 字符变为 12,890 字符；这只是规模说明，不作为效果依据。

## 评估与版本边界

先冻结候选和输入，再各调用一次 R05/R06，使用原证据校验与隔离提交。基线是使用 P4 学习 Prompt 的既有 P6 合法输出，不重新调用基线。按 PROTOCOL.md 评价，不以语义结果重采样。

潜在风险：更强调跨任务价值可能让模型过早泛化；更强调当前支持再协调历史可能遗漏旧比较；缩短提示可能减少逐项核对力度。这些用真实输出检查，不能因表述更清晰预先认定改善。真实结果出来前不决定采用，不修改生产 Prompt 注册表。

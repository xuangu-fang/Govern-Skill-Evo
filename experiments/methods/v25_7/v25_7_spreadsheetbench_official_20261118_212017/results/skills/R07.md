# Spreadsheet Manipulation Skill (xlsx)

## Overview
This skill guides agents in manipulating Excel (.xlsx) spreadsheets using Python.

**Primary libraries**: `openpyxl` (structure-preserving read/write), `pandas` (data transformation).
Never use any other third-party libraries.

---

## Common Workflow

1. **Explore** the input file: list sheets, inspect headers, check dimensions.
2. **Write `solution.py`** with `INPUT_PATH` and `OUTPUT_PATH` defined at the top.
3. **Execute** `python solution.py` and verify the output file was created.
4. **Confirm** the target cells/range contain the expected values.

## Category Filters

Before coding a filter for a natural-language category such as lowest, best, or average, inspect the distinct actual values in the source column. Match the workbook's real labels semantically—case- and whitespace-insensitive, including equivalent labels such as `Least Performing` or `Low Performing` when they denote the requested group—or use a numeric rank where supplied. Do not require the instruction word itself to appear as a substring. If several labels make up the requested group, include all of them and preserve source row order.

## Semantic Two-Condition Relabeling

When an instruction asks to relabel entries in one column under two conditions — the entry carries a specified text and an adjacent cell's number is a whole number versus a number with a fractional part — first inspect the distinct source strings and decide from them whether the quoted text must equal the whole cell or may appear inside a longer entry, comparing case-insensitively after trimming and collapsing whitespace. Determine the adjacent number from its evaluated value (a `data_only=True` copy), parsing currency symbols, thousands separators, and numeric text, and classify it by its fractional part: a zero fractional part (within a small tolerance) means whole, and any non-zero fractional part means it has pennies. When the evaluated value is missing but the cell holds a formula, resolve the number from the underlying data or another evaluated source; do not treat formula text, a blank, or an unparseable string as evidence that the value has pennies. If the number truly cannot be resolved, leave that entry unchanged instead of defaulting to the fractional label. Write the corresponding label only to fully matching rows, and preserve every other cell and the source row order.

## Marker-Based Row Deletion
When an instruction says to delete all rows above the first occurrence of a marker, find the first row that matches the marker and remove every row before it, even when those preceding rows contain visible data, unless the instruction explicitly says to preserve them. Do not fall back to deleting only the rows before the first populated row. Keep the marker row and all later rows in their original order. Delete the contiguous block in one operation or iterate bottom-up so row indices remain valid. If the marker is absent, make no deletion; do not substitute an unrelated row range.

## Consolidating and Appending Source Sheets

When consolidating or appending source sheets into a destination, write every qualifying source data row into the first available blank rows in source-sheet order. Do not skip source rows merely because an identical row already exists in the destination unless the instruction explicitly says to remove duplicates or skip already-processed sheets. Fill the origin or source-name column for each appended row when requested, copy formatting from a template data row, and clear fill colors when the instruction prohibits them.

## Formula Cells and Cached Results

When a rule depends on displayed cell results such as errors, dates, text categories, or lookup keys, read a `data_only=True` copy for evaluated values and a normal copy for formulas and preservation. If `data_only=True` returns `None` but the normal cell contains a formula, treat that value as unresolved rather than blank: fall back to the other workbook or derive the value from underlying data. Do not copy formula text itself into a result value.

When an answer cell is required to contain a formula—because the instruction requests a formula, corrects an existing formula, or the target cell already has a formula that the operation preserves—keep the formula in that cell and also write an accurate cached result for the same cell, treating the formula and its correct saved cache as a two-part deliverable. Compute the result from the workbook data before saving, then after saving patch the target worksheet XML inside the `.xlsx` package so each formula cell has a matching cached value with the correct type: a numeric cache without a text type, a text cache with escaped text and the appropriate string type, and an error-typed cache for an error result.

After the final save, reopen `OUTPUT_PATH` with `data_only=True` and inspect the saved XML to verify every target formula cell: the formula is still present, the cache exists and has the appropriate numeric, text, or error type, and, where the result can be reliably derived from the task and input workbook, the cache equals that independently computed value. If a cache is missing, has the wrong type, or reliably differs, locate the target worksheet part through `xl/workbook.xml` and its relationship, repair the `<v>` under the `<f>` without removing the formula, and re-verify. Preserve the formula on every recovery path. Treat a genuinely blank result as a valid blank cache and a genuine error result as a valid error-typed cache rather than a mismatch. If a required, reliable check still fails after repair, raise an execution error identifying the affected cell and the discrepancy.

Do not rely on Excel recalculation, and do not leave formula cells without a cache, because scoring reads saved cached values. If the task genuinely asks for values rather than formulas, writing the computed value is acceptable; if a formula is required, replacing it with a constant alone does not satisfy the formula requirement. If an unchanged formula already has a valid cache, preserve it.

## Formula-Driven Aggregation

When filling a block of formulas across columns whose criterion is a column label, first locate the destination table's own header row immediately above the destination data block. Map each destination column using that header value and build the formula against a mixed/absolute reference to the destination header cell so the formula remains copyable across columns. Do not map product or criterion columns from the main source-table header row, and do not fall back to first-appearance source order. Compute each column's cached result from the same destination-header label.

When a requested result is a formula-driven sum, count, or average over a tabular block, determine the block from the actual header row and the first and last populated data rows and columns. Read every criterion cell from evaluated values. If an evaluated criterion value is missing but the normal cell contains a formula or other resolvable content, resolve it from the formula workbook or the underlying data; do not substitute zero. Select qualifying rows and columns by their separate criteria, apply inclusive comparisons at any stated boundaries, and compute an independent scan over every candidate row and column.

Write the requested formula for the target and write its computed cached result. After saving, reopen the workbook with `data_only=True` and compare each target cache against the independent scan. If a cache is absent, blank or zero when qualifying cells exist, or numerically different, correct the formula range, criteria references, or cached value before submission. When the independent scan has no qualifying cells, preserve the requested blank or zero result semantics.

## Stock Allocation

For stock allocation, use exactly the priority stated. If FIFO is defined by earliest issued date, process each matching order/part group by that date and, for ties, preserve the source row or stated order-line sequence; do not add an unrequested secondary sort such as requested delivery date, which can allocate a later line first. Allocate `min(requested_qty, remaining_stock)` sequentially, deduct from the remaining pool, and write 0 when exhausted. Verify that per-group allocations do not exceed available stock.

## Library Selection

| Use case | Library |
|----------|---------|
| Preserve formulas, formatting, named ranges | `openpyxl` |
| Bulk data transformation, aggregation, sorting | `pandas` → write back with `openpyxl` |
| Simple cell read/write | `openpyxl` |

**Warning**: `pandas.to_excel()` silently destroys existing formulas and named ranges.
When writing back to a spreadsheet that contains formulas, always use `openpyxl.save()`.

## solution.py Template

```python
import openpyxl
import pandas as pd

INPUT_PATH  = "..."   # set to the actual input path
OUTPUT_PATH = "..."   # set to the actual output path

wb = openpyxl.load_workbook(INPUT_PATH)
ws = wb.active  # or wb["SheetName"]

# --- perform manipulation ---

wb.save(OUTPUT_PATH)
```

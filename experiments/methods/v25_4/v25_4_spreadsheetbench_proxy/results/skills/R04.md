# Spreadsheet Manipulation Skill (xlsx)

## Overview
This skill guides agents in manipulating Excel (.xlsx) spreadsheets using Python.

**Primary libraries**: `openpyxl` (structure-preserving read/write), `pandas` (data transformation).
Never use any other third-party libraries.

---

## Common Workflow

1. **Explore** the input file: list sheets, inspect headers, check dimensions.
2. **Write `solution.py`** with `INPUT_PATH` and `OUTPUT_PATH` defined at the top.
3. **Execute** `python solution.py` and verify the output file was created.
4. **Confirm** the target cells/range contain the expected values.

---

## Library Selection

| Use case | Library |
|----------|---------|
| Preserve formulas, formatting, named ranges | `openpyxl` |
| Bulk data transformation, aggregation, sorting | `pandas` → write back with `openpyxl` |
| Simple cell read/write | `openpyxl` |

**Warning**: `pandas.to_excel()` silently destroys existing formulas and named ranges.
When writing back to a spreadsheet that contains formulas, always use `openpyxl.save()`.

### Formula caches and `data_only`

When formulas are involved, load the workbook twice: a `data_only=False` copy that you mutate and save (so formulas, formatting and named ranges are preserved), and a `data_only=True` copy used only to read existing cached results and source values. openpyxl does not calculate formulas, and evaluation reads saved cell values with `data_only=True`, so a formula you write has no readable value unless a cache exists.

When a target cell must hold a formula but scoring reads saved values, compute the result in Python, write the formula into the cell, save, and then inject that computed result into the cell's cached `<v>` in the worksheet XML. Locate the worksheet part robustly rather than guessing a path: read the workbook part's sheet entry to obtain its relationship id, look up the matching relationship target, and normalize that target once — strip a leading `/` when the target is package-absolute, keep it as is when it already begins with `xl/`, and only otherwise join the relative target onto `xl/` — so that a doubled prefix such as `xl//xl/worksheets/...` can never be produced. Inside the sheet XML, find the cells with a namespace-aware recursive search: `<c>` elements live under `sheetData > row` and are not direct children of the worksheet root, so search `.//{main}c` (or `.//{main}sheetData/{main}row/{main}c`) — a regex over the whole sheet XML that matches the cell's `r` attribute is an equivalent alternative. Preserve the cell's existing `<f>` formula, remove or replace any old `<v>`, and give the cache the correct type: no `t` attribute for a numeric result, `t="str"` for a text result, `t="b"` for a boolean. When the task only requires the computed result and not a formula, write the value directly instead. Reopen the saved file afterwards and confirm the target reads back the computed value, so that an injection that silently changed nothing cannot pass unnoticed.

After saving, reopen the saved output with `data_only=True` and confirm that every required formula target has a non-None cached value matching the value you computed. If a target is still missing or wrong, repair its cached value in the saved file and recheck; if it still fails, raise an execution error naming the cell together with its expected and observed value so the program can be corrected.

## solution.py Template

```python
import openpyxl
import pandas as pd

INPUT_PATH  = "..."   # set to the actual input path
OUTPUT_PATH = "..."   # set to the actual output path

wb = openpyxl.load_workbook(INPUT_PATH)
ws = wb.active  # or wb["SheetName"]

# --- perform manipulation ---

wb.save(OUTPUT_PATH)
```

### Date and time values

When the task asks for a cell to display or be formatted as a date or time, write the underlying date/time value and set the cell's `number_format` to the requested pattern instead of writing a preformatted text string. This keeps the cell value type and display consistent with the request; if a formula is required, combine it with a cached temporal value.

### Worked examples take precedence over summary wording

When an instruction's general summary wording conflicts with explicit worked examples or a detailed operational specification in the same instruction, treat the examples and the detailed requirements as authoritative for the exact output: label text and spelling, value type and formatting, how multiple values are combined or collapsed, and their order.
